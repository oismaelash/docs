A Pilot Status foi construída para ser operada por IA. Existem três formas complementares de conectar LLMs e agentes ao WhatsApp: o **servidor MCP** hospedado, a **API REST** simples com o cabeçalho `x-api-key` e os **bots orientados por webhook** que reagem a mensagens recebidas em tempo real.

## Servidor MCP (conector hospedado)

A Pilot Status disponibiliza um servidor oficial de Model Context Protocol que expõe a API pública `/v1` como **148 ferramentas MCP** — enviar mensagens, ler conversas e mensagens não lidas, gerenciar números, templates, webhooks, grupos, chamadas de voz e muito mais.

O conector hospedado roda em:

```text
https://mcp.pilotstatus.com.br/mcp
```

Adicione-o no claude.ai em **Configurações → Conectores → Adicionar conector personalizado**. O claude.ai executa o login OAuth 2.1 (SSO da Pilot Status) — nenhuma chave de API é compartilhada com o cliente. Durante o login você vê uma **tela de consentimento** onde aprova o acesso a **toda a conta** (só proprietário ou administrador do workspace) ou concede apenas **números específicos** (uma concessão por número restringe todas as ferramentas a esses números). A conexão age no workspace selecionado na sua sessão da Pilot Status no momento da autorização. O Claude Code e o ChatGPT conectam com OAuth do mesmo jeito; o Cursor e o VS Code usam uma chave de API. Passo a passo de cada cliente: [Conectar o seu cliente](/pt-BR/integrations/mcp-server#conectar-o-seu-cliente).

Clientes configurados por arquivo podem pular o OAuth e enviar uma chave `ps_*` no cabeçalho `x-api-key`:

```json
{
  "mcpServers": {
    "pilot-status": {
      "type": "http",
      "url": "https://mcp.pilotstatus.com.br/mcp",
      "headers": { "x-api-key": "ps_sua_chave_aqui" }
    }
  }
}
```

Com uma conexão OAuth ou uma chave de workspace, passe `whatsappNumberId` (obtido em `numbers_list`) a toda ferramenta que age num número — mensagens, conversas, templates, webhooks; uma chave de número (`ps_number_…`) já indica o número.

Dois endpoints, mesmas credenciais — conecte um deles por agente, não os dois:

- **`/mcp`** — as 148 ferramentas; o seu cliente mostra cada chamada para você aprovar. Melhor para uma ou duas chamadas por vez.
- **`/code`** — [modo de código](/pt-BR/integrations/mcp-code-mode): duas ferramentas, `describe` e `execute`, e o agente escreve um script TypeScript que chama `await ps.<ferramenta>(args)`. Melhor para laços, relatórios e contexto apertado.

As ferramentas destrutivas (`templates_delete`, `workspace_archive`, `workspace_transfer_ownership`, `workspace_members_remove`) devolvem antes uma prévia e um `confirm_token`; o agente precisa mostrar a prévia e esperar o seu sim antes da segunda chamada. [Confirmação para ferramentas destrutivas](/pt-BR/integrations/mcp-server#confirmação-para-ferramentas-destrutivas)

Consulte a [página do Servidor MCP](/pt-BR/integrations/mcp-server) para autenticação e hospedagem própria, e a [Referência de ferramentas MCP](/pt-BR/integrations/mcp-tools) para todas as ferramentas com os argumentos obrigatórios.

## Ensine qualquer LLM sobre a Pilot Status

Aponte seu modelo ou agente de código para a referência canônica legível por máquina:

```text
https://pilotstatus.com.br/llms.txt
```

Ela vincula endpoints, esquemas de webhook, conceitos e códigos de erro — tudo o que uma IA precisa para escrever uma integração correta.

## Bots orientados por webhook

O padrão clássico: inscreva um webhook em `message.received`, passe o payload pelo seu LLM e responda pela API.

```javascript
app.post("/hooks/whatsapp", async (req, res) => {
  res.sendStatus(200); // acknowledge first
  const { event, data } = req.body;
  if (event !== "message.received") return;

  const reply = await llm.complete(data.content); // your model call

  await fetch("https://pilotstatus.com.br/v1/messages/send", {
    method: "POST",
    headers: {
      "x-api-key": process.env.PILOT_STATUS_API_KEY,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ text: reply, destinationNumber: data.from }),
  });
});
```

<Tip>
  A Pilot Status dispara webhooks em milissegundos após cada evento, então os agentes podem responder quase instantaneamente. Faça a deduplicação por `data.id` e mantenha seu handler rápido — execute a chamada ao LLM de forma assíncrona.
</Tip>

Os detalhes de configuração estão no [guia Receber Mensagens](/pt-BR/guides/receive-messages).

## API REST direta

Qualquer framework capaz de fazer requisições HTTP (LangChain, n8n, Make, backends personalizados) pode usar a API diretamente. A autenticação é sempre pelo cabeçalho `x-api-key: ps_...`; a URL base é `https://pilotstatus.com.br/v1` e o único endpoint de envio é `POST /v1/messages/send` (modo template, texto ou mídia). Os [SDKs](/pt-BR/integrations/sdks) oficiais encapsulam isso para Node.js, Python e n8n.
