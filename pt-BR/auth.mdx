Esta página é para **agentes de IA e desenvolvedores** que precisam se autenticar na Pilot Status (API de mensagens do WhatsApp). Ela é autossuficiente: tudo o que um agente precisa para obter e usar uma credencial está aqui.

## Obter uma credencial

Não há cadastro automático pela API. Uma pessoa cria a conta e a chave:

1. Cadastre-se em [https://pilotstatus.com.br](https://pilotstatus.com.br).
2. No painel, abra **Chaves de API** e crie uma chave. As chaves começam com `ps_` (por exemplo `ps_workspace_...`, `ps_number_...`, `ps_account_...`).
3. Guarde a chave como segredo (variável de ambiente, cofre). Ela aparece uma única vez.

Veja [Chaves de API no painel](/pt-BR/dashboard/api-keys) e [Tipos de chave](/pt-BR/concepts/key-types).

## Métodos

### API REST: `x-api-key`

URL base: `https://pilotstatus.com.br/v1`. Envie a chave no cabeçalho `x-api-key`.

```bash
curl https://pilotstatus.com.br/v1/numbers \
  -H "x-api-key: ps_sua_chave"
```

Detalhes: [Autenticação da API](/pt-BR/api/authentication).

### Servidor MCP: `x-api-key` ou `Authorization: Bearer`

Endpoint: `https://mcp.pilotstatus.com.br/mcp` (Streamable HTTP). Aceita a chave `ps_` em qualquer um dos cabeçalhos:

```http
x-api-key: ps_sua_chave
```

```http
Authorization: Bearer ps_sua_chave
```

Detalhes: [Servidor MCP](/pt-BR/integrations/mcp-server).

### OAuth 2.1 para conectores MCP

Clientes MCP que não guardam uma chave fixa (por exemplo os conectores do claude.ai ou do ChatGPT) usam OAuth 2.1:

- Metadados do servidor de autorização: `https://pilotstatus.com.br/.well-known/oauth-authorization-server`
- Registro dinâmico de cliente (RFC 7591): `POST https://pilotstatus.com.br/api/oauth/register`
- Fluxo authorization code com **PKCE `S256`** (clientes públicos, `token_endpoint_auth_method: none`)
- Grant types: `authorization_code`, `refresh_token`

O usuário entra e consente no navegador; o conector então envia `Authorization: Bearer <access_token>` ao servidor MCP.

#### Escopos

| Escopo | Permite |
|---|---|
| `messages:send` | Enviar mensagens |
| `messages:read` | Ler logs e conteúdo de mensagens |
| `conversations:read` | Ler conversas |
| `numbers:read` | Listar e ler números |
| `numbers:write` | Atualizar números |
| `templates:read` | Ler templates |
| `templates:write` | Criar e gerenciar templates |
| `analytics:read` | Ler analytics |
| `flows:read` | Ler WhatsApp Flows |

Nenhum token é emitido com um escopo que o papel do membro que consentiu não tenha.

## Usar a credencial

- Envie-a em toda requisição; não há sessão nem cookie.
- `401` significa credencial ausente, inválida, revogada ou expirada. Clientes OAuth devem renovar ou autorizar de novo.
- `403` significa credencial válida, mas sem permissão para aquela ação.
- Nunca coloque a chave em código do navegador, URLs ou logs. Se vazar, gere outra no painel.
