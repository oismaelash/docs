A **Skill da Pilot Status** ensina um agente de IA a usar a API pública `/v1` por meio de uma ferramenta de linha de comando incluída, o `pilot-status`. Funciona no Claude Code, no Claude Desktop / claude.ai (com execução de código), no Codex e em qualquer agente compatível com [Agent Skills](https://agentskills.io). Você também pode usar o CLI diretamente.

- **Login OAuth** no navegador, o mesmo servidor de autorização do [MCP hospedado](/pt-BR/integrations/mcp-server). Nenhuma chave para copiar; o token fica na sua máquina e se renova sozinho.
- **Chave de API** para CI e servidores (`PILOT_STATUS_API_KEY`).
- **Um comando por recurso da API pública**: os mesmos nomes e argumentos das ferramentas do MCP.
- **Ações destrutivas ou pagas, e envios a terceiros, nunca rodam sem confirmação**: mostram uma prévia e param até você repetir o comando com `--yes`.

Requer **Node.js 18+**. Sem dependências: o CLI é um único arquivo.

## Login

```bash
node pilot-status/scripts/pilot-status.mjs login
```

O navegador abre na tela de consentimento da Pilot Status (aparece como **Pilot Status CLI**). Aprove para o workspace desejado.

- **Sem navegador nesta máquina** (SSH, container): `login --no-browser`, abra a URL impressa em qualquer lugar e cole de volta a URL em que o navegador terminou.
- **Vários workspaces**: um login por workspace com `login --profile <nome>`; depois `--profile <nome>` em qualquer comando, ou `use <nome>`. `profiles` lista todos.
- **CI / servidores**: defina `PILOT_STATUS_API_KEY` (tem prioridade sobre qualquer perfil) ou use `login --api-key` lendo a chave da entrada padrão.
- **Sair**: `logout` revoga o login. Um token de acesso já emitido vale no máximo mais uma hora.

As credenciais ficam no Secret Service do Linux quando disponível; senão, em `~/.config/pilot-status/credentials.json` com permissão `0600`. No macOS o Keychain é opcional: `PILOT_STATUS_CREDENTIALS=keychain`.

## Uso

```bash
pilot-status tools --group messages          # lista os comandos
pilot-status describe <comando>              # descrição + JSON Schema dos argumentos
pilot-status run <comando> --json '{"...":"..."}' [--number <id-do-numero>]
pilot-status api GET /v1/...                 # qualquer endpoint, direto
```

Todo comando imprime JSON. `--json @arquivo.json` e `--json -` (entrada padrão) também funcionam.

### Confirmação antes de ações destrutivas, pagas ou de envio

Apagar, sobrescrever, desconectar, cobrar ou **enviar algo a terceiros** (mensagem ou template, story, grupo, ligação) **nunca acontece na primeira chamada**. O comando mostra `"status": "CONFIRMATION_REQUIRED"` com uma prévia (telefones mascarados nos 4 últimos dígitos) e sai com código `3`. Repita o mesmo comando com `--yes` para aplicar. A Skill instrui o agente a mostrar a prévia e esperar o seu sim explícito.

Jobs sem uma pessoa (CI, cron) que precisam enviar sem confirmação definem `PILOT_STATUS_ALLOW_SEND=1`. Ela dispensa a confirmação **só de envio**: comandos destrutivos e pagos continuam pedindo `--yes`. Um agente nunca a define. `tools` e a prévia dizem por que um comando pede confirmação (`confirmReason`: `destructive`, `charge` ou `send`).

### Códigos de saída

| Código | Significado |
|---|---|
| `0` | OK |
| `1` | Erro da API (veja `error` / `code`) |
| `2` | Uso incorreto |
| `3` | Confirmação necessária |
| `4` | Faça login de novo |
