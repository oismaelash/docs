Incorpore a **caixa de entrada do WhatsApp (Chat)** do Pilot Status no seu próprio SaaS, white-label, por meio de um iframe hospedado mais o SDK `@pilot-status/embed`.

## Pré-requisitos compartilhados (Chat \+ Connect)

1. **Chave de API do tenant** (`ps_`, com escopo de tenant) — gerada em **Chaves do workspace** (`/workspace-api-keys`). Ela **nunca** sai do seu backend. (Uma chave com escopo de número só pode incorporar o próprio número.)
2. **SDK** — `<script src="https://pilotstatus.com.br/embed.js">` ou `npm i @pilot-status/embed`; chame `PilotStatus.init()`.
3. **`allowedOrigins`** — ao emitir o token do Chat, liste as origens exatas (`scheme://host[:port]`, 1–20) autorizadas a incorporar.
4. **Token por superfície** — o Chat usa `POST /v1/embed/sessions` (`surface: "chat"`, um JWT de curta duração mantido em memória). O Connect usa `POST /v1/numbers/remote-pairing` (um token de pareamento na URL — veja [Incorpore a Página de Connect](/pt-BR/integrations/embed-connect)).
5. **Renovação** — o TTL do token do Chat é de 15 min com uma janela de atualização deslizante; ao expirar por completo, o SDK chama `onSessionExpired`.

## Fluxo do Chat

<Steps>
  <Step title="Configuração única">
    Seu backend lista os números com `GET /v1/numbers` (`x-api-key`) e armazena o mapa `cliente → [whatsappNumberIds]`.
  </Step>
  <Step title="Emita um token a cada carregamento de página">
    Seu frontend solicita um token ao seu backend; o backend chama:

    ```bash
    curl -X POST "https://pilotstatus.com.br/v1/embed/sessions" \
      -H "x-api-key: ps_your_tenant_key" \
      -H "Content-Type: application/json" \
      -d '{
        "surface": "chat",
        "whatsappNumberIds": ["wn_abc123"],
        "allowedOrigins": ["https://app.yoursaas.com"],
        "ttlSeconds": 900
      }'
    ```

    Resposta `201`: `{ token, surface, whatsappNumberIds, allowedOrigins, expiresAt }`. O backend encaminha **apenas o JWT** para o frontend.
  </Step>
  <Step title="Monte a caixa de entrada">
    ```html
    <script src="https://pilotstatus.com.br/embed.js"></script>
    <div id="inbox"></div>
    <script>
      PilotStatus.init();
      const { token } = await fetch("/api/my-saas/embed-token").then(r => r.json());
      const chat = PilotStatus.chat.mount("#inbox", {
        token, locale: "en", theme: "light",
        onUnreadCount: (n) => {},
        onConversationOpened: (id) => {},
        onSessionExpired: async () => {
          const { token: t } = await fetch("/api/my-saas/embed-token").then(r => r.json());
          chat.destroy();
          PilotStatus.chat.mount("#inbox", { token: t, locale: "en" });
        },
      });
      // chat.setTheme("dark"); chat.setLocale("pt"); chat.destroy();
    </script>
    ```
  </Step>
</Steps>

## Altura do chat (SDK 0.3.0)

A partir do `@pilot-status/embed` **0.3.0** o iframe do chat tem **altura fixa**: ele não cresce mais com a conversa. A lista de mensagens rola dentro do iframe e o campo de mensagem fica fixo embaixo.

- A altura vem da opção `height` de `PilotStatus.chat.mount` (padrão `"600px"`; aceita qualquer medida CSS: `"600px"`, `"80vh"`, `"100%"`).
- Com `height: "100%"`, o container precisa ter altura própria (ex.: `height: 70vh` ou um layout flex com altura definida). `100%` de um container sem altura vira zero.
- Mensagem nova recebida **nunca desce a conversa sozinha**: aparece o botão de ir para as mais recentes, com o contador de novas. Quem envia a própria mensagem continua descendo.

```html
<div id="inbox" style="height: 70vh"></div>
<script>
  PilotStatus.chat.mount("#inbox", { token, height: "100%" });
</script>
```

<Warning>
Hosts com o SDK antigo (≤ 0.2.x) ficam nos 600px iniciais: o chat hospedado não envia mais `resize`. Atualize com `npm i @pilot-status/embed@^0.3.0`.
</Warning>

## Chamadas de WhatsApp no chat incorporado

Todo token de chat (`surface: "chat"`) pode **receber e fazer chamadas de WhatsApp**, sem opt-in e sem campo novo. O widget toca nas chamadas recebidas (atender / recusar / desligar) e pode ligar para o contato aberto. Tudo fica limitado aos `whatsappNumberIds` do token: chamada em qualquer outro número dá `403`.

- **Microfone:** o SDK já cria o iframe com `allow="microphone"`. Se você monta o `<iframe>` na mão, inclua `allow="microphone"`.
- **Configuração de chamadas** (ativar chamadas no número, preferências de atendimento) continua no painel da Pilot Status; o embed não altera.
- **Cobrança (Meta):** só **chamada iniciada pela empresa em número oficial (API Cloud da Meta)** é cobrada, pela Meta, na sua WABA: por minuto, em pulsos de 6 segundos, e só quando atendida. Chamada recebida (iniciada pelo usuário) é gratuita. Número conectado por QR code não tem cobrança da Meta. A Pilot Status não cobra nada pelas chamadas. Avise seus clientes com número oficial antes de mostrar o botão de ligar para visitantes.

## Protocolo postMessage (pai ↔ iframe)

Envelope: `{ source: "pilot-status-embed", v: 1, type, payload }`. Mensagens sem esse `source` são ignoradas; a origem é validada em **ambos** os lados.

| Passo | Quem | Mensagem |
| --- | --- | --- |
| A | SDK (pai) | cria `<iframe src="chat.pilotstatus.com.br/?parentOrigin=<origin>">` (sandbox `allow-scripts allow-same-origin allow-forms allow-popups`) |
| B | iframe → pai | `ready` (o SDK valida `origin === chat.pilotstatus.com.br`) |
| C | SDK → iframe | `init{ token, locale, theme }` (o iframe valida `origin === parentOrigin`) |
| D | iframe | mantém o token **em memória** apenas — nunca na URL/localStorage |
| E | iframe → pai | `resize{height}` (só Connect desde 0.3.0), `chat:unread-count{count}`, `chat:conversation-opened{conversationId}`, `session-expired` |
| — | SDK → iframe | `set-theme{theme}`, `set-locale{locale}` em tempo de execução |

## Modelo de segurança

- A `x-api-key` fica **apenas** no seu backend; o navegador só manipula o JWT de curta duração.
- O JWT tem **escopo rígido** para os seus `whatsappNumberIds` — as rotas do chat reverificam a cada requisição (defesa em profundidade).
- Token apenas em memória, TTL de ~15 min com atualização deslizante; `allowedOrigins` fixa quem pode incorporar; a origem do postMessage é validada em ambos os lados.
