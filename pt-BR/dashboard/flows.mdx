A tela Flows é onde você gerencia os [Flows do WhatsApp](/pt-BR/concepts/flows) de uma conta do WhatsApp Business (WABA): formulários que abrem dentro da conversa do WhatsApp. Você cria um rascunho, envia o JSON, confere o preview, publica e — nos Flows cujas telas chamam o seu backend — liga o endpoint `data_exchange`.

<Note>
  Flows existem apenas em **números Meta (API Oficial)**. Um Flow pertence à **WABA**, não ao número: todos os números Meta da mesma WABA veem a mesma lista.
</Note>

## Como chegar

Clique em **Flows** na barra lateral esquerda (marcado como **beta**) ou pressione **H** em qualquer lugar fora de um campo de texto. A rota é `/flows`.

A tela segue o número selecionado no topo do painel:

- **Flows** some da barra lateral enquanto o número selecionado não for Meta. Selecione um número Meta para ele voltar.
- Se você abrir `/flows` com um número não Meta selecionado, a tela diz **"Flows existem apenas em números Meta (API Oficial)."** e não oferece ações.
- Se o número é Meta mas ainda não tem WABA associada, a tela pede que você conclua a verificação da conta primeiro.

Não há limite por plano: a tela funciona igual em todos os planos.

## O que você vê

De cima para baixo:

1. **Cabeçalho** — os botões **Criar Flow** e **Gerar Flow com I.A.** (o botão de I.A. aparece só enquanto a I.A. estiver disponível na plataforma).
2. Filtro **Estado** — **Todos os estados**, **Rascunho**, **Publicado**, **Descontinuado**, **Bloqueado**, **Limitado**.
3. Aviso **Flow sem número** — só quando se aplica (veja a seção **Flow sem número**, abaixo).
4. Tabela **Flows da conta** — uma linha por Flow da WABA.
5. Um quadro dizendo **"Esta conta tem mais N Flows em outro número"** quando os seus outros números Meta estão em outras WABAs, com um botão **Ver os N de …** que troca o número selecionado.
6. Depois de clicar numa linha: a ação **Clonar**, **JSON do Flow**, **Preview do Flow**, o painel do endpoint, **Traços do endpoint (o que nós vimos)**, **Publicar** e a **Zona de perigo**. Antes de escolher um, a tela diz **"Escolha um Flow na lista acima."**

### A tabela de Flows

| Coluna | O que mostra |
| --- | --- |
| **Nome** | O nome do Flow, com o **ID do Flow na Meta** embaixo (ou **ainda não está na Meta**). |
| **Estado** | `Rascunho`, `Publicado`, `Descontinuado`, `Bloqueado`, `Limitado` — o estado na Meta. |
| **Categorias** | As categorias que a Meta usa para classificar o formulário. |
| **Versão do JSON** | A versão do Flow JSON que a Meta compilou. |
| **Saúde** | O veredito de saúde da Meta, ou **sem relato da Meta**. |
| **Atualizado em** | Última alteração. |

O rodapé mostra **Mostrando X de Y nesta conta do WhatsApp Business**, com **Anterior** / **Próxima** para paginar. Uma lista filtrada vazia pede que você volte o filtro para **Todos os estados** antes de concluir que não há nenhum Flow. Se a lista não carregar, a tela avisa e oferece **Tentar de novo** — isso não é o mesmo que a conta estar vazia, então não crie um duplicado.

## Ações e modais

### Criar Flow

**Criar Flow** abre o modal **Criar Flow**:

- **Nome** — exemplo *Formulário de contato*.
- **Categorias** — escolha ao menos uma: **Cadastro**, **Entrar**, **Agendamento**, **Geração de leads**, **Fale conosco**, **Suporte ao cliente**, **Pesquisa**, **Outra**.
- **Clonar de** — opcionalmente, parta de um Flow existente desta conta, ou mantenha **Não clonar — começar vazio**.

O Flow novo é criado na Meta como **rascunho**. Envie o JSON dele em seguida.

### Clonar um Flow

Com um Flow selecionado, **Clonar "nome"** abre o mesmo modal com o título **Clonar Flow**, já preenchido a partir desse Flow (o nome ganha *(cópia)*). Um Flow publicado é imutável na Meta, então clonar é como uma nova versão começa. O clone nasce como rascunho com uma cópia do JSON; publicá-lo continua sendo um passo à parte.

### Gerar Flow com I.A.

**Gerar Flow com I.A.** abre um modal com o mesmo nome. Descreva o formulário em **O que o formulário deve fazer** e clique em **Gerar**. A I.A. escreve o documento do Flow, cria o rascunho na Meta e envia o documento para a Meta compilar — não feche a janela enquanto isso acontece.

No fim você vê o nome do Flow, as categorias e, se houver, a lista **O que a I.A. não conseguiu colocar no formulário**. **Abrir o Flow** seleciona-o. Se a Meta recusou o documento gerado, o rascunho existe mesmo assim e o documento fica na caixa de JSON para você corrigir e enviar de novo.

### JSON do Flow

A seção **JSON do Flow** carrega o documento que a Meta guarda para o Flow selecionado e permite editá-lo:

- Alterne entre as vistas **Árvore** e **Texto**; **Formatar** indenta um JSON válido; **Copiar** copia o conteúdo. Esses quatro controles aparecem em português em qualquer idioma da interface.
- **Salvar e validar na Meta** envia o texto exatamente como está. **Não** publica. Se a Meta recusar, você recebe a lista: **"A validação apontou N problemas:"**.
- Só um **rascunho** aceita um JSON novo. Num Flow publicado a caixa fica só de leitura — clone o Flow e envie o JSON na cópia.

### Preview do Flow

**Gerar link de preview** pede à Meta um link que abre o Flow exatamente como ele vai aparecer na conversa. Funciona em rascunho, o que faz dele a última conferência antes de publicar. Depois de ter um link:

- **Abrir em outra aba** — o quadro na página pode aparecer em branco porque a Meta recusa ser embutida; a aba funciona.
- **Gerar de novo** reaproveita o link vivo; **Revogar este link e gerar outro** invalida o antigo.
- O link mostra a validade e **não pede login** — quem o receber abre o Flow.

<Warning>
  **O preview NÃO é um sandbox.** Cada passo de `data_exchange` no preview chama o **seu** webhook de verdade, com o mesmo corpo e a mesma assinatura da produção.
</Warning>

### Publicar

**Publicar "nome"…** abre o diálogo **Publicar Flow**. **Publicar é definitivo: não há como despublicar.** A Meta congela o JSON; depois disso o Flow só pode ser descontinuado ou clonado. Digite o nome do Flow em **Digite o nome do Flow para confirmar** e clique em **Publicar**. Se a Meta recusar, o diálogo lista os erros de validação.

Só um rascunho pode ser publicado. Um Flow `data_exchange` também precisa que a Meta já aponte para nós (**Registrar na Meta**, abaixo) — senão a Meta recusa publicá-lo.

### Zona de perigo

São duas ações diferentes, e uma não substitui a outra.

- **Descontinuar Flow** — para um Flow que já saiu do rascunho. Ele continua na lista, com as respostas que já recebeu, e deixa de abrir em novas conversas. Não há como voltar atrás: para ter o formulário de novo, clone e publique uma nova versão.
- **Apagar definitivamente** — **só rascunhos**. Digite o nome do Flow para confirmar. Não tem volta.

### Flow sem número

O aviso **Flow sem número** lista Flows que ainda apontam para o endpoint de um número que foi apagado. A Meta continua chamando esse endereço morto, ninguém responde, e o formulário não abre para o cliente.

Cada linha tem **Reapontar para &lt;número&gt;**, que registra o endpoint de um número desta WABA que tenha chave de endpoint. Se nenhum número tiver, o aviso pede que você gere uma chave primeiro. O aviso aparece só para Proprietário e Administrador.

## O painel do endpoint (`data_exchange`)

Só é necessário nos Flows cujas telas chamam o seu backend. O contrato completo está em [Conecte a sua API a um Flow](/pt-BR/guides/flow-data-exchange); esta seção explica o que cada parte do painel significa. Escolha antes um número Meta no topo — a chave é do número.

### Chave deste NÚMERO

A Meta guarda **uma única chave por número**, usada por **todos** os Flows desse número. O painel mostra o estado da chave — por exemplo **"A Meta confirmou a chave deste número."**, **"Este número não tem chave."**, ou uma mensagem **PENDENTE DE VERIFICAÇÃO** quando a Meta tem outra chave, nenhuma, ou não pôde ser consultada.

- **Gerar par novo** — cria um par RSA e registra a metade pública na Meta. Quando já existe uma chave ativa, pergunta antes: **"Gerar um par novo SUBSTITUI a chave registrada na Meta para este número."** Confirme com **Sim, gerar e substituir**. Todos os Flows `data_exchange` desse número passam para a chave nova na mesma hora.
- **Importar chave existente** — cole a **Chave privada (PEM) deste número** e, se ela tiver, a **Passphrase (só se a chave tiver uma)**, e clique em **Importar chave**. Importar não muda nada na Meta; comparamos a sua chave com a que a Meta tem registrada. Se a Meta tiver outra chave, a importação é recusada. Se a Meta não tiver nenhuma ou não puder ser consultada, a chave fica guardada como **PENDENTE DE VERIFICAÇÃO**.
- **Ver a chave pública deste número** — expande o PEM da chave pública.

<Note>
  O painel diz que a passphrase é guardada. A [referência da API](/pt-BR/api/flows#gerar-rotacionar-ou-importar) diz que ela é usada uma vez para abrir a chave e não fica guardada. Guarde a sua própria cópia.
</Note>

### Destino deste Flow

**URL do endpoint deste Flow** é o **seu** webhook, para onde repassamos as chamadas `data_exchange` deste Flow já decifradas. É por Flow, precisa ser `https://`, e **Gravar destino** fica desabilitado até o número ter chave. Gravar uma URL vazia limpa o destino e mantém o segredo.

### Segredo de assinatura — mostrado uma vez

Na primeira vez que você grava um destino, o painel mostra **"Segredo de assinatura — mostrado UMA vez."** com um botão **Copiar**. Use-o para verificar o header `x-pilot-status-signature` de cada pedido que repassamos ([como](/pt-BR/guides/flow-data-exchange#a-assinatura)).

<Warning>
  **Copie antes de sair da tela.** Guardamos o segredo cifrado e não conseguimos mostrá-lo de novo. Nas visitas seguintes o painel só diz **"Já existe um segredo de assinatura para este Flow. Está cifrado e não pode ser lido de novo."** O suporte também não consegue lê-lo.

  **Perdeu ou vazou?** O painel não tem botão de rotacionar. Envie `PUT /v1/flows/{flowId}/endpoint` com `{"url": "<sua url>", "rotateSecret": true}`. A resposta traz o `secret` novo, uma única vez. O segredo antigo para de valer na mesma hora. Veja [Endpoint do Flow](/pt-BR/api/flows#endpoint-do-flow).
</Warning>

### Apontar a Meta para cá

Gravar a URL não avisa a Meta de nada. **Registrar na Meta** grava o endereço do nosso proxy no `endpoint_uri` do Flow na Meta; sem isso a Meta recusa publicar o Flow. Quando a Meta já aponta para nós, o painel diz **"A Meta já aponta para cá. Nada a fazer."** e o botão vira **Registrar de novo**.

Se a Meta aponta o Flow para outro lugar, aparece **"A Meta já aponta este Flow para outro endereço."** com esse endereço. **Assumir mesmo assim** passa todas as trocas do Flow para a Pilot Status; quem responde lá deixa de recebê-las, e a Meta não guarda o valor anterior. **Cancelar** deixa como está.

### Aviso de divergência do endpoint_uri

**"A Meta não está nos chamando para este Flow."** significa que o `endpoint_uri` registrado na Meta não é o nosso. O aviso mostra **Na Meta:** e **Nosso:** lado a lado. Enquanto durar, as respostas do formulário vão para outro lugar e nada aparece nos traços — não é um defeito do seu backend. Corrija com **Registrar na Meta**.

O que a Meta tem é lido por uma sincronização de hora em hora, então uma mudança recente pode levar até uma hora para aparecer. Outras situações aparecem em **Avisos desta ligação**.

### Traços do endpoint (o que nós vimos)

Cada chamada `data_exchange` deste Flow vista pelo nosso proxy: o que enviamos ao seu webhook, o que ele respondeu e quanto demorou. O resumo separa as chamadas que **falharam no seu backend** das que **não tinham destino configurado**. Os traços ficam guardados por **24h**; **Atualizar** recarrega. Trocas bem-sucedidas guardam só metadados, nunca os corpos.

## Valores para copiar, e onde ficam

| Valor | Onde na tela | Mostrado uma vez? | Como obter de novo |
| --- | --- | --- | --- |
| **Segredo de assinatura** (HMAC do `x-pilot-status-signature`) | Painel do endpoint, logo após o primeiro **Gravar destino** | **Sim** | Não pode ser lido de novo. Rotacione com `PUT /v1/flows/{flowId}/endpoint` + `"rotateSecret": true` |
| **Chave pública do número** | **Ver a chave pública deste número** | Não | No mesmo lugar, ou `GET /v1/numbers/{numberId}/flow-endpoint-key` |
| **Chave privada / passphrase** | Nunca mostradas — você as cola na importação | — | Guarde a sua cópia; nenhum endpoint as devolve |
| **URL do nosso proxy** (`endpoint_uri`) | Só no quadro de divergência, como **Nosso:** | Não | `GET /v1/flows/{flowId}/endpoint` → `endpointUri`. Trate como credencial |
| **Link de preview** | **Preview do Flow** | Até expirar | **Gerar de novo** |
| **ID do Flow na Meta** | Embaixo do nome, na tabela | Não | `GET /v1/flows` |

## Pela API / MCP

Toda chamada `/v1` usa uma chave de API vinculada a um número Meta. Referência completa: [API de Flows](/pt-BR/api/flows).

| Ação na tela | API | Tool MCP |
| --- | --- | --- |
| Listar | `GET /v1/flows` | `flows_list` |
| Criar / clonar | `POST /v1/flows` | `flows_create` |
| Renomear / mudar categorias (sem botão nesta tela) | `PATCH /v1/flows/{id}` | `flows_update` |
| Salvar e validar o JSON | `POST /v1/flows/{id}/json` | `flows_json_upload` |
| Publicar | `POST /v1/flows/{id}/publish` (`"confirm": true`) | `flows_publish` |
| Descontinuar | `POST /v1/flows/{id}/deprecate` | `flows_deprecate` |
| Apagar um rascunho | `DELETE /v1/flows/{id}` | `flows_delete` |
| Chave do número: ler / gerar / importar | `GET` / `POST /v1/numbers/{numberId}/flow-endpoint-key` | `flows_endpoint_key_get` / `flows_endpoint_key_rotate` (só gerar) |
| Destino, segredo de assinatura, rotacionar segredo | `GET` / `PUT /v1/flows/{id}/endpoint` | — (só API) |
| Registrar na Meta | `POST /v1/flows/{id}/endpoint` | — (só API) |
| Link de preview | `POST /v1/flows/{id}/preview` | — |
| Traços | `GET /v1/flows/{id}/traces` | — |
| Respostas do formulário (não estão nesta tela) | `GET /v1/flows/{id}/responses` | `flows_responses_list` |
| Gerar com I.A., reapontar **Flow sem número** | Só no painel | — |

A tela não lista as respostas dos formulários. Elas chegam no webhook `flow.response_received` — veja [Receba as respostas de um Flow](/pt-BR/guides/flow-responses).
