A tela **Webhooks** é onde você aponta os eventos de um número de WhatsApp para o seu endpoint HTTPS e acompanha o que foi entregue. É a versão no painel da [API de webhooks](/pt-BR/api/webhooks/configure); os payloads estão na [referência de eventos](/pt-BR/api/webhooks/events).

## Como chegar

Menu lateral → **Webhooks**, ou direto em `/webhooks` (atalho **W** na paleta de comandos). `/webhooks?new=1` abre o modal **Novo Webhook** direto.

**Quem vê:** **Proprietário** e **Administrador**. Tanto ler a lista quanto qualquer mudança nela (criar, editar, ativar/inativar, excluir, gerar novo segredo, reenviar, retomar entrega) exigem as permissões de webhook, que só esses dois papéis têm. Atendente e Analista não veem o item no menu.

<Note>
  A tela trabalha sobre o número selecionado no cabeçalho. Cada webhook pertence a **um número**, então a lista, os eventos oferecidos e os logs de entrega são sempre os do número do cabeçalho. Troque o número no cabeçalho para ver os webhooks de outro número.
</Note>

## O que você vê

- **Ações do cabeçalho** — **Novo Webhook** sempre; com um webhook selecionado, também **Editar webhook**, **Inativar** / **Ativar** e **Deletar**. **Novo Webhook** fica desabilitado enquanto o número de teste compartilhado está selecionado (_"Número de teste: selecione um número seu para criar um webhook."_).
- **Cards de estatística** — sem webhook selecionado: **Total de Webhooks**, **Ativos**, **Inativos**. Com um webhook selecionado, passam a mostrar as entregas dele: **Total de Eventos**, **Sucesso**, **Falhas**.
- **Dois cards de ajuda** — link para a **Docs** (eventos e payloads) e indicação do [WebhookGuru](https://webhookguru.online/) para testar e depurar um endpoint.
- **Seletor de webhook** (_Selecionar webhook..._) e, com um selecionado, o **log de entregas** com seus filtros.

Se a lista falhar ao carregar, aparece **"Não deu para carregar seus webhooks"** com **Tentar de novo** — isso **não** quer dizer que você não tem nenhum, então não crie um novo por causa disso. Quando o número ainda não está aprovado para produção, a mensagem diz isso; os webhooks dos seus outros números seguem funcionando.

## Criar um webhook — modal "Novo Webhook"

| Campo | Observações |
| --- | --- |
| **Nome** (opcional) | Um rótulo para você, ex.: _WhatsApp Principal_. |
| **URL** \* | Seu endpoint (`https://` recomendado; `http://` também é aceito). Obrigatório. Endereços que apontam para dentro de uma rede privada — `localhost`, IP de loopback ou privado, ou um nome de host sem ponto — são recusados. |
| **Eventos** | Os eventos que este webhook recebe, numa lista com busca (**Selecione os eventos**, **Buscar evento**). A lista depende do provedor do número (números WhatsApp Web e números da Meta Cloud API emitem eventos diferentes); ela fica vazia até o número do cabeçalho ser identificado. |

**Selecionar todos** assina o webhook em **Todos os eventos** (`*`): tudo o que o provedor do número emite hoje **e** qualquer evento que for criado depois. O campo passa a mostrar **Todos os eventos** e a legenda **Todos os eventos selecionados**. Desmarcar um evento com **Todos os eventos** ligado troca o curinga pela lista explícita dos eventos restantes — a partir daí, tipos de evento novos deixam de entrar automaticamente. Fora isso, a legenda conta o que você marcou (_"N evento(s) selecionado(s)"_) ou diz **Nenhum evento selecionado**.

O modal também mostra estes avisos:

- O status **Lido** (`message.read`) só chega quando o contato que recebeu a mensagem tem a confirmação de leitura habilitada no WhatsApp.
- **"Todos os eventos" (`*`) não inclui "Lead recebido (Meta Ads)"**: ele traz dados pessoais e só é enviado se você marcar esse evento explicitamente. Marcá-lo com **Todos os eventos** ligado mantém o curinga e acrescenta o evento de lead ao lado.
- Quando você marca `message.received` mas não `message.reply` (e o número oferece esse evento), um aviso lembra que _"Mensagens que respondem a outra saem em message.reply, não em message.received. Sem assinar message.reply, você não as recebe."_

Todos os eventos da lista, inclusive os de grupo e de canal, podem ser escolhidos em qualquer plano.

Clique em **Criar Webhook** (o aviso diz **Webhook criado!**). Um número pode ter mais de um webhook; as recusas são a mesma URL duas vezes no mesmo número, o teto de **50 webhooks por workspace** e uma URL recusada (veja acima). O aviso de erro mostra o motivo dado pelo servidor, para você saber o que mudar. Veja [Quantos webhooks por número](/pt-BR/api/webhooks/configure).

### O segredo de assinatura — mostrado uma vez

Logo depois de criar, abre o diálogo **Segredo de assinatura** com o segredo em claro, a nota _"Mostrado uma única vez. Guarde-o agora — nenhuma leitura o devolve de novo."_ e dois botões: **Copiar** (o aviso diz **Segredo copiado**) e **Guardei**.

<Warning>
  **O segredo de assinatura aparece uma única vez.** Copie-o antes de fechar o diálogo — **Guardei**, o ícone de fechar e um clique fora do diálogo o fecham de vez. Se **Copiar** não funcionar no seu navegador, selecione o segredo na tela e copie à mão. Nem o painel, nem a API, nem o suporte do Pilot Status conseguem mostrá-lo de novo — ele não fica guardado em lugar nenhum de onde possa ser lido.

  **Perdeu?** Abra o webhook → **Editar webhook** → **Gerar novo segredo**. Isso cria um segredo novo e o mostra uma vez, no mesmo diálogo.
</Warning>

Toda entrega leva o cabeçalho `x-pilot-status-signature`: o **HMAC-SHA256 do corpo bruto da requisição**, em hexadecimal, chaveado com este segredo. Como verificar no seu receptor: [Verificar a assinatura](/pt-BR/api/webhooks/configure).

## Editar um webhook — modal "Editar Webhook"

Selecione o webhook e clique em **Editar webhook**. Você muda **Nome**, **URL** e **Eventos** com os mesmos campos acima e clica em **Salvar** (**Webhook atualizado!**). Se o salvamento for recusado, o aviso de erro traz o motivo dado pelo servidor (por exemplo, uma URL recusada ou a mesma URL já usada por outro webhook deste número); senão, diz **Falha ao atualizar webhook**.

No topo do modal, o bloco **Segredo de assinatura** mostra o estado de assinatura do webhook:

- **Entregas assinadas** — o webhook tem segredo.
- **Sem assinatura** — o webhook é anterior à assinatura (criado antes de 15/09/2026); as entregas dele saem sem `x-pilot-status-signature`. Gerar um segredo liga a assinatura.

**Gerar novo segredo** (Proprietário e Administrador, como toda mudança nesta tela) pede confirmação numa janela do navegador: _"Gerar um novo segredo invalida o atual IMEDIATAMENTE — as entregas passam a ser assinadas com o novo e o antigo para de funcionar. Continuar?"_

<Warning>
  Gerar um novo segredo invalida o atual **imediatamente** — não há janela de sobreposição nem de carência. As entregas passam a ser assinadas com o novo e o antigo para de verificar no instante em que você confirma. Atualize o seu receptor na hora (ou aceite os dois segredos por um minuto) para não recusar entregas reais.
</Warning>

O aviso diz **Novo segredo gerado** e o segredo novo aparece uma vez no diálogo **Segredo de assinatura**, igual ao da criação (mesmos **Copiar** / **Guardei**, mesma regra de "mostrado uma vez"). Num webhook sem assinatura, é também assim que você liga a assinatura. Se falhar, o aviso diz **Falha ao gerar o segredo**.

## Ativar, inativar, excluir

- **Inativar** mantém o webhook e para de entregar a ele; **Ativar** liga de novo. É escolha sua — diferente de um destino pausado (abaixo).
- **Deletar** abre **Excluir Webhook** (_"Tem certeza que deseja excluir o webhook …"_). A exclusão é definitiva: a assinatura deixa de existir, e um webhook criado de novo ganha um segredo novo.

## Logs de entrega

Escolha um webhook no seletor para ver as entregas dele, das mais recentes para as mais antigas. Ao selecioná-lo, o período começa em **hoje, de 00:00 até o minuto atual**, para você ver primeiro as entregas do dia. Colunas: **Data/Hora**, **Evento**, **Status** (`SUCCESS` / `FAILED`), **HTTP Code**, **Duração**. Sem nada no período, a tabela diz **Nenhum evento registrado**.

Filtros:

- **Status** — **Todos**, **Sucesso**, **Falha**.
- **Filtrar por evento** — os eventos que este webhook assina pelo nome. Um webhook em **Todos os eventos** oferece só `*` aqui; para ele, deixe este filtro em **Todos** e filtre por status e data.
- **De** / **Até** — seletores de data e hora, com os atalhos **Hoje (dia inteiro)** e **Ontem (dia inteiro)** (de 00:00 a 23:59 daquele dia).
- **Limpar filtros** zera tudo, inclusive a seleção do webhook.

A tabela carrega 50 entregas por vez e carrega mais conforme você rola; entregas novas aparecem sozinhas enquanto você olha.

<Note>
  Os filtros de evento e de data são aplicados pelo servidor. O filtro **Status**, os cards **Total de Eventos** / **Sucesso** / **Falhas** e o rodapé _"Mostrando X de Y eventos"_ trabalham sobre as entregas já carregadas na página (Y é quantas estão carregadas, não o histórico inteiro do período). Role para baixo para trazer entregas mais antigas para as contagens, ou estreite o período.
</Note>

### Modal "Detalhes do Evento"

Clique numa linha para abrir **Detalhes do Evento**: **Evento**, **Status**, **HTTP Code**, **Data/Hora**, **Duração**, **Webhook**, o **Payload** enviado (com **Copiar**) e, quando o seu endpoint respondeu com corpo, a **Response**.

**Reenviar** — numa entrega `FAILED`, o modal mostra **Reenviar** (Proprietário e Administrador). Ele manda de novo o payload guardado para a URL atual do webhook, assinado com o segredo atual, como uma entrega nova que aparece como linha nova no log. O aviso diz **Entrega reenviada**, ou **Falha ao reenviar entrega** se não deu para colocá-la na fila (por exemplo, uma entrega sem payload guardado). Um membro restrito a alguns números só reenvia entregas de webhook ligado a um dos números dele. Entregas com sucesso não têm o botão **Reenviar**.

## Quando a entrega fica pausada

Se o seu endpoint recusa quase tudo (taxa de sucesso de 20% ou menos nas últimas 50 entregas, depois de pelo menos 20), o Pilot Status **pausa a entrega para aquele destino** para parar de martelá-lo. Isso não é o mesmo que **Inativar** — você não desligou nada.

O que aparece:

- Com o webhook selecionado, um aviso âmbar **"Entrega pausada para este destino"**: mostra a taxa de sucesso, quantos eventos estão **guardados para reenvio** e quantos se perderam.
- Com outro webhook selecionado, um aviso **"N destino(s) com entrega pausada"** listando-os — clique para ir ao primeiro.

O Pilot Status continua testando o destino sozinho: a cada 5 minutos deixa passar **uma** entrega. Assim que uma dá certo, a entrega volta sozinha e os eventos guardados (mantidos por até 48 horas) saem na próxima nova tentativa de hora em hora.

Você não precisa esperar por isso: corrija o endpoint e clique em **Retomar entrega**. Até 1.000 eventos guardados são antecipados e reenviados **espaçados** (cerca de 5 por segundo por destino, então 1.000 levam uns 3 a 4 minutos), não todos de uma vez — o aviso diz _"Entrega retomada — N evento(s) reenviado(s) agora"_. O que passar de 1.000 continua guardado e sai na própria nova tentativa de hora em hora; nada é descartado.

### Para onde vai o alerta de pausa

O **Proprietário** da conta é avisado no instante em que a entrega é pausada, **sempre por e-mail** e por **WhatsApp** só se ele tiver telefone verificado na conta, com lembretes depois de 1, 6 e 24 horas enquanto continuar pausada. O link do alerta abre `/webhooks?webhook=<id>`, que troca o cabeçalho para o número do webhook e rola até o aviso. Se o link for de outro workspace, aparece _"Não encontramos esse webhook neste workspace."_

Quando o Proprietário não tem WhatsApp cadastrado, a tela mostra **"Avisos de destino pausado saem só por e-mail"** — clique para cadastrar o número em **Perfil → Informações**.

## Links diretos

| URL | Abre |
| --- | --- |
| `/webhooks?new=1` | O modal **Novo Webhook**. |
| `/webhooks?edit=<webhookId>` | O modal **Editar Webhook** daquele webhook. |
| `/webhooks?webhook=<webhookId>` | O webhook selecionado, no número dele, com o aviso de pausa à vista (o link dos alertas de pausa). |

Com `?webhook=`, a tela primeiro procura o webhook no workspace atual, troca o cabeçalho para um número ao qual o webhook está ligado (mantém o número atual se o webhook estiver ligado a ele), seleciona o webhook e rola até o aviso. Se o webhook não estiver ligado a nenhum número que você possa selecionar, abre o modal **Editar Webhook**. Se você estava deslogado, entra primeiro e cai no mesmo link. `?new=1` exige a mesma permissão de **Novo Webhook**.

## Pela API / MCP

| Ação no painel | API | Ferramenta MCP |
| --- | --- | --- |
| Listar webhooks | [`GET /v1/webhooks`](/pt-BR/api/webhooks/configure) | `webhooks_list` |
| Ver um webhook | `GET /v1/webhooks/{id}` | `webhook_get` |
| Novo Webhook | `POST /v1/webhooks` (o `201` traz o `secret` uma vez) | `webhooks_create` |
| Editar / Ativar / Inativar | `PATCH /v1/webhooks/{id}` (`name`, `url`, `events`, `active`) | `webhooks_update` |
| Deletar | `DELETE /v1/webhooks/{id}` | `webhooks_delete` |
| Logs de entrega | `GET /v1/webhooks/{id}/logs` | `webhook_events` |
| Gerar novo segredo | `POST /v1/webhooks/{id}/rotate-secret` | `webhooks_rotate_secret` |
| Retomar entrega | `POST /v1/webhooks/{id}/reactivate` | `webhooks_reactivate` |
| Reenviar entrega com falha | — | **Só no painel** |
