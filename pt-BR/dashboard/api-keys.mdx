O Pilot Status tem três tipos de chave de API, e cada um fica num lugar diferente do painel:

| Tipo | Prefixo | Tela | Menu lateral |
| --- | --- | --- | --- |
| **Chave de número** | `ps_number_` | **API Keys** — `/api-keys` | **API Keys**, no grupo **Numero selecionado** |
| **Chave de workspace** (principal + com nome) | `ps_workspace_` | **Chaves do workspace** — `/workspace-api-keys` | **API Keys**, no grupo **Workspace** |
| **Chave da conta** | `ps_account_` | **Perfil → API** — `/profile?tab=api` | **Perfil**, depois a aba **API** |

O menu lateral mostra duas entradas chamadas **API Keys**: a do grupo **Numero selecionado** é a tela por número; a do grupo **Workspace** é a tela de chaves do workspace. O que cada tipo de chave pode fazer está em [Tipos de chave](/pt-BR/api/key-types).

<Warning>
  **Toda chave completa aparece uma única vez.** Ao gerar ou regenerar qualquer chave — de número, principal, com nome ou da conta — o valor completo aparece num diálogo uma vez só. Depois de fechar, o painel mostra apenas o prefixo e os quatro últimos caracteres (`ps_number_••••••••3b5d`). Ninguém, nem o suporte do Pilot Status, consegue mostrá-la de novo. Se você perdeu uma chave, **regenere-a** (chave de número ou principal) ou **revogue-a e crie outra** (chave com nome ou da conta) — e atualize a integração que usava a antiga.
</Warning>

## Quem pode usar estas telas

| Ação | Proprietário | Administrador | Atendente | Analista |
| --- | --- | --- | --- | --- |
| Abrir **API Keys** e **Chaves do workspace** (`apikeys:read`) | ✅ | ✅ | — | — |
| Gerar / regenerar a chave padrão de um **número** (`apikeys:rotate`) | ✅ | ✅ | — | — |
| Gerar / regenerar a chave **principal** do workspace (`apikeys:reveal`) | ✅ | — | — | — |
| Criar / revogar chaves **com nome** do workspace | ✅ | ✅ | — | — |
| Botões de revogação de emergência | ✅ | ✅ | — | — |
| Abas **Webhooks** e **Entregas** de Chaves do workspace (`phone_lines:webhooks`) | ✅ | ✅ | — | — |
| Criar / revogar as próprias **chaves da conta** (Perfil → API) | ✅ | ✅ | ✅ | ✅ |

Atendentes e Analistas não veem nenhuma das entradas **API Keys** no menu. O Administrador vê o cartão da chave principal, mas não o botão; o cartão diz _"Gerar a chave principal é ação do proprietário — ela volta em claro uma única vez."_

## API Keys (`/api-keys`) — a chave padrão do número

Título **API Keys**, subtítulo _"Gerencie suas chaves de acesso à API"_. A tela é sobre **o número selecionado no cabeçalho**: troque o número no cabeçalho para gerenciar a chave de outro. Sem número selecionado, ela diz _"Selecione um número no cabeçalho para gerenciar sua API key."_

Cada número tem **uma chave padrão**, com escopo restrito a ele — não existe "criar outra chave" para um número, só regenerar. O cartão **Chave padrão do número** explica: _"Cada número tem uma única API key padrão, com escopo restrito a este número. Regenerar substitui a chave anterior."_

### O que você vê

O cartão da chave mostra:

- **Chave** — mascarada: prefixo, oito pontos, quatro últimos caracteres. O valor completo nunca aparece aqui.
- Um **selo de escopo**: _"Escopo: apenas o número {number}"_ para chave de número, ou _"Escopo: workspace (todos os números)"_ para uma chave antiga de escopo de tenant, com a dica _"Para enviar por um número, esta chave exige o header x-whatsapp-number-id."_
- **Criada** e **Último uso** (`-` se nunca usada).
- O botão **Regenerar API key**. Sem chave ainda, o cartão diz _"Nenhuma API Key criada"_ e o botão é **Gerar API key**.

Se a chave não pôde ser carregada, o cartão **Não deu para ler a chave deste número** pede para não gerar uma nova antes de recarregar (gerar substitui a anterior) e oferece **Tentar de novo**.

O número de teste do Pilot Status não pode ter chave: _"Número de teste: selecione um número seu para criar uma API key."_

### Gerar ou regenerar a chave

1. Clique em **Gerar API key** (ou **Regenerar API key**).
2. Confirme o aviso do navegador — _"Tem certeza? Regenerar invalida a chave atual imediatamente."_
3. O diálogo **API Key criada** mostra a chave completa com um botão de copiar e o aviso _"Atenção: por segurança, a chave completa será exibida somente desta vez. Copie e guarde agora."_ Copie e clique em **Fechar**.

A chave antiga para de funcionar na hora; toda integração que a usa quebra até você colar a nova. Só o Proprietário e os Administradores veem o botão habilitado; os demais leem _"Só o proprietário e administradores podem regenerar a chave deste número."_

### Revogar as chaves deste número (botão de emergência)

**Revogar as chaves deste número**, no canto superior direito, abre um diálogo de mesmo nome. Ele conta as chaves que vai destruir (_"Isto revoga {keys} chave(s) do número {number}. As chaves dos outros números e a chave de workspace não são tocadas."_), deixa marcar **Emitir uma chave padrão nova para este número em seguida** (desmarcado toda vez que o diálogo abre) e pede que você digite o nome do workspace. Se você pediu chave nova, ela aparece uma vez no próprio diálogo.

<Note>
  Revogar as chaves de um número **não fecha o número**: uma chave de workspace continua podendo enviar por ele com o header `x-whatsapp-number-id`. Para fechar também essa via, revogue a chave de workspace na tela **Chaves do workspace** (abaixo). Webhooks e conexões de número continuam funcionando; só param as integrações que enviam uma chave de API.
</Note>

### Privacidade & retenção e Configurações do número

Abaixo da chave, a mesma tela tem dois painéis do número selecionado:

- **Privacidade & retenção** — **Modo**: **Armazenar sempre**, **Armazenar por X dias** (com **Dias de retenção**) ou **Não armazenar (somente repasse)**; botão **Salvar privacidade**. Veja [Retenção de dados](/pt-BR/trust/data-retention) e [API keys](/pt-BR/api/api-keys).
- **Configurações do número** — **Sempre online**, **Rejeitar chamadas** (com **Mensagem ao rejeitar**, _"Vazio = não responde"_), **Marcar como lida**, **Ignorar grupos**, **Ignorar status**, **Ignorar canais**, **Importar histórico ao conectar**, **Enviar histórico nos webhooks**; as opções que dependem do provedor oferecem **Padrão do provedor**, **Ligado** ou **Desligado**. Botão **Salvar configurações**. As mesmas configurações existem na tela **Números**.

## Chaves do workspace (`/workspace-api-keys`)

Título **Chaves do workspace**, subtítulo _"As chaves de API do workspace atual."_ A tela tem três abas, guardadas no endereço como `?tab=`:

| Aba | `?tab=` | Conteúdo |
| --- | --- | --- |
| **Chaves** | `chaves` (padrão) | Chave principal, chaves com nome, link para as chaves por número |
| **Webhooks** | `webhooks` | Os webhooks do workspace: lista, criar, editar, ativar/pausar, excluir |
| **Entregas** | `entregas` | Contadores e as últimas 50 entregas do webhook selecionado |

Sem a permissão de webhooks, só existe a aba **Chaves**. `Ctrl/⌘+N` abre **Novo webhook** a partir de qualquer aba.

### Aba Chaves — Chave principal

O cartão **Chave principal**: _"É a chave que o agente de IA do app e as integrações usam. Regenerar troca só a chave principal — as chaves com nome continuam valendo."_

Mostra **Chave** (mascarada), **Criada em** e **Último uso** (ou **Nunca usada**), e o botão **Regerar** — ou **Gerar chave principal** quando o workspace ainda não tem uma (_"Este workspace ainda não tem chave principal."_).

1. Clique em **Regerar**. O diálogo **Regerar a chave principal?** avisa _"A chave principal anterior será invalidada imediatamente. As chaves com nome não são afetadas."_ (Na primeira chave: **Gerar a chave principal?** — _"A chave completa será exibida somente uma vez."_)
2. Confirme. O diálogo **Chave principal gerada** mostra a chave completa, o botão **Copiar chave** e _"Atenção: a chave completa será exibida somente desta vez. Copie e guarde agora."_ Clique em **Fechar** depois de guardar.

**Só o Proprietário.** A chave principal não pode ser revogada — só regenerada.

Abaixo do cartão, Proprietário e Administradores veem dois botões de emergência:

- **Revogar a chave de workspace** — diálogo de mesmo nome: revoga só a(s) chave(s) de workspace; as chaves por número não são tocadas.
- **Revogar TUDO (workspace + números)** — diálogo **Revogar TODAS as chaves da conta**: revoga todas as chaves de workspace **e** todas as chaves por número, com a contagem do servidor (_"Isto revoga {keys} chave(s) deste workspace, cobrindo {numbers} número(s)"_).

Os dois pedem que você digite o nome do workspace (_"Para confirmar, digite o nome do workspace: {name}"_) e oferecem **Emitir uma chave de workspace nova em seguida** (desmarcado por padrão); o botão é **Revogar tudo e emitir uma chave nova**. A chave nova, se pedida, aparece **uma vez** no diálogo — e é uma chave de **workspace**, não de número: para enviar por um número ela exige `x-whatsapp-number-id`. Se a sua integração usava chave de número, crie a nova em **API Keys** (`/api-keys`).

Use-os quando uma chave vazou e você não sabe qual. Para trocar uma única chave conhecida, regenere ou revogue só ela.

### Aba Chaves — Chaves com nome

**Chaves com nome**: _"Chaves extras do workspace, uma por integração, para revogar uma sem derrubar as outras."_ A chave principal também aparece nesta lista, com o selo **Principal**.

- **Criar uma chave** — digite o **Nome da chave** (ex.: _"Integração do CRM"_, até 60 caracteres) e clique em **Criar chave**. O diálogo **Chave "{name}" criada** mostra a chave completa uma vez, com **Copiar chave** e **Fechar**.
- **Revogar** — numa linha (não na principal). O diálogo **Revogar a chave "{name}"?** avisa _"Toda integração que usa esta chave para de funcionar na hora. Não dá para desfazer."_; confirme com **Revogar chave**.
- Cada linha mostra o nome, a chave mascarada, **Criada em {date}** e **Último uso em {date}** / **Nunca usada**.

Até **50** chaves ativas por workspace, contando a principal (_"Limite de {limit} chaves atingido. Revogue uma que não usa mais para criar outra."_). Chave com nome não se regenera: revogue e crie outra. Uma chave com nome criada por um membro é revogada quando ele sai do workspace — veja [Membros](/pt-BR/dashboard/members).

### Aba Chaves — Chaves por número

Um cartão **Chaves por número** com **Abrir chaves por número**, que leva a `/api-keys`.

### Aba Webhooks — webhooks do workspace

**Webhooks do workspace**: _"Um só cadastro para os eventos do workspace: os das linhas telefônicas e a recarga da carteira paga (wallet.topup_paid). As entregas são assinadas com o cabeçalho x-pilot-status-signature."_ É um cadastro diferente dos webhooks de número da tela [**Webhooks**](/pt-BR/dashboard/webhooks).

- Contadores: **Total de Webhooks**, **Ativos**, **Inativos**.
- Um seletor de webhook (**Selecionar webhook...**, com busca). Ao escolher um, aparece o resumo (nome, URL, eventos, **Ativo**/**Pausado**, última entrega) e as ações: editar, ativar/inativar, excluir.
- **Novo webhook** abre o modal **Novo webhook**: **Nome** (opcional, ex.: _"Integração do CRM"_), **URL \*** e **Eventos** (escolha os eventos, ou **Todos os eventos das Linhas**). _"“Todos os eventos” cobre só os eventos das Linhas: a recarga da carteira paga (wallet.topup_paid) só chega se você marcar esse evento."_ Clique em **Criar webhook**.
- Editar abre **Editar webhook** com os mesmos campos; salve com **Salvar alterações**.
- Excluir pergunta **Excluir este webhook?** — _"As entregas para esta URL param na hora."_

<Warning>
  **O segredo de assinatura (`plwh_…`) aparece uma única vez.** Logo depois de **Criar webhook**, o diálogo **Segredo de assinatura** o mostra com **Copiar** e a nota _"Mostrado uma única vez. Guarde-o agora — nenhuma leitura o devolve de novo."_ Toda entrega leva `x-pilot-status-signature`: o HMAC-SHA256 do corpo bruto, em hexadecimal, chaveado com este segredo. Os webhooks do workspace **não têm rotação de segredo**: se você perdeu o segredo, exclua o webhook e crie de novo — o novo recebe outro segredo, mostrado uma vez.
</Warning>

### Aba Entregas

**Entregas**: _"As últimas 50 entregas do webhook selecionado, com o status e a resposta do seu endpoint. Clique numa linha para ver o payload enviado."_

Escolha o webhook no mesmo seletor (a seleção é compartilhada com a aba **Webhooks**). Você vê os contadores **Total de entregas**, **Entregues**, **Falhas** e uma tabela com **Quando**, **Evento**, **Situação** (**Pendente**, **Entregue**, **Falhou**), **Resposta** e **Tentativas**. Clicar numa linha abre o detalhe da entrega com o payload. Este cadastro não tem filtros nem reenvio.

## Perfil → API — chaves da conta

**Perfil**, aba **API** (`/profile?tab=api`), tem as **Chaves da conta**: _"Uma chave da conta é sua, não de um workspace: ela gerencia seus workspaces e age dentro de qualquer workspace em que você é membro ativo. Cada requisição escolhe o workspace pelo cabeçalho x-workspace-id e roda com o seu papel nele."_ O selo diz **Escopo: Tudo em todos os workspaces**.

Todo membro, de qualquer papel, cria e revoga as próprias chaves da conta aqui (até **20** por usuário), com o mesmo fluxo **Nome da chave** / **Criar chave** / **Revogar** e o mesmo diálogo de exibição única das chaves com nome. Proprietário e Administradores veem também um cartão **Chaves do workspace** com **Abrir chaves do workspace**.

<Note>
  O diálogo **Revogar as chaves deste número** ainda diz _"revogue a chave de workspace em Perfil → API"_. A chave de workspace mudou de lugar: revogue ou regenere-a em **Chaves do workspace** (`/workspace-api-keys`).
</Note>

## Pela API / MCP

| Ação no painel | API | Ferramenta MCP |
| --- | --- | --- |
| Listar as chaves por número | [`GET /v1/api-keys`](/pt-BR/api/api-keys) (chave de workspace) | `api_keys_list` (por OAuth/MCP, só o proprietário do workspace, conferido a cada chamada e registrado na auditoria — veja [Segredos e chaves de API por OAuth](/pt-BR/integrations/mcp-server#segredos-e-chaves-de-api-por-oauth)) |
| Regenerar a chave de um número | [`POST /v1/api-keys`](/pt-BR/api/api-keys) com `whatsappNumberId` | `api_keys_regenerate_number` |
| Regenerar a chave principal | [`POST /v1/api-keys/regenerate`](/pt-BR/api/api-keys) | — |
| Listar / criar / revogar chaves com nome | [`/v1/workspaces/{id}/api-keys`](/pt-BR/api/workspaces#chaves-do-workspace) (chave da conta) | `workspaces_api_keys_list`, `workspaces_api_keys_create`, `workspaces_api_keys_revoke` |
| Webhooks do workspace: listar, ler, criar, editar, excluir | [`/v1/workspace/webhooks`](/pt-BR/api/workspace-webhooks) | `workspace_webhooks_list`, `workspace_webhooks_get`, `workspace_webhooks_create`, `workspace_webhooks_update`, `workspace_webhooks_delete` |
| Entregas de webhook do workspace | `GET /v1/workspace/webhooks/{id}/deliveries[/{deliveryId}]` | `workspace_webhooks_deliveries_list`, `workspace_webhooks_deliveries_get` |
| Revogação de emergência (número / workspace / tudo) | Só no painel | — |
| Chaves da conta (Perfil → API) | Só no painel | — |
| Privacidade & retenção, Configurações do número | [`PATCH /v1/numbers/{id}`](/pt-BR/api/numbers/settings) | `numbers_settings_update` |

Autenticação e headers (`x-api-key`, `x-whatsapp-number-id`, `x-workspace-id`) estão em [Autenticação](/pt-BR/api/authentication).
