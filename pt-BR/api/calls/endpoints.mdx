# Referência da API de Chamadas

URL base: `https://pilotstatus.com.br/v1` Cabeçalhos: `Content-Type: application/json`, `x-api-key: <your_api_key>`.

<Note>
  As chamadas funcionam em **dois provedores**: números **Meta Cloud API** e números **não oficiais (Pilot Status web)** (conectados por QR). Qualquer outro provedor retorna `400 FEATURE_NOT_SUPPORTED`. Veja a [visão geral](/pt-BR/api/calls/overview).
</Note>

<Warning>
  **Meta exige SDP.** No provedor Meta a mídia flui pelo navegador via WebRTC — você fornece uma oferta SDP ao iniciar e uma resposta SDP ao atender. **O provedor não oficial não usa SDP:** a mídia é tratada no **servidor**, então `sdpOffer`/`sdpAnswer` permanecem `null` e não há modelo de permissão BIC nem superfície de configurações de chamada.
</Warning>

## Autenticação

Todo endpoint `/v1/calls*` atua sobre **um número de WhatsApp**:

- uma **chave de número** (`ps_number_`) atua sobre o próprio número;
- uma **chave de workspace** (`ps_workspace_`), uma **chave de conta** (`ps_account_`, com `x-workspace-id`) ou um **token OAuth** precisa indicar o número no cabeçalho `x-whatsapp-number-id` — sem ele, a resposta é `403 TENANT_SCOPE_NOT_ALLOWED`. Veja [Autenticação](/pt-BR/api/authentication).

Com chave de conta ou token OAuth, o papel do usuário no workspace é conferido a cada requisição:

| Endpoints | Permissão | Papéis permitidos |
| --- | --- | --- |
| `GET`·`PUT /v1/calls/settings` | `calls:settings:manage` | ADMIN, OWNER |
| Todos os outros endpoints `/v1/calls*` | `calls:handle` | AGENT, ADMIN, OWNER |

Qualquer outro papel recebe `403 PERMISSION_DENIED`. Um token OAuth com acesso concedido só a alguns números recebe `403 NUMBER_NOT_IN_GRANT` para uma chamada de outro número.

## Endpoints

Os provedores marcados são os que suportam cada endpoint. Chamar um endpoint em um provedor não suportado retorna `400 FEATURE_NOT_SUPPORTED`. Se um número não oficial não estiver conectado, os endpoints retornam `409 WHATSAPP_INSTANCE_NOT_CONNECTED`.

| Método | Endpoint | Provedores | Descrição |
| --- | --- | --- | --- |
| `POST` | `/v1/calls` | META, não oficial | Inicia uma chamada iniciada pela empresa (BIC). |
| `GET` | `/v1/calls` | META, não oficial | Lista as chamadas do número (mais recentes primeiro; `limit` 1–100, `before` cursor ISO 8601). |
| `GET` | `/v1/calls/{callId}` | META, não oficial | Uma chamada; adicione `?includeSdp=1` para receber `sdpOffer`/`sdpAnswer` (Meta). |
| `POST` | `/v1/calls/{callId}/accept` | META, não oficial | Atende uma chamada recebida (UIC). No Meta, com resposta SDP; no não oficial, sem SDP. |
| `POST` | `/v1/calls/{callId}/reject` | META, não oficial | Recusa uma chamada recebida (sem corpo). |
| `POST` | `/v1/calls/{callId}/terminate` | META, não oficial | Desliga uma chamada ativa (sem corpo). |
| `POST` | `/v1/calls/{callId}/pre-accept` | **Somente META** | Resposta SDP antecipada OPCIONAL (reduz cortes no áudio; a chamada só conecta ao aceitar). |
| `GET` | `/v1/calls/settings` | **Somente META** | Lê o objeto de configurações `calling` do número. |
| `PUT` | `/v1/calls/settings` | **Somente META** | Atualização parcial das configurações `calling`. |
| `GET` | `/v1/calls/permissions?to=<phone>` | **Somente META** | Verifica se a empresa pode ligar para `to`. |
| `POST` | `/v1/calls/permissions/request` | **Somente META** | Envia a solicitação interativa de permissão de chamada (dentro da janela de 24h). |
| `POST` | `/v1/calls/{callId}/play` | **Somente não oficial** | Reproduz um arquivo de áudio na chamada (mídia no servidor); `hangupAfterPlay` opcional. |
| `POST` | `/v1/calls/{callId}/realtime-session` | **Somente não oficial** | Abre uma sessão WebSocket full-duplex de áudio PCM16. |

`{callId}` aceita **ou** o id de chamada do Pilot Status (o `id` do objeto de chamada) **ou** o id do provedor (`externalCallId` — `wacid.…` da Meta, o CallID no não oficial).

## 1. Iniciar uma chamada (BIC)

<CodeGroup>

```bash Meta (com SDP)
curl -X POST "https://pilotstatus.com.br/v1/calls" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{
    "to": "+5511999999999",
    "sdp": "v=0\r\no=- 4611731400430051336 2 IN IP4 127.0.0.1\r\n...",
    "sdpType": "offer",
    "bizOpaqueCallbackData": "order-42"
  }'
```

```bash Não oficial (sem SDP)
curl -X POST "https://pilotstatus.com.br/v1/calls" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "to": "+5511999999999" }'
```

</CodeGroup>

```json
HTTP 201
{ "id": "cmc1x2y3z0000abcd1234efgh", "externalCallId": "wacid.ABGG...", "status": "INITIATED" }
```

- **Meta:** `sdp` é a **oferta** RFC 8866 produzida pelo SEU cliente WebRTC. O SDP do lado da empresa deve usar `a=setup:active`. Sem permissão, a Meta retorna 138006 → o endpoint expõe `code: "META_CALL_PERMISSION_REQUIRED"`.
- **não oficial:** não envie `sdp` — a mídia é tratada no servidor. Não há modelo de permissão BIC.
- `to` é um telefone E.164 (`+` opcional) ou um BSUID da Meta.
- `bizOpaqueCallbackData` (opcional, até 512 caracteres) fica gravado na chamada e é devolvido no webhook de encerramento.
- `sdp` tem no máximo 128 KB. `sdpType` aceita apenas `"offer"` (o padrão).
- `externalCallId` é `null` se o provedor ainda não devolveu um id de chamada.
- A chamada é registrada antes de o provedor ser acionado: se o provedor recusar, ela fica na lista com `status: "FAILED"`, `errorCode` e `errorMessage`.

## 2. Atender uma chamada recebida (UIC)

Quando um usuário liga para o seu número, você recebe o webhook **`call.ringing`**. Então:

<CodeGroup>

```bash Meta (com resposta SDP)
# busca a chamada com a oferta SDP
curl "https://pilotstatus.com.br/v1/calls/wacid.ABGG...?includeSdp=1" \
  -H "x-api-key: ps_your_key_here"

# atende (corpo: sua resposta SDP; sdpType usa "answer" como padrão)
curl -X POST "https://pilotstatus.com.br/v1/calls/wacid.ABGG.../accept" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "sdp": "v=0\r\n..." }'
```

```bash Não oficial (sem SDP)
curl -X POST "https://pilotstatus.com.br/v1/calls/cmc1x2y3z0000abcd1234efgh/accept" \
  -H "x-api-key: ps_your_key_here"
```

</CodeGroup>

```bash
# recusa / desliga (sem corpo, ambos provedores)
curl -X POST "https://pilotstatus.com.br/v1/calls/wacid.ABGG.../reject" -H "x-api-key: ps_your_key_here"
curl -X POST "https://pilotstatus.com.br/v1/calls/wacid.ABGG.../terminate" -H "x-api-key: ps_your_key_here"
```

`accept`/`pre-accept`/`reject`/`terminate` respondem `{ "success": true, "id": "…", "status": "…" }` — `ACCEPTED` após `accept`, `REJECTED` após `reject`, `COMPLETED` após `terminate`; o `pre-accept` mantém o status atual. `sdpType` aceita apenas `"answer"` (o padrão). O `pre-accept` (**somente Meta**) é opcional (resposta SDP antecipada para reduzir cortes); a chamada só conecta no `accept`.

## 3. Habilitar chamadas e configurações (somente Meta)

<Note>
  As seções 3 e 4 aplicam-se **apenas a números Meta**. No provedor não oficial não há superfície de configurações de chamada nem modelo de permissão BIC — chamar esses endpoints retorna `400 FEATURE_NOT_SUPPORTED`.
</Note>

O Pilot Status tenta habilitar chamadas automaticamente quando um número Meta conecta. Leia/ajuste a qualquer momento:

```bash
curl "https://pilotstatus.com.br/v1/calls/settings" \
  -H "x-api-key: ps_your_key_here"

curl -X PUT "https://pilotstatus.com.br/v1/calls/settings" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "status": "ENABLED", "call_icon_visibility": "DEFAULT" }'
```

- O `PUT` é **parcial**: envie apenas `status`, `call_icon_visibility`, `callback_permission_status`, `call_hours`, `voicemail` (o objeto `sip` é rejeitado).
- Um `call_hours` enviado **substitui** o objeto armazenado por completo (semântica da Meta).
- Números com um limite de mensagens **abaixo de 2.000/dia ainda não podem habilitar chamadas** (erro 138015 da Meta, devolvido como `META_CALLING_TIER_TOO_LOW` → o Pilot Status marca o número como `PENDING_TIER` e re-tenta conforme o tier sobe).
- Habilitar também exige que a WABA tenha o **campo de webhook `calls` subscrito** (ou SIP configurado); sem isso a Meta retorna **138018** (`META_CALLING_PREREQUISITES_MISSING`) e o Pilot Status marca o número como `PENDING_WEBHOOK`. Subscreva o campo `calls` na WABA (ou configure SIP) e tente de novo.
- Você também pode disparar pelo painel — o botão **Habilitar chamada** nos **detalhes Meta** do número (página Números) responde `ENABLED`, `PENDING_TIER` ou `PENDING_WEBHOOK`.
- Valores: `status`, `callback_permission_status`, `call_hours.status` e `voicemail.status` aceitam `ENABLED` | `DISABLED`; `call_icon_visibility` aceita `DEFAULT` | `DISABLE_ALL`. `call_hours` também pode trazer `timezone_id`, `weekly_operating_hours` (`day_of_week`, `open_time`, `close_time`) e `holiday_schedule` (`date`, `start_time`, `end_time`).
- Pelo menos um campo é obrigatório. Qualquer campo fora da lista acima (inclusive `sip`) é rejeitado com `400 Validation error`.
- O `GET` retorna `{ "calling": { ... } }` (o objeto como a Meta o expõe); o `PUT` retorna `{ "success": true }`.
- Credenciais SIP nunca são solicitadas nem retornadas.

## 4. Permissão de chamada (somente Meta, obrigatória antes de uma BIC)

```bash
# verificar
curl "https://pilotstatus.com.br/v1/calls/permissions?to=%2B5511999999999" \
  -H "x-api-key: ps_your_key_here"

# solicitar (dentro da janela de atendimento de 24h)
curl -X POST "https://pilotstatus.com.br/v1/calls/permissions/request" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "to": "+5511999999999", "text": "May we call you about your order?" }'
```

Resposta da verificação:

```json
{
  "permission": { "status": "temporary", "expiration_time": 1768550400 },
  "actions": [
    {
      "action_name": "start_call",
      "can_perform_action": true,
      "limits": [{ "time_period": "PT24H", "max_allowed": 1, "current_usage": 0 }]
    }
  ]
}
```

- `to` é obrigatório nos dois endpoints (`400 MISSING_TO` na verificação). No pedido, aceita um telefone E.164 ou um BSUID da Meta.
- `text` (opcional, de 1 a 1024 caracteres) é o motivo exibido ao usuário.
- O endpoint de pedido responde `201` com `{ "messageId": "wamid.…" }`.

A resposta do usuário chega como o evento de webhook **`call.permission_updated`** (`status`: `NO_PERMISSION` | `TEMPORARY` | `PERMANENT`). A Meta limita a taxa de solicitações de permissão (erro 138009) e o volume de BIC (100 chamadas/24h por número — erro 138012).

## 5. Reproduzir áudio na chamada (somente não oficial)

Nos números não oficiais a mídia é tratada no servidor, então você pode instruir o backend a **baixar um arquivo de áudio e reproduzi-lo** na chamada ativa. O backend busca a URL através de um guard de SSRF.

```bash
curl -X POST "https://pilotstatus.com.br/v1/calls/cmc1x2y3z0000abcd1234efgh/play" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "mediaUrl": "https://example.com/greeting.mp3", "hangupAfterPlay": true }'
```

```json
{ "success": true, "id": "cmc1x2y3z0000abcd1234efgh", "status": "ACCEPTED" }
```

- `mediaUrl` (**obrigatório**) — URL http(s) pública (até 2048 caracteres) de um arquivo `.mp3`, `.wav` ou `.opus`. O backend baixa o arquivo antes: até **20 MiB**, timeout de 30 segundos, no máximo 3 redirecionamentos. Uma URL que resolve para endereço privado/interno retorna `400 CALL_MEDIA_URL_BLOCKED`; um arquivo maior, `400 CALL_MEDIA_TOO_LARGE`; qualquer outra falha de download, `400 CALL_MEDIA_DOWNLOAD_FAILED`.
- `hangupAfterPlay` (opcional) — encerra a chamada automaticamente quando a reprodução termina. `POST /v1/calls` \+ `play` com `hangupAfterPlay: true` forma um bot completo de "ligar, falar, desligar" sem timer no cliente.

<Warning>
  Endpoint **somente não oficial** — em um número Meta retorna `400 FEATURE_NOT_SUPPORTED`.
</Warning>

## 6. Sessão de áudio em tempo real (somente não oficial)

Abre uma sessão WebSocket **full-duplex de áudio PCM16** para transmitir áudio de/para a chamada ao vivo.

```bash
curl -X POST "https://pilotstatus.com.br/v1/calls/cmc1x2y3z0000abcd1234efgh/realtime-session" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "mode": "talk" }'
```

```json
{ "wsUrl": "wss://<host-de-mídia-dedicado>/call/media/realtime/ws/...?token=...", "token": "d3f4...", "expiresInSeconds": 120 }
```

- `mode` (**obrigatório**) — `"talk"` envia o seu áudio e recebe o do outro lado; `"listen"` só recebe.
- O socket transporta quadros de áudio binários PCM16 little-endian brutos (WebSocket simples, não WebRTC).
- Se o provedor não devolver sessão, o endpoint responde `502 CALL_REALTIME_SESSION_UNAVAILABLE`.

<Note>
  A `wsUrl` retornada aponta para um **host de mídia dedicado** — conecte-se **diretamente** a ela (não é feito proxy). O token é de **uso único** com TTL de ~2 minutos. A camada HTTP não faz upgrade de WebSocket. Endpoint **somente não oficial** (Meta → `400 FEATURE_NOT_SUPPORTED`).
</Note>

## 7. Objeto de chamada (DTO)

```json
{
  "id": "cmc1x2y3z0000abcd1234efgh",
  "externalCallId": "wacid.ABGG...",
  "direction": "INBOUND",
  "status": "COMPLETED",
  "peerNumber": "5511999999999",
  "fromNumber": "5511999999999",
  "conversationId": "conv_abc",
  "bizOpaqueCallbackData": null,
  "startedAt": "2026-07-03T15:00:00.000Z",
  "connectedAt": "2026-07-03T15:00:05.000Z",
  "endedAt": "2026-07-03T15:02:05.000Z",
  "durationSeconds": 120,
  "errorCode": null,
  "errorMessage": null,
  "createdAt": "2026-07-03T15:00:00.000Z",
  "updatedAt": "2026-07-03T15:02:05.000Z"
}
```

- `status`: `INITIATED` | `RINGING` | `ACCEPTED` | `REJECTED` | `COMPLETED` | `FAILED` | `MISSED`.
- `direction`: `INBOUND` (UIC) | `OUTBOUND` (BIC).
- Os SDPs (`sdpOffer`/`sdpAnswer`) aparecem apenas com `?includeSdp=1` em `GET /v1/calls/{callId}` — nunca na listagem. No provedor não oficial permanecem `null` (mídia no servidor).
- `durationSeconds` é definido apenas quando a chamada foi atendida.
- `externalCallId` é `null` enquanto o provedor não atribuiu um id de chamada.
- Quando as configurações de privacidade do número ocultam a chamada (números somente repasse, ou chamadas mais antigas que a janela de retenção), `peerNumber`, `fromNumber` e os SDPs vêm `null` e o objeto traz `"redacted": true`.
- `GET /v1/calls` retorna `{ "calls": [ ... ] }`. Para paginar, passe o `createdAt` da última chamada como `before`. `limit` fora de 1–100 retorna `400 INVALID_LIMIT`; um `before` que não é data retorna `400 INVALID_BEFORE`.

## Webhooks

Estes eventos disparam para **ambos os provedores** (META e não oficial):

<Card title="Eventos de chamada" icon="phone">
  `call.ringing` · `call.connected` · `call.ended` (com `duration` em segundos quando atendida) · `call.missed`
</Card>

O evento `call.permission_updated` é **exclusivo da Meta** — números não oficiais não têm modelo de permissão de chamada. (No objeto de chamada REST retornado por `GET /v1/calls`, o campo equivalente é `durationSeconds`.)

## Faturamento

- **Meta:** as BIC são cobradas pela Meta na WABA (por minuto, pulsos de 6s, apenas quando atendida). As UIC são gratuitas.
- **não oficial:** sem cobrança por minuto da Meta.
- O Pilot Status não cobra nada pelas chamadas em nenhum dos provedores.

## Erros comuns

Erros de validação respondem `400` com `{ "error": "Validation error", "details": { "formErrors": [...], "fieldErrors": { ... } } }` (sem `code`).

| Status | `code` | Quando |
| --- | --- | --- |
| `400` | `FEATURE_NOT_SUPPORTED` | O número não suporta o endpoint (endpoint exclusivo da Meta em número não oficial ou vice-versa, ou um provedor que não é META nem não oficial). |
| `400` | `NUMBER_NOT_FOUND` | A credencial não está vinculada a um número. |
| `400` | `INVALID_BODY` | O corpo não é JSON válido (corpo vazio é lido como `{}`). Veja [Corpo JSON malformado](/pt-BR/api/overview#corpo-json-malformado). |
| `400` | `INVALID_LIMIT`, `INVALID_BEFORE` | `limit` / `before` inválidos em `GET /v1/calls`. |
| `400` | `MISSING_TO` | `GET /v1/calls/permissions` sem `to`. |
| `400` | `CALL_MEDIA_URL_BLOCKED`, `CALL_MEDIA_TOO_LARGE`, `CALL_MEDIA_DOWNLOAD_FAILED` | O `play` não conseguiu baixar a `mediaUrl`. |
| `401` | — | Credencial ausente ou inválida. |
| `403` | `TENANT_SCOPE_NOT_ALLOWED` | Credencial de workspace/conta sem `x-whatsapp-number-id`. |
| `403` | `PERMISSION_DENIED` | Chave de conta / usuário OAuth cujo papel não tem `calls:handle` (ou `calls:settings:manage` nas configurações). |
| `403` | `NUMBER_NOT_IN_GRANT` | Token OAuth sem acesso ao número da chamada. |
| `404` | `CALL_NOT_FOUND` | O `callId` não pertence ao número da credencial. |
| `409` | `WHATSAPP_INSTANCE_NOT_CONNECTED` | O número não oficial não está conectado. |
| `409` | `LINKED_WHATSAPP_INSTANCE_NOT_FOUND` | A instância vinculada à chave não existe mais. |
| `502` | `WHATSAPP_INVALID_JSON` | O provedor respondeu com JSON inválido. |
| `502` | `CALL_REALTIME_SESSION_UNAVAILABLE` | `realtime-session`: o provedor não devolveu sessão. |
| `503` | `WHATSAPP_SESSION_KEY_MISSING` | A chave de sessão do número não está configurada. |
| status do provedor | código mapeado | O provedor recusou a chamada; `details: { status, body }` traz a resposta dele. Números não oficiais usam `WHATSAPP_UPSTREAM_ERROR`. |

Os erros de chamada da Meta são encaminhados com um `code` mapeado:

| --- | --- |
| 131044 | `META_CALLING_PAYMENT_REQUIRED` — a WABA não tem método de pagamento; chamadas iniciadas pela empresa são cobradas pela Meta, adicione um cartão em Configurações de pagamento do WhatsApp Manager. |
| 138000 | `META_CALLING_NOT_ENABLED` |
| 138002 | `META_CALL_CONCURRENT_LIMIT` |
| 138006 | `META_CALL_PERMISSION_REQUIRED` |
| 138009 | `META_CALL_PERMISSION_REQUEST_LIMIT` |
| 138012 | `META_CALL_LIMIT_REACHED` (100 chamadas/24h por número) |
| 138013 | `META_CALLING_NOT_AVAILABLE_REGION` |
| 138014 | `META_CALLING_DISABLED_QUALITY` |
| 138015 | `META_CALLING_TIER_TOO_LOW` (tier de mensagens abaixo de 2.000/dia; o painel mostra `PENDING_TIER`) |
| 138018 | `META_CALLING_PREREQUISITES_MISSING` (subscreva o campo de webhook `calls` ou configure SIP; o painel mostra `PENDING_WEBHOOK`) |
| 138019–138023 | `META_CALL_MEDIA_FAILED` |
