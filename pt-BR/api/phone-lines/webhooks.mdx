# Webhooks das linhas telefônicas

<Tip>
  Teste com a sua key no Playground: [`GET /v1/phone-lines/webhooks`](/pt-BR/playground/phone-lines/listar-webhooks-das-linhas), [`POST /v1/phone-lines/webhooks`](/pt-BR/playground/phone-lines/criar-webhook-de-linha), [`GET …/{id}`](/pt-BR/playground/phone-lines/obter-webhook-de-linha), [`PATCH …/{id}`](/pt-BR/playground/phone-lines/atualizar-webhook-de-linha), [`DELETE …/{id}`](/pt-BR/playground/phone-lines/excluir-webhook-de-linha), [`GET …/{id}/deliveries`](/pt-BR/playground/phone-lines/listar-entregas-do-webhook), [`GET …/deliveries/{deliveryId}`](/pt-BR/playground/phone-lines/obter-entrega-do-webhook).
</Tip>

As linhas telefônicas enviam seus eventos para os **webhooks das linhas**: um cadastro próprio, separado dos [webhooks de número](/pt-BR/api/webhooks/configure). Os dois nunca se misturam:

- Um webhook de número — mesmo um inscrito em `"*"` — **nunca** recebe um evento `phone_line.*`.
- Um webhook de linha recebe **apenas** eventos `phone_line.*`, nunca eventos de mensagem ou de número.

## Configurar

Gerencie os webhooks das linhas **pelo painel** ou **pela API** — é o mesmo cadastro: o que você criar por um caminho aparece no outro. No painel, em **Linhas → Webhooks das linhas** (`/linhas/webhooks`), como **Proprietário ou Administrador**; na API, com uma chave **com escopo de tenant** em [`/v1/phone-lines/webhooks`](#pela-api). As regras são as mesmas nos dois:

- **Nome** — opcional, até 100 caracteres, para distinguir seus webhooks na lista. Se ficar em branco, o webhook recebe o nome do host da URL (`hooks.example.com`), como nos webhooks de número. Esse nome do webhook não é enviado nas entregas (o `name` de uma entrega é o da linha).
- **URL de destino** — precisa ser `https` e apontar para um endereço público. Uma URL que aponte para um endereço interno ou de rede privada — `localhost`, um IP de loopback ou privado, um host sem ponto, ou um nome que resolva para um desses — é recusada ao salvar (`WEBHOOK_URL_REFUSED`), já que nunca seria chamada.
- **Eventos** — escolha um ou mais dos eventos abaixo, ou **todos** (`"*"`). Neste cadastro, `"*"` significa todos os eventos de linha. É obrigatório escolher pelo menos um.
- **Segredo de assinatura** — exibido **uma única vez**, quando o webhook é criado (começa com `plwh_`): no painel, logo depois de criar; na API, na resposta do `POST`. Guarde-o imediatamente: nada o exibe de novo, e não há rotação. Para trocá-lo, crie um novo webhook, passe seu receptor a usar o segredo dele e exclua o antigo.
- **Pausar / retomar, editar (nome, URL e eventos) e excluir.** Editar nunca muda o segredo de assinatura. Uma URL nova é conferida do mesmo jeito que na criação; salvar sem mudar a URL não a confere de novo, então um webhook sempre pode ser pausado.
- **Log de entregas** — por webhook: evento, status (pendente, entregue, com falha), tentativas, o status HTTP que seu endpoint respondeu e o último erro.

Um workspace pode ter mais de um webhook de linha; cada um recebe os eventos em que se inscreveu.

### Pela API

| Método | Endpoint | Descrição |
| --- | --- | --- |
| `GET` | `/v1/phone-lines/webhooks` | Lista os webhooks das linhas (do mais antigo para o mais novo) e o catálogo de eventos. |
| `POST` | `/v1/phone-lines/webhooks` | Cria um webhook. Devolve o segredo de assinatura, **só desta vez**. |
| `GET` | `/v1/phone-lines/webhooks/{id}` | Obtém um webhook. |
| `PATCH` | `/v1/phone-lines/webhooks/{id}` | Edita nome, URL e eventos, ou pausa e retoma (`active`). |
| `DELETE` | `/v1/phone-lines/webhooks/{id}` | Exclui um webhook. |
| `GET` | `/v1/phone-lines/webhooks/{id}/deliveries` | As entregas mais recentes do webhook, sem o corpo. |
| `GET` | `/v1/phone-lines/webhooks/{id}/deliveries/{deliveryId}` | Uma entrega completa, com o corpo enviado. |

<Note>
  Exige uma chave **com escopo de tenant** — uma chave com escopo de número recebe **403 `NUMBER_SCOPE_NOT_ALLOWED`**, como em todo endpoint `/v1/phone-lines`. Com um token OAuth / MCP, o usuário precisa ser **Proprietário ou Administrador** (`phone_lines:webhooks`) — caso contrário, `403 PERMISSION_DENIED`. Todos podem ser testados no **Playground → [Linhas telefônicas](/pt-BR/playground/phone-lines/listar-webhooks-das-linhas)**.
</Note>

#### Criar um webhook

`POST https://pilotstatus.com.br/v1/phone-lines/webhooks` com `{ name?, url, events }`. Responde **`201`** com `{ "webhook": { … } }`, enviado com `Cache-Control: no-store`.

<ParamField body="url" type="string" required>
  A URL `https` pública que recebe as entregas.
</ParamField>

<ParamField body="events" type="string[]" required>
  Um ou mais nomes da [tabela de eventos](#eventos), ou `["*"]` para todos os eventos de linha. Repetidos são ignorados.
</ParamField>

<ParamField body="name" type="string">
  Até 100 caracteres. Ausente ou em branco, vira o host da URL.
</ParamField>

Qualquer outro campo no corpo é recusado com **400 `UNKNOWN_FIELDS`**, que nomeia os campos.

<CodeGroup>

```bash cURL
curl -X POST "https://pilotstatus.com.br/v1/phone-lines/webhooks" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_tenant_scoped_key" \
  -d '{
    "name": "Meu app",
    "url": "https://hooks.example.com/pilot/phone-lines",
    "events": ["phone_line.code_received", "phone_line.payment_failed"]
  }'
```

```json Resposta (201)
{
  "webhook": {
    "id": "cmh1w8b2k0001wh8example3d",
    "name": "Meu app",
    "url": "https://hooks.example.com/pilot/phone-lines",
    "events": ["phone_line.code_received", "phone_line.payment_failed"],
    "active": true,
    "secret": "plwh_3f9a1c7e5b2d8f4a6c0e9b1d7f3a5c8e2b4d6f8a0c1e3b5d",
    "createdAt": "2026-10-27T13:58:02.000Z"
  }
}
```

</CodeGroup>

<Warning>
  **O `secret` só vem nesta resposta.** Nenhuma leitura — `GET`, `PATCH`, a lista — o devolve, e não há rotação. Guarde-o no seu servidor antes de fazer qualquer outra coisa; perdeu, crie um webhook novo e exclua o antigo. A criação **não** é idempotente: repetir o `POST` (por exemplo, depois de um timeout) cria um segundo webhook, com outro segredo — confira a lista antes de criar de novo.
</Warning>

#### Listar e obter

`GET https://pilotstatus.com.br/v1/phone-lines/webhooks` responde `{ "webhooks": [ … ], "events": [ … ] }`: os webhooks do workspace, do mais antigo para o mais novo, e o catálogo de eventos que um webhook de linha pode assinar. `GET …/webhooks/{id}` responde `{ "webhook": { … } }`. Um webhook de outro workspace responde **404 `WEBHOOK_NOT_FOUND`**, como um id que não existe.

```json Resposta (200) — GET /v1/phone-lines/webhooks
{
  "webhooks": [
    {
      "id": "cmh1w8b2k0001wh8example3d",
      "name": "Meu app",
      "url": "https://hooks.example.com/pilot/phone-lines",
      "events": ["phone_line.code_received", "phone_line.payment_failed"],
      "active": true,
      "lastDeliveryAt": "2026-10-27T14:11:51.000Z",
      "lastStatusCode": 200,
      "createdAt": "2026-10-27T13:58:02.000Z"
    }
  ],
  "events": [
    "phone_line.purchased",
    "phone_line.audio_received",
    "phone_line.code_received",
    "phone_line.code_failed",
    "phone_line.renewed",
    "phone_line.payment_failed",
    "phone_line.suspended",
    "phone_line.returned",
    "phone_line.canceled",
    "phone_line.verification_updated"
  ]
}
```

| Campo | Descrição |
| --- | --- |
| `id` | O id do webhook, para os caminhos `/v1/phone-lines/webhooks/{id}`. |
| `name` | Nunca vazio: o nome dado, ou o host da URL. |
| `url` | A URL de destino. |
| `events` | Os eventos assinados, ou `["*"]`. |
| `active` | `false` quando pausado: um webhook pausado não recebe entregas. |
| `lastDeliveryAt` | ISO 8601 da última entrega **bem-sucedida**, ou `null`. Uma tentativa que falha não o muda. |
| `lastStatusCode` | O último status HTTP que o seu endpoint respondeu, com sucesso ou não, ou `null`. |
| `createdAt` | ISO 8601 — quando o webhook foi criado. |

#### Editar, pausar e excluir

`PATCH https://pilotstatus.com.br/v1/phone-lines/webhooks/{id}` aceita `name`, `url`, `events` e `active`, todos opcionais; o que não vier fica como está. Responde `{ "webhook": { … } }` sem o segredo, que nunca muda. Só uma URL que **muda** é conferida de novo — pausar ou trocar os eventos sempre funciona, mesmo que a URL salva fosse recusada hoje. Um `name` enviado em branco volta a ser o host da URL.

```bash
# Pausar
curl -X PATCH "https://pilotstatus.com.br/v1/phone-lines/webhooks/cmh1w8b2k0001wh8example3d" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_tenant_scoped_key" \
  -d '{ "active": false }'
```

`DELETE https://pilotstatus.com.br/v1/phone-lines/webhooks/{id}` responde `{ "ok": true }`. As entregas pendentes do webhook são descartadas.

#### Log de entregas

`GET https://pilotstatus.com.br/v1/phone-lines/webhooks/{id}/deliveries` responde `{ "deliveries": [ … ] }`, da mais recente para a mais antiga, **sem o corpo** de cada entrega.

<ParamField query="limit" default="50" type="integer">
  De 1 a 200. Qualquer outro valor → **400 `INVALID_LIMIT`**.
</ParamField>

```json Resposta (200)
{
  "deliveries": [
    {
      "id": "cmh1w9c4m0002dl8example5f",
      "event": "phone_line.code_received",
      "status": "DELIVERED",
      "attempts": 1,
      "responseStatus": 200,
      "lastError": null,
      "createdAt": "2026-10-27T14:11:51.000Z",
      "deliveredAt": "2026-10-27T14:11:52.000Z"
    }
  ]
}
```

`status` é `PENDING`, `DELIVERED` ou `FAILED`; `responseStatus` é o status HTTP que o seu endpoint respondeu, e `lastError`, o último erro quando não houve resposta aceita.

`GET https://pilotstatus.com.br/v1/phone-lines/webhooks/{id}/deliveries/{deliveryId}` responde `{ "delivery": { … } }` com os mesmos campos e mais três da **última tentativa**: `durationMs`, `responseBody` (a resposta do seu endpoint, até 1.000 caracteres) e `payload` — o corpo exato que foi enviado e assinado, como **string** JSON. Calcule o HMAC sobre essa string com o seu segredo e você obtém o `x-pilot-status-signature` que a entrega levou. Enviado com `Cache-Control: no-store`.

<Warning>
  O `payload` de um `phone_line.code_received` traz o código de ativação, que é uma credencial. A lista nunca o traz; a leitura de uma entrega traz. Não registre essa resposta em log.
</Warning>


#### Erros

Os erros seguem o [envelope das linhas](/pt-BR/api/phone-lines/overview#erros): `error` bilíngue e `code`. Os de autenticação e escopo (`401`, `403 NUMBER_SCOPE_NOT_ALLOWED`, `TENANT_REQUIRED`, `WORKSPACE_ARCHIVED`, `PERMISSION_DENIED`, `WORKSPACE_MEMBERSHIP_REQUIRED`) são os mesmos de todo `/v1/phone-lines`.

| Status | `code` | Onde | O que aconteceu |
| --- | --- | --- | --- |
| `400` | `INVALID_BODY` | `POST`, `PATCH` | O corpo não é um objeto JSON. |
| `400` | `UNKNOWN_FIELDS` | `POST`, `PATCH` | Campos além de `name`, `url`, `events` (e `active`, no `PATCH`). `details.unknownFields` diz quais. |
| `400` | `INVALID_FIELD_TYPE` | `POST`, `PATCH` | Um campo veio com o tipo errado — por exemplo `"active": "false"` ou `null`. `details.field` e `details.expected` dizem qual e o que era esperado. |
| `400` | `INVALID_WEBHOOK` | `POST`, `PATCH` | `url` ausente, inválida ou que não é `https`, ou `events` vazio ou com um evento desconhecido. |
| `400` | `INVALID_WEBHOOK_NAME` | `POST`, `PATCH` | `name` com mais de 100 caracteres. |
| `400` | `WEBHOOK_URL_REFUSED` | `POST`, `PATCH` | A URL aponta para um endereço interno ou de rede privada. |
| `400` | `INVALID_LIMIT` | `GET …/deliveries` | `limit` não é um inteiro de 1 a 200. |
| `404` | `WEBHOOK_NOT_FOUND` | `…/{id}`, `…/deliveries` | Nenhum webhook com esse id no seu workspace. |
| `404` | `WEBHOOK_DELIVERY_NOT_FOUND` | `…/deliveries/{deliveryId}` | Nenhuma entrega com esse id nesse webhook. |
| `500` | `INTERNAL_ERROR` | todos | Falha inesperada. |

<Accordion title="Mensagens de erro exatas">
  | `code` | `error` |
  | --- | --- |
  | `INVALID_WEBHOOK` | `Invalid webhook: use an https URL and known events. \| Webhook inválido: use uma URL https e eventos conhecidos.` |
  | `INVALID_WEBHOOK_NAME` | `Invalid webhook name: use at most 100 characters. \| Nome do webhook inválido: use no máximo 100 caracteres.` |
  | `WEBHOOK_URL_REFUSED` | `Webhook URL refused: it points to an internal or private network address, which we never call. Use a public address. \| URL do webhook recusada: ela aponta para um endereço interno ou de rede privada, que nunca chamamos. Use um endereço público.` |
  | `WEBHOOK_NOT_FOUND` | `Webhook not found. \| Webhook não encontrado.` |
  | `WEBHOOK_DELIVERY_NOT_FOUND` | `Webhook delivery not found. \| Entrega do webhook não encontrada.` |

  `INVALID_BODY`, `UNKNOWN_FIELDS`, `INVALID_FIELD_TYPE` e `INVALID_LIMIT` montam a mensagem a partir da requisição — ela cita o campo com problema — e seguem o mesmo padrão `English | Portuguese`.
</Accordion>

## Eventos

| Evento | Quando é disparado |
| --- | --- |
| `phone_line.purchased` | Uma linha foi comprada (pelo painel ou por `POST /v1/phone-lines`) — um evento por número comprado. |
| `phone_line.audio_received` | A ligação de um pedido de código foi capturada e a gravação armazenada (`CAPTURED`) — antes de o código ser lido, o que pode levar alguns minutos. Traz a [`audioUrl`](#a-url-da-gravação) da gravação. |
| `phone_line.code_received` | Um pedido de código terminou: **uma vez por pedido**, com o `code`, ou com `code: null` e o `failureReason` quando terminou sem código. |
| `phone_line.code_failed` | Um pedido de código terminou sem código, de forma definitiva — uma vez, com o `reason`. Sempre acompanhado de um `phone_line.code_received` com `code` `null`. |
| `phone_line.renewed` | Uma cobrança de renovação deu certo, inclusive uma cobrança atrasada que reativa uma linha em `PAYMENT_PENDING` ou `SUSPENDED`. |
| `phone_line.payment_failed` | Uma cobrança de renovação falhou e a linha passou de `ACTIVE` para `PAYMENT_PENDING`. Uma vez por renovação — as novas tentativas seguintes não o disparam de novo. |
| `phone_line.suspended` | A linha continuava sem pagamento 2 dias após a falha e agora está `SUSPENDED`. |
| `phone_line.returned` | A linha foi devolvida à operadora (`RETURNED`) — 1 dia após a suspensão, imediatamente quando uma linha sem pagamento é cancelada ou fica de fora no **Escolher quais linhas manter** do painel, ou 3 dias depois da recusa da verificação do titular sob a qual foi comprada. `reason` diz qual. |
| `phone_line.canceled` | Uma linha cancelada no fim do período chegou a `currentPeriodEnd` e agora está `CANCELED`. |
| `phone_line.verification_updated` | A verificação do titular mudou de estado: foi concluída (aprovada automaticamente ou enviada para análise manual) ou revisada (aprovada, rejeitada ou com outro documento solicitado). |

<Note>
  Todo pedido de código aceito termina com **um** `phone_line.code_received` — com o código, ou com `code: null` —, então aguardar só esse evento basta. Uma transcrição que falha é refeita a partir da gravação armazenada (até 3 tentativas no total); só o resultado final é enviado, nunca as tentativas intermediárias. Um pedido recusado na criação (`503 SUPPLIER_UNAVAILABLE`, `poll_not_scheduled`) não envia evento: quem o fez já recebeu o erro.

  `phone_line.audio_received` e `phone_line.code_failed` foram adicionados em 28/09/2026. Um webhook inscrito em todos os eventos (`"*"`) os recebe; um webhook com uma lista explícita recebe só os eventos da lista — edite-o para incluí-los.
</Note>

## Formato do payload

Toda entrega é um `POST` com corpo JSON:

```json
{
  "id": "cmg5k4d1v0003dl8example2m",
  "event": "phone_line.purchased",
  "createdAt": "2026-10-01T14:03:11.000Z",
  "data": {
    "lineId": "cmg5k2l1n0001pl8example9x",
    "number": "551148637200",
    "name": "(11) 4863-7200",
    "currentPeriodEnd": "2026-11-01T14:03:11.000Z"
  }
}
```

| Campo | Descrição |
| --- | --- |
| `id` | O id da entrega — o mesmo em todas as retentativas desta entrega. **Use-o para deduplicar.** Cada webhook recebe sua própria entrega, então dois webhooks inscritos no mesmo evento recebem `id`s diferentes. |
| `event` | O nome do evento. |
| `createdAt` | ISO 8601 — quando o evento foi registrado. |
| `data` | Os campos do evento, descritos abaixo. |

Cabeçalhos:

| Cabeçalho | Valor |
| --- | --- |
| `Content-Type` | `application/json` |
| `x-pilot-status-signature` | HMAC-SHA256 do corpo bruto, codificado em hexadecimal, usando o segredo do webhook como chave. |
| `Idempotency-Key` | O mesmo valor do `id` do corpo. |

Todo evento sobre uma linha — todos, menos `phone_line.verification_updated` — traz o `lineId`, o `number` e o **`name`** da linha: o nome que sua equipe deu a ela no painel ou, quando ela não tem nome, o número formatado (`(11) 4863-7200`), igual ao [`name`](/pt-BR/api/phone-lines/list#campos-do-objeto-linha) do objeto linha. Uma linha é comprada sem nome, então `phone_line.purchased` sempre traz o número formatado. `name` é o nome no momento do evento: renomear uma linha não envia evento, e a retentativa de uma entrega traz o nome com que ela foi registrada. Como o `displayName` nos webhooks de número, é um rótulo — identifique as linhas pelo `lineId`.

<Note>
  **Aqui os números não têm `+`.** `number` traz os dígitos E.164 sem o sinal de mais (`551148637200`), exatamente como nos endpoints `/v1/phone-lines` — ao contrário dos webhooks de número, cujos campos de telefone trazem `+`.
</Note>

## A URL da gravação

Os três eventos de um pedido de código — `phone_line.audio_received`, `phone_line.code_received` e `phone_line.code_failed` — trazem **`audioUrl`**: a URL absoluta de [`GET /v1/phone-lines/activations/{activationId}/audio`](/pt-BR/api/phone-lines/activation-codes#baixar-a-gravação), que serve a gravação da ligação.

```text
https://pilotstatus.com.br/v1/phone-lines/activations/cmg5k3a7c0002ac8example4q/audio
```

- **Quando o pedido tem gravação, ela está lá.** `phone_line.audio_received` sempre a traz — ele é enviado depois que a gravação é armazenada. `phone_line.code_received` e `phone_line.code_failed` a trazem sempre que a ligação foi armazenada: com o código, e também quando nenhum código pôde ser lido (`no_code_in_transcript`, `transcription_failed`), que é justamente quando você mais quer ouvir.
- **`null` quando não há gravação** — a chave vem sempre. É um pedido que terminou antes de qualquer ligação ser armazenada: `no_call_in_window`, `canceled_by_customer`, `audio_download_failed` ou `audio_store_failed`.
- **Ela não contém credencial.** Busque-a com a sua chave **com escopo de tenant** (`x-api-key`), como qualquer endpoint `/v1/phone-lines`; sem chave ela responde `401`, e a chave de outro workspace recebe `404`. Guardar ou registrar a URL em log não expõe a gravação.
- **Ela para de responder quando a linha sai do seu workspace.** Uma linha `RETURNED` ou `CANCELED` tem as gravações apagadas, e a URL passa a responder `404`.

```bash
curl "https://pilotstatus.com.br/v1/phone-lines/activations/cmg5k3a7c0002ac8example4q/audio" \
  -H "x-api-key: ps_your_tenant_scoped_key" \
  -o activation.wav
```

## Verificar a assinatura

Todo webhook de linha tem um segredo, então **toda entrega é assinada**. `x-pilot-status-signature` é o **HMAC-SHA256 do corpo bruto da requisição**, codificado em hexadecimal, usando o segredo do webhook como chave (a string inteira, incluindo o prefixo `plwh_`). Calcule-o sobre os bytes exatamente como foram recebidos — antes de qualquer parse do JSON — e compare em tempo constante.

**Com o SDK Python** (`pilot-status` 1.16.0 ou superior), `verify_webhook_signature(raw_body, signature_header, secret)` faz isso por você — a mesma função dos webhooks de número, chamada com o segredo `plwh_...` inteiro. Passe o corpo exatamente como chegou — `request.get_data()` no Flask, `await request.body()` no FastAPI —, nunca o JSON já interpretado e re-serializado. A comparação é em tempo constante, e a função devolve `False` — nunca lança exceção — para cabeçalho ausente ou malformado, segredo vazio ou corpo adulterado:

```bash
pip install "pilot-status>=1.16.0"
```

<CodeGroup>

```python Flask
import os

from flask import Flask, abort, request
from pilot_status import WEBHOOK_SIGNATURE_HEADER, verify_webhook_signature

app = Flask(__name__)
SECRET = os.environ["PILOT_STATUS_WEBHOOK_SECRET"]  # the full plwh_... string

@app.post("/hooks/pilot-status")
def pilot_status_hook():
    raw = request.get_data()  # the raw bytes that were signed, not json.dumps(request.json)
    if not verify_webhook_signature(raw, request.headers.get(WEBHOOK_SIGNATURE_HEADER), SECRET):
        abort(401)
    # ... parse json.loads(raw) and process it
    return "", 200
```

```python FastAPI
import os

from fastapi import FastAPI, HTTPException, Request
from pilot_status import WEBHOOK_SIGNATURE_HEADER, verify_webhook_signature

app = FastAPI()
SECRET = os.environ["PILOT_STATUS_WEBHOOK_SECRET"]  # the full plwh_... string

@app.post("/hooks/pilot-status")
async def pilot_status_hook(request: Request):
    raw = await request.body()  # the raw bytes that were signed
    if not verify_webhook_signature(raw, request.headers.get(WEBHOOK_SIGNATURE_HEADER), SECRET):
        raise HTTPException(status_code=401)
    # ... parse json.loads(raw) and process it
    return {}
```

</CodeGroup>

**Sem o SDK**, calcule você mesmo:

<CodeGroup>

```javascript Node
const crypto = require("node:crypto");

// rawBody: the request body exactly as received (Buffer or string).
function isValidSignature(rawBody, signatureHeader, secret) {
  const expected = crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  const received = String(signatureHeader ?? "");
  return (
    received.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(received))
  );
}
```

```python Python
import hashlib
import hmac

# raw_body: the request body exactly as received (bytes).
def is_valid_signature(raw_body: bytes, signature_header: str | None, secret: str) -> bool:
    expected = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature_header or "")
```

</CodeGroup>

É o mesmo cálculo usado nos webhooks de número, então um receptor que já verifica esses webhooks funciona aqui com o segredo deste webhook. A assinatura cobre apenas o corpo — não há cabeçalho de timestamp —, então use o `id` para descartar duplicatas.

## Entrega e retentativas

- **Responda com qualquer `2xx` em até 10 segundos.** Qualquer outra coisa — outro status, um timeout, um erro de conexão — conta como tentativa com falha.
- **6 tentativas no total**: a primeira imediatamente, depois novas tentativas com intervalos de cerca de 30 s, 1 min, 2 min, 4 min e 8 min — normalmente cerca de **15 minutos** do início ao fim. Depois da última, a entrega é marcada como falha no log. Uma entrega que não pôde ser enfileirada de início é retomada por uma varredura horária, então a primeira tentativa dela pode vir mais tarde.
- **Redirecionamentos não são seguidos.** Uma resposta `3xx` conta como tentativa com falha.
- **Pelo menos uma vez.** Se o seu endpoint processou o evento, mas não respondeu a tempo, a retentativa o entrega de novo, com o mesmo `id`. A ordem não é garantida.
- **Webhooks pausados ou excluídos.** Um evento é entregue somente aos webhooks que estão ativos e inscritos no momento em que ele acontece. Cada tentativa confere o webhook de novo: uma entrega cujo webhook está pausado quando uma tentativa chega — inclusive uma que já está nas retentativas — é marcada como falha e não é enviada depois; excluir um webhook descarta as entregas pendentes dele. Os eventos nunca são reenviados a um webhook criado ou retomado depois.
- **Destinos internos são recusados.** Uma URL cujo host resolve para um endereço de rede privada ou interna não é chamada, nem recebe novas tentativas. Uma URL assim já é recusada quando você salva o webhook; isto cobre um nome cujo DNS passou a apontar para dentro depois. Já uma consulta DNS que falha é diferente: não impede salvar e, na entrega, recebe novas tentativas como qualquer outra falha.

<Tip>
  Trate esses eventos como notificações, não como a fonte da verdade. Quando algum puder ter se perdido — seu endpoint ficou fora do ar por mais tempo do que duram as retentativas —, leia o estado atual com [`GET /v1/phone-lines`](/pt-BR/api/phone-lines/list).
</Tip>
