# Cancelar Envios Agendados

```text
DELETE https://pilotstatus.com.br/v1/messages/cancel
```

Cancela o **agendamento** de uma ou mais mensagens que ainda estão na **fila** para envio futuro (`QUEUED` com `deliverAt` / `deliverBy` no futuro). A linha da mensagem **não** é excluída: o status passa a ser **`CANCELED`**, e os Logs \+ o histórico de rastreamento permanecem.

<Note>
  `CANCELED` **não** é `FAILED` e não é um dos valores de `errorCode` de erro de entrega listados em [Códigos de Erro de Log](/pt-BR/api/messages/log-error-codes).
</Note>

## Cabeçalhos

- `Content-Type: application/json`
- `x-api-key: ps_...` (ou `x-api-key-id`) — a mesma chave de `POST /v1/messages/send`: uma chave **com escopo de número**, ou uma chave da conta com [`x-whatsapp-number-id`](/pt-BR/api/authentication)

**Tokens OAuth / MCP e chaves de conta** (`ps_account_`) também precisam da permissão `messages:cancel_scheduled` (papéis `AGENT`, `ADMIN`, `OWNER`).

## Corpo

<ParamField body="messageIds" type="string[]" required>
  De 1 a **100** `id`s internos de mensagem (o `id` devolvido pelo envio) por requisição. Só mensagens do número da chave são encontradas.
</ParamField>

```json
{ "messageIds": ["<id1>", "<id2>"] }
```

## Exemplo

```bash
curl -X DELETE "https://pilotstatus.com.br/v1/messages/cancel" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "messageIds": ["msg_abc", "msg_def"] }'
```

<Note>
  Este endpoint usa `DELETE` com um **corpo JSON**; `curl`, `fetch` e a maioria dos clientes HTTP oferecem suporte a isso.
</Note>

## Resposta (200)

```json
{
  "cancelled": ["msg_abc"],
  "failed": [{ "id": "msg_def", "reason": "Not queued" }]
}
```

- Apenas mensagens que ainda podem ser agendadas aparecem em `cancelled`; as demais são listadas em `failed` com um `reason`: `Message not found`, `Not queued`, `Not scheduled (no future deliverBy)`, `Missing WhatsApp instance` ou `Could not cancel (state changed)`. A resposta é `200` mesmo quando nada foi cancelado.
- Após o cancelamento, `GET /v1/messages/{messageId}` retorna `"status": "CANCELED"`.
- A página de **Logs** oferece suporte ao mesmo fluxo por meio da seleção em massa de linhas agendadas.

## Erros comuns

- `400 INVALID_BODY` — o corpo não é JSON válido, inclusive vazio. Veja [Corpo JSON malformado](/pt-BR/api/overview#corpo-json-malformado).
- `400` — `{"error": "Validation failed", "details": {…}}`: `messageIds` ausente ou vazio, mais de 100 IDs, uma string vazia.
- `401` — credencial ausente/inválida (`{"error": "Invalid API key"}`).
- `403 TENANT_SCOPE_NOT_ALLOWED` — chave da conta sem `x-whatsapp-number-id`.
- `403 PERMISSION_DENIED` — token OAuth/MCP ou chave de conta cujo papel não tem `messages:cancel_scheduled`.
