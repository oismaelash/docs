Recupere as mensagens recebidas que contam como não lidas para o número conectado. O estado de não lida **não** é derivado de um campo `readAt` por mensagem (o `readAt` por mensagem não é mantido para mensagens recebidas). Em vez disso, ele é derivado do `unreadCount` de cada conversa — o mesmo contador exibido no painel — e o `total` da resposta é a **soma do `unreadCount` entre as conversas não lidas**. Cada item inclui essa contagem de não lidas no nível da conversa.

## Endpoint

`GET https://pilotstatus.com.br/v1/messages/unread`

<Note>
  Atua sobre **um número**: use uma API key **com escopo de número** (`ps_*`) no cabeçalho `x-api-key`, ou uma chave da conta que indique o número no header [`x-whatsapp-number-id`](/pt-BR/api/authentication). Uma chave da conta sem esse header recebe `403 TENANT_SCOPE_NOT_ALLOWED`.

  **Tokens OAuth / MCP e chaves de conta** (`ps_account_`) também precisam da permissão `chat:read` (papéis `AGENT`, `ADMIN`, `OWNER`); o papel `ANALYST` é recusado com `403 PERMISSION_DENIED`. Uma chave `ps_` clássica não é afetada por papéis.
</Note>

Para obter só as **contagens**, de um ou vários números numa chamada, use [`GET /v1/messages/unread/counts`](#contagens-por-número).

## Parâmetros de query

<ParamField query="pageSize" default="30" type="integer">
  Resultados por página (1–100).
</ParamField>

<ParamField query="cursor" type="string">
  Cursor keyset: o `nextCursor` da resposta anterior, sem alterar. É o jeito de paginar além das primeiras páginas. Não pode ser combinado com `page > 1` nem com `offset` (`400 INVALID_PAGINATION`); um valor que não seja um cursor devolvido por este endpoint dá `400 INVALID_CURSOR`.
</ParamField>

<ParamField query="page" default="1" type="integer">
  Número da página (≥ 1). `page × pageSize` não pode passar de `10000`.
</ParamField>

<ParamField query="offset" type="integer">
  Linhas a pular (≥ 0), no lugar de `page`. `offset + pageSize` não pode passar de `10000`.
</ParamField>

Não há filtro de intervalo de datas neste endpoint. As mensagens vêm das mais recentes para as mais antigas (`providerTimestamp`, depois `id`), e cada conversa não lida contribui com as suas `unreadCount` mensagens recebidas mais recentes — no máximo **100** por conversa.

## Efeito do modo PII

A resposta depende do **modo PII** configurado para o número (definido no painel, no painel Privacidade & retenção da página API Keys ou nas configurações do número). Este endpoint usa **redigir-e-mostrar** (redact-and-show): nenhuma linha é escondida — uma linha coberta pela política de PII mantém o envelope, tem `text`, `media`, os campos de participante, `from`, `fromName`, `userId` e `username` em `null`, e traz `redacted: true`.

| Modo PII | Efeito |
| --- | --- |
| `STORE_INDEFINITE` (padrão) | Todas as mensagens não lidas são retornadas na íntegra. |
| `STORE_X_DAYS` | As linhas **fora** da janela de retenção são redigidas; as de dentro voltam na íntegra. |
| `RELAY_ONLY` | Todas as linhas são redigidas e a resposta adiciona `"notice": "PII_RELAY_ONLY"`. O `total` continua informando os contadores das conversas. |

## Campos do objeto de mensagem

Cada item tem os campos de um item de [`GET /v1/messages/history`](/pt-BR/api/messages/history#campos-do-objeto-de-mensagem) (`id`, `conversationId`, `direction` — aqui sempre `INBOUND` —, `providerKind`, `externalMessageId`, `status`, `messageType`, `origin`, `text`, `participantName`, `participantPhone`, `participantUserId`, `repliedToExternalId`, `media`, `sentAt`, `deliveredAt`, `readAt`, `providerTimestamp`, `createdAt`, `referral`, `redacted`), mais:

<ResponseField name="from" type="string | null">
  O contato em E.164 com `+` inicial, tirado da conversa (com `participantPhone` como reserva). `null` quando redigido ou quando o contato não tem telefone (contato só com username).
</ResponseField>

<ResponseField name="fromName" type="string | null">
  Nome de exibição do contato, da conversa quando conhecido.
</ResponseField>

<ResponseField name="userId" type="string | null">
  O Business-Scoped User ID (BSUID) da Meta do contato, quando conhecido — serve como `destinationNumber` em [`POST /v1/messages/send`](/pt-BR/api/messages/send).
</ResponseField>

<ResponseField name="username" type="string | null">
  O username de WhatsApp do contato, quando conhecido.
</ResponseField>

<ResponseField name="conversationUnreadCount" type="integer" required>
  Contagem de não lidas daquela conversa.
</ResponseField>

Na prática `readAt` é sempre `null`: o `readAt` por mensagem não é mantido para mensagens recebidas; o estado de não lida fica na conversa (`conversationUnreadCount`).

## Erros comuns

- `400 INVALID_PAGINATION` — `page × pageSize` ou `offset + pageSize` acima de `10000`, `offset` negativo ou não inteiro, ou `cursor` combinado com `page > 1` / `offset`.
- `400 INVALID_CURSOR` — `cursor` não é um valor devolvido por este endpoint.
- `400 NUMBER_NOT_FOUND` — a credencial não indica nenhum número de WhatsApp.
- `401` — credencial ausente ou inválida (`{"error": "Invalid API key"}`).
- `403 TENANT_SCOPE_NOT_ALLOWED` — chave da conta sem `x-whatsapp-number-id`.
- `403 PERMISSION_DENIED` — token OAuth/MCP ou chave de conta cujo papel não tem `chat:read` (`ANALYST`).

Teste no Playground: [Mensagens não lidas](/pt-BR/playground/conversations/unread-messages).

## Contagens por número

```text
GET https://pilotstatus.com.br/v1/messages/unread/counts
```

A **contagem** de não lidas de cada número numa chamada — sem conteúdo de mensagem. O `total` de um número é exatamente o `total` que `GET /v1/messages/unread` devolve para ele.

<ParamField query="whatsappNumberIds" type="string">
  Opcional. Ids de `WhatsAppNumber` separados por vírgula (ou repetidos), no máximo **100**. Omitido: todos os números que a credencial alcança.
</ParamField>

Quais números a credencial alcança:

- uma chave **com escopo de número**, ou uma chave da conta com `x-whatsapp-number-id` — só esse número;
- um **token OAuth / MCP restrito a alguns números**, ou a chave de conta de um membro restrito a alguns números — esses números;
- uma chave **da conta inteira** (chave de workspace, token do workspace inteiro) sem o header — todos os números do workspace.

Diferente da listagem, este endpoint **não** recusa uma chave da conta inteira. Ele exige a mesma permissão `chat:read` de tokens OAuth / MCP e chaves de conta.

```bash
curl "https://pilotstatus.com.br/v1/messages/unread/counts" \
  -H "x-api-key: ps_workspace_sua_chave_aqui"
```

```json Resposta (200)
{
  "byNumber": [
    { "whatsappNumberId": "cmnum_01", "number": "5511999999999", "displayName": "Suporte", "total": 12 },
    { "whatsappNumberId": "cmnum_02", "number": "5511888888888", "displayName": null, "total": 0 }
  ],
  "total": 12
}
```

Os números que você indicou voltam na ordem em que foram indicados; senão, do número mais antigo para o mais novo. Contadores não são PII, então um número `RELAY_ONLY` também informa a contagem.

| Status | `code` | Quando |
| --- | --- | --- |
| `400` | `TOO_MANY_NUMBERS` | Mais de 100 ids em `whatsappNumberIds`. |
| `400` | `NUMBER_REQUIRED` | Concessão OAuth por número sem número para ler. |
| `400` | `NUMBER_NOT_FOUND` | A credencial não indica nenhum número de WhatsApp. |
| `403` | `NUMBER_NOT_IN_GRANT` | Um número indicado está fora do que a credencial alcança. |
| `403` | `PERMISSION_DENIED` | Token OAuth/MCP ou chave de conta cujo papel não tem `chat:read`. |
| `404` | `NUMBER_NOT_FOUND` | Um número indicado não é um número deste workspace; `whatsappNumberIds` no corpo diz quais. |

Essas recusas trazem `{ "error": "<English> | <Português>", "code": "…" }`. Teste no Playground: [Não lidas por número](/pt-BR/playground/conversations/unread-counts).
