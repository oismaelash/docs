---

mode: "wide"
---

Ao receber mensagens com mídia pelos webhooks da Meta Cloud API, o payload traz um `mediaId`. Este endpoint baixa o arquivo de mídia real e o devolve em base64 e como uma URL hospedada pelo Pilot Status.

Você também pode obter o `mediaId` a partir do campo `media.id` das mensagens de entrada retornadas por `GET /v1/messages/unread`, `GET /v1/messages/group` e `GET /v1/messages/history` — em números **Meta**, `media.id` é o valor a ser passado aqui.

<Note>
  Em números **não oficiais (Pilot Status web)** não há `mediaId`; essas mensagens carregam `media.url` (uma URL de download direto), que você busca diretamente.
</Note>

## Endpoint

`GET https://pilotstatus.com.br/v1/media/{mediaId}?phoneNumberId={phoneNumberId}`

## Autenticação

Uma chave **com escopo de número** em `x-api-key`, ou uma chave da conta que indique um número no header [`x-whatsapp-number-id`](/pt-BR/api/authentication) — sem ele, `403 TENANT_SCOPE_NOT_ALLOWED`. **Tokens OAuth / MCP e chaves de conta** (`ps_account_`) também precisam da permissão `chat:read` (`403 PERMISSION_DENIED` para o papel `ANALYST`).

## Parâmetros de query

<ParamField query="phoneNumberId" type="string" required>
  O Meta Phone Number ID que recebeu a mensagem. Mesmo valor que `phoneNumberId` no payload do webhook. Precisa pertencer a um número do seu workspace (senão, `404 NUMBER_NOT_FOUND`).
</ParamField>

## Exemplo

<CodeGroup>

```bash cURL
curl "https://pilotstatus.com.br/v1/media/abc123?phoneNumberId=123456789012345" \
  -H "x-api-key: ps_sua_chave_aqui"
```

```json Resposta (200)
{
  "url": "https://media.pilotstatus.com.br/public/tenants/_ephemeral/…/v1-media/3f2a.jpg",
  "base64": "data:image/jpeg;base64,/9j/4AAQ...",
  "mimeType": "image/jpeg",
  "fileName": "foto.jpg",
  "mediaId": "abc123"
}
```

</CodeGroup>

## Campos de resposta

<ResponseField name="url" type="string | null">
  Uma cópia do arquivo hospedada no armazenamento do Pilot Status — baixe como qualquer URL. `null` se a cópia falhou (use então o `base64`).
</ResponseField>

<ResponseField name="base64" type="string | null">
  Data URI completo (`data:<mimeType>;base64,<data>`) pronto para incorporar ou decodificar. `null` para arquivo acima de **16 MiB** — então `base64Omitted` explica o motivo e o `url` é o caminho para obtê-lo.
</ResponseField>

<ResponseField name="mimeType" type="string" required>
  Tipo MIME da mídia (ex.: `image/jpeg`, `video/mp4`, `audio/ogg`, `application/pdf`).
</ResponseField>

<ResponseField name="fileName" type="string | null">
  Nome original do arquivo quando disponível (documentos); caso contrário, `null`.
</ResponseField>

<ResponseField name="mediaId" type="string" required>
  O ID de mídia solicitado.
</ResponseField>

<ResponseField name="base64Omitted" type="object">
  Presente só quando o arquivo é grande demais para vir embutido: `{ "reason": "MEDIA_TOO_LARGE_FOR_INLINE", "byteLength": <tamanho>, "maxBytes": 16777216 }`.
</ResponseField>

## Erros

| Status | `code` | Quando |
| --- | --- | --- |
| `400` | `MISSING_PHONE_NUMBER_ID` | Falta o parâmetro de query `phoneNumberId`. |
| `400` | `META_TOKEN_MISSING` | O número não tem token de acesso da Meta (não é número oficial). |
| `401` | — | Credencial ausente ou inválida (`{"error": "Invalid API key"}`). |
| `403` | `TENANT_SCOPE_NOT_ALLOWED` | Chave da conta sem `x-whatsapp-number-id`. |
| `403` | `PERMISSION_DENIED` | Token OAuth/MCP ou chave de conta cujo papel não tem `chat:read`. |
| `403` | `NUMBER_NOT_IN_GRANT` | Token restrito a alguns números, e `phoneNumberId` não é um deles. |
| `404` | `NUMBER_NOT_FOUND` | Nenhum número do seu workspace tem esse `phoneNumberId`. |
| `404` | `MEDIA_NOT_FOUND` | A Meta não conhece o id de mídia, ou ele expirou. |
| `500` | `MEDIA_DOWNLOAD_FAILED` | O download na Meta falhou. |
| `502` | `MEDIA_TOO_LARGE_AND_REHOST_FAILED` | O arquivo passa de 16 MiB e também não pôde ser copiado (`byteLength`, `maxBytes` no corpo). |

Teste no Playground: [Baixar mídia](/pt-BR/playground/media/download-media-meta).

## Notas

1. O número de WhatsApp referenciado por `phoneNumberId` deve ter um `metaAccessToken` válido configurado no Pilot Status.
2. Os downloads de mídia devem ocorrer antes que a URL assinada pela Meta expire (normalmente alguns minutos após o webhook ser recebido).
3. O campo `base64` é um data URI completo pronto para uso direto — até 16 MiB; acima disso, use `url`.
4. Para figurinhas, o tipo MIME é normalmente `image/webp`.
5. Para áudio, a Meta pode retornar `audio/ogg` (mensagens de voz) ou `audio/mp4`.

## Campos do payload do webhook (Meta Cloud API)

Webhooks de entrada da Meta Cloud API (`message.received`, `message.reply`) incluem estes campos relacionados a mídia quando aplicável:

- `content` — corpo do texto ou legenda da mídia
- `mediaType` — `"image"` | `"video"` | `"audio"` | `"document"` | `"sticker"` | `"location"` | `"contacts"` | `"interactive"` | `"button"` | `"reaction"`
- `mediaId` — ID do objeto de mídia da Meta
- `mediaMimeType` — tipo MIME
- `mediaCaption` — legenda quando disponível
- `mediaFilename` — nome do arquivo original (documentos)
- `mediaDownloadHint` — instruções para download via este endpoint
