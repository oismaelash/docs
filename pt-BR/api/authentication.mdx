# Autenticação da API

Toda requisição à API do Pilot Status exige uma chave de API em um destes cabeçalhos:

- `x-api-key`: a chave bruta (`ps_*`)
- `x-api-key-id`: o ID da chave de API (o backend resolve internamente)

<Warning>
  Não há autenticação por Bearer token. Nunca envie `Authorization: Bearer` — use sempre o cabeçalho `x-api-key` (ou `x-api-key-id`).
</Warning>

## Prefixo da chave

Todas as chaves brutas começam com `ps_`. As chaves criadas a partir de 28/10/2026 também trazem o tipo: `ps_number_` (chave de número), `ps_workspace_` (chave de workspace) ou `ps_account_` (chave de conta). As chaves antigas (`ps_` + hex) continuam funcionando sem mudança. Veja [Tipos de chave](/pt-BR/api/key-types).

## Onde encontrar uma chave de API

- Chave com **escopo de número**: painel `/api-keys` — cada número de WhatsApp tem **uma chave padrão** que você pode **Regenerar** (não há subchaves / não há relação pai-filho).
- Chave com **escopo de tenant** (chave de workspace): painel **Chaves do workspace** (`/workspace-api-keys`) — a **chave principal** do workspace, mais **chaves com nome**, uma por integração.
- **Chave de conta** (`ps_account_`): painel **Perfil → API** — a sua própria chave, que age em qualquer workspace de que você é membro, escolhido pelo cabeçalho `x-workspace-id`. Veja [Chaves de conta](/pt-BR/api/key-types#chaves-de-conta).

<Note>
  A chave de API bruta é exibida apenas uma vez quando gerada/regenerada. Guarde-a com segurança.
</Note>

## Escopo da chave (número vs. tenant)

Toda chave de API tem um **escopo** que determina quais endpoints ela pode chamar. Ambos os escopos autenticam da mesma forma (`x-api-key: ps_*` ou `x-api-key-id`).

| Escopo | Vinculada a | Pode chamar | Onde encontrar |
| --- | --- | --- | --- |
| **Escopo de número** (padrão) | Um número de WhatsApp | Todos os endpoints de ação/dados desse número — `POST /v1/messages/send`, status de mensagem, cancelamento, grupos, newsletters, templates, analytics, mídia | Painel → página **API Keys** (uma chave padrão por número; **Regenerar**) |
| **Escopo de tenant** (chave de workspace) | O tenant (sem número) | Tudo. Ciclo de vida de números — `/v1/numbers/*` e `/v1/remote-pairing/*` — recursos da conta (`/v1/api-keys`, `/v1/branding`, `/v1/subscription/extra-numbers`, `/v1/billing/checkout`, `/v1/webhooks/*`, `/v1/embed/sessions`) **e** qualquer endpoint por número, de qualquer número do tenant, indicando-o no cabeçalho `x-whatsapp-number-id`. | Painel → **Chaves do workspace** |

### Chave com escopo de número

O tipo de chave padrão. Ela é vinculada a um único número de WhatsApp e é usada para todas as operações de ação e dados desse número (envio de mensagens, consultas de status, grupos, newsletters, templates, analytics, mídia). Ela rastreia toda ação executada para esse número.

### Chave com escopo de tenant

Uma chave com escopo de tenant — uma **chave de workspace** (`ps_workspace_`) — **não tem número associado**. Ela é destinada a plataformas SaaS que conectam e gerenciam múltiplos números (incluindo os números de seus clientes) via API pública. Cada workspace tem uma **chave principal** (a que o agente de IA do app usa) e pode ter **chaves com nome**, uma por integração, revogadas de forma independente. Veja [Chaves de workspace](/pt-BR/api/key-types#chaves-de-workspace).

- Ela gerencia números via `/v1/numbers/*` e `/v1/remote-pairing/*`, e gerencia recursos da conta: `/v1/api-keys` (listar a chave de cada número e regenerá-la), `/v1/branding`, `/v1/subscription/extra-numbers`, `/v1/billing/checkout`, `/v1/webhooks/*` e `/v1/embed/sessions` (connect).
- É o **único** escopo que pode gerenciar chaves de API por número via `POST /v1/api-keys` — uma chave com escopo de número não pode.
- Pode chamar qualquer endpoint **por número** — inclusive envio — indicando o número no cabeçalho `x-whatsapp-number-id`. Não é preciso uma chave separada por número.
- Ela é gerada/regenerada no painel, em **Chaves do workspace** (`/workspace-api-keys`). Antes de 28/10/2026 ela ficava em **Perfil → API**, que agora guarda as suas chaves de conta.

### Agir sobre um número específico com a chave de tenant

Envie `x-whatsapp-number-id` com o id do número em que quer agir. Aceita tanto o `WhatsAppNumber.id` quanto o `WhatsAppInstance.id` primário devolvido por `GET /v1/numbers`.

```bash
curl -X POST "https://pilotstatus.com.br/v1/messages/send" \
  -H "x-api-key: ps_sua_chave_de_tenant" \
  -H "x-whatsapp-number-id: <id de GET /v1/numbers>" \
  -H "Content-Type: application/json" \
  -d '{"destinationNumber":"5511999999999","text":"Oi"}'
```

Sem o cabeçalho, um endpoint por número responde **HTTP 403**, pedindo que você indique o número:

```json
{
  "error": "This endpoint acts on a single WhatsApp number: send the x-whatsapp-number-id header naming the number to act on (its id or instance id from GET /v1/numbers) | Este endpoint atua sobre um único número de WhatsApp: envie o header x-whatsapp-number-id indicando o número desejado (o id dele ou o id da instância, obtidos em GET /v1/numbers)",
  "code": "TENANT_SCOPE_NOT_ALLOWED"
}
```

Um id que não pertence ao seu tenant é rejeitado com **HTTP 404** — uma chave de tenant nunca alcança o número de outro tenant. Corpo: `{"error":"x-whatsapp-number-id does not name a WhatsApp number of this account | …","code":"NUMBER_NOT_FOUND"}`.

## Regenerar / rotacionar chaves

Regenere a chave padrão de um número pela página **API Keys** do painel, ou via API:

```bash
curl -X POST "https://pilotstatus.com.br/v1/api-keys/regenerate" \
  -H "x-api-key: ps_your_current_key"
```

Regenerar invalida a chave anterior imediatamente; a nova chave bruta é retornada apenas uma vez. Chamado com uma chave de workspace — a principal ou uma com nome —, ele gera uma nova chave **principal** do workspace; as chaves com nome continuam valendo.

## Exemplos de requisições

<CodeGroup>

```bash x-api-key
curl "https://pilotstatus.com.br/v1/messages/msg_abc" \
  -H "x-api-key: ps_your_key_here"
```

```bash x-api-key-id
curl "https://pilotstatus.com.br/v1/messages/msg_abc" \
  -H "x-api-key-id: ck_xxx"
```

</CodeGroup>

## Erros comuns

- `401` — cabeçalho `x-api-key` / `x-api-key-id` ausente ou inválido.
- `403` — chave válida, mas operação bloqueada (ex.: uma chave com escopo de tenant chamando um endpoint de ação por número → `code: "TENANT_SCOPE_NOT_ALLOWED"`, ou uma chave com escopo de número chamando um endpoint exclusivo de tenant → `code: "NUMBER_SCOPE_NOT_ALLOWED"`).
- As chaves de conta acrescentam `400 WORKSPACE_ID_REQUIRED`, `403 WORKSPACE_MEMBERSHIP_REQUIRED` e `403 ACCOUNT_KEY_REQUIRED` — veja [Tipos de chave → Erros](/pt-BR/api/key-types#erros).

## Boas práticas de segurança

<Warning>
  Use chaves de API apenas no **backend** — nunca as exponha em código de frontend, aplicativos móveis ou JavaScript no lado do cliente.
</Warning>

- Armazene a chave em variáveis de ambiente / um gerenciador de segredos.
- Trate a resposta de criação/regeneração como sensível (não registre a chave completa em logs).
