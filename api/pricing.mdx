The published **Meta / WhatsApp Business Platform** per-message rate for a single market + currency + category — the list price Meta charges per delivered message. This is Meta's public rate card exposed as reference data; it is **not** your account's real billing.

## Endpoint

`GET https://pilotstatus.com.br/v1/meta/pricing`

<Note>
  Any valid credential works: a number key (`ps_number_`), a workspace key (`ps_workspace_`), an account key (`ps_account_`, with `x-workspace-id`) or an OAuth token. No number header and no workspace role is required — pricing is global reference data, not tied to a number.
</Note>

## Query parameters

<ParamField query="market" type="string">
  Market code: ISO 3166-1 alpha-2 for countries (`BR`, `GB`, `IN`…), `NAM` for North America, or a region bucket (`AFR`, `APAC`, `CEEU`, `LATAM`, `MDE`, `WEU`, `GLO`).
</ParamField>

<ParamField query="currency" type="string">
  ISO 4217 currency code (`USD`, `BRL`, `EUR`, `GBP`, `INR`…).
</ParamField>

`market` and `currency` are case-insensitive (upper-cased before the lookup), and so is `category` (lower-cased).

<ParamField query="category" type="string">
  `marketing`, `utility`, `authentication`, `service` or `authentication_international`. Required together with `market` and `currency`.
</ParamField>

<ParamField query="tiers" type="boolean">
  `true`, `1` or `yes` → also return `volumeTiers` (Meta charges a lower price per message as monthly volume grows).
</ParamField>

## Modes

| Call | Returns |
| --- | --- |
| No `market` / `currency` / `category` | **Metadata** — the available markets (code + name), currencies and categories. |
| `market` + `currency` + `category` | The **flat price** for that combination. |
| Anything partial | `400 MARKET_CURRENCY_CATEGORY_REQUIRED`. |

## Response fields

<ResponseField name="market" type="string">Market code echoed back.</ResponseField>
<ResponseField name="marketName" type="string | null">Human-readable market name (`null` when the market has no name on file).</ResponseField>
<ResponseField name="currency" type="string">ISO 4217 currency echoed back.</ResponseField>
<ResponseField name="category" type="string">The requested category.</ResponseField>
<ResponseField name="pricePerMessage" type="number">
  List price per delivered message in the requested currency.

  ⚠️ Since **2026-10-01** `service` answers the market's **Utility** rate, never `0` — see the warning below. When the market has no Utility rate, `service` gets `404 PRICE_NOT_FOUND` instead of a misleading `0`. Read the value; do not hard-code which categories are free.
</ResponseField>
<ResponseField name="volumeTiers" type="array">
  Only when `tiers=1`. Each `{ from, to, pricePerMessage }` — the price drops as monthly volume grows; `to` is `null` on the unbounded top tier. Empty for categories without volume tiering (Marketing / Service).
</ResponseField>
<ResponseField name="fetchedAt" type="string">ISO 8601 of when the published card this price came from was last read. Always present. Not an effective date.</ResponseField>
<ResponseField name="source" type="string">Where the price came from: `whatsappbusiness.com` (the weekly refreshed table) or `developers.facebook.com` (the 2026-10-01 card Meta published, used for a market/currency until the weekly sync has refreshed it).</ResponseField>

In metadata mode the response is `{ markets: [{ code, name }], currencies: [...], categories: [...], source }`, with `markets` sorted by name and `source` always `whatsappbusiness.com`.

## Message categories

| Category | What it covers |
| --- | --- |
| `marketing` | Promotions, offers, product suggestions, re-engagement. |
| `utility` | Transactional / user-triggered updates (order, payment, delivery). |
| `authentication` | One-time passwords and identity verification. |
| `authentication_international` | Authentication to certain international destinations (its own rate). |
| `service` | Replies within the 24h customer service window. Was free (`0`) until 2026-09-30; **since 2026-10-01 priced at the Utility rate** — see the warning below. |

<Note>
  Meta only changes prices on the 1st day of each quarter (≈1 month notice), so this rate card is refreshed on a schedule. Treat the values as indicative and confirm against Meta's official rate cards for exact billing.
</Note>

## ⚠️ Since 1 October 2026, Service is no longer free

Meta changes its billing on that date, and it is the most consequential change on this page:

|  | Until 2026-09-30 | From 2026-10-01 |
| --- | --- | --- |
| **Service** (24 h window) | free, no cap | **1,000 delivered free per month, PER NUMBER**; after that, the country's **Utility** rate |
| **Utility** inside the 24 h window | free | **charged** |

⛔ **The allowance is per NUMBER, not per WABA.** Each number has its own 1,000 — putting several customers on one WhatsApp account does not make them share an allowance. 1:1 and group conversations draw on the same per-number allowance.

⚠️ **With no payment method on file at Meta, delivery stops past the 1,000.** Not silent degradation: the messages stop going out.

⇒ **What this means for anyone reading this route:** `pricePerMessage` for `service` no longer answers `0`: it returns the market's Utility rate (the list price beyond the 1,000 free per number). An integration that treats "service is always free" as a constant undercounts cost. Read the value instead of assuming it — that is what it is returned for.

📌 **For the exact amount billed on one specific message**, do not reconstruct it from this card: read `metaPricing` on [`GET /v1/messages/{messageId}`](/api/messages/status), or the `pricing` block on that message's delivery status in your webhook. `pricing.type` separates `free_customer_service` (inside the allowance) from `regular` (billed), and it is Meta's own verdict.

## There is no validity date in the response — and why

<Warning>
  **The response carries no `effectiveFrom` / `effectiveTo`.** There is no field telling you which quarter a price belongs to or when it stops applying, so you cannot tell from this response alone whether you are holding the current table.

  The reason is upstream: the published rate cards we mirror (`whatsappbusiness.com`, `developers.facebook.com`) state the prices, not the dates they took effect. Emitting an `effectiveFrom` would mean inventing one.
</Warning>

Until that is exposed, pin the moment yourself: **record the date you read each price** alongside the value, and re-read the card early in each quarter (Meta changes prices only on the 1st of a quarter). If you need the exact figure Meta billed for a specific message, do not reconstruct it from this table at all — read `pricing.category` and `pricing.type` straight off that message's delivery status in the [Meta native webhook envelope](/api/webhooks/events#statuses-—-this-is-where-the-billed-category-is). That is Meta's own verdict for that message, including whether it was charged.

<Note>
  **The response carries the AGE of the price.** `fetchedAt` says when we last pulled the published card, and `source` says where from. It is not an effective date — and there is none to give, for the reason above — but it answers the practical question: _am I using the current quarter's card?_

## Common errors

- `400 MARKET_CURRENCY_CATEGORY_REQUIRED` — provide `market`, `currency` and `category` together (or none, for metadata).
- `400 INVALID_CATEGORY` — the `category` value is not one of the five valid categories.
- `400 WORKSPACE_ID_REQUIRED` — account key (`ps_account_`) without the `x-workspace-id` header.
- `401` — missing or invalid credential.
- `404 PRICE_NOT_FOUND` — no published rate for that market + currency + category (including `service` in a market without a Utility rate).
