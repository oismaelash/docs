# Calls API reference

Base URL: `https://pilotstatus.com.br/v1` Headers: `Content-Type: application/json`, `x-api-key: <your_api_key>` (or `x-api-key-id`).

<Note>
  Calling works on **two** provider kinds: **META** (Meta Cloud API numbers) and **unofficial (Pilot Status web)** QR-connected numbers. Any other provider returns `400 FEATURE_NOT_SUPPORTED`. See the [overview](/api/calls/overview).
</Note>

## Authentication

Every `/v1/calls*` endpoint acts on **one WhatsApp number**:

- a **number key** (`ps_number_`) acts on its own number;
- a **workspace key** (`ps_workspace_`), an **account key** (`ps_account_`, with `x-workspace-id`) or an **OAuth token** must name the number in the `x-whatsapp-number-id` header — without it the answer is `403 TENANT_SCOPE_NOT_ALLOWED`. See [Authentication](/api/authentication).

With an account key or an OAuth token, the user's workspace role is checked on every request:

| Endpoints | Permission | Roles allowed |
| --- | --- | --- |
| `GET`·`PUT /v1/calls/settings` | `calls:settings:manage` | ADMIN, OWNER |
| Every other `/v1/calls*` endpoint | `calls:handle` | AGENT, ADMIN, OWNER |

Any other role gets `403 PERMISSION_DENIED`. An OAuth token granted only some numbers gets `403 NUMBER_NOT_IN_GRANT` for a call of another number.

<Warning>
  **SDP handling differs by provider.** META is WebRTC: you supply an SDP **offer** on `POST /v1/calls` and an SDP **answer** on `accept` — media flows browser ↔ WhatsApp. The unofficial (Pilot Status web) provider takes **no SDP** (`sdpOffer`/`sdpAnswer` stay `null`); media is handled **server-side** and you drive audio with the unofficial-only `/play` and `/realtime-session` endpoints.
</Warning>

## Endpoints

| Method | Endpoint | Providers | Description |
| --- | --- | --- | --- |
| `POST` | `/v1/calls` | META, Unofficial | Start a business-initiated call (BIC). META needs an SDP offer; Unofficial takes no SDP. |
| `GET` | `/v1/calls` | META, Unofficial | List the number's calls (newest first; `limit` 1–100, `before` ISO 8601 cursor). |
| `GET` | `/v1/calls/{callId}` | META, Unofficial | One call; add `?includeSdp=1` for `sdpOffer`/`sdpAnswer` (META only; `null` on Unofficial). |
| `POST` | `/v1/calls/{callId}/accept` | META, Unofficial | Answer an inbound (UIC) call. META supplies the SDP answer; Unofficial takes no body. |
| `POST` | `/v1/calls/{callId}/reject` | META, Unofficial | Decline an incoming call (no body). |
| `POST` | `/v1/calls/{callId}/terminate` | META, Unofficial | Hang up an active call (no body). |
| `POST` | `/v1/calls/{callId}/pre-accept` | **META only** | OPTIONAL early SDP answer (reduces audio clipping; call connects only on accept). |
| `GET` | `/v1/calls/settings` | **META only** | Read the number's `calling` settings object. |
| `PUT` | `/v1/calls/settings` | **META only** | Partial update of the `calling` settings. |
| `GET` | `/v1/calls/permissions?to=<phone>` | **META only** | Probe whether the business may call `to`. |
| `POST` | `/v1/calls/permissions/request` | **META only** | Send the interactive call-permission request (inside the 24h window). |
| `POST` | `/v1/calls/{callId}/play` | **Unofficial only** | Play an audio file into an active call (server downloads it); optional `hangupAfterPlay`. |
| `POST` | `/v1/calls/{callId}/realtime-session` | **Unofficial only** | Open a full-duplex PCM16 audio WebSocket for the call. |

`{callId}` accepts **either** the Pilot Status call id (the `id` of the call object) **or** the provider call id (`externalCallId` — Meta `wacid.…` on META, the CallID on Unofficial).

<Note>
  Endpoints marked **META only** return `400 FEATURE_NOT_SUPPORTED` on Unofficial numbers, and endpoints marked **Unofficial only** return `400 FEATURE_NOT_SUPPORTED` on META numbers. Unofficial has no BIC permission model and no calling-settings surface. An Unofficial number that is not connected returns `409 WHATSAPP_INSTANCE_NOT_CONNECTED`.
</Note>

## 1. Enable calling on the number <sub>(META only)</sub>

Pilot Status tries to enable calling automatically when a Meta number connects. Read/adjust anytime:

```bash
curl "https://pilotstatus.com.br/v1/calls/settings" \
  -H "x-api-key: ps_your_key_here"

curl -X PUT "https://pilotstatus.com.br/v1/calls/settings" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "status": "ENABLED", "call_icon_visibility": "DEFAULT" }'
```

- `PUT` is **partial**: send only `status`, `call_icon_visibility`, `callback_permission_status`, `call_hours`, `voicemail` (the `sip` object is rejected).
- A posted `call_hours` **replaces** the stored object entirely (Meta semantics).
- Numbers with a messaging limit **below 2,000/day cannot enable calling** yet (Meta error 138015, returned as `META_CALLING_TIER_TOO_LOW` → Pilot Status marks the number `PENDING_TIER` and retries as the tier climbs).
- Enabling also requires the WABA to have the **`calls` webhook field subscribed** (or SIP configured); without it Meta returns **138018** (`META_CALLING_PREREQUISITES_MISSING`) and Pilot Status marks the number `PENDING_WEBHOOK`. Subscribe the `calls` field on the WABA (or set up SIP), then retry.
- You can trigger enablement from the dashboard too — the **Enable calling** button under a number's **Meta details** (Numbers page) reports back `ENABLED`, `PENDING_TIER`, or `PENDING_WEBHOOK`.
- Values: `status`, `callback_permission_status`, `call_hours.status` and `voicemail.status` take `ENABLED` | `DISABLED`; `call_icon_visibility` takes `DEFAULT` | `DISABLE_ALL`. `call_hours` may also carry `timezone_id`, `weekly_operating_hours` (`day_of_week`, `open_time`, `close_time`) and `holiday_schedule` (`date`, `start_time`, `end_time`).
- At least one field is required. Any field not listed above (including `sip`) is rejected with `400 Validation error`.
- `GET` returns `{ "calling": { ... } }` (the object as Meta exposes it); `PUT` returns `{ "success": true }`.
- SIP credentials are never requested nor returned.

<Note>
  Unofficial numbers have no calling-settings surface — this endpoint returns `400 FEATURE_NOT_SUPPORTED`. Calling is available whenever the Unofficial instance is connected.
</Note>

## 2. Call permission (required before a BIC) <sub>(META only)</sub>

```bash
# probe
curl "https://pilotstatus.com.br/v1/calls/permissions?to=%2B5511999999999" \
  -H "x-api-key: ps_your_key_here"

# request (inside the 24h service window)
curl -X POST "https://pilotstatus.com.br/v1/calls/permissions/request" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "to": "+5511999999999", "text": "May we call you about your order?" }'
```

Probe response:

```json
{
  "permission": { "status": "temporary", "expiration_time": 1768550400 },
  "actions": [
    {
      "action_name": "start_call",
      "can_perform_action": true,
      "limits": [{ "time_period": "PT24H", "max_allowed": 1, "current_usage": 0 }]
    }
  ]
}
```

- `to` is required on both endpoints (`400 MISSING_TO` on the probe). It accepts an E.164 phone or a Meta BSUID on the request endpoint.
- `text` (optional, 1–1024 characters) is the reason shown to the user.
- The request endpoint answers `201` with `{ "messageId": "wamid.…" }`.

The user's answer arrives as the **`call.permission_updated`** webhook event (`status`: `NO_PERMISSION` | `TEMPORARY` | `PERMANENT`). Meta rate-limits permission requests (error 138009) and BIC volume (100 calls/24h per number — error 138012).

<Note>
  Unofficial has no BIC permission model — the permissions endpoints return `400 FEATURE_NOT_SUPPORTED`. Place BIC calls directly.
</Note>

## 3. Start a call (BIC)

<CodeGroup>

```bash META (SDP offer)
curl -X POST "https://pilotstatus.com.br/v1/calls" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{
    "to": "+5511999999999",
    "sdp": "v=0\r\no=- 4611731400430051336 2 IN IP4 127.0.0.1\r\n...",
    "sdpType": "offer",
    "bizOpaqueCallbackData": "order-42"
  }'
```

```bash Unofficial (no SDP)
curl -X POST "https://pilotstatus.com.br/v1/calls" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{
    "to": "+5511999999999",
    "bizOpaqueCallbackData": "order-42"
  }'
```

</CodeGroup>

```json
HTTP 201
{ "id": "cmc1x2y3z0000abcd1234efgh", "externalCallId": "wacid.ABGG...", "status": "INITIATED" }
```

- **META:** `sdp` is the RFC 8866 **offer** produced by YOUR WebRTC client. The business-side SDP must use `a=setup:active`. Without permission, Meta returns 138006 → the endpoint surfaces `code: "META_CALL_PERMISSION_REQUIRED"`.
- **Unofficial:** omit `sdp`/`sdpType` — media is server-side. Drive audio afterwards with `/play` or `/realtime-session`.
- `to` is an E.164 phone (optional `+`) or a Meta BSUID.
- `bizOpaqueCallbackData` (optional, up to 512 characters) is stored on the call and echoed back on the terminate webhook.
- `sdp` is at most 128 KB. `sdpType` accepts only `"offer"` (the default).
- `externalCallId` is `null` if the provider has not returned a call id yet.
- The call is recorded before the provider is contacted: if the provider refuses, the call stays in the list with `status: "FAILED"`, `errorCode` and `errorMessage`.

## 4. Answer an inbound call (UIC)

When a user calls your number you receive the **`call.ringing`** webhook. Then:

<CodeGroup>

```bash META (SDP answer)
# fetch the call with the SDP offer
curl "https://pilotstatus.com.br/v1/calls/wacid.ABGG...?includeSdp=1" \
  -H "x-api-key: ps_your_key_here"

# answer (body: your SDP answer; sdpType defaults to "answer")
curl -X POST "https://pilotstatus.com.br/v1/calls/wacid.ABGG.../accept" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "sdp": "v=0\r\n..." }'
```

```bash Unofficial (no SDP)
curl -X POST "https://pilotstatus.com.br/v1/calls/cmc1x2y3z0000abcd1234efgh/accept" \
  -H "x-api-key: ps_your_key_here"
```

</CodeGroup>

```bash
# decline / hang up (no body — both providers)
curl -X POST "https://pilotstatus.com.br/v1/calls/wacid.ABGG.../reject" -H "x-api-key: ps_your_key_here"
curl -X POST "https://pilotstatus.com.br/v1/calls/wacid.ABGG.../terminate" -H "x-api-key: ps_your_key_here"
```

`accept`/`pre-accept`/`reject`/`terminate` respond `{ "success": true, "id": "…", "status": "…" }` — `ACCEPTED` after `accept`, `REJECTED` after `reject`, `COMPLETED` after `terminate`; `pre-accept` keeps the current status. `sdpType` accepts only `"answer"` (the default). On META, `pre-accept` is optional (early SDP answer to reduce clipping) — the call connects only on `accept`; on Unofficial `accept` takes no body and `pre-accept` is unavailable.

## 5. Play audio into a call <sub>(Unofficial only)</sub>

Play a pre-recorded audio file into an active Unofficial call. The backend downloads the file (behind an SSRF guard) and streams it server-side into the call. When the call is not active yet, the audio is queued and starts as soon as the user answers.

```bash
curl -X POST "https://pilotstatus.com.br/v1/calls/cmc1x2y3z0000abcd1234efgh/play" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "mediaUrl": "https://example.com/greeting.mp3", "hangupAfterPlay": true }'
```

```json
{ "success": true, "id": "cmc1x2y3z0000abcd1234efgh", "status": "ACCEPTED" }
```

- `mediaUrl` — public http(s) URL (up to 2048 characters) of an `.mp3`, `.wav` or `.opus` file. The backend downloads it first: up to **20 MiB**, 30-second timeout, at most 3 redirects. A URL that resolves to a private/internal address returns `400 CALL_MEDIA_URL_BLOCKED`; a larger file `400 CALL_MEDIA_TOO_LARGE`; any other download failure `400 CALL_MEDIA_DOWNLOAD_FAILED`.
- `hangupAfterPlay` (optional) — end the call automatically when playback finishes. Perfect for notification flows: `POST /v1/calls` \+ `play` with `hangupAfterPlay: true` is a complete "call, speak, hang up" bot with no client-side timer.

<Tip>
  Host the audio on **fast storage** (S3/CDN): the backend downloads the file before handing it to the media server, so playback can only start after that download completes. A slow file host adds seconds of silence at the start of the call.
</Tip>

<Note>
  Returns `400 FEATURE_NOT_SUPPORTED` on META numbers (use the WebRTC media stream instead).
</Note>

## 6. Realtime audio session <sub>(Unofficial only)</sub>

Open a full-duplex PCM16 audio WebSocket for an active Unofficial call — ideal for streaming a live agent or a realtime voice model.

```bash
curl -X POST "https://pilotstatus.com.br/v1/calls/cmc1x2y3z0000abcd1234efgh/realtime-session" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "mode": "talk" }'
```

```json
{
  "wsUrl": "wss://<dedicated-media-host>/call/media/realtime/ws/...?token=...",
  "token": "d3f4...",
  "expiresInSeconds": 120
}
```

- `mode` (**required**) — `"talk"` sends your audio and receives the peer's; `"listen"` only receives.
- The socket carries raw binary PCM16 little-endian audio frames (plain WebSocket, not WebRTC).
- If the provider returns no session, the endpoint answers `502 CALL_REALTIME_SESSION_UNAVAILABLE`.

<Warning>
  The returned `wsUrl` lives on a **dedicated media host** — connect to it **directly**, not through the API base URL. The token is **single-use** with a short TTL (~2 minutes). The HTTP layer does not upgrade WebSocket connections, so the realtime socket is not proxied through `/v1`.
</Warning>

<Note>
  Returns `400 FEATURE_NOT_SUPPORTED` on META numbers.
</Note>

## 7. Call object (DTO)

```json
{
  "id": "cmc1x2y3z0000abcd1234efgh",
  "externalCallId": "wacid.ABGG...",
  "direction": "INBOUND",
  "status": "COMPLETED",
  "peerNumber": "5511999999999",
  "fromNumber": "5511999999999",
  "conversationId": "conv_abc",
  "bizOpaqueCallbackData": null,
  "startedAt": "2026-07-03T15:00:00.000Z",
  "connectedAt": "2026-07-03T15:00:05.000Z",
  "endedAt": "2026-07-03T15:02:05.000Z",
  "durationSeconds": 120,
  "errorCode": null,
  "errorMessage": null,
  "createdAt": "2026-07-03T15:00:00.000Z",
  "updatedAt": "2026-07-03T15:02:05.000Z"
}
```

- `status`: `INITIATED` | `RINGING` | `ACCEPTED` | `REJECTED` | `COMPLETED` | `FAILED` | `MISSED`.
- `direction`: `INBOUND` (UIC) | `OUTBOUND` (BIC).
- SDPs (`sdpOffer`/`sdpAnswer`) appear only with `?includeSdp=1` on `GET /v1/calls/{callId}` and only on META — on Unofficial they are always `null`.
- `durationSeconds` is set only when the call was answered.
- `externalCallId` is `null` while the provider has not assigned a call id.
- When the number's privacy settings hide the call (relay-only numbers, or calls older than the retention window), `peerNumber`, `fromNumber` and the SDPs are `null` and the object carries `"redacted": true`.
- `GET /v1/calls` returns `{ "calls": [ ... ] }`. To page, pass the `createdAt` of the last call as `before`. `limit` outside 1–100 returns `400 INVALID_LIMIT`; a `before` that is not a date returns `400 INVALID_BEFORE`.

## Webhooks

`call.ringing`, `call.connected`, `call.ended` (carries `duration` in seconds when the call was answered), and `call.missed` fire for **both META and Unofficial** numbers. `call.permission_updated` is **META only** — Unofficial numbers have no call-permission model. (In the REST call object returned by `GET /v1/calls`, the equivalent field is `durationSeconds`.)

## Billing

- **META:** business-initiated calls (BIC) are billed by Meta on the WABA — per minute, in 6-second pulses, only while the call is answered. User-initiated calls (UIC) are free.
- **Unofficial:** no Meta per-minute charge.
- Pilot Status charges nothing for calling on either provider.

## Common errors

Validation errors answer `400` with `{ "error": "Validation error", "details": { "formErrors": [...], "fieldErrors": { ... } } }` (no `code`).

| Status | `code` | When |
| --- | --- | --- |
| `400` | `FEATURE_NOT_SUPPORTED` | The number does not support this endpoint (a Meta-only endpoint on Unofficial or vice-versa, or a provider that is neither META nor Unofficial). |
| `400` | `NUMBER_NOT_FOUND` | The credential is not bound to a number. |
| `400` | `INVALID_BODY` | The body is not valid JSON (an empty body is read as `{}`). See [Malformed JSON body](/api/overview#malformed-json-body). |
| `400` | `INVALID_LIMIT`, `INVALID_BEFORE` | Bad `limit` / `before` on `GET /v1/calls`. |
| `400` | `MISSING_TO` | `GET /v1/calls/permissions` without `to`. |
| `400` | `CALL_MEDIA_URL_BLOCKED`, `CALL_MEDIA_TOO_LARGE`, `CALL_MEDIA_DOWNLOAD_FAILED` | `play` could not download `mediaUrl`. |
| `401` | — | Missing or invalid credential. |
| `403` | `TENANT_SCOPE_NOT_ALLOWED` | Workspace/account credential without `x-whatsapp-number-id`. |
| `403` | `PERMISSION_DENIED` | Account key / OAuth user whose role lacks `calls:handle` (or `calls:settings:manage` for settings). |
| `403` | `NUMBER_NOT_IN_GRANT` | OAuth token not granted the call's number. |
| `404` | `CALL_NOT_FOUND` | The `callId` does not belong to the credential's number. |
| `409` | `WHATSAPP_INSTANCE_NOT_CONNECTED` | The Unofficial number is not connected. |
| `409` | `LINKED_WHATSAPP_INSTANCE_NOT_FOUND` | The instance linked to the key no longer exists. |
| `502` | `WHATSAPP_INVALID_JSON` | The provider answered with invalid JSON. |
| `502` | `CALL_REALTIME_SESSION_UNAVAILABLE` | `realtime-session`: the provider returned no session. |
| `503` | `WHATSAPP_SESSION_KEY_MISSING` | The number's session key is not configured. |
| provider status | mapped code | The provider refused the call; `details: { status, body }` carries its answer. Unofficial numbers use `WHATSAPP_UPSTREAM_ERROR`. |

| 138002 | `META_CALL_CONCURRENT_LIMIT` |
| 138006 | `META_CALL_PERMISSION_REQUIRED` |
| 138009 | `META_CALL_PERMISSION_REQUEST_LIMIT` |
| 138012 | `META_CALL_LIMIT_REACHED` (100 calls/24h per number) |

| 138014 | `META_CALLING_DISABLED_QUALITY` |
