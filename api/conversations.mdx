List conversations for the connected number, ordered by the most recent message activity (`lastMessageAt` descending; conversations without one last).

## Endpoint

`GET https://pilotstatus.com.br/v1/conversations`

<Note>
  Acts on **one number**: use a **number-scoped** API key (`ps_*`) in the `x-api-key` header (or `x-api-key-id`), or an account-wide key that names the number in the [`x-whatsapp-number-id`](/api/authentication) header. An account-wide key without that header gets `403 TENANT_SCOPE_NOT_ALLOWED`.

  **OAuth / MCP tokens and account keys** (`ps_account_`) also need the `chat:read` permission (roles `AGENT`, `ADMIN`, `OWNER`); the `ANALYST` role is refused with `403 PERMISSION_DENIED`. A classic `ps_` key is not affected by roles.
</Note>

## Query parameters

<ParamField query="startDate" type="string">
  ISO 8601 datetime. Filter conversations whose last message is **on or after** this date.
</ParamField>

<ParamField query="endDate" type="string">
  ISO 8601 datetime. Filter conversations whose last message is **on or before** this date.
</ParamField>

<ParamField query="page" default="1" type="integer">
  Page number (≥ 1).
</ParamField>

<ParamField query="pageSize" default="30" type="integer">
  Results per page (1–100).
</ParamField>

Both `startDate` and `endDate` are optional individually. When supplied, each must be a valid ISO 8601 string and `startDate` must not be later than `endDate`; otherwise `400 INVALID_DATE_RANGE` is returned.

## PII mode effect

The response depends on the **PII mode** configured for the number — changed in the dashboard on the API Keys page (Privacy & retention panel) or on the number's settings in Numbers:

| PII mode | Effect |
| --- | --- |
| `STORE_INDEFINITE` (default) | All conversations returned (subject to date filters). |
| `STORE_X_DAYS` | Conversations are returned in full — retention is applied **per message** on the message endpoints, not to the conversation row, so its peer and `lastMessagePreview` stay. |
| `RELAY_ONLY` | Conversations **are** returned (not an empty list), but every row is **redacted** (`redacted: true`, peer identity and last-message preview `null`). The response includes a `notice: "PII_RELAY_ONLY"` field. |

## Conversation object fields

<ResponseField name="id" type="string" required>
  Pilot Status conversation ID.
</ResponseField>

<ResponseField name="whatsappNumberId" type="string" required>
  The number the conversation belongs to.
</ResponseField>

<ResponseField name="type" type="string" required>
  `"DIRECT"`, `"GROUP"` or `"NEWSLETTER"`.
</ResponseField>

<ResponseField name="from" type="string | null">
  Contact phone in E.164 (with `+`) for individuals; `null` for groups/newsletters, for contacts with no phone (lid-only or username-only) and when redacted.
</ResponseField>

<ResponseField name="fromName" type="string | null">
  Contact or group display name when available.
</ResponseField>

<ResponseField name="peerLid" type="string | null">
  WhatsApp LID of the contact, when known.
</ResponseField>

<ResponseField name="userId" type="string | null">
  Meta Business-Scoped User ID (BSUID) — the durable key of a Meta contact. Present even when `from` is `null` (a contact who uses a username), and accepted as `destinationNumber` on [`POST /v1/messages/send`](/api/messages/send).
</ResponseField>

<ResponseField name="username" type="string | null">
  The contact's WhatsApp username, when known.
</ResponseField>

<ResponseField name="profilePicUrl" type="string | null">
  Profile picture URL, when known.
</ResponseField>

<ResponseField name="lastMessagePreview" type="string | null">
  Short preview of the last message.
</ResponseField>

<ResponseField name="lastDirection" type="string | null">
  `INBOUND` or `OUTBOUND` — direction of the last message.
</ResponseField>

<ResponseField name="unreadCount" type="integer" required>
  Unread inbound messages in the conversation — the counter behind [`GET /v1/messages/unread`](/api/messages/unread).
</ResponseField>

<ResponseField name="lastMessageAt" type="string | null">
  ISO 8601 — last message activity. Conversations without it sort last.
</ResponseField>

<ResponseField name="lastInboundAt" type="string | null">
  ISO 8601 — last message received from the contact (what the 24-hour service window counts from).
</ResponseField>

<ResponseField name="createdAt" type="string" required>
  ISO 8601 — when the conversation was first created.
</ResponseField>

<ResponseField name="updatedAt" type="string" required>
  ISO 8601 — last update of the conversation record.
</ResponseField>

<ResponseField name="redacted" type="boolean">
  Present (`true`) only on a redacted conversation: `from`, `fromName`, `peerLid`, `userId`, `username`, `profilePicUrl` and `lastMessagePreview` are `null`.
</ResponseField>

## Common errors

- `400 INVALID_DATE_RANGE` — `startDate` or `endDate` is not a valid ISO 8601 string, or `startDate > endDate`.
- `400 INVALID_PAGINATION` — `page × pageSize` above `10000`.
- `400 NUMBER_NOT_FOUND` — the credential names no WhatsApp number.
- `401` — missing or invalid credential (`{"error": "Invalid API key"}`).
- `403 TENANT_SCOPE_NOT_ALLOWED` — an account-wide key without `x-whatsapp-number-id`.
- `403 PERMISSION_DENIED` — OAuth/MCP token or account key whose role lacks `chat:read` (`ANALYST`).
