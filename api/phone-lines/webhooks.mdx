# Phone line webhooks

<Tip>
  Try them with your key in the Playground: [`GET /v1/phone-lines/webhooks`](/playground/phone-lines/list-line-webhooks), [`POST /v1/phone-lines/webhooks`](/playground/phone-lines/create-line-webhook), [`GET …/{id}`](/playground/phone-lines/get-line-webhook), [`PATCH …/{id}`](/playground/phone-lines/update-line-webhook), [`DELETE …/{id}`](/playground/phone-lines/delete-line-webhook), [`GET …/{id}/deliveries`](/playground/phone-lines/list-line-webhook-deliveries), [`GET …/deliveries/{deliveryId}`](/playground/phone-lines/get-line-webhook-delivery).
</Tip>

Phone lines send their events to **phone-line webhooks**: a registry of their own, separate from the [number webhooks](/api/webhooks/configure). The two never mix:

- A number webhook — even one subscribed to `"*"` — **never** receives a `phone_line.*` event.
- A phone-line webhook receives **only** `phone_line.*` events, never message or number events.

## Configure

Manage phone-line webhooks **in the dashboard** or **through the API** — it is the same registry: what you create through one shows up in the other. In the dashboard, under **Phone lines → Line webhooks** (`/linhas/webhooks`), as an **Owner or Admin**; in the API, with a **tenant-scoped** key on [`/v1/phone-lines/webhooks`](#through-the-api). The rules are the same on both:

- **Name** — optional, up to 100 characters, to tell your webhooks apart in the list. Left blank, the webhook is named after the URL's host (`hooks.example.com`), as number webhooks are. This webhook name is not sent in the deliveries (the `name` in a delivery is the line's).
- **Destination URL** — must be `https`, and must reach a public address. A URL that points to an internal or private network address — `localhost`, a loopback or private IP, a host name without a dot, or a name that resolves to one of those — is refused when you save it (`WEBHOOK_URL_REFUSED`), since it would never be called.
- **Events** — pick one or more of the events below, or **all** (`"*"`). Inside this registry `"*"` means every phone-line event. At least one is required.
- **Signing secret** — shown **once**, when the webhook is created (it starts with `plwh_`): in the dashboard, right after creating it; in the API, in the `POST` response. Store it right away: nothing shows it again, and there is no rotation. To change it, create a new webhook, move your receiver to its secret, and delete the old one.
- **Pause / resume, edit (name, URL and events), and delete.** Editing never changes the signing secret. A new URL is checked the same way as on creation; saving without changing the URL does not check it again, so a webhook can always be paused.
- **Delivery log** — per webhook: event, status (pending, delivered, failed), attempts, the HTTP status your endpoint answered and the last error.

A workspace can have more than one phone-line webhook; each receives the events it subscribed to.

<Note>
  This registry is also reachable as [workspace webhooks](/api/workspace-webhooks), at `/v1/workspace/webhooks` and on the **Workspace keys** screen, which add the wallet event `wallet.topup_paid`. The list here shows those webhooks too; one that names `wallet.topup_paid` can be read and deleted here, but editing it here gets **400 `INVALID_WEBHOOK`** — edit it on `/v1/workspace/webhooks`.
</Note>

### Through the API

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/v1/phone-lines/webhooks` | List the phone-line webhooks (oldest first) and the event catalogue. |
| `POST` | `/v1/phone-lines/webhooks` | Create a webhook. Returns the signing secret, **this one time only**. |
| `GET` | `/v1/phone-lines/webhooks/{id}` | Get a webhook. |
| `PATCH` | `/v1/phone-lines/webhooks/{id}` | Edit name, URL and events, or pause and resume (`active`). |
| `DELETE` | `/v1/phone-lines/webhooks/{id}` | Delete a webhook. |
| `GET` | `/v1/phone-lines/webhooks/{id}/deliveries` | The webhook's latest deliveries, without their body. |
| `GET` | `/v1/phone-lines/webhooks/{id}/deliveries/{deliveryId}` | One delivery in full, with the body that was sent. |

<Note>
  Requires a **tenant-scoped** key — a number-scoped key gets **403 `NUMBER_SCOPE_NOT_ALLOWED`**, as on every `/v1/phone-lines` endpoint. With an OAuth / MCP token, the user must be an **Owner or Admin** (`phone_lines:webhooks`) — `403 PERMISSION_DENIED` otherwise. All of them can be tried in the **Playground → [Phone Lines](/playground/phone-lines/list-line-webhooks)**.
</Note>

#### Create a webhook

`POST https://pilotstatus.com.br/v1/phone-lines/webhooks` with `{ name?, url, events }`. Answers **`201`** with `{ "webhook": { … } }`, sent with `Cache-Control: no-store`.

<ParamField body="url" type="string" required>
  The public `https` URL that receives the deliveries.
</ParamField>

<ParamField body="events" type="string[]" required>
  One or more names from the [events table](#events), or `["*"]` for every phone-line event. Duplicates are ignored.
</ParamField>

<ParamField body="name" type="string">
  Up to 100 characters. Absent or blank, it becomes the URL's host.
</ParamField>

Any other body field is refused with **400 `UNKNOWN_FIELDS`**, which names the fields.

<CodeGroup>

```bash cURL
curl -X POST "https://pilotstatus.com.br/v1/phone-lines/webhooks" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_tenant_scoped_key" \
  -d '{
    "name": "My app",
    "url": "https://hooks.example.com/pilot/phone-lines",
    "events": ["phone_line.code_received", "phone_line.payment_failed"]
  }'
```

```json Response (201)
{
  "webhook": {
    "id": "cmh1w8b2k0001wh8example3d",
    "name": "My app",
    "url": "https://hooks.example.com/pilot/phone-lines",
    "events": ["phone_line.code_received", "phone_line.payment_failed"],
    "active": true,
    "secret": "plwh_3f9a1c7e5b2d8f4a6c0e9b1d7f3a5c8e2b4d6f8a0c1e3b5d",
    "createdAt": "2026-10-27T13:58:02.000Z"
  }
}
```

</CodeGroup>

<Warning>
  **The `secret` comes only in this response.** No read — `GET`, `PATCH`, the list — returns it, and there is no rotation. Store it on your server before doing anything else; if you lose it, create a new webhook and delete the old one. Creating is **not** idempotent: repeating the `POST` (after a timeout, for example) creates a second webhook with another secret — check the list before creating again.
</Warning>

#### List and get

`GET https://pilotstatus.com.br/v1/phone-lines/webhooks` answers `{ "webhooks": [ … ], "events": [ … ] }`: the workspace's webhooks, oldest first, and the catalogue of events a phone-line webhook can subscribe to. `GET …/webhooks/{id}` answers `{ "webhook": { … } }`. A webhook of another workspace answers **404 `WEBHOOK_NOT_FOUND`**, like an id that does not exist.

```json Response (200) — GET /v1/phone-lines/webhooks
{
  "webhooks": [
    {
      "id": "cmh1w8b2k0001wh8example3d",
      "name": "My app",
      "url": "https://hooks.example.com/pilot/phone-lines",
      "events": ["phone_line.code_received", "phone_line.payment_failed"],
      "active": true,
      "lastDeliveryAt": "2026-10-27T14:11:51.000Z",
      "lastStatusCode": 200,
      "createdAt": "2026-10-27T13:58:02.000Z"
    }
  ],
  "events": [
    "phone_line.purchased",
    "phone_line.audio_received",
    "phone_line.code_received",
    "phone_line.code_failed",
    "phone_line.renewed",
    "phone_line.payment_failed",
    "phone_line.suspended",
    "phone_line.returned",
    "phone_line.canceled",
    "phone_line.verification_updated"
  ]
}
```

| Field | Description |
| --- | --- |
| `id` | The webhook id, for the `/v1/phone-lines/webhooks/{id}` paths. |
| `name` | Never empty: the name given, or the URL's host. |
| `url` | The destination URL. |
| `events` | The subscribed events, or `["*"]`. |
| `active` | `false` when paused: a paused webhook receives no deliveries. |
| `lastDeliveryAt` | ISO 8601 of the last **successful** delivery, or `null`. A failed attempt does not change it. |
| `lastStatusCode` | The last HTTP status your endpoint answered, successful or not, or `null`. |
| `createdAt` | ISO 8601 — when the webhook was created. |

#### Edit, pause and delete

`PATCH https://pilotstatus.com.br/v1/phone-lines/webhooks/{id}` takes `name`, `url`, `events` and `active`, all optional; whatever is not sent stays as it is. It answers `{ "webhook": { … } }` without the secret, which never changes. Only a URL that **changes** is checked again — pausing or changing the events always works, even when the stored URL would be refused today. A `name` sent blank goes back to the URL's host.

```bash
# Pause
curl -X PATCH "https://pilotstatus.com.br/v1/phone-lines/webhooks/cmh1w8b2k0001wh8example3d" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_tenant_scoped_key" \
  -d '{ "active": false }'
```

`DELETE https://pilotstatus.com.br/v1/phone-lines/webhooks/{id}` answers `{ "ok": true }`. The webhook's pending deliveries are discarded.

#### Delivery log

`GET https://pilotstatus.com.br/v1/phone-lines/webhooks/{id}/deliveries` answers `{ "deliveries": [ … ] }`, newest first, **without the body** of each delivery.

<ParamField query="limit" default="50" type="integer">
  From 1 to 200. Any other value → **400 `INVALID_LIMIT`**.
</ParamField>

```json Response (200)
{
  "deliveries": [
    {
      "id": "cmh1w9c4m0002dl8example5f",
      "event": "phone_line.code_received",
      "status": "DELIVERED",
      "attempts": 1,
      "responseStatus": 200,
      "lastError": null,
      "createdAt": "2026-10-27T14:11:51.000Z",
      "deliveredAt": "2026-10-27T14:11:52.000Z"
    }
  ]
}
```

`status` is `PENDING`, `DELIVERED` or `FAILED`; `responseStatus` is the HTTP status your endpoint answered, and `lastError` the last error when no accepted answer came back.

`GET https://pilotstatus.com.br/v1/phone-lines/webhooks/{id}/deliveries/{deliveryId}` answers `{ "delivery": { … } }` with the same fields plus three from the **last attempt**: `durationMs`, `responseBody` (your endpoint's answer, up to 1,000 characters) and `payload` — the exact body that was sent and signed, as a JSON **string**. Compute the HMAC over that string with your secret and you get the `x-pilot-status-signature` the delivery carried. Sent with `Cache-Control: no-store`.

<Warning>
  The `payload` of a `phone_line.code_received` carries the activation code, which is a credential. The list never carries it; reading one delivery does. Do not log that response.
</Warning>


#### Errors

Errors follow the [phone-lines envelope](/api/phone-lines/overview#errors): a bilingual `error` and a `code`. The authentication and scope errors (`401`, `403 NUMBER_SCOPE_NOT_ALLOWED`, `TENANT_REQUIRED`, `WORKSPACE_ARCHIVED`, `PERMISSION_DENIED`, `WORKSPACE_MEMBERSHIP_REQUIRED`) are the same as on every `/v1/phone-lines` endpoint.

| Status | `code` | Where | What happened |
| --- | --- | --- | --- |
| `400` | `INVALID_BODY` | `POST`, `PATCH` | The body is not a JSON object. |
| `400` | `UNKNOWN_FIELDS` | `POST`, `PATCH` | Fields other than `name`, `url`, `events` (and `active`, on `PATCH`). `details.unknownFields` says which. |
| `400` | `INVALID_FIELD_TYPE` | `POST`, `PATCH` | A field has the wrong type — for example `"active": "false"` or `null`. `details.field` and `details.expected` say which and what was expected. |
| `400` | `INVALID_WEBHOOK` | `POST`, `PATCH` | `url` missing, invalid or not `https`, or `events` empty or with an unknown event. |
| `400` | `INVALID_WEBHOOK_NAME` | `POST`, `PATCH` | `name` longer than 100 characters. |
| `400` | `WEBHOOK_URL_REFUSED` | `POST`, `PATCH` | The URL points to an internal or private network address. |
| `400` | `INVALID_LIMIT` | `GET …/deliveries` | `limit` is not an integer from 1 to 200. |
| `404` | `WEBHOOK_NOT_FOUND` | `…/{id}`, `…/deliveries` | No webhook with that id in your workspace. |
| `404` | `WEBHOOK_DELIVERY_NOT_FOUND` | `…/deliveries/{deliveryId}` | No delivery with that id on that webhook. |
| `500` | `INTERNAL_ERROR` | all | Unexpected failure. |

<Accordion title="Exact error messages">
  | `code` | `error` |
  | --- | --- |
  | `INVALID_WEBHOOK` | `Invalid webhook: use an https URL and known events. \| Webhook inválido: use uma URL https e eventos conhecidos.` |
  | `INVALID_WEBHOOK_NAME` | `Invalid webhook name: use at most 100 characters. \| Nome do webhook inválido: use no máximo 100 caracteres.` |
  | `WEBHOOK_URL_REFUSED` | `Webhook URL refused: it points to an internal or private network address, which we never call. Use a public address. \| URL do webhook recusada: ela aponta para um endereço interno ou de rede privada, que nunca chamamos. Use um endereço público.` |
  | `WEBHOOK_NOT_FOUND` | `Webhook not found. \| Webhook não encontrado.` |
  | `WEBHOOK_DELIVERY_NOT_FOUND` | `Webhook delivery not found. \| Entrega do webhook não encontrada.` |

  `INVALID_BODY`, `UNKNOWN_FIELDS`, `INVALID_FIELD_TYPE` and `INVALID_LIMIT` build their message from the request — it names the field at fault — and follow the same `English | Portuguese` pattern.
</Accordion>

## Events

| Event | When it fires |
| --- | --- |
| `phone_line.purchased` | A line was bought (dashboard or `POST /v1/phone-lines`) — one event per number bought. |
| `phone_line.audio_received` | The call of a code request was captured and its recording stored (`CAPTURED`) — before the code is read, which can take a few minutes. Carries the recording's [`audioUrl`](#the-recording-url). |
| `phone_line.code_received` | A code request finished: **once per request**, with the `code`, or with `code: null` and its `failureReason` when it ended without one. |
| `phone_line.code_failed` | A code request ended without a code, for good — once, with the `reason`. Always paired with a `phone_line.code_received` whose `code` is `null`. |
| `phone_line.renewed` | A renewal charge succeeded, including a late one that brings a `PAYMENT_PENDING` or `SUSPENDED` line back. |
| `phone_line.payment_failed` | A renewal charge failed and the line went from `ACTIVE` to `PAYMENT_PENDING`. Once per renewal — the retries that follow do not fire it again. |
| `phone_line.suspended` | The line was still unpaid 2 days after the failure and is now `SUSPENDED`. |
| `phone_line.returned` | The line was returned to the carrier (`RETURNED`) — 1 day after suspension, at once when an unpaid line is cancelled or left out in the dashboard's **Choose which lines to keep**, or 3 days after the rejection of the holder verification it was bought under. `reason` says which. |
| `phone_line.canceled` | A line cancelled at period end reached `currentPeriodEnd` and is now `CANCELED`. |
| `phone_line.verification_updated` | The account holder verification changed state: finished (approved automatically, or sent to manual review), or reviewed (approved, rejected, or another document requested). |

<Note>
  Every accepted code request ends with **one** `phone_line.code_received` — with the code, or with `code: null` — so waiting on that event alone is enough. A failed transcription is retried from the stored recording (up to 3 attempts in all); only the final outcome is sent, never the attempts in between. A request refused at creation (`503 SUPPLIER_UNAVAILABLE`, `poll_not_scheduled`) sends no event: its caller already got the error.

  `phone_line.audio_received` and `phone_line.code_failed` were added on 2026-09-28. A webhook subscribed to all events (`"*"`) receives them; a webhook with an explicit list receives only the events it lists — edit it to add them.
</Note>

## Payload format

Every delivery is a `POST` with a JSON body:

```json
{
  "id": "cmg5k4d1v0003dl8example2m",
  "event": "phone_line.purchased",
  "createdAt": "2026-10-01T14:03:11.000Z",
  "data": {
    "lineId": "cmg5k2l1n0001pl8example9x",
    "number": "551148637200",
    "name": "(11) 4863-7200",
    "currentPeriodEnd": "2026-11-01T14:03:11.000Z"
  }
}
```

| Field | Description |
| --- | --- |
| `id` | The delivery id — the same on every retry of this delivery. **Dedupe on it.** Each webhook gets its own delivery, so two webhooks subscribed to the same event receive different `id`s. |
| `event` | The event name. |
| `createdAt` | ISO 8601 — when the event was recorded. |
| `data` | The event's fields, below. |

Headers:

| Header | Value |
| --- | --- |
| `Content-Type` | `application/json` |
| `x-pilot-status-signature` | Hex-encoded HMAC-SHA256 of the raw body, keyed with the webhook's secret. |
| `Idempotency-Key` | Same value as the body's `id`. |

Every event about a line — all but `phone_line.verification_updated` — carries the line's `lineId`, `number` and **`name`**: the name your team gave it in the dashboard or, when it has none, its formatted number (`(11) 4863-7200`), the same as [`name`](/api/phone-lines/list#line-object-fields) on the line object. A line is bought without a name, so `phone_line.purchased` always carries the formatted number. `name` is the name at the time of the event: renaming a line sends no event, and a retry of a delivery carries the name it was recorded with. Like `displayName` in the number webhooks, it is a label — match lines by `lineId`.

<Note>
  **Numbers here have no `+`.** `number` is E.164 digits without the plus sign (`551148637200`), exactly as in the `/v1/phone-lines` endpoints — unlike the number webhooks, whose phone fields carry `+`.
</Note>

## The recording URL

The three events of a code request — `phone_line.audio_received`, `phone_line.code_received` and `phone_line.code_failed` — carry **`audioUrl`**: the absolute URL of [`GET /v1/phone-lines/activations/{activationId}/audio`](/api/phone-lines/activation-codes#download-the-recording), which serves the call recording.

```text
https://pilotstatus.com.br/v1/phone-lines/activations/cmg5k3a7c0002ac8example4q/audio
```

- **When the request has a recording, it is there.** `phone_line.audio_received` always has it — it is sent once the recording is stored. `phone_line.code_received` and `phone_line.code_failed` have it whenever the call was stored: with the code, and also when no code could be read (`no_code_in_transcript`, `transcription_failed`), which is when you most want to listen.
- **`null` when there is none** — the key is always present. That is a request that ended before any call was stored: `no_call_in_window`, `canceled_by_customer`, `audio_download_failed` or `audio_store_failed`.
- **It holds no credential.** Fetch it with your **tenant-scoped** key (`x-api-key`), like any `/v1/phone-lines` endpoint; without a key it answers `401`, and another workspace's key gets `404`. Storing or logging the URL does not expose the recording.
- **It stops answering when the line leaves your workspace.** A `RETURNED` or `CANCELED` line has its recordings deleted, and the URL then answers `404`.

```bash
curl "https://pilotstatus.com.br/v1/phone-lines/activations/cmg5k3a7c0002ac8example4q/audio" \
  -H "x-api-key: ps_your_tenant_scoped_key" \
  -o activation.wav
```

## Verify the signature

Every phone-line webhook has a secret, so **every delivery is signed**. `x-pilot-status-signature` is the hex-encoded **HMAC-SHA256 of the raw request body**, keyed with the webhook's secret (the whole string, `plwh_` prefix included). Compute it over the bytes exactly as received — before any JSON parsing — and compare in constant time.

**With the Python SDK** (`pilot-status` 1.16.0 or later), `verify_webhook_signature(raw_body, signature_header, secret)` does it for you — the same function as for the number webhooks, called with the full `plwh_...` secret. Pass the body exactly as it came off the wire — Flask `request.get_data()`, FastAPI `await request.body()` — never the parsed and re-serialized JSON. It compares in constant time and returns `False`, never raising, for a missing or malformed header, an empty secret or a tampered body:

```bash
pip install "pilot-status>=1.16.0"
```

<CodeGroup>

```python Flask
import os

from flask import Flask, abort, request
from pilot_status import WEBHOOK_SIGNATURE_HEADER, verify_webhook_signature

app = Flask(__name__)
SECRET = os.environ["PILOT_STATUS_WEBHOOK_SECRET"]  # the full plwh_... string

@app.post("/hooks/pilot-status")
def pilot_status_hook():
    raw = request.get_data()  # the raw bytes that were signed, not json.dumps(request.json)
    if not verify_webhook_signature(raw, request.headers.get(WEBHOOK_SIGNATURE_HEADER), SECRET):
        abort(401)
    # ... parse json.loads(raw) and process it
    return "", 200
```

```python FastAPI
import os

from fastapi import FastAPI, HTTPException, Request
from pilot_status import WEBHOOK_SIGNATURE_HEADER, verify_webhook_signature

app = FastAPI()
SECRET = os.environ["PILOT_STATUS_WEBHOOK_SECRET"]  # the full plwh_... string

@app.post("/hooks/pilot-status")
async def pilot_status_hook(request: Request):
    raw = await request.body()  # the raw bytes that were signed
    if not verify_webhook_signature(raw, request.headers.get(WEBHOOK_SIGNATURE_HEADER), SECRET):
        raise HTTPException(status_code=401)
    # ... parse json.loads(raw) and process it
    return {}
```

</CodeGroup>

**Without the SDK**, compute it yourself:

<CodeGroup>

```javascript Node
const crypto = require("node:crypto");

// rawBody: the request body exactly as received (Buffer or string).
function isValidSignature(rawBody, signatureHeader, secret) {
  const expected = crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  const received = String(signatureHeader ?? "");
  return (
    received.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(received))
  );
}
```

```python Python
import hashlib
import hmac

# raw_body: the request body exactly as received (bytes).
def is_valid_signature(raw_body: bytes, signature_header: str | None, secret: str) -> bool:
    expected = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature_header or "")
```

</CodeGroup>

It is the same computation as the number webhooks, so a receiver that already verifies those works here with this webhook's secret. The signature covers the body only — there is no timestamp header — so rely on `id` to discard duplicates.

## Delivery and retries

- **Answer with any `2xx` within 10 seconds.** Anything else — another status, a timeout, a connection error — counts as a failed attempt.
- **6 attempts in total**: the first right away, then retries about 30 s, 1 min, 2 min, 4 min and 8 min apart — normally about **15 minutes** end to end. After the last one the delivery is marked failed in the log. A delivery that could not be queued at first is picked up again by an hourly sweep, so its first attempt can come later.
- **Redirects are not followed.** A `3xx` answer counts as a failed attempt.
- **At least once.** A retry after your endpoint processed the event but did not answer in time delivers it again, with the same `id`. Order is not guaranteed.
- **Paused or deleted webhooks.** An event is delivered only to webhooks that are active and subscribed when it happens. Every attempt checks the webhook again: a delivery whose webhook is paused when an attempt is due — including one already in its retries — is marked failed and is not sent later; deleting a webhook drops its pending deliveries. Events are never replayed to a webhook created or resumed afterwards.
- **Internal destinations are refused.** A URL whose host resolves to a private or internal network address is not called, and is not retried. Such a URL is already refused when you save the webhook; this covers a name whose DNS moved inside afterwards. A DNS lookup that fails is different: it does not block saving, and at delivery it is retried like any other failure.

<Tip>
  Treat these events as notifications, not as the source of truth. When one could have been missed — your endpoint was down for longer than the retries — read the current state with [`GET /v1/phone-lines`](/api/phone-lines/list).
</Tip>
