Retrieve messages from **GROUP** conversations for the connected number.

## Endpoint

`GET https://pilotstatus.com.br/v1/messages/group`

<Note>
  Acts on **one number**: use a **number-scoped** API key (`ps_*`) in the `x-api-key` header, or an account-wide key that names the number in the [`x-whatsapp-number-id`](/api/authentication) header. An account-wide key without that header gets `403 TENANT_SCOPE_NOT_ALLOWED`.

  **OAuth / MCP tokens and account keys** (`ps_account_`) also need the `chat:read` permission (roles `AGENT`, `ADMIN`, `OWNER`); the `ANALYST` role is refused with `403 PERMISSION_DENIED`. A classic `ps_` key is not affected by roles.
</Note>

<Note>
  The endpoint reads the group messages **stored** for the number — it never calls the provider, so it does not fail for a number with no groups: the list is simply empty. On an official (Meta) number there are group messages only if the number takes part in groups through Meta's Groups API.
</Note>

## Query parameters

<ParamField query="startDate" type="string">
  ISO 8601 datetime. Filter messages created **on or after** this date.
</ParamField>

<ParamField query="endDate" type="string">
  ISO 8601 datetime. Filter messages created **on or before** this date.
</ParamField>

<ParamField query="page" default="1" type="integer">
  Page number (≥ 1).
</ParamField>

<ParamField query="pageSize" default="30" type="integer">
  Results per page (1–100).
</ParamField>

Both `startDate` and `endDate` are optional individually. When supplied, each must be a valid ISO 8601 string and `startDate` must not be later than `endDate`; otherwise `400 INVALID_DATE_RANGE` is returned.

Results are ordered by `createdAt` descending (newest first).

## PII mode effect

The response depends on the **PII mode** configured for the number — changed in the dashboard on the API Keys page (Privacy & retention panel) or on the number's settings in Numbers.

The query lower and upper bounds come **only** from the caller's `startDate` / `endDate` — PII mode never narrows the queried date range. Instead, rows that fall outside the number's PII retention window are still returned, but **redacted**: their `text`, `media`, and participant fields are set to `null` and the row carries `redacted: true`.

| PII mode | Effect |
| --- | --- |
| `STORE_INDEFINITE` (default) | All group messages returned in full (subject to `startDate` / `endDate`). |
| `STORE_X_DAYS` | All matching rows are returned. Rows older than the retention window are redacted (`text`, `media`, and participant fields `null`, `redacted: true`); rows within the window are returned in full. |
| `RELAY_ONLY` | All matching rows are returned but **every** row is redacted (`text`, `media`, and participant fields `null`, `redacted: true`), and the response includes a `notice: "PII_RELAY_ONLY"` field. |

Each item has the same shape as the items of [`GET /v1/messages/history`](/api/messages/history): the group is identified by `conversationId` (list the group conversations, with their names, in [`GET /v1/conversations`](/api/conversations), where `type` is `GROUP`) and the member who wrote by `participantPhone` / `participantName`.

## Message object fields

<ResponseField name="id" type="string" required>
  Pilot Status internal message ID.
</ResponseField>

<ResponseField name="conversationId" type="string" required>
  ID of the parent conversation (direct or group).
</ResponseField>

<ResponseField name="direction" type="string" required>
  `"INBOUND"` (received) or `"OUTBOUND"` (sent).
</ResponseField>

<ResponseField name="providerKind" type="string" required>
  Engine of the number that handled the message: `META` on official numbers; `EVO_GO` or `EVO_V2` on unofficial (Pilot Status web) numbers. Unlike `media.provider`, this field carries the internal engine tag.
</ResponseField>

<ResponseField name="externalMessageId" type="string | null">
  Provider message id (e.g. Meta `wamid`) when available.
</ResponseField>

<ResponseField name="status" type="string" required>
  Message status (`QUEUED`, `SENT`, `DELIVERED`, `READ`, `PLAYED`, `FAILED`, `CANCELED`). Received messages are usually `DELIVERED` or `READ`.
</ResponseField>

<ResponseField name="messageType" type="string" required>
  `text`, `image`, `audio`, `video`, `document`, `sticker`, `location`, `contacts`, `interactive`, `reaction`, `button`, `template` or `unknown`.
</ResponseField>

<ResponseField name="origin" type="string | null">
  Where an outbound message came from, when recorded: `APP` — sent from the WhatsApp Business app on the phone or another tool on the same WABA; `CHATWOOT` — an agent reply from a native Chatwoot WhatsApp Cloud inbox, sent through the [Meta layer](/api/layer/meta); `LAYER` — sent through the Meta layer by any other client. A message Pilot Status sent itself may carry `API` or `null`. `null` on inbound messages: read `direction` to tell sent from received. The set grows, so treat a value you do not recognise as outbound.
</ResponseField>

<ResponseField name="text" type="string | null">
  Message text or caption when available.
</ResponseField>

<ResponseField name="participantName" type="string | null">
  WhatsApp display name of the counterpart/sender when available.
</ResponseField>

<ResponseField name="participantPhone" type="string | null">
  Phone of the counterpart/sender when available (in a group, the member who wrote).
</ResponseField>

<ResponseField name="participantUserId" type="string | null">
  Meta Business-Scoped User ID (BSUID) of the counterpart/sender, when Meta supplied one.
</ResponseField>

<ResponseField name="repliedToExternalId" type="string | null">
  `externalMessageId` of the message this one replies to, when available.
</ResponseField>

<ResponseField name="media" type="object | null">
  Media descriptor `{ provider, id, url, mimeType, fileName }` when the message carries media; `null` otherwise.

  - `media.provider` — `"META"` on Meta Cloud API numbers, `"WEB"` on unofficial (Pilot Status web) numbers.
  - `media.id` — **Meta** media id. Set on `META` inbound media — pass it to [`GET /v1/media/{mediaId}`](/api/media-download) to download the bytes; `null` for `WEB`.
  - `media.url` — Direct download URL when available. **META** inbound media is mirrored to Pilot Status storage (so META messages usually carry both `id` **and** `url`); web numbers provide their own link. Best-effort — may be `null`.
  - `media.mimeType` — Media MIME type when known (may be `null`).
  - `media.fileName` — Media file name when known (may be `null`).
</ResponseField>

<ResponseField name="sentAt" type="string | null">
  ISO 8601 — when the message was sent.
</ResponseField>

<ResponseField name="deliveredAt" type="string | null">
  ISO 8601 — when the message was delivered.
</ResponseField>

<ResponseField name="readAt" type="string | null">
  ISO 8601 — when the message was read (only when read receipts are enabled).
</ResponseField>

<ResponseField name="providerTimestamp" type="string" required>
  ISO 8601 — provider's timestamp for the message.
</ResponseField>

<ResponseField name="createdAt" type="string" required>
  ISO 8601 — when the record was created in Pilot Status.
</ResponseField>

<ResponseField name="referral" type="object | null">
  Click-to-WhatsApp ad origin of the message, when it came from an ad (official numbers) — the same object described in [`GET /v1/referrals`](/api/referrals). `null` otherwise.
</ResponseField>

<ResponseField name="redacted" type="boolean">
  Present (`true`) only when the row falls outside the number's PII retention window (or the number is `RELAY_ONLY`). Redacted rows keep their `id`, timestamps and delivery metadata, but `text`, `media`, `participantName`, `participantPhone` and `participantUserId` are `null`.
</ResponseField>

## Common errors

- `400 INVALID_DATE_RANGE` — `startDate` or `endDate` is not a valid ISO 8601 string, or `startDate > endDate`.
- `400 INVALID_PAGINATION` — `page × pageSize` above `10000`; narrow the dates instead of paging further.
- `400 NUMBER_NOT_FOUND` — the credential names no WhatsApp number.
- `401` — missing or invalid credential (`{"error": "Invalid API key"}`).
- `403 TENANT_SCOPE_NOT_ALLOWED` — an account-wide key without `x-whatsapp-number-id`.
- `403 PERMISSION_DENIED` — OAuth/MCP token or account key whose role lacks `chat:read` (`ANALYST`).
