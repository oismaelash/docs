---
title: "GET /v1/messages/unread — Unread Messages"
description: "Retrieve all inbound messages that have not been read yet for the connected number."
mode: "wide"
---

Retrieve the inbound messages that count as unread for the connected number. Unread is **not** derived from a per-message `readAt` flag (per-message `readAt` is not maintained for inbound messages). Instead, it is derived from each conversation's `unreadCount` — the same counter shown in the dashboard — and the response `total` is the **sum of `unreadCount` across the unread conversations**. Each item includes that conversation-level unread count.

## Endpoint

`GET https://pilotstatus.com.br/v1/messages/unread`

<Note>
  Acts on **one number**: use a **number-scoped** API key (`ps_*`) in the `x-api-key` header, or an account-wide key that names the number in the [`x-whatsapp-number-id`](/api/authentication) header. An account-wide key without that header gets `403 TENANT_SCOPE_NOT_ALLOWED`.

  **OAuth / MCP tokens and account keys** (`ps_account_`) also need the `chat:read` permission (roles `AGENT`, `ADMIN`, `OWNER`); the `ANALYST` role is refused with `403 PERMISSION_DENIED`. A classic `ps_` key is not affected by roles.
</Note>

To get only the **counts**, for one or several numbers in one call, use [`GET /v1/messages/unread/counts`](#counts-per-number).

## Query parameters

<ParamField query="pageSize" default="30" type="integer">
  Results per page (1–100).
</ParamField>

<ParamField query="cursor" type="string">
  Keyset cursor: the `nextCursor` of the previous response, unchanged. The way to page past the first pages. Cannot be combined with `page > 1` or `offset` (`400 INVALID_PAGINATION`); a value that is not a cursor returned by this endpoint is `400 INVALID_CURSOR`.
</ParamField>

<ParamField query="page" default="1" type="integer">
  Page number (≥ 1). `page × pageSize` may not exceed `10000`.
</ParamField>

<ParamField query="offset" type="integer">
  Rows to skip (≥ 0), instead of `page`. `offset + pageSize` may not exceed `10000`.
</ParamField>

There is no date-range filter on this endpoint. Messages come newest first (`providerTimestamp`, then `id`), and each unread conversation contributes its latest `unreadCount` inbound messages — at most **100** per conversation.

## PII mode effect

The response depends on the **PII mode** configured for the number (set in the dashboard, on the API Keys page's Privacy & retention panel or in the number's settings). This endpoint uses **redact-and-show**: rows are not hidden — a row the PII policy covers keeps its envelope, has `text`, `media`, the participant fields, `from`, `fromName`, `userId` and `username` set to `null`, and carries `redacted: true`.

| PII mode | Effect |
| --- | --- |
| `STORE_INDEFINITE` (default) | All unread messages returned in full. |
| `STORE_X_DAYS` | Rows **outside** the retention window are redacted; rows inside it are returned in full. |
| `RELAY_ONLY` | Every row is redacted and the response adds `"notice": "PII_RELAY_ONLY"`. `total` still reports the conversations' counters. |

`total` is the **sum of `unreadCount`** over the number's unread conversations, so it can be larger than the rows you can page through (each conversation contributes at most 100). `nextCursor` is set when the page came back full; pass it as `cursor` to get the next page, and stop when it is `null`.

## Message object fields

Each item has the fields of a [`GET /v1/messages/history`](/api/messages/history#message-object-fields) item (`id`, `conversationId`, `direction` — always `INBOUND` here —, `providerKind`, `externalMessageId`, `status`, `messageType`, `origin`, `text`, `participantName`, `participantPhone`, `participantUserId`, `repliedToExternalId`, `media`, `sentAt`, `deliveredAt`, `readAt`, `providerTimestamp`, `createdAt`, `referral`, `redacted`), plus:

<ResponseField name="from" type="string | null">
  The contact in E.164 with a leading `+`, taken from the conversation (falls back to `participantPhone`). `null` when redacted or when the contact has no phone (username-only contact).
</ResponseField>

<ResponseField name="fromName" type="string | null">
  Contact display name, from the conversation when known.
</ResponseField>

<ResponseField name="userId" type="string | null">
  The contact's Meta Business-Scoped User ID (BSUID), when known — usable as `destinationNumber` on [`POST /v1/messages/send`](/api/messages/send).
</ResponseField>

<ResponseField name="username" type="string | null">
  The contact's WhatsApp username, when known.
</ResponseField>

<ResponseField name="conversationUnreadCount" type="integer" required>
  Unread count of that conversation.
</ResponseField>

`readAt` is in practice always `null`: per-message `readAt` is not maintained for inbound messages; unread state lives on the conversation (`conversationUnreadCount`).

## Common errors

- `400 INVALID_PAGINATION` — `page × pageSize` or `offset + pageSize` above `10000`, a negative or non-integer `offset`, or `cursor` combined with `page > 1` / `offset`.
- `400 INVALID_CURSOR` — `cursor` is not a value this endpoint returned.
- `400 NUMBER_NOT_FOUND` — the credential names no WhatsApp number.
- `401` — missing or invalid credential (`{"error": "Invalid API key"}`).
- `403 TENANT_SCOPE_NOT_ALLOWED` — an account-wide key without `x-whatsapp-number-id`.
- `403 PERMISSION_DENIED` — OAuth/MCP token or account key whose role lacks `chat:read` (`ANALYST`).

## Counts per number

```text
GET https://pilotstatus.com.br/v1/messages/unread/counts
```

The unread **count** of each number in one call — no message content. A number's `total` is exactly the `total` that `GET /v1/messages/unread` returns for it.

<ParamField query="whatsappNumberIds" type="string">
  Optional. Comma-separated (or repeated) `WhatsAppNumber` ids, at most **100**. Omitted: every number the credential reaches.
</ParamField>

Which numbers the credential reaches:

- a **number-scoped** key, or an account-wide key with `x-whatsapp-number-id` — that number only;
- an **OAuth / MCP token restricted to some numbers**, or an account key of a member restricted to some numbers — those numbers;
- an **account-wide** key (workspace key, full-workspace token) without the header — every number of the workspace.

Unlike the list, this endpoint does **not** refuse an account-wide key. It needs the same `chat:read` permission on OAuth / MCP tokens and account keys.

```bash
curl "https://pilotstatus.com.br/v1/messages/unread/counts" \
  -H "x-api-key: ps_workspace_your_key_here"
```

```json Response (200)
{
  "byNumber": [
    { "whatsappNumberId": "cmnum_01", "number": "5511999999999", "displayName": "Support", "total": 12 },
    { "whatsappNumberId": "cmnum_02", "number": "5511888888888", "displayName": null, "total": 0 }
  ],
  "total": 12
}
```

Numbers you named come back in the order you named them; otherwise oldest number first. Counters are not PII, so a `RELAY_ONLY` number reports its count too.

| Status | `code` | When |
| --- | --- | --- |
| `400` | `TOO_MANY_NUMBERS` | More than 100 ids in `whatsappNumberIds`. |
| `400` | `NUMBER_REQUIRED` | A per-number OAuth grant with no number to read. |
| `400` | `NUMBER_NOT_FOUND` | The credential names no WhatsApp number. |
| `403` | `NUMBER_NOT_IN_GRANT` | A named number is outside what the credential reaches. |
| `403` | `PERMISSION_DENIED` | OAuth/MCP token or account key whose role lacks `chat:read`. |
| `404` | `NUMBER_NOT_FOUND` | A named number is not a number of this workspace; `whatsappNumberIds` in the body lists which. |

These refusals carry `{ "error": "<English> | <Português>", "code": "…" }`. Try it in the Playground: [Unread counts per number](/playground/conversations/unread-counts).
