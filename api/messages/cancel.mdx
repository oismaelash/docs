# Cancel Scheduled Sends

```text
DELETE https://pilotstatus.com.br/v1/messages/cancel
```

Cancels **scheduling** for one or more messages that are still **queued** for a future send (`QUEUED` with a future `deliverAt` / `deliverBy`). The message row is **not** deleted: status becomes **`CANCELED`**, and Logs \+ trace history remain.

<Note>
  `CANCELED` is **not** `FAILED` and is not one of the delivery-error `errorCode` values listed in [Log Error Codes](/api/messages/log-error-codes).
</Note>

## Headers

- `Content-Type: application/json`
- `x-api-key: ps_...` (or `x-api-key-id`) — same key as `POST /v1/messages/send`: a **number-scoped** key, or an account-wide key with [`x-whatsapp-number-id`](/api/authentication)

**OAuth / MCP tokens and account keys** (`ps_account_`) also need the `messages:cancel_scheduled` permission (roles `AGENT`, `ADMIN`, `OWNER`).

## Body

<ParamField body="messageIds" type="string[]" required>
  1 to **100** internal message `id`s (the `id` returned by the send) per request. Only messages of the key's number are found.
</ParamField>

```json
{ "messageIds": ["<id1>", "<id2>"] }
```

## Example

```bash
curl -X DELETE "https://pilotstatus.com.br/v1/messages/cancel" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{ "messageIds": ["msg_abc", "msg_def"] }'
```

<Note>
  This endpoint uses `DELETE` with a **JSON body**; `curl`, `fetch`, and most HTTP clients support it.
</Note>

## Response (200)

```json
{
  "cancelled": ["msg_abc"],
  "failed": [{ "id": "msg_def", "reason": "Not queued" }]
}
```

- Only still-schedulable messages appear in `cancelled`; others are listed in `failed` with a `reason`: `Message not found`, `Not queued`, `Not scheduled (no future deliverBy)`, `Missing WhatsApp instance` or `Could not cancel (state changed)`. The answer is `200` even when nothing was cancelled.
- After canceling, `GET /v1/messages/{messageId}` returns `"status": "CANCELED"`.
- The **Logs** page supports the same flow via bulk selection of scheduled rows.

## Common errors

- `400 INVALID_BODY` — the body is not valid JSON, empty included. See [Malformed JSON body](/api/overview#malformed-json-body).
- `400` — `{"error": "Validation failed", "details": {…}}`: missing or empty `messageIds`, more than 100 IDs, an empty string.
- `401` — missing/invalid credential (`{"error": "Invalid API key"}`).
- `403 TENANT_SCOPE_NOT_ALLOWED` — an account-wide key without `x-whatsapp-number-id`.
- `403 PERMISSION_DENIED` — OAuth/MCP token or account key whose role lacks `messages:cancel_scheduled`.
