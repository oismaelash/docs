Every endpoint below authenticates with a **number-scoped API key** (`x-api-key`) whose number is a **Meta (Cloud API)** number. The WABA is derived from that number — there is no parameter to name one, by design.

| Permission | Covers |
| --- | --- |
| `flows:read` | Listing Flows and reading form responses |
| `flows:manage` | Every write — create, update, upload JSON, publish, deprecate, delete — **and the whole `data_exchange` surface (the endpoint key and the Flow endpoint), reads included** |

<Warning>
  **Reading the endpoint key or the Flow endpoint needs `flows:manage`, not `flows:read`**, even though both are `GET`s. Their responses carry `endpointUrl` / `endpointUri` / `metaEndpointUri`, and the token inside those URLs is a **credential**: Meta authenticates to the endpoint by decrypting, and the matching public key is public by construction. Whoever holds both can forge a request Pilot Status will decrypt and forward to your webhook under our signature. A read-only credential is still a credential — which is also why the value never appears on `GET /v1/flows`.
</Warning>

<Note>
  `flows:read` is a slug of its own and is **not** `templates:read`. A template listing returns text your workspace wrote; a Flow response returns what a **customer** typed into a form — a name, a phone, sometimes a document number. The two are gated separately on purpose.
</Note>

## List Flows

```bash
curl "https://pilotstatus.com.br/v1/flows?page=1&pageSize=30" \
  -H "x-api-key: ps_your_key_here"
```

```json
{
  "flows": [
    {
      "id": "flw_local_1",
      "metaFlowId": "1122334455",
      "name": "Agendamento",
      "metaStatus": "PUBLISHED",
      "categories": ["APPOINTMENT_BOOKING"],
      "jsonVersion": "7.1",
      "healthStatus": "AVAILABLE",
      "clonedFromFlowId": null,
      "supersededByFlowId": null,
      "createdAt": "2026-08-30T12:00:00.000Z",
      "updatedAt": "2026-09-01T09:12:00.000Z"
    }
  ],
  "total": 1, "page": 1, "pageSize": 30
}
```

<Note>
  `id` is the **local id** and is the only id you ever send back to us. `metaFlowId` is Meta's own and is read-only — it is `null` while a Flow exists here but has not reached Meta.
</Note>

## Create or clone

```bash
curl -X POST "https://pilotstatus.com.br/v1/flows" \
  -H "x-api-key: ps_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Agendamento v2",
    "categories": ["APPOINTMENT_BOOKING"],
    "cloneFromFlowId": "flw_local_1"
  }'
```

Returns `201` with the new Flow in `DRAFT`. Omit `cloneFromFlowId` to start from scratch.

<Warning>
  `cloneFromFlowId` is the **local id** of the source Flow — the `id` field, not `metaFlowId`. Cloning is the only way to change a Flow that has been published.
</Warning>

## Rename and re-categorize

```bash
curl -X PATCH "https://pilotstatus.com.br/v1/flows/flw_local_1" \
  -H "x-api-key: ps_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Agendamento (matriz)", "categories": ["APPOINTMENT_BOOKING"] }'
```

Accepts **only** `name` and `categories`. This never publishes and never deprecates — those have endpoints of their own, so that a mistake in a form cannot reach an irreversible operation.

## Upload the Flow JSON

```bash
curl -X POST "https://pilotstatus.com.br/v1/flows/flw_local_1/json" \
  -H "x-api-key: ps_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "flowJson": "{\"version\":\"7.1\",\"screens\":[...]}" }'
```

A `200` means the document compiled, and `validationErrors` is then always empty:

```json
{ "validationErrors": [] }
```

A document Meta refuses comes back as **`422` `FLOW_JSON_INVALID`**, with Meta's own list attached:

```json
{
  "error": "A Meta recusou este Flow JSON. Veja validationErrors.",
  "errorEN": "Meta rejected this Flow JSON. See validationErrors.",
  "code": "FLOW_JSON_INVALID",
  "validationErrors": [ { "error": "...", "line_start": 12, "message": "..." } ]
}
```

<Warning>
  **This is deliberately NOT how Meta's own API behaves, and the difference is the point.**

  Meta answers `200` with the problems listed _inside_ the payload — so an apparent success over an invalid document is the normal case there, and a client that only checks the status ships a Flow that never compiled.

  This route reads the list rather than the Graph status, and answers `422` whenever it is non-empty. A `200` from us therefore means what a `200` should mean. Read `validationErrors` on the `422` — it is Meta's own answer, verbatim.

  `flowJson` is a **string**, never a nested object: Meta compiles the exact bytes, and re-serializing would silently reorder what you wrote.
</Warning>

## Publish

```bash
curl -X POST "https://pilotstatus.com.br/v1/flows/flw_local_1/publish" \
  -H "x-api-key: ps_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "confirm": true }'
```

<Warning>
  **Irreversible on Meta.** A published Flow can never be edited or unpublished — only cloned into a new one. `"confirm": true` is required; without it the request is refused with `400`.
</Warning>

## Deprecate

```bash
curl -X POST "https://pilotstatus.com.br/v1/flows/flw_local_1/deprecate" \
  -H "x-api-key: ps_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "supersededByFlowId": "flw_local_2" }'
```

Retires the Flow without deleting it, and without deleting the responses people already submitted. `supersededByFlowId` is optional — but if you send it, it must name a real Flow of yours: an empty string is refused rather than silently ignored, because a broken version chain is invisible afterwards.

## Delete

```bash
curl -X DELETE "https://pilotstatus.com.br/v1/flows/flw_local_1" \
  -H "x-api-key: ps_your_key_here"
```

Only a `DRAFT` can be deleted. Anything else returns `409`.

## Read form responses

```bash
curl "https://pilotstatus.com.br/v1/flows/flw_local_1/responses?page=1&pageSize=30" \
  -H "x-api-key: ps_your_key_here"
```

Returns what customers submitted, joined to the contact who answered, within the retention window. Responses past their expiry are never served.

<Note>
  **This is the stored copy, not the live one.** For submissions as they arrive, subscribe to the `flow.response_received` webhook event — the answers come with it, already parsed. The chat message that carries a submission holds only Meta's label (`Sent` / `Enviado`), so a webhook subscribed to `messages` alone sees nothing. See [Receive Flow responses](/guides/flow-responses).
</Note>

<Warning>
  **A short page can be a truncated page, and it says so.** `FlowResponse` carries no `flowId` column — the only edge from a Flow to its answers runs through the session token — so one request correlates at most **10,000** of that Flow's sends. Past that ceiling the payload carries `"notice": "FLOW_RESPONSES_WINDOW_TRUNCATED"` alongside the normal `responses`/`total`/`page`/`pageSize`/`totalPages`.

  It is a **`200`**, not an error, and the field is absent whenever nothing was cut. Read it: a caller that reconciles against a short page without checking `notice` concludes submissions were lost.
</Warning>

## `data_exchange` endpoint key

<Note>
  Only needed for Flows whose screens call your backend — see [Connect your API to a Flow](/guides/flow-data-exchange) for the full picture. `{numberId}` is the number your API key is bound to. The private key never leaves Pilot Status and is returned by no endpoint; `endpointUrl` is the base to register on your Flow, with the Flow id appended as a final segment.

  **The key is per number; the forwarding URL is per Flow.** Both have a surface here — the key below, the URL under [Flow endpoint](#flow-endpoint) — and neither appears on `GET /v1/flows`, deliberately: an API key can be a third-party application, and the address of your internal webhook is not something a read-only integration is owed.
</Note>

<Note>
  **Both endpoints act on the key's own number, and `{numberId}` in the path must agree with it.** A number-scoped key names its number by itself; an account-wide key must narrow with `x-whatsapp-number-id`. A path id that does not match answers `404` `FLOW_NUMBER_NOT_FOUND` — never `403`, and the same body whether the id belongs to another tenant or to another of your own numbers, so that a wrong guess learns nothing.

  `uploadedAt` is `null` when a pair was generated here but Meta never accepted it. That is not the same as no key at all, and it is the state a repeat `POST` resumes rather than replaces.
</Note>

### Read the current state

```bash
curl "https://pilotstatus.com.br/v1/numbers/{numberId}/flow-endpoint-key" \
  -H "x-api-key: ps_your_key_here"
```

```json
{
  "configured": true,
  "publicKey": "-----BEGIN PUBLIC KEY-----\n...",
  "uploadedAt": "2026-09-02T10:00:00.000Z",
  "endpointUrl": "https://pilotstatus.com.br/api/flows/endpoint/AbC123...",
  "metaStatus": "VALID"
}
```

| `metaStatus` | Meaning |
| --- | --- |
| `VALID` | Meta holds the key we hold. Nothing to do. |
| `MISMATCH` | Meta holds a **different** key. Every `data_exchange` Flow on this number is failing — rotate. |
| `NOT_SET` | Meta holds no key for this number yet. |
| `UNKNOWN` | We could not read Meta's side. |

<Warning>
  **`UNKNOWN` is not `NOT_SET`, and collapsing them is expensive.** A Graph call that failed says nothing about what Meta holds. Treating it as "no key" means rotating — and rotating replaces a key that was probably fine.
</Warning>

### Generate, rotate, or import

One `POST`, two verbs. **The presence of `privateKey` decides which**, and they are not interchangeable: generating registers a new public key at Meta and replaces whatever was there; importing registers nothing.

| Body | What it does |
| --- | --- |
| `{}` | **Generate** — mint an RSA-2048 pair, store the private half encrypted, register the public half with Meta. |
| `{"privateKey": "-----BEGIN PRIVATE KEY-----\n…"}` | **Import** — store the key you already own. Nothing is registered with Meta. |
| `{"privateKey": "…", "passphrase": "…"}` | Import a passphrase-protected PEM. |
| `{…, "confirm": true}` | Required when either verb would replace a key that is **live** at Meta. |

Only `confirm`, `privateKey` and `passphrase` are accepted; anything else is refused, never ignored. The response is the read shape above plus `"replaced"`, which says whether a key that was live has just been displaced — a `200` alone does not.

```bash
# Generate
curl -X POST "https://pilotstatus.com.br/v1/numbers/{numberId}/flow-endpoint-key" \
  -H "x-api-key: ps_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```bash
# Import
curl -X POST "https://pilotstatus.com.br/v1/numbers/{numberId}/flow-endpoint-key" \
  -H "x-api-key: ps_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "privateKey": "-----BEGIN PRIVATE KEY-----\nMIIEvQIBADAN...\n-----END PRIVATE KEY-----\n" }'
```

<Warning>
  **Replacing a LIVE key requires `{"confirm": true}`, on both verbs.**

  Generating is destructive at Meta: Meta holds exactly one public key per phone number, so registering a new one replaces the old — and the previous private half is overwritten here at the same moment. It cannot be restored, and every `data_exchange` exchange in flight on that number stops decrypting.

  Importing is destructive **here**: nothing at Meta changes, but the stored private half is replaced, and if Meta cannot confirm the new one the number is left holding a key that may decrypt nothing. The two are refused with different codes for that reason — `FLOW_ENDPOINT_KEY_REQUIRES_CONFIRMATION` and `FLOW_ENDPOINT_KEY_IMPORT_REQUIRES_CONFIRMATION` — because a caller who read "this replaces your Meta registration" after an import would go checking Meta for a change that never happened.

  ⚠️ The **first** setup does not ask, and neither does retrying a key Meta never accepted (`uploadedAt: null`) — there is nothing to destroy in either case. A confirmation demanded where nothing can be lost trains the reflex that disarms it in the one case where it protects.
</Warning>

<Note>
  **An import is verified before it is stored.** We derive the public half from the key you sent and compare it with Meta's: a match is stored and stamped (`metaStatus: "VALID"`); a **mismatch is refused outright** with `FLOW_ENDPOINT_KEY_IMPORT_MISMATCH` and nothing is written; a Graph call we could not make leaves the key stored with `uploadedAt: null` and `metaStatus` `UNKNOWN`/`NOT_SET`, which is the "not confirmed" state, not a failure.
</Note>

<Warning>
  **`passphrase` is used once and is not stored.** It opens the PEM; the key is then kept normalised and encrypted at rest, and the passphrase has no reader afterwards. Keep your own copy — we cannot return it. Send it only when the key has one (an empty string is a passphrase, not the absence of one), and never on its own: `passphrase` without `privateKey` is refused with `FLOW_ENDPOINT_KEY_PASSPHRASE_ORPHAN`, because that same request would otherwise **generate** a pair and replace your registration at Meta.
</Warning>

## Flow endpoint

Where a `data_exchange` Flow's decrypted exchanges are forwarded. Per **Flow**, `flows:manage` on every verb including the `GET`, and `{flowId}` is the **local** id from `GET /v1/flows`.

```bash
curl "https://pilotstatus.com.br/v1/flows/{flowId}/endpoint" \
  -H "x-api-key: ps_your_key_here"
```

```bash
curl -X PUT "https://pilotstatus.com.br/v1/flows/{flowId}/endpoint" \
  -H "x-api-key: ps_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "url": "https://api.your-company.com/flows/booking" }'
```

```json
{
  "flowId": "flw_local_1",
  "url": "https://api.your-company.com/flows/booking",
  "hasSecret": true,
  "endpointUri": "https://pilotstatus.com.br/api/flows/endpoint/AbC123.../1122334455",
  "metaEndpointUri": null,
  "drift": false,
  "numberHasKey": true,
  "numberKeyUploadedAt": "2026-09-02T10:00:00.000Z",
  "warnings": ["FLOW_ENDPOINT_META_URI_UNKNOWN"],
  "secret": "9f2c…"
}
```

| Field | Meaning |
| --- | --- |
| `url` | Your destination. `null` when the Flow has none. |
| `hasSecret` | Whether a signing secret exists. The secret itself is never readable. |
| `endpointUri` | **Our** proxy URL for this Flow — the value Meta's `endpoint_uri` must hold. |
| `metaEndpointUri` | What Meta has registered, as the hourly sync last read it. |
| `drift` | `true` only when both are known and differ — Meta is calling someone else. |
| `numberHasKey` / `numberKeyUploadedAt` | The key state of the number this credential is bound to. |
| `warnings` | Every reason this Flow will not work. Treat the set as open. |
| `secret` | **Only on the response that minted it**, and never again. |

<Note>
  Body fields: `url` (required, `https://` or an explicit `null` to clear — never omitted) and `rotateSecret` (boolean). `PUT` and `PATCH` are the same operation. The number comes from the credential and is refused in the body (`FLOW_NUMBER_FROM_KEY`).

  **Saving the URL does not register anything at Meta** — that is a separate act against a separate system, so that a rename cannot silently hijack a Flow already pointed at someone else's endpoint. `metaEndpointUri`, `drift` and `warnings` are how you see the difference.
</Note>

<Warning>
  **`secret` is shown exactly once, on the request that minted it.** It is stored encrypted with no read path back. `secret: null` on a later save means one already existed and was kept — `hasSecret` is what says whether there is one at all. `{"rotateSecret": true}` mints a fresh one, and is the only exit from a secret that leaked.
</Warning>

Full walkthrough, including the contract your endpoint must satisfy: [Connect your API to a Flow](/guides/flow-data-exchange).

## Errors

Every failure of this surface answers the same envelope — there is exactly one shape to read, and one spelling:

```json
{ "error": "<Portuguese>", "errorEN": "<English>", "code": "<CODE>" }
```

`FLOW_JSON_INVALID` adds a `validationErrors` array; `FLOW_UNKNOWN_FIELDS` adds the offending keys. Never assume the set of codes is closed — branch on the ones you handle and fall through to `code` for the rest.

| Code | Status | Meaning |
| --- | --- | --- |
| `FLOW_NOT_FOUND` | 404 | No Flow with that id inside your key's WABA |
| `FLOW_NOT_DRAFT` | 409 | The Flow left `DRAFT` — clone it to start a new version |
| `FLOW_REQUIRES_META_NUMBER` | 422 | The key's number is not a Meta number, or has no WABA |
| `FLOW_NUMBER_FROM_KEY` | 400 | The request named the number (`whatsappNumberId`, `numberId` or `wabaId`, in body or query) — it comes from the key, and is never accepted alongside it |
| `FLOW_JSON_INVALID` | 422 | Meta refused the document — read `validationErrors` |
| `FLOW_JSON_REQUIRED` | 400 | `flowJson` absent or empty |
| `FLOW_NAME_REQUIRED` | 400 | `name` missing on create |
| `FLOW_NAME_INVALID` | 400 | `name` present but not a usable string |
| `FLOW_CATEGORY_INVALID` | 400 | A category outside the set Meta accepts |
| `FLOW_CLONE_SOURCE_INVALID` | 400 | `cloneFromFlowId` is not a usable local id |
| `FLOW_PATCH_EMPTY` | 400 | `PATCH` with neither `name` nor `categories` |
| `FLOW_UNKNOWN_FIELDS` | 400 | The body carried a field the route does not accept |
| `FLOW_PUBLISH_REQUIRES_CONFIRMATION` | 400 | `publish` without `"confirm": true` |
| `FLOW_DEPRECATE_INVALID_SUCCESSOR` | 400 | `supersededByFlowId` present but blank or unknown |
| `FLOW_ENDPOINT_KEY_REQUIRES_CONFIRMATION` | 400 | Generating over a LIVE key without `"confirm": true` |
| `FLOW_ENDPOINT_KEY_IMPORT_REQUIRES_CONFIRMATION` | 400 | Importing over a LIVE key without `"confirm": true` |
| `FLOW_ENDPOINT_KEY_IMPORT_MISMATCH` | 400 | The imported key is not the one Meta has registered. **Nothing was written** |
| `FLOW_ENDPOINT_KEY_PASSPHRASE_REQUIRED` | 400 | The PEM is passphrase-protected and none was sent |
| `FLOW_ENDPOINT_KEY_PASSPHRASE_WRONG` | 400 | The passphrase does not open the key — the key itself was not rejected |
| `FLOW_ENDPOINT_KEY_PASSPHRASE_ORPHAN` | 400 | `passphrase` with no `privateKey`. Refused, not ignored: without the key this request would **generate** a pair |
| `FLOW_ENDPOINT_KEY_PEM_INVALID` | 400 | `privateKey` is unreadable as PEM, is not RSA, or is under 2048 bits |
| `FLOW_ENDPOINT_KEY_IMPORT_INVALID` | 400 | `privateKey` or `passphrase` present but not a string |
| `FLOW_ENDPOINT_KEY_UNAVAILABLE` | 500 | Ours. The private half cannot be stored encrypted, and we refuse to generate rather than store it in the clear |
| `FLOW_ENDPOINT_URL_REQUIRED` | 400 | `url` absent or unusable. It may be `null` **explicitly**, never by omission |
| `FLOW_ENDPOINT_URL_NOT_HTTPS` | 400 | The destination is not `https://`. The refused URL is not echoed back |
| `FLOW_ENDPOINT_ROTATE_INVALID` | 400 | `rotateSecret` is not a boolean. `"true"` is not coerced |
| `FLOW_ENDPOINT_SECRET_UNAVAILABLE` | 500 | Ours. The signing secret cannot be stored encrypted, and forwarding unsigned is not an option |
| `FLOW_NUMBER_WABA_MISMATCH` | 422 | The key's number is not in the WABA that owns this Flow and can never send it |
| `FLOW_NUMBER_NOT_FOUND` | 404 | The number in the path is not the number this key is bound to |
| `FLOW_BODY_INVALID` | 400 | Malformed body, or a required field missing |
| `INVALID_PAGINATION` | 400 | `page` × `pageSize` past the deep-offset ceiling |
| `INTERNAL_ERROR` | 500 | Ours. Retry, then tell support the code |

<Note>
  The last two carry **no `FLOW_` prefix** — they are shared across the public API and keep their global spelling. A client matching on `code.startsWith("FLOW_")` would miss both.
</Note>
