# Logout WhatsApp instance

`POST /v1/numbers/{id}/logout` disconnects a WhatsApp instance (logout) without removing it from the database. This is different from `DELETE /v1/numbers/{id}`, which deletes the number (a 30-day soft delete).

```bash
curl -X POST "https://pilotstatus.com.br/v1/numbers/wa_abc/logout" \
  -H "x-api-key: ps_your_token_here"
```

Response:

```json
{
  "ok": true,
  "instances": [
    {
      "instanceId": "inst_123",
      "ok": true
    }
  ]
}
```

## When to use it

- When you want to disconnect a WhatsApp instance temporarily without deleting it.
- When you need to reconnect a number to a different device.
- When troubleshooting connection issues and need to reset the connection state.

## Differences from DELETE

| Operation | What it does |
| --- | --- |
| `POST /v1/numbers/{id}/logout` | Disconnects WhatsApp (unlinks device) but keeps the instance in the database. You can reconnect later. |
| `DELETE /v1/numbers/{id}` | Disconnects AND deletes the number — a 30-day soft delete, undone with `POST /v1/numbers/{id}/restore`. |
| `DELETE /v1/numbers/{id}/purge` | Deletes the number permanently, right away. Cannot be undone. |

## Request parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | string | Yes | The WhatsApp instance ID or WhatsApp number ID. |

## Response

### Success (200)

```json
{
  "ok": true,
  "instances": [
    {
      "instanceId": "inst_123",
      "ok": true
    }
  ]
}
```

| Field | Type | Description |
| --- | --- | --- |
| `ok` | boolean | Overall success status. |
| `instances` | array | Array of logout results for each instance. |
| `instances[].instanceId` | string | The instance ID. |
| `instances[].ok` | boolean | Whether logout succeeded for this instance. |
| `instances[].error` | string | Error message if logout failed (only present when `ok` is false). |

### Errors

| Status | Body | Meaning |
| --- | --- | --- |
| `401` | `{ "error": "…" }` | Invalid or missing API key. |
| `404` | `{ "error": "Number not found" }` | No such number for this API key. |
| `500` | `{ "error": "Internal server error" }` | Server error (check logs). |

## Notes

- The top-level `ok` is **always `true`** once the number is found — check each `instances[].ok`. When the provider refuses the logout of a connection (any error, including "instance not found" or a `401`), that entry comes back `ok: false` with the provider's message in `error`, and its stored state is **not** changed.
- After a successful logout, the instance state will be `LOGOUT` in the database.
- A Meta (Cloud API) number has no connection to log out: the call answers `{ "ok": true, "instances": [] }`.
- `{id}` may be the number id or the instance id. Over OAuth or with an account key (`ps_account_`) it needs `numbers:connect` (Admin or Owner) — `403 PERMISSION_DENIED` otherwise; an OAuth token granted other numbers gets `403 NUMBER_NOT_IN_GRANT`.
- You can reconnect the instance later using `GET /v1/numbers/{id}/connect`.
