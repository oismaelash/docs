WhatsApp channels use identifiers ending in `@newsletter`. Pilot Status offers **optional listing** of those channels (id and name when known) for the **same WhatsApp instance** tied to your API key as `POST /v1/messages/send`.

<Warning>
  Channels/newsletters are **not supported for Meta Cloud API numbers**: `GET /v1/newsletters` answers `400 NOT_SUPPORTED_FOR_META`.
</Warning>

## Public API

`GET https://pilotstatus.com.br/v1/newsletters`

- **200** with `{ "newsletters": [ { "id": "…@newsletter", "name": "…" } ] }`. `name` can be `null`.
- The session must be **connected** (`OPEN`); otherwise **409** with `WHATSAPP_INSTANCE_NOT_CONNECTED`.
- When the number has no WhatsApp session behind it, **200** with an empty `newsletters` array.
- The list is **cached for up to 1 hour**.

### Authentication

A **number key** (`ps_number_`) acts on its own number. A **workspace key** (`ps_workspace_`), an **account key** (`ps_account_`, with `x-workspace-id`) or an **OAuth token** must name the number in `x-whatsapp-number-id`; without it the answer is `403 TENANT_SCOPE_NOT_ALLOWED`. With an account key or an OAuth token, the user's role must include `chat:read` (**AGENT**, **ADMIN** or **OWNER**); otherwise `403 PERMISSION_DENIED`. See [Authentication](/api/authentication).

### Errors

| Status | `code` | When |
| --- | --- | --- |
| `400` | `NOT_SUPPORTED_FOR_META` | The number is a Meta Cloud API number. |
| `403` | `TENANT_SCOPE_NOT_ALLOWED` | Workspace/account credential without `x-whatsapp-number-id`. |
| `403` | `PERMISSION_DENIED` | Account key / OAuth user whose role lacks `chat:read`. |
| `409` | `WHATSAPP_INSTANCE_NOT_CONNECTED` | The session is not `OPEN`. |
| `409` | `LINKED_WHATSAPP_INSTANCE_NOT_FOUND` | The instance linked to the key no longer exists. |
| provider status | `WHATSAPP_UPSTREAM_ERROR` | The WhatsApp provider refused the call; `details: { status, body }` carries its answer. |
| `502` | `WHATSAPP_INVALID_JSON` | The provider answered with invalid JSON. |
| `503` | `WHATSAPP_SESSION_KEY_MISSING` | The number's session key is not configured. |

## Example

<CodeGroup>

```bash cURL
curl "https://pilotstatus.com.br/v1/newsletters" \
  -H "x-api-key: ps_number_your_key"
```

```json Response (200)
{
  "newsletters": [
    { "id": "120363123456789012@newsletter", "name": "Product Updates" }
  ]
}
```

</CodeGroup>

## Dashboard (session)

On **Numbers**, when the number is connected (**OPEN**), use **List WhatsApp newsletters** for the same data.

## Webhooks and sending

- Inbound channel traffic is delivered as **`message.newsletter`** (see webhooks documentation).
- `POST /v1/messages/send` and channel listing are independent flows; see the send-message docs for destination rules.

## n8n

The official node may load options from `GET /v1/newsletters` in the optional **Additional fields** control when a list is returned.
