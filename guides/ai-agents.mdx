Pilot Status is built to be driven by AI. There are three complementary ways to connect LLMs and agents to WhatsApp: the hosted **MCP server**, the plain **REST API** with the `x-api-key` header, and **webhook-driven bots** that react to inbound messages in real time.

## MCP server (hosted connector)

Pilot Status ships an official Model Context Protocol server that exposes the public `/v1` API as **148 MCP tools** — send messages, read conversations and unread messages, manage numbers, templates, webhooks, groups, voice calls, and more.

The hosted connector runs at:

```text
https://mcp.pilotstatus.com.br/mcp
```

Add it in claude.ai under **Settings → Connectors → Add custom connector**. claude.ai runs the OAuth 2.1 login (Pilot Status SSO) — no API key is shared with the client. During login you see a **consent screen** where you approve access to the **entire account** (workspace Owner or Admin only) or grant only **specific numbers** (a per-number grant restricts every tool to those numbers). The connection acts on the workspace selected in your Pilot Status session when you authorize. Claude Code and ChatGPT connect with OAuth the same way; Cursor and VS Code use an API key. Step by step for each client: [Connect your client](/integrations/mcp-server#connect-your-client).

Clients configured by file can skip OAuth and send a `ps_*` key in the `x-api-key` header instead:

```json
{
  "mcpServers": {
    "pilot-status": {
      "type": "http",
      "url": "https://mcp.pilotstatus.com.br/mcp",
      "headers": { "x-api-key": "ps_your_key_here" }
    }
  }
}
```

With an OAuth connection or a workspace key, pass `whatsappNumberId` (from `numbers_list`) to every tool that acts on a number — messages, conversations, templates, webhooks; a number key (`ps_number_…`) already names its number.

Two endpoints, same credentials — connect one of them per agent, not both:

- **`/mcp`** — the 148 tools; your client shows each call for you to approve. Best for one or two calls at a time.
- **`/code`** — [Code Mode](/integrations/mcp-code-mode): two tools, `describe` and `execute`, and the agent writes a TypeScript script that calls `await ps.<tool>(args)`. Best for loops, reports and tight context.

Destructive tools (`templates_delete`, `workspace_archive`, `workspace_transfer_ownership`, `workspace_members_remove`) first return a preview and a `confirm_token`; the agent must show the preview and wait for your yes before the second call. [Confirmation for destructive tools](/integrations/mcp-server#confirmation-for-destructive-tools)

See the [MCP Server integration page](/integrations/mcp-server) for authentication and self-hosting, and the [MCP tool reference](/integrations/mcp-tools) for every tool with its required arguments.

## Teach any LLM about Pilot Status

Point your model or coding agent at the canonical machine-readable reference:

```text
https://pilotstatus.com.br/llms.txt
```

It links endpoints, webhook schemas, concepts, and error codes — everything an AI needs to write a correct integration.

## Webhook-driven bots

The classic pattern: subscribe a webhook to `message.received`, run the payload through your LLM, and reply via the API.

```javascript
app.post("/hooks/whatsapp", async (req, res) => {
  res.sendStatus(200); // acknowledge first
  const { event, data } = req.body;
  if (event !== "message.received") return;

  const reply = await llm.complete(data.content); // your model call

  await fetch("https://pilotstatus.com.br/v1/messages/send", {
    method: "POST",
    headers: {
      "x-api-key": process.env.PILOT_STATUS_API_KEY,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ text: reply, destinationNumber: data.from }),
  });
});
```

<Tip>
  Pilot Status fires webhooks within milliseconds of each event, so agents can respond nearly instantly. Deduplicate by `data.id` and keep your handler fast — do the LLM call asynchronously.
</Tip>

Setup details are in the [Receive Messages guide](/guides/receive-messages).

## Direct REST API

Any framework that can make HTTP requests (LangChain, n8n, Make, custom backends) can use the API directly. Authentication is always the `x-api-key: ps_...` header; the base URL is `https://pilotstatus.com.br/v1`, and the only send endpoint is `POST /v1/messages/send` (template, text, or media mode). The official [SDKs](/integrations/sdks) wrap this for Node.js, Python, and n8n.
