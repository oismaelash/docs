A **WhatsApp Flow** is a form that opens inside the chat: a booking screen, a lead form, a survey. The customer taps a button, fills in one or more screens, and submits. This guide walks through the whole path, from creating a Flow to reading the answers.

<Warning>
  Flows are available **only on official API (Meta Cloud API) numbers**. They are not available on numbers connected by QR code. A Flow belongs to the WhatsApp Business Account (WABA), so every Meta number of that WABA can send it.
</Warning>

## Lifecycle

| Status | What you can do |
| --- | --- |
| `DRAFT` | Edit the Flow JSON, preview it, send it as a test with `mode: "draft"`, delete it. |
| `PUBLISHED` | Send it to any customer. The JSON can no longer change. |
| `DEPRECATED` | Retired: it can no longer be sent. |

- **Publishing is irreversible.** To change a published Flow, **clone** it into a new draft, edit the clone and publish it.
- **Only a `DRAFT` can be deleted.** A published Flow can only be deprecated.

## Create a Flow

<Tabs>
  <Tab title="Dashboard">
    Open the **Flows** screen. Create a draft, write its JSON in the editor (or **generate it with AI** from a description), preview it and publish. See [The Flows screen](/dashboard/flows).
  </Tab>
  <Tab title="API">
    1. `POST /v1/flows` creates the draft ([create](/playground/flows/create-flow)).
    2. `POST /v1/flows/{id}/json` uploads the Flow JSON ([upload JSON](/playground/flows/upload-flow-json)).
    3. `POST /v1/flows/{id}/preview` returns a preview link ([preview](/playground/flows/preview-flow)).
    4. `POST /v1/flows/{id}/publish` publishes it ([publish](/playground/flows/publish-flow)).
    5. `POST /v1/flows/{id}/deprecate` retires it later ([deprecate](/playground/flows/deprecate-flow)).

    Full reference: [Flows API](/api/flows).
  </Tab>
</Tabs>

### Categories

Every Flow has one or more categories: `SIGN_UP`, `SIGN_IN`, `APPOINTMENT_BOOKING`, `LEAD_GENERATION`, `CONTACT_US`, `CUSTOMER_SUPPORT`, `SURVEY`, `OTHER`.

## Send a Flow

**In a message.** Add a `flow` block to [`POST /v1/messages/send`](/playground/messages/send-message):

```json
{
  "destinationNumber": "+5511999999999",
  "text": "Book your visit",
  "flow": {
    "flowId": "2038526810137974",
    "cta": "Book now",
    "action": "navigate",
    "screen": "WELCOME",
    "data": { "name": "Ana" }
  }
}
```

| Field | Rule |
| --- | --- |
| `flowId` | The Flow id at Meta. Required. |
| `cta` | Button text, up to **30 characters**. Required. |
| `action` | `navigate` or `data_exchange`. |
| `screen`, `data` | Only with `navigate`. With `data_exchange` the request is refused with `FLOW_PAYLOAD_NOT_ALLOWED`. |
| `mode` | `draft` to send an unpublished Flow for testing. |

This requires an open 24-hour window. Details: [Dynamic Flows](/guides/send-flow-dynamic).

**In a template.** Add a **FLOW button** to a template. The Flow is fixed when the template is created and can be sent outside the 24-hour window. See [Templates](/concepts/templates).

## Receive the answers

A submitted Flow triggers the **`flow.response_received`** webhook event, with the answers as structured data. Subscribe to it explicitly. You can also list stored answers with `GET /v1/flows/{id}/responses` ([list responses](/playground/flows/list-flow-responses)). Details: [Flow responses](/guides/flow-responses).

## Connect your API (data_exchange)

A `data_exchange` Flow asks your backend for each screen while the customer fills it in.

- **Each number has its own encryption key.** Generate or import it on the Flows screen or via the API ([generate key](/playground/numbers/generate-flow-endpoint-key)).
- **Pilot Status is the endpoint Meta calls.** It decrypts the request and forwards plain JSON to your URL, signed with the `x-pilot-status-signature` header. Verify the signature before trusting the body.
- **The endpoint URL is a credential.** Treat it like a secret and do not share it.
- **Rotating the key affects every `data_exchange` Flow on that number** at once. Plan the rotation.

Details: [Connect your API to a Flow](/guides/flow-data-exchange) and [Flows with live data](/guides/flow-live-data).

## Debug with traces

`GET /v1/flows/{id}/traces` lists recent endpoint calls ([list traces](/playground/flows/list-flow-traces)). Traces are kept for **24 hours**, and the request body is stored **only when the call failed**.
