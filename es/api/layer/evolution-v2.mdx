La API Layer Evolution V2 de Pilot Status es un puente de compatibilidad transparente para aplicaciones creadas sobre Evolution API V2. Cambiar tu URL base al endpoint de la capa de Pilot Status es todo lo que necesitas para mover tu infraestructura: los cuerpos de tus solicitudes, el procesamiento de respuestas, los handlers de webhook y los headers de autenticación quedan exactamente como están.

## URL base

Actualiza la variable de entorno de tu URL base o la configuración de tu cliente HTTP a lo siguiente:

```text
https://pilotstatus.com.br/api/layer/evolution-v2/
```

Cada ruta que hoy llamas en tu servidor Evolution V2 se agrega a esta URL base sin ninguna modificación.

## Autenticación

Sigue enviando el **token de instancia** en el header `apikey`, exactamente como espera Evolution V2:

```text
apikey: YOUR_INSTANCE_TOKEN
```

La capa **no** acepta una API key `ps_` de Pilot Status. La instancia viene del segmento de ruta `{instance}`, y `apikey` tiene que ser uno de los tokens de **esa** instancia:

- el token de la instancia Evolution V2 que **migraste** en el panel (**Numbers → Connect → Migrate**, donde ingresas el nombre y el token de la instancia anterior), así que ni el nombre de la instancia ni el token en tu código cambian; o
- el token propio de la instancia de Pilot Status.

Una instancia desconocida, o un token que no le pertenece, responde `404` `{ "status": 404, "error": "Not Found", "message": "Instance not found" }`. Una solicitud sin `apikey` responde `401`. `Authorization: Bearer` y `x-api-key` no se leen.

## Operaciones compatibles

Cada operación de abajo se acepta en formato Evolution V2 y se ejecuta sobre tu número de Pilot Status. En cada ruta, `{instance}` es el **último segmento de la ruta** y es el nombre de la instancia: el nombre de la instancia que migraste, o el nombre de la instancia de Pilot Status (consulta [Mapeo del nombre de instancia](#mapeo-del-nombre-de-instancia)). Las operaciones de envío y de mensajes se balancean entre las instancias conectadas del número (`sendReaction` es la excepción: no se balancea). Cualquier ruta que no esté en este catálogo devuelve **404**; las rutas globales (de todo el servidor) devuelven **403**: consulta [Bloqueadas (globales)](#bloqueadas-globales) más abajo.

### Instancia

| Método | Ruta |
| --- | --- |
| `POST` | `/instance/restart/{instance}` |
| `GET` | `/instance/connect/{instance}` |
| `GET` | `/instance/connectionState/{instance}` |
| `POST` | `/instance/setPresence/{instance}` |
| `DELETE` | `/instance/logout/{instance}` |
| `DELETE` | `/instance/delete/{instance}` |

### Mensajes

Envía mensajes de todos los tipos a través de un número conectado. Cada ruta termina en `/{instance}`, el nombre de la instancia (un parámetro de ruta: nunca lo pongas en el cuerpo).

### Bloqueadas (globales)

Las rutas de todo el servidor (globales) no forman parte de la capa de migración y siempre devuelven **403**. Esto incluye: `GET /` (raíz), `POST /verify-creds`, `GET /manager`, `GET /metrics`, `GET /assets/*`, `POST /instance/create` y `GET /instance/fetchInstances`. En su lugar, aprovisiona y gestiona tus números mediante el panel de Pilot Status o la API nativa. Cualquier ruta que no figure en este catálogo devuelve **404**.

## Las URLs de la solicitud deben ser públicas

Algunas operaciones hacen que el proveedor descargue o llame a una URL que envías. Desde 2026-09-28, Pilot Status verifica cada una de esas URLs antes de reenviar la solicitud. Si alguna apunta a una dirección de red interna o privada (`localhost`, una IP de loopback o privada, un nombre de host sin punto, o un nombre que resuelve a alguna de esas), la solicitud se rechaza con **400** y no se reenvía nada:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "Refused: a URL in the request points to an internal or private network address, which we never fetch. Use a public address."
}
```

Las URLs verificadas:

- **Multimedia enviada por URL:** `sendMedia` (`media`), `sendPtv` (`video`), `sendWhatsAppAudio` (`audio`), `sendSticker` (`sticker`), un `sendStatus` de imagen o video (`content`), `sendButtons` (`thumbnailUrl`) y `sendCarousel` (el `thumbnailUrl` de cada tarjeta).
- **Vistas previas de enlaces:** el enlace en el `text` de `sendText`, que se previsualiza a menos que envíes `linkPreview: false`.
- **Fotos:** `updateProfilePicture` (`picture`) y `updateGroupPicture` (`image`).
- **Webhook e integraciones:** `webhook/set` (`webhook.url`), `chatwoot/set` (`url`, `logo`), y el `create` / `update` de `typebot` (`url`, también en `typebot/start`), `dify`, `flowise` y `evolutionBot` (`apiUrl`), `n8n` (`webhookUrl`), `evoai` (`agentUrl`) y `openai` (`functionUrl`).

Solo se verifican los valores `http(s)`: la multimedia en base64 y `data:` pasa sin cambios, y una carga multipart se reenvía tal cual. Un nombre de host que no resuelve no se rechaza aquí.

## Ejemplo: enviar texto mediante la capa Evolution V2

La solicitud de abajo es una llamada estándar de envío de texto de Evolution V2 enrutada a través de la capa de Pilot Status. Observa que el cuerpo de la solicitud usa el formato Evolution V2 sin cambios.

```bash
curl -X POST 'https://pilotstatus.com.br/api/layer/evolution-v2/message/sendText/MyInstance' \
  -H 'apikey: YOUR_INSTANCE_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "number": "5511999999999",
    "text": "Hello from Pilot Status via API Layer! 👋"
  }'
```

Reemplaza `MyInstance` por el nombre de tu instancia: consulta abajo.

## Mapeo del nombre de instancia

En Evolution V2, cada instancia representa una conexión de WhatsApp identificada por un nombre. La capa lee ese nombre del **último segmento de la ruta** y lo resuelve, en este orden:

1. el **nombre anterior de la instancia** que ingresaste al migrar la instancia en el panel (**Numbers → Connect → Migrate**), así que las rutas que tu código ya llama siguen funcionando sin cambios;
2. de lo contrario, el **nombre de instancia** de Pilot Status de la conexión.

**No** es el nombre visible que le diste al número. Por ejemplo, si migraste una instancia llamada `SupportLine`, tus solicitudes siguen usando:

```text
POST /message/sendText/SupportLine
```

con el token de esa instancia en `apikey`. Si tienes varios números, cada uno es su propia instancia, con su propio nombre y token, de forma coherente con cómo Evolution V2 gestiona varias instancias.
