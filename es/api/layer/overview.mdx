La API Layer de Pilot Status te permite migrar tu integración de WhatsApp existente a Pilot Status sin tocar el código de tu aplicación. En lugar de reescribir tus llamadas a la API, apuntas tu URL base al endpoint de la capa de Pilot Status correspondiente a tu proveedor, y a partir de ahí Pilot Status se encarga de la traducción de forma transparente.

## Cómo funciona la API Layer

Cuando tu aplicación envía una solicitud a `https://pilotstatus.com.br/api/layer/{provider}/`, Pilot Status la recibe, traduce la solicitud al formato nativo de la API de Pilot Status, ejecuta la operación y devuelve una respuesta en el formato que tu código ya espera. Los cuerpos de tus solicitudes, los headers, los tokens de autenticación y los payloads de webhook no cambian.

Esta traducción ocurre en el servidor y en tiempo real. Desde el punto de vista de tu aplicación, sigue hablando con una Evolution API compatible: solo cambió la infraestructura que la respalda.

## Pasos de migración

Sigue estos cuatro pasos para cambiar tu integración a Pilot Status:

1. **Encuentra tu URL base actual** en el código de tu aplicación o en la configuración de variables de entorno: es la URL raíz que tu cliente HTTP usa para todas las solicitudes a Evolution API.
2. **Reemplázala** por `https://pilotstatus.com.br/api/layer/evolution-v2/` o `https://pilotstatus.com.br/api/layer/evolution-go/`, según el formato de proveedor que use tu código.
3. **Migra tu instancia** en el panel de Pilot Status (**Numbers → Connect → Migrate**), indicando el nombre y el token actuales de tu instancia, y luego escanea el código QR. Ese registro es lo que permite a la capa reconocer el token que tu código ya envía en `apikey`.
4. **Prueba con un envío de mensaje**: usa el mismo cuerpo de solicitud y los mismos headers que ya tienes y confirma que recibes el mismo formato de respuesta.

El siguiente ejemplo muestra que un solo cambio de variable de entorno es todo lo que separa tu configuración actual de Pilot Status:

```bash
# Antes (servidor Evolution)
POST https://your-evolution-server.com/message/sendText/MyInstance
```

```bash
# Después (Pilot Status Layer)
POST https://pilotstatus.com.br/api/layer/evolution-v2/message/sendText/MyInstance
```

Todo lo que viene después de la URL base (la ruta, el cuerpo de la solicitud y los headers) se mantiene exactamente igual.

## Qué se conserva

Cuando usas la API Layer, Pilot Status conserva lo siguiente para que tu integración siga funcionando sin modificaciones:

- **Formato del cuerpo de la solicitud**: los mismos campos JSON que tu código envía hoy
- **Formato de la respuesta**: la misma estructura JSON que tu código procesa hoy
- **Estructura del payload de webhook**: los eventos llegan en el formato que tus handlers ya esperan
- **Eventos de webhook**: los eventos se reenvían a tu webhook en el formato de evento nativo de tu proveedor; la página de cada capa de proveedor lista los eventos exactos que emite
- **Headers de autenticación**: en las capas Evolution GO y Evolution V2 sigues enviando el **token de instancia** que tu código ya envía en `apikey` (registrado al migrar la instancia; ahí **no** se acepta una API key `ps_`). En la capa Meta envías una clave `ps_` de Pilot Status en `x-api-key`, `Authorization: Bearer` o `?access_token=`
- **Integraciones existentes**: herramientas como n8n, Make y otras plataformas low-code que se conectan a Evolution API siguen funcionando con solo actualizar la URL base en la configuración de su nodo HTTP

<Note>
  La API Layer es un puente de compatibilidad. Para integraciones nuevas, usa la API nativa de Pilot Status para tener acceso a todas las funciones.
</Note>
