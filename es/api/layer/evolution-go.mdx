La API Layer Evolution GO de Pilot Status te da un reemplazo directo para tu servidor Evolution GO. Mantienes cada cuerpo de solicitud, header y ruta exactamente como están hoy: el único cambio que haces es reemplazar tu URL base. Pilot Status traduce tus solicitudes compatibles con Evolution GO a su API nativa y devuelve las respuestas en el formato que tu código ya maneja.

## URL base

Apunta tu cliente HTTP o tu variable de entorno a la siguiente URL base para empezar a usar la capa Evolution GO:

```text
https://pilotstatus.com.br/api/layer/evolution-go/
```

Todas las rutas que usas actualmente con tu servidor Evolution GO se agregan directamente a esta URL. No se requieren otros cambios.

## Autenticación

Envía el **token de la instancia** en el header `apikey`, el mismo header que usa Evolution GO:

```text
apikey: YOUR_INSTANCE_TOKEN
```

La capa **no** acepta una API key `ps_` de Pilot Status. Busca el valor de `apikey` como token de instancia, en este orden:

1. el token de la instancia Evolution GO que **migraste** en el panel (**Numbers → Connect → Migrate**, donde ingresas el nombre y el token de la instancia anterior), para que el token que tu código ya envía siga funcionando;
2. si no, el token de la propia instancia de Pilot Status.

Un token que no coincide con ninguno responde `404` `{ "status": 404, "error": "Not Found", "message": "Instance not found" }`. Una solicitud sin `apikey` responde `401`.

Este es el único header que lee la capa. `Authorization: Bearer` y `x-api-key` **no** se aceptan: una solicitud que lleva la clave solo en uno de ellos recibe `401 Unauthorized`.

## Operaciones admitidas

Cada solicitud es una llamada a `<METHOD> https://pilotstatus.com.br/api/layer/evolution-go<PATH>`. La instancia se resuelve a partir del token `apikey`, así que las rutas de Evolution GO que normalmente llevan un segmento de instancia **no** lo necesitan aquí. Las operaciones de envío se balancean automáticamente entre las instancias conectadas de tu número.

<Note>
  Cualquier ruta que no aparezca abajo devuelve **404**. Las rutas globales o exclusivas de administración devuelven **403**: nunca se exponen a través de la capa (consulta [Rutas bloqueadas](#bloqueadas-adminglobal)).
</Note>

<Accordion title="POST /send/text: enviar mensaje de texto">
Envía un mensaje de texto simple; cuando `linkPreview` es true, el servidor enriquece la primera URL de `text` con una tarjeta de vista previa OpenGraph.

| Campo | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `number` | string | Sí | MSISDN o JID del destinatario (por ejemplo, `5511999999999` o `5511999999999@s.whatsapp.net`, grupo `...@g.us`). |
| `text` | string | Sí | Cuerpo del mensaje. |
| `linkPreview` | boolean | No | Obtiene los metadatos OpenGraph de la primera URL de `text` y adjunta una vista previa. |
| `id` | string | No | Id de mensaje proporcionado por el cliente para rastreo/idempotencia. |
| `delay` | integer | No | Milisegundos de espera (como "escribiendo") antes de enviar. |
| `mentionedJid` | string | No | JID(s) a mencionar. |
| `mentionAll` | boolean | No | Menciona a todos los participantes (grupos). |
| `formatJid` | boolean | No | Formatea automáticamente `number` como JID (predeterminado `true`); usa `false` para enviar el valor tal cual. |
| `quoted` | object | No | Referencia de respuesta: `{ "messageId", "participant" }`. |

```json
{
  "number": "5511999999999",
  "text": "Hello from Pilot Status! https://pilotstatus.com.br",
  "linkPreview": true,
  "delay": 1200,
  "quoted": {
    "messageId": "3EB0C767D097B7C7A0A1",
    "participant": "5511988888888@s.whatsapp.net"
  }
}
```

## Las URLs de la solicitud deben ser públicas

Algunas operaciones hacen que el proveedor descargue o llame a una URL que envías. Desde el 2026-09-28, Pilot Status verifica cada una de esas URLs antes de reenviar la solicitud. Si alguna apunta a una dirección de red interna o privada (`localhost`, una IP de loopback o privada, un nombre de host sin punto, o un nombre que resuelve a una de esas), la solicitud se rechaza con **400** y no se reenvía nada:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "Refused: a URL in the request points to an internal or private network address, which we never fetch. Use a public address."
}
```

Las URLs que se verifican:

- **Multimedia enviada por URL:** `/send/media` (`url`), `/send/sticker` (`sticker`), `/send/button` (`imageUrl`) y `/send/carousel` (el `thumbnailUrl` de cada tarjeta).
- **Enlaces:** `/send/link` (`imgUrl`, y el enlace en `text`), y el enlace en el `text` de `/send/text` cuando envías `linkPreview: true`.
- **Imágenes:** `/user/profilePicture` y `/group/photo` (`image`).
- **Webhook:** `/instance/connect` (`webhookUrl`).

Solo se verifican los valores `http(s)`: la multimedia en base64 y `data:` pasa sin cambios, y una subida multipart se reenvía tal cual. Un nombre de host que no resuelve no se rechaza aquí.

## Ejemplo: enviar texto a través de la capa Evolution GO

La solicitud de abajo es una llamada real a la capa Evolution GO: un `POST /send/text` estándar, en el que solo cambia la URL base para enrutar a través de Pilot Status. No hay segmento de instancia en la ruta: el header `apikey` selecciona la instancia.

```bash
curl -X POST 'https://pilotstatus.com.br/api/layer/evolution-go/send/text' \
  -H 'apikey: YOUR_INSTANCE_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{ "number": "5511999999999", "text": "Hello from Pilot Status! 👋" }'
```

Los campos del cuerpo son los mismos que tu código de Evolution GO ya envía a `POST /send/text`: `number` y `text`, más campos opcionales como `delay`, `quoted` y `mentionedJid`. El formato de la respuesta es idéntico al que consume tu código actual.
