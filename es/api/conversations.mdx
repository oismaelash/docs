Lista las conversaciones del número conectado, ordenadas por la actividad de mensajes más reciente (`lastMessageAt` descendente; las conversaciones sin ese valor van al final).

## Endpoint

`GET https://pilotstatus.com.br/v1/conversations`

<Note>
  Actúa sobre **un número**: usa una API key **con alcance de número** (`ps_*`) en el header `x-api-key` (o `x-api-key-id`), o una clave de toda la cuenta que indique el número en el header [`x-whatsapp-number-id`](/es/api/authentication). Una clave de toda la cuenta sin ese header recibe `403 TENANT_SCOPE_NOT_ALLOWED`.

  **Los tokens OAuth / MCP y las claves de cuenta** (`ps_account_`) también necesitan el permiso `chat:read` (roles `AGENT`, `ADMIN`, `OWNER`); el rol `ANALYST` se rechaza con `403 PERMISSION_DENIED`. Una clave `ps_` clásica no se ve afectada por los roles.
</Note>

## Parámetros de consulta

<ParamField query="startDate" type="string">
  Fecha y hora ISO 8601. Filtra las conversaciones cuyo último mensaje es **igual o posterior** a esta fecha.
</ParamField>

<ParamField query="endDate" type="string">
  Fecha y hora ISO 8601. Filtra las conversaciones cuyo último mensaje es **igual o anterior** a esta fecha.
</ParamField>

<ParamField query="page" default="1" type="integer">
  Número de página (≥ 1).
</ParamField>

<ParamField query="pageSize" default="30" type="integer">
  Resultados por página (1–100).
</ParamField>

`startDate` y `endDate` son opcionales por separado. Cuando se envían, cada uno debe ser un string ISO 8601 válido y `startDate` no puede ser posterior a `endDate`; de lo contrario se devuelve `400 INVALID_DATE_RANGE`.

## Efecto del modo PII

La respuesta depende del **modo PII** configurado para el número, que se cambia en el panel en la página API Keys (panel Privacy & retention) o en la configuración del número en Numbers:

| Modo PII | Efecto |
| --- | --- |
| `STORE_INDEFINITE` (predeterminado) | Se devuelven todas las conversaciones (sujetas a los filtros de fecha). |
| `STORE_X_DAYS` | Las conversaciones se devuelven completas: la retención se aplica **por mensaje** en los endpoints de mensajes, no a la fila de la conversación, así que su contacto y `lastMessagePreview` se mantienen. |
| `RELAY_ONLY` | Las conversaciones **sí** se devuelven (no es una lista vacía), pero cada fila está **ocultada** (`redacted: true`, identidad del contacto y vista previa del último mensaje en `null`). La respuesta incluye un campo `notice: "PII_RELAY_ONLY"`. |

## Campos del objeto conversación

<ResponseField name="id" type="string" required>
  ID de la conversación en Pilot Status.
</ResponseField>

<ResponseField name="whatsappNumberId" type="string" required>
  El número al que pertenece la conversación.
</ResponseField>

<ResponseField name="type" type="string" required>
  `"DIRECT"`, `"GROUP"` o `"NEWSLETTER"`.
</ResponseField>

<ResponseField name="from" type="string | null">
  Teléfono del contacto en E.164 (con `+`) para personas; `null` para grupos/newsletters, para contactos sin teléfono (solo lid o solo username) y cuando está ocultado.
</ResponseField>

<ResponseField name="fromName" type="string | null">
  Nombre visible del contacto o del grupo, cuando está disponible.
</ResponseField>

<ResponseField name="peerLid" type="string | null">
  LID de WhatsApp del contacto, cuando se conoce.
</ResponseField>

<ResponseField name="userId" type="string | null">
  Business-Scoped User ID (BSUID) de Meta: la clave duradera de un contacto de Meta. Está presente incluso cuando `from` es `null` (un contacto que usa un username), y se acepta como `destinationNumber` en [`POST /v1/messages/send`](/es/api/messages/send).
</ResponseField>

<ResponseField name="username" type="string | null">
  El username de WhatsApp del contacto, cuando se conoce.
</ResponseField>

<ResponseField name="profilePicUrl" type="string | null">
  URL de la foto de perfil, cuando se conoce.
</ResponseField>

<ResponseField name="lastMessagePreview" type="string | null">
  Vista previa breve del último mensaje.
</ResponseField>

<ResponseField name="lastDirection" type="string | null">
  `INBOUND` u `OUTBOUND`: dirección del último mensaje.
</ResponseField>

<ResponseField name="unreadCount" type="integer" required>
  Mensajes entrantes no leídos de la conversación: el contador detrás de [`GET /v1/messages/unread`](/es/api/messages/unread).
</ResponseField>

<ResponseField name="lastMessageAt" type="string | null">
  ISO 8601: última actividad de mensajes. Las conversaciones sin este valor se ordenan al final.
</ResponseField>

<ResponseField name="lastInboundAt" type="string | null">
  ISO 8601: último mensaje recibido del contacto (desde donde cuenta la ventana de servicio de 24 horas).
</ResponseField>

<ResponseField name="createdAt" type="string" required>
  ISO 8601: cuándo se creó la conversación por primera vez.
</ResponseField>

<ResponseField name="updatedAt" type="string" required>
  ISO 8601: última actualización del registro de la conversación.
</ResponseField>

<ResponseField name="redacted" type="boolean">
  Presente (`true`) solo en una conversación ocultada: `from`, `fromName`, `peerLid`, `userId`, `username`, `profilePicUrl` y `lastMessagePreview` son `null`.
</ResponseField>

## Errores comunes

- `400 INVALID_DATE_RANGE`: `startDate` o `endDate` no es un string ISO 8601 válido, o `startDate > endDate`.
- `400 INVALID_PAGINATION`: `page × pageSize` mayor que `10000`.
- `400 NUMBER_NOT_FOUND`: la credencial no indica ningún número de WhatsApp.
- `401`: credencial ausente o inválida (`{"error": "Invalid API key"}`).
- `403 TENANT_SCOPE_NOT_ALLOWED`: una clave de toda la cuenta sin `x-whatsapp-number-id`.
- `403 PERMISSION_DENIED`: token OAuth/MCP o clave de cuenta cuyo rol no tiene `chat:read` (`ANALYST`).
