Este endpoint devuelve los mismos agregados que muestra la pantalla de Analytics del dashboard (KPIs, serie diaria, desglose por estado, templates principales y orígenes principales) para **un número de WhatsApp**.

## Endpoint

`GET https://pilotstatus.com.br/v1/analytics/dashboard`

<Note>
  Actúa sobre **un número**: usa una **key de número** (`ps_number_`), o una **key de workspace** (`ps_workspace_`), una **key de cuenta** (`ps_account_`, con `x-workspace-id`) o un token OAuth que indique el número en el header [`x-whatsapp-number-id`](/es/api/authentication). Una credencial de todo el workspace sin ese header recibe `403 TENANT_SCOPE_NOT_ALLOWED`.

  Todos los roles del workspace (OWNER, ADMIN, AGENT, ANALYST) tienen el permiso `analytics:read`, así que los tokens OAuth y las keys de cuenta no se rechazan por rol, pero el usuario detrás de ellos debe seguir siendo miembro activo del workspace.
</Note>

## Parámetros de consulta

<ParamField query="period" default="30d" type="string">
  Ventana del reporte: `7d`, `30d` o `90d`. Cualquier otro valor se **trata silenciosamente como `30d`** (sin error). La ventana empieza a la hora actual del día, hace N−1 días.
</ParamField>

<ParamField query="timezone" default="UTC" type="string">
  Zona horaria IANA usada para agrupar la serie diaria, por ejemplo `America/Sao_Paulo`. Se acepta `tz` como alias; si se envían ambos, gana `timezone`. El valor se devuelve en la respuesta.
</ParamField>

<CodeGroup>

```bash cURL
curl "https://pilotstatus.com.br/v1/analytics/dashboard?period=7d&timezone=America/Sao_Paulo" \
  -H "x-api-key: ps_number_your_key_here"
```

## Campos de la respuesta

Todos los totales cuentan los mensajes **salientes** del número creados en la ventana (enviados por la API, el chat del dashboard, templates, etc.); `totalReceived` es la única cifra de entrada. Las tasas y porcentajes son números de 0 a 100, redondeados a 2 decimales, y valen `0` cuando el denominador es 0.

| Campo | Significado |
| --- | --- |
| `period` | La ventana usada realmente (`7d`, `30d` o `90d`). |
| `timezone` | La zona horaria solicitada (predeterminada `UTC`). |
| `totalSent` | Todos los mensajes despachados en la ventana: `totalDelivered + totalFailed + totalQueued`. |
| `totalDelivered` | Mensajes con estado `SENT`, `DELIVERED` o `READ`. |
| `totalRead` | Mensajes con estado `READ`. |
| `totalFailed` | Mensajes con estado `FAILED`. |
| `totalQueued` | Mensajes que siguen en `QUEUED`. |
| `deliveryRate` | `totalDelivered / totalSent`. |
| `readRate` | `totalRead / totalDelivered`. |
| `failureRate` | `totalFailed / totalSent`. |
| `responseRate` | El mismo valor que `readRate`. |
| `avgDeliveryTime` | Promedio de segundos desde la creación hasta `deliveredAt` (el dispositivo del destinatario confirmó el mensaje), solo sobre los mensajes **entregados** del período; `0` si no se entregó ninguno. Hasta el 2026-11-09 medía desde la creación hasta `sentAt` (el proveedor aceptó el mensaje), así que reportaba el tiempo de despacho, no el de entrega. |
| `avgReadTime` | Promedio de segundos desde `sentAt` hasta `readAt`, sobre los mensajes que fueron leídos. |
| `messagesOverTime` | Una entrada por día calendario de la ventana en `timezone` (7, 30 o 90 entradas, del más antiguo al más reciente, los días sin tráfico en cero): `date` (`YYYY-MM-DD`), `total`, `queued`, `sent` (todo lo despachado ese día), `delivered` (`SENT`/`DELIVERED`/`READ`), `read`, `failed`. |
| `statusDistribution` | Conteos: `queued`, `delivered` (incluye los leídos), `read`, `failed`. |
| `statusPercentages` | Los mismos cuatro como porcentaje de `totalSent`. `delivered` incluye `read`, así que no suman 100. |
| `totalReceived` | Mensajes entrantes recibidos por el número en la ventana. |
| `topTemplates` | Hasta 5 templates por envíos entregados: `templateVersionId` (el id del template, o su nombre en envíos antiguos), `templateId` (o `null`), `templateName`, `version` (siempre `null`), `count`. |
| `topOrigins` | Envíos entregados agrupados por origen, de mayor a menor: `API`, `CHAT`, `DASHBOARD`, `CHATWOOT`, `SYSTEM` o `APP` (enviado desde el teléfono, sin solicitud a Pilot Status). |

Los resultados se guardan en caché hasta 60 segundos por número, período y zona horaria, así que un mensaje enviado hace un momento puede tardar hasta un minuto en aparecer.

## Errores

| Status | Code | Causa |
| --- | --- | --- |
| `400` | `WORKSPACE_ID_REQUIRED` | Key de cuenta (`ps_account_`) sin el header `x-workspace-id`. |
| `401` | — | Credencial ausente o inválida. |
| `403` | `TENANT_SCOPE_NOT_ALLOWED` | Se usó una credencial de todo el workspace sin `x-whatsapp-number-id`. |
| `403` | `NUMBER_NOT_IN_GRANT` | Token OAuth o key de cuenta restringidos a otros números. |
| `403` | `WORKSPACE_MEMBERSHIP_REQUIRED` | El usuario detrás del token o la key de cuenta no es miembro activo del workspace. |
| `404` | `NUMBER_NOT_FOUND` | `x-whatsapp-number-id` no corresponde a un número de este workspace. |
| `409` | — | La credencial no está vinculada a un número de WhatsApp (`{"error": "API key is not linked to a WhatsApp number"}`). |
