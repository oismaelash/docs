# Cerrar sesión de una instancia de WhatsApp

`POST /v1/numbers/{id}/logout` desconecta una instancia de WhatsApp (logout) sin eliminarla de la base de datos. Esto es distinto de `DELETE /v1/numbers/{id}`, que elimina el número (un borrado lógico de 30 días).

```bash
curl -X POST "https://pilotstatus.com.br/v1/numbers/wa_abc/logout" \
  -H "x-api-key: ps_your_token_here"
```

Respuesta:

```json
{
  "ok": true,
  "instances": [
    {
      "instanceId": "inst_123",
      "ok": true
    }
  ]
}
```

## Cuándo usarlo

- Cuando quieres desconectar una instancia de WhatsApp temporalmente sin eliminarla.
- Cuando necesitas reconectar un número a otro dispositivo.
- Cuando estás resolviendo problemas de conexión y necesitas reiniciar el estado de la conexión.

## Diferencias con DELETE

| Operación | Qué hace |
| --- | --- |
| `POST /v1/numbers/{id}/logout` | Desconecta WhatsApp (desvincula el dispositivo) pero mantiene la instancia en la base de datos. Puedes reconectarla después. |
| `DELETE /v1/numbers/{id}` | Desconecta Y elimina el número: un borrado lógico de 30 días, que se deshace con `POST /v1/numbers/{id}/restore`. |
| `DELETE /v1/numbers/{id}/purge` | Elimina el número de forma permanente, de inmediato. No se puede deshacer. |

## Parámetros de la solicitud

| Parámetro | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `id` | string | Sí | El ID de la instancia de WhatsApp o el ID del número de WhatsApp. |

## Respuesta

### Éxito (200)

```json
{
  "ok": true,
  "instances": [
    {
      "instanceId": "inst_123",
      "ok": true
    }
  ]
}
```

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `ok` | boolean | Estado general de éxito. |
| `instances` | array | Arreglo con el resultado del logout de cada instancia. |
| `instances[].instanceId` | string | El ID de la instancia. |
| `instances[].ok` | boolean | Si el logout tuvo éxito para esta instancia. |
| `instances[].error` | string | Mensaje de error si el logout falló (solo presente cuando `ok` es false). |

### Errores

| Estado | Cuerpo | Significado |
| --- | --- | --- |
| `401` | `{ "error": "…" }` | Clave de API inválida o ausente. |
| `404` | `{ "error": "Number not found" }` | No existe ese número para esta clave de API. |
| `500` | `{ "error": "Internal server error" }` | Error del servidor (revisa los logs). |

## Notas

- El `ok` de nivel superior es **siempre `true`** una vez que se encuentra el número: revisa cada `instances[].ok`. Cuando el proveedor rechaza el logout de una conexión (cualquier error, incluido "instance not found" o un `401`), esa entrada vuelve con `ok: false` y el mensaje del proveedor en `error`, y su estado guardado **no** cambia.
- Después de un logout exitoso, el estado de la instancia será `LOGOUT` en la base de datos.
- Un número de Meta (Cloud API) no tiene conexión de la que cerrar sesión: la llamada responde `{ "ok": true, "instances": [] }`.
- `{id}` puede ser el id del número o el id de la instancia. Por OAuth o con una clave de cuenta (`ps_account_`) necesita `numbers:connect` (Admin u Owner); de lo contrario, `403 PERMISSION_DENIED`. Un token OAuth con acceso a otros números recibe `403 NUMBER_NOT_IN_GRANT`.
- Puedes reconectar la instancia después con `GET /v1/numbers/{id}/connect`.
