Los miembros están en **Profile → Membros** (`/profile?tab=membros`). La pestaña solo aparece para **Owner y Admin**. Tiene tres tarjetas: **Equipe** (el equipo: invitaciones y miembros), **Workspace** (nombre y nuevos workspaces) y, solo para el Owner, **Zona de perigo** (zona de peligro: transferir la propiedad, archivar).

<Note>
  Las etiquetas de esta pestaña (incluido el nombre de la pestaña, **Membros**) están en portugués sea cual sea el idioma del dashboard; la única excepción es la casilla **Use my backup card**, que sigue el idioma del dashboard. A continuación, cada etiqueta se cita tal como aparece, con su significado entre paréntesis.
</Note>

## La tarjeta del equipo

**Equipe** muestra un resumen como **3 membros · 1 convite(s) pendente(s)** y la lista de personas. Cada fila tiene el nombre y el correo de la persona, una insignia de rol (**Proprietário** (Owner, con una corona), **Administrador** (Admin), **Atendente** (Agent) o **Analista** (Analyst)) y, para las invitaciones, el estado:

| Insignia | Significado |
| --- | --- |
| **Convite pendente** | Invitación enviada, todavía sin respuesta. |
| **Convite expirado** | No se aceptó en 7 días; el enlace ya no funciona. |
| **Convite recusado** | La persona la rechazó. |

Debajo de una invitación pendiente, una línea indica cómo fue el correo: **E-mail enviado em …** (enviado), **Enviando o e-mail…** (todavía en la cola) o **E-mail não entregue. Use "Reenviar" — o link é a única forma de entrar.** (no entregado: reenvíalo o comparte el enlace tú mismo).

Cada fila también muestra qué números ve la persona: **Todos os números** (todos los números) o los elegidos.

## Invitar a alguien

En **Convidar alguém** (invitar a alguien): escribe el correo, elige el rol y haz clic en **Convidar**. Debajo del rol, una línea lo explica:

- **Administrador**: maneja la operación diaria: todo excepto el dinero y las credenciales en claro.
- **Atendente**: atiende a los clientes: conversaciones, etiquetas y envíos.
- **Analista**: solo los números, sin acceso a las conversaciones (el corte de PII).

Para Atendente y Analista, **Acesso aos números:** (acceso a los números) tiene un botón que abre el diálogo de alcance de números; consulta [Limitar a un miembro a algunos números](#limitar-a-un-miembro-a-algunos-números). Para Administrador, la pantalla dice **Administradores veem todos os números.** (los Admins ven todos los números).

La persona recibe un correo con un enlace válido por **7 días**.

<Warning>
  **El enlace de invitación se muestra una sola vez**, justo después de enviarla, en **Link do convite** con un botón **Copiar**: *Guardamos só o hash: este link não aparece de novo. Se perder, use "Reenviar".* Pilot Status solo almacena un hash del enlace, así que ni el dashboard ni el soporte pueden volver a mostrarlo. Si lo pierdes, usa **Reenviar**: eso emite un enlace nuevo e invalida el anterior.
</Warning>

Esa también es la salida cuando el correo no es una opción: copia el enlace y entrégalo como quieras.

Reglas que aplica el formulario:

- **Owner nunca se puede asignar.** Convertirse en propietario es una [transferencia de la propiedad](#transferir-la-propiedad), con su propia confirmación.
- **El Owner puede invitar a Admins, Agents y Analysts. Un Admin solo puede invitar a Agents y Analysts**: crear un Admin cambia quién está a cargo, y esa es decisión del propietario.

Invitar a un correo que ya tiene una invitación pendiente vuelve a enviar esa invitación, con el rol y los números que elegiste ahora y un enlace nuevo (**Convite reenviado.**). El número de prueba compartido no se ofrece en la elección de números.

Si la invitación se crea pero el correo no se pudo poner en cola, la pantalla advierte **Convite criado, mas o e-mail NÃO saiu. Copie o link abaixo e envie você mesmo — ele é a única forma de entrar e não aparece de novo.** (la invitación existe pero el correo no salió: copia el enlace y envíalo tú mismo).

Errores que puedes ver: **Esta pessoa já está no workspace.** (ya es miembro), **Você já está neste workspace.** (te invitaste a ti mismo), **E-mail inválido.**, **Seu papel não pode atribuir esse papel.** (tu rol no puede asignar ese rol) y **Muitos convites em pouco tempo. Tente daqui a pouco.** (demasiadas invitaciones; espera un poco).

Es posible que las invitaciones todavía no estén disponibles en tu cuenta. En ese caso, el formulario se reemplaza por un aviso de que las invitaciones están en **liberação gradual** (lanzamiento gradual), **Reenviar** está deshabilitado y el servidor rechaza nuevas invitaciones y reenvíos. No es un límite del plan y no hay nada que hacer; los miembros existentes siguen funcionando, y una invitación ya enviada todavía se puede aceptar o rechazar.

## Miembros ilimitados

Todos los planes, incluido Free, tienen **miembros ilimitados**. No hay contador de puestos ni tope de miembros: invita a tantas personas como necesites, y ni las invitaciones ni los miembros activos cuentan para ningún límite. Lo que cambia entre planes es cuántos números puedes conectar; consulta [Planes](/es/plans).

Una invitación pendiente que no se acepta en 7 días expira y simplemente deja de funcionar. No hay nada que limpiar ni ningún proceso que ejecutar.

## Reenviar y revocar

**Reenviar**, en una fila pendiente (incluidas las expiradas), emite un enlace nuevo e invalida el anterior: *Convite reenviado — o link anterior deixou de valer.* Owner y Admin pueden reenviar. Una invitación rechazada no tiene **Reenviar**: para invitar de nuevo a esa persona, usa **Convidar** con el mismo correo.

**Revogar** (revocar), en una fila pendiente, es la misma acción que eliminar a un miembro: un solo botón, porque una invitación y una membresía son la misma fila por debajo. Las filas de invitación (pendientes, expiradas o rechazadas) muestran **Revogar**; las activas muestran **Remover**. Ambas son **exclusivas del Owner**. Revocar pregunta **Revogar o convite de …?** (*el enlace deja de funcionar; puedes volver a invitar más tarde*) con **Revogar convite**.

## Cambiar un rol

El **Owner** cambia el rol desde el selector de rol de la fila (Administrador, Atendente, Analista) y confirma en **Tornar … [rol]?** con **Trocar papel**. El selector solo está en los miembros activos; para cambiar el rol de una invitación pendiente, invita de nuevo al mismo correo con el rol nuevo. Un Admin ve los roles pero no puede cambiarlos. El cambio surte efecto en la siguiente solicitud de la persona: no hay caché que esperar ni necesidad de que vuelva a iniciar sesión en el dashboard.

Promover a un Agent o Analyst a Admin elimina su límite de números, porque los Admins ven todo el workspace por definición; la confirmación lo indica (*A restrição de números deixa de valer: passa a ver todos os números.*).

La fila del Owner no tiene controles: el propietario no puede ser eliminado ni degradado; transfiere la propiedad primero (*O proprietário não pode ser removido nem rebaixado. Transfira a posse antes.*).

<Note>
  Cambiar el rol o los números de alguien, eliminarlo o transferir la propiedad (para ambas personas) desconecta las apps conectadas de esa persona: conectores MCP y otras apps autorizadas mediante OAuth. Esto aplica a todas las apps que la persona autorizó, en cualquier workspace; tiene que volver a autorizarlas.
</Note>

## Limitar a un miembro a algunos números

Para un **Atendente** o **Analista**, el botón de números de la fila (o **Acesso aos números:** en el formulario de invitación) abre **Números que … pode ver** (números que … puede ver). Owner y Admin pueden hacerlo. *Fuera del alcance, los números desaparecen del selector y el servidor rechaza las solicitudes: no es solo la pantalla ocultándolos.*

Elige uno:

- **Todos os números**: todos los números, *incluidos los que se conecten más tarde*.
- **Só os números escolhidos**: solo los números que marques. **Marcar todos** los marca todos y **Limpar** los desmarca; con más de 6 números hay una búsqueda por nombre o número. Debes marcar al menos uno: una elección vacía no se puede guardar.

Haz clic en **Salvar** (o **Aplicar** en el formulario de invitación). Un miembro limitado a números específicos **no** obtiene números nuevos automáticamente: agrégalos aquí cuando conectes uno. Los Owners y Admins siempre ven todos los números, así que sus filas muestran el alcance sin botón (si lo intentas de todos modos: *Proprietário e Administrador sempre veem todos os números.*).

## Eliminar a alguien, y sus API keys

El Owner hace clic en **Remover** y confirma **Remover … do workspace?** (*la persona pierde el acceso de inmediato; para volver, necesita una nueva invitación*) con **Remover do workspace**.

Eliminar a un miembro surte efecto de inmediato: sus tokens OAuth y MCP dejan de funcionar en la siguiente llamada (`401`, en todas las rutas), y los refresh tokens que tenga se revocan, así que nada puede revivir el acceso anterior. Un cambio de rol o de números también se aplica a esos tokens en la siguiente llamada: solo alcanzan lo que la persona alcanza hoy.

**Las API keys son diferentes, y Pilot Status se detendrá a preguntar.** Si la persona creó API keys en este workspace que no están revocadas (usadas o no), la eliminación se bloquea y se abre el diálogo **… criou N chave(s) de API** (… creó N API key(s)): *siguen funcionando después de la eliminación; decide antes de continuar*. Lista cada clave (su nombre, sus últimos cuatro caracteres, cuándo se usó por última vez (o **nunca usada**)) con tres botones:

<CardGroup cols={2}>
  <Card title="Revogar as chaves e remover" icon="ban">
    Revoca las claves y elimina. Las claves dejan de funcionar de inmediato; cualquier integración que dependa de ellas se rompe ahora.
  </Card>

  <Card title="Manter as chaves (passam para mim)" icon="key">
    Conserva las claves; se te reasignan a ti. Nada se rompe; ahora son tuyas.
  </Card>
</CardGroup>

**Cancelar** deja todo como estaba. No hay opción predeterminada, a propósito. Revocar en silencio tumba integraciones de producción en medio de una salida de personal; dejar claves huérfanas es peor, porque siguen funcionando y nadie sabe de quién son.

<Note>
  Revocar una clave nunca la elimina: el registro se conserva para que el historial de mensajes y llamadas siga apuntando a algo real. Una clave revocada simplemente deja de autenticar.
</Note>

## La tarjeta del workspace

**Workspace**: *cada workspace tiene sus propios números, miembros y facturación.*

- **Nome do workspace** (nombre del workspace): el nombre que se muestra en el selector de workspaces y en la invitación que reciben los miembros. Hasta 60 caracteres; **Salvar nome** lo guarda. Owner y Admin.
- **Criar outro workspace** (crear otro workspace): escribe el nombre del nuevo workspace (hasta 60 caracteres) y haz clic en **Criar workspace**. Te unes como Owner, se convierte en el workspace activo y el selector de workspaces aparece arriba. **Use my backup card** (desmarcada por defecto): *si la billetera del nuevo workspace no cubre un cargo, tu tarjeta de respaldo lo paga.* Si ya eres propietario del número máximo de workspaces, la pantalla dice *Você já atingiu o limite de … workspaces dos quais pode ser dono.* Consulta [cuántos workspaces puedes tener](/es/api/workspaces#cuántos-workspaces-puedes-tener).

## Zona de peligro

Solo el **Owner** ve **Zona de perigo**.

### Transferir la propiedad

Elige quién asume en **Escolha quem assume…** (solo se listan las personas que ya **aceptaron** la invitación; *Ninguém aceitou convite ainda* cuando no hay nadie) y haz clic en **Transferir**. El diálogo **Transferir a posse para …?** explica: *pasas a ser Admin y pierdes el acceso a la facturación, a revelar credenciales y a destruir números; solo el nuevo propietario puede devolvértela.* **Transferir a posse** confirma, y la página se recarga con el nuevo propietario.

### Archivar el workspace

Archivar **deja a todos sin acceso, incluido tú**, y no se puede deshacer desde el dashboard: revertirlo requiere al soporte. Escribe el nombre exacto del workspace para confirmar y haz clic en **Arquivar**. Luego se te lleva de vuelta al dashboard.

## Aceptar una invitación

La persona invitada abre el enlace e inicia sesión. **El correo de la cuenta debe coincidir con el correo que se invitó**: de lo contrario, cualquiera que interceptara el enlace podría unirse con su propia cuenta, y la invitación dejaría de ser nominal.

Luego el enlace muestra lo que se ofrece (el workspace, el rol y la dirección a la que se envió la invitación) y pregunta. **Abrir el enlace no te une a nada**; aceptar es un clic deliberado.

Una vez aceptada, el workspace pasa a ser el activo de inmediato. A partir de entonces sigue disponible en el selector de workspaces.

### Rechazar

La misma pantalla ofrece **Recusar** (rechazar), tras una confirmación (**Sim, recusar** o **Voltar**), porque no se puede deshacer desde el lado del invitado: rechazar inutiliza el enlace, y entrar más tarde implica ser invitado de nuevo. El invitado ve entonces **Convite recusado**: *Não avisamos ninguém automaticamente. Se foi engano, peça um novo convite a quem te chamou.* (no se avisa a nadie automáticamente; si fue un error, pide una nueva invitación).

La invitación no se elimina: quien la envió ve que la fila pasa a **Convite recusado**, que es justamente la razón de que exista ese estado. Antes, una invitación rechazada y una revocada eran indistinguibles, y la diferencia es lo que decide entre reenviar y tener una conversación.

Una invitación rechazada deja de funcionar de inmediato.

## Qué puede hacer cada rol

Cada fila indica qué puede hacer ese rol en el dashboard. Admin incluye todo lo que puede hacer un Agent, y Owner lo incluye todo.

| Rol | Qué agrega |
| --- | --- |
| **Analista** (Analyst) | Ve los números, las plantillas y las analíticas. Sin conversaciones, contactos ni contenido de mensajes. |
| **Atendente** (Agent) | Lo que ve un Analyst, más conversaciones, envíos (incluidos los envíos masivos y la cancelación de los programados), contactos, llamadas, grupos y lectura de Flows. |
| **Administrador** (Admin) | Todo lo que hace un Agent, más: conectar, editar, eliminar y restaurar números; webhooks e integraciones; administrar plantillas y Flows; ver y regenerar API keys; configuración del workspace y personalización de la página de conexión; invitar a Agents y Analysts y elegir sus números; leer la facturación; ver las líneas telefónicas y administrar sus webhooks. |
| **Proprietário** (Owner) | Todo, más lo que mueve dinero o no se puede deshacer: planes, tarjeta, recargas de la billetera y datos de facturación; mostrar API keys en claro; purgar números de forma permanente; comprar y cancelar líneas telefónicas; invitar a Admins, cambiar roles, eliminar miembros; transferir la propiedad y archivar el workspace. |

Los Agents y Analysts también pueden limitarse a algunos números; consulta [Limitar a un miembro a algunos números](#limitar-a-un-miembro-a-algunos-números).

## Hazlo por API / MCP

Escribir en la lista de miembros requiere una credencial con un **usuario** detrás (un token OAuth/MCP o una [clave de cuenta](/es/api/key-types#claves-de-cuenta) (`ps_account_`, con `x-workspace-id`)), que actúa con el rol actual de ese usuario. Una clave de workspace o de número recibe `403 MACHINE_CREDENTIAL_CANNOT_MANAGE_MEMBERS`. Detalles en [la API del workspace](/es/api/workspace).

| En esta pantalla | API | Herramienta MCP |
| --- | --- | --- |
| Leer el workspace | `GET /v1/workspace` | `workspace_get` |
| Listar miembros e invitaciones | `GET /v1/workspace/members` | `workspace_members_list` |
| Invitar | `POST /v1/workspace/members` | `workspace_members_invite` |
| Reenviar una invitación | `POST /v1/workspace/members/{id}/resend` | `workspace_members_resend` |
| Cambiar un rol | `PATCH /v1/workspace/members/{id}` | `workspace_members_update` |
| Cambiar los números de un miembro | [`PATCH /v1/workspace/members/{id}/numbers`](/es/api/workspace#cambiar-qué-números-ve-un-miembro) | `workspace_members_set_numbers` |
| Eliminar / revocar (con `?apiKeyAction=revoke` o `keep`) | [`DELETE /v1/workspace/members/{id}`](/es/api/workspace#eliminar-un-miembro-que-creó-claves-de-api) | `workspace_members_remove` |
| Listar / crear workspaces | [`GET` / `POST /v1/workspaces`](/es/api/workspaces) (solo clave de cuenta) | `workspaces_list`, `workspaces_create` |
| Renombrar el workspace | [`PATCH /v1/workspace`](/es/api/workspace#renombrar-el-workspace) | `workspace_update` |
| Transferir la propiedad | [`POST /v1/workspace/transfer-ownership`](/es/api/workspace#transferir-la-propiedad): **solo el token OAuth o la clave de cuenta del propietario**; ninguna clave de workspace o de número llega a él | `workspace_transfer_ownership` |
| Archivar el workspace | [`POST /v1/workspace/archive`](/es/api/workspace#archivar-el-workspace): **solo el token OAuth o la clave de cuenta del propietario**; ninguna clave de workspace o de número llega a él | `workspace_archive` |
