Pilot Status tiene tres tipos de API key, y cada uno vive en un lugar distinto del panel:

| Tipo | Prefijo | Pantalla | Barra lateral |
| --- | --- | --- | --- |
| **Clave de número** | `ps_number_` | **API Keys**: `/api-keys` | **API Keys**, bajo **Selected Number** |
| **Clave de workspace** (principal + con nombre) | `ps_workspace_` | **Workspace keys**: `/workspace-api-keys` | **API Keys**, bajo **Workspace** |
| **Clave de cuenta** | `ps_account_` | **Profile → API**: `/profile?tab=api` | **Profile**, luego la pestaña **API** |

La barra lateral muestra dos entradas llamadas **API Keys**: la del grupo **Selected Number** es la pantalla por número; la del grupo **Workspace** es la pantalla de claves del workspace. Lo que puede hacer cada tipo de clave se explica en [Tipos de clave](/es/concepts/key-types).

<Warning>
  **Cada clave en bruto se muestra una vez.** Cuando generas o regeneras cualquier clave (de número, principal, con nombre o de cuenta), el valor completo aparece en un diálogo una sola vez. Después de cerrarlo, el panel muestra solo el prefijo y los últimos cuatro caracteres (`ps_number_••••••••3b5d`). Nadie, incluido el soporte de Pilot Status, puede volver a mostrártela. Si perdiste una clave, **regenérala** (clave de número o principal) o **revócala y crea otra** (clave con nombre o de cuenta), y actualiza la integración que usaba la anterior.
</Warning>

## Quién puede usar estas pantallas

| Acción | Owner | Admin | Agent | Analyst |
| --- | --- | --- | --- | --- |
| Abrir **API Keys** y **Workspace keys** (`apikeys:read`) | ✅ | ✅ | — | — |
| Generar / regenerar la clave predeterminada de un **número** (`apikeys:rotate`) | ✅ | ✅ | — | — |
| Generar / regenerar la clave **principal** del workspace (`apikeys:reveal`) | ✅ | — | — | — |
| Crear / revocar claves de workspace **con nombre** | ✅ | ✅ | — | — |
| Botones de revocación de emergencia | ✅ | ✅ | — | — |
| Pestañas **Webhooks** y **Deliveries** de Workspace keys (`phone_lines:webhooks`) | ✅ | ✅ | — | — |
| Crear / revocar tus propias **claves de cuenta** (Profile → API) | ✅ | ✅ | ✅ | ✅ |

Agents y Analysts no ven ninguna de las dos entradas **API Keys** en la barra lateral. Un Admin ve la tarjeta de la clave principal sin el botón **Regenerate** / **Generate primary key**. Cuando el workspace aún no tiene clave principal, la tarjeta dice _"Generating the primary key is an owner action — it is shown in plaintext only once."_ (generar la clave principal es una acción del dueño; se muestra en texto plano una sola vez); cuando ya tiene una, el botón simplemente no está.

## API Keys (`/api-keys`): la clave predeterminada del número

Título **API Keys**, subtítulo _"Manage your API access keys"_. La pantalla trata sobre **el número seleccionado en el encabezado**: cambia de número en el encabezado para administrar la clave de otro número. Sin número seleccionado dice _"Select a number in the header to manage its API key."_ (selecciona un número en el encabezado para administrar su API key).

Cada número tiene **una clave predeterminada**, con alcance a ese número: no existe "crear otra clave" para un número, solo regenerar. La tarjeta informativa **Number default key** lo indica: _"Each number has a single default API key, scoped to this number. Regenerating replaces the previous key."_ (cada número tiene una única API key predeterminada, con alcance a este número; regenerarla reemplaza la anterior).

### Qué ves

La tarjeta de la clave muestra:

- **Key**: enmascarada, con prefijo, ocho puntos y los últimos cuatro caracteres. El valor completo nunca se muestra aquí.
- Una **insignia de alcance**: _"Scope: number \{number\} only"_ para una clave de número, o _"Scope: workspace (all numbers)"_ para una clave antigua con alcance de tenant, con la indicación _"To send through a number, this key requires the x-whatsapp-number-id header."_ (para enviar por un número, esta clave requiere el encabezado x-whatsapp-number-id).
- **Created** y **Last used** (`-` si nunca se usó).
- El botón **Regenerate API key**. Sin clave aún, la tarjeta dice _"No API key created"_ y el botón es **Generate API key**.

Si la clave no se pudo cargar, la tarjeta **Could not read this number's key** te indica que no generes una nueva antes de recargar (generar reemplaza la clave anterior) y ofrece **Try again**.

El número de prueba de Pilot Status no puede tener clave: _"Test number: select one of your numbers to create an API key."_ (número de prueba: selecciona uno de tus números para crear una API key).

### Generar o regenerar la clave

1. Haz clic en **Generate API key** (o **Regenerate API key**).
2. Confirma el aviso del navegador: _"Are you sure? Regenerating immediately invalidates the current key."_ (¿estás seguro? Regenerar invalida de inmediato la clave actual); para un número sin clave aún: _"Do you want to generate an API key for this number?"_ (¿quieres generar una API key para este número?).
3. El diálogo **API Key created** muestra la clave completa con un botón para copiar y la advertencia _"Warning: for security, the full key is shown only this once. Copy and store it now."_ (por seguridad, la clave completa se muestra solo esta vez; cópiala y guárdala ahora). Cópiala y luego haz clic en **Close**.

El aviso dice _"API Key created! Copy it now, it will not be shown again."_ (¡API Key creada! Cópiala ahora, no se volverá a mostrar). La clave anterior deja de funcionar de inmediato; cualquier integración que la use falla hasta que pegues la nueva. No hay periodo de gracia. Generar y regenerar requieren el rol Owner o Admin, los mismos roles que pueden abrir esta pantalla.

### Revocar las claves de este número (botón de emergencia)

**Revoke this number's keys**, arriba a la derecha, abre un diálogo con el mismo nombre. Cuenta las claves que va a destruir (_"This revokes \{keys\} key(s) of number \{number\}. Other numbers' keys and the workspace key are left untouched."_: revoca \{keys\} clave(s) del número \{number\}; las claves de otros números y la clave del workspace no se tocan), te permite marcar **Issue a new default key for this number afterwards** (desmarcado cada vez que se abre el diálogo) y te pide escribir el nombre del workspace. Si pediste una clave nueva, se muestra una vez en el mismo diálogo.

<Note>
  Revocar las claves de un número **no cierra el número**: una clave de workspace todavía puede enviar por él con el encabezado `x-whatsapp-number-id`. Para cerrar también ese camino, revoca la clave de workspace en la pantalla **Workspace keys** (ver más abajo). Los webhooks y las conexiones de números siguen funcionando; solo dejan de funcionar las integraciones que envían una API key.
</Note>

### Privacy & retention y Number settings

Debajo de la clave, la misma pantalla tiene dos paneles para el número seleccionado:

- **Privacy & retention**: **Mode**: **Store indefinitely**, **Store for X days** (con **Retention days**) o **Don't store (relay only)**; botón **Save privacy**. Consulta [Retención de datos](/es/trust/data-retention) y [API keys](/es/api/api-keys).
- **Number settings**: **Always online**, **Reject calls** (con **Reject message**, _"Empty = no reply"_, vacío = sin respuesta), **Mark as read**, **Ignore groups**, **Ignore status**, **Ignore channels**, **Import history on connect**, **Send history to webhooks**; cada interruptor que depende del proveedor ofrece **Provider default**, **On** u **Off**. Botón **Save settings**. Las mismas opciones están disponibles en la pantalla **Numbers**.

## Workspace keys (`/workspace-api-keys`)

Título **Workspace keys**, subtítulo _"The API keys of the current workspace."_ (las API keys del workspace actual). La pantalla tiene tres pestañas, que se guardan en la dirección como `?tab=`:

| Pestaña | `?tab=` | Contenido |
| --- | --- | --- |
| **Keys** | `chaves` (por defecto) | Clave principal, claves con nombre, enlace a las claves por número |
| **Webhooks** | `webhooks` | Los webhooks del workspace: listar, crear, editar, activar/pausar, eliminar |
| **Deliveries** | `entregas` | Contadores y las últimas 50 entregas del webhook seleccionado |

Sin el permiso de webhooks (Agent, Analyst, que de todos modos no pueden abrir la pantalla), solo existe **Keys**. `Ctrl/⌘+N` abre **New webhook** desde cualquier pestaña.

### Pestaña Keys: clave principal

La tarjeta **Primary key**: _"This is the key the in-app AI agent and the integrations use. Regenerating replaces only the primary key — the named keys keep working."_ (esta es la clave que usan el agente de IA de la app y las integraciones; regenerarla reemplaza solo la clave principal y las claves con nombre siguen funcionando).

Muestra **Key** (enmascarada), **Created at** y **Last used** (o **Never used**), y el botón **Regenerate**, o **Generate primary key** cuando el workspace aún no tiene una (_"This workspace has no primary key yet."_).

1. Haz clic en **Regenerate**. El diálogo **Regenerate the primary key?** advierte _"The previous primary key will be invalidated immediately. Named keys are not affected."_ (la clave principal anterior se invalidará de inmediato; las claves con nombre no se ven afectadas). Para una primera clave: **Generate the primary key?**, _"The full key will be shown only once."_ (la clave completa se mostrará una sola vez).
2. Confirma. El diálogo **Primary key generated** muestra la clave completa, un botón **Copy key** y _"Warning: the full key is shown only this once. Copy and store it now."_ Ciérralo con **Close** cuando la hayas guardado.

**Solo el Owner.** La clave principal no se puede revocar, solo regenerar.

Debajo de la tarjeta, Owners y Admins ven dos botones de emergencia:

- **Revoke the workspace key**: diálogo con el mismo nombre; revoca solo la(s) clave(s) del workspace; las claves por número no se tocan.
- **Revoke EVERYTHING (workspace + numbers)**: diálogo **Revoke ALL account keys**; revoca todas las claves de workspace **y** todas las claves por número, mostrando el conteo del servidor (_"This revokes \{keys\} key(s) of this workspace, covering \{numbers\} number(s)"_).

Ambos te piden escribir el nombre del workspace (_"To confirm, type the workspace name: \{name\}"_) y ofrecen **Issue a new workspace key afterwards** (desmarcado por defecto); el botón es **Revoke everything and issue a new key**. Una clave nueva, si se pidió, se muestra **una vez** en el diálogo, y es una clave de **workspace**, no de número: para enviar por un número necesita `x-whatsapp-number-id`. Si tu integración usaba una clave de número, crea la nueva en **API Keys** (`/api-keys`).

Úsalos cuando se filtró una clave y no sabes cuál. Para reemplazar una sola clave conocida, regenera o revoca esa clave.

### Pestaña Keys: claves con nombre

**Named keys**: _"Extra workspace keys, one per integration, so you can revoke one without taking the others down."_ (claves de workspace adicionales, una por integración, para que puedas revocar una sin afectar a las demás). La clave principal también aparece en esta lista con la insignia **Primary**.

- **Crear una clave**: escribe un **Key name** (por ejemplo _"CRM integration"_, hasta 60 caracteres) y haz clic en **Create key**. El diálogo **Key "\{name\}" created** muestra la clave completa una vez, con **Copy key** y **Close**.
- **Revoke**: en una fila (no en la principal). El diálogo **Revoke the key "\{name\}"?** advierte _"Every integration using this key stops working immediately. This cannot be undone."_ (toda integración que use esta clave deja de funcionar de inmediato; no se puede deshacer); confirma con **Revoke key**.
- Cada fila muestra el nombre, la clave enmascarada, **Created \{date\}** y **Last used \{date\}** / **Never used**.

Solo Owners y Admins ven el campo de creación y los botones **Revoke**. Hasta **50** claves activas por workspace, incluida la principal (_"Limit of \{limit\} keys reached. Revoke one you no longer use to create another."_: se alcanzó el límite; revoca una que ya no uses para crear otra). Las claves con nombre no se pueden regenerar: revoca y crea otra. Una clave con nombre creada por un miembro se revoca cuando ese miembro sale del workspace; consulta [Miembros](/es/dashboard/members).

### Pestaña Keys: claves por número

Una tarjeta **Per-number keys** con **Open per-number keys**, que te lleva a `/api-keys`.

### Pestaña Webhooks: webhooks del workspace

**Workspace webhooks**: _"One registry for the workspace events: the phone line ones and the paid wallet top-up (wallet.topup_paid). Deliveries are signed with the x-pilot-status-signature header."_ (un registro para los eventos del workspace: los de las líneas telefónicas y la recarga pagada de la billetera; las entregas se firman con el encabezado x-pilot-status-signature). Es un registro distinto de los webhooks de número de la [pantalla **Webhooks**](/es/dashboard/webhooks).

- Contadores: **Total Webhooks**, **Active**, **Inactive**.
- Un selector de webhook (**Select webhook...**, con búsqueda). Al seleccionar uno se muestra su resumen (nombre, URL, eventos, **Active**/**Paused**, última entrega) y sus acciones: editar, activar/desactivar, eliminar.
- **New webhook** abre el modal **New webhook**: **Name** (opcional, por ejemplo _"CRM integration"_), **URL \*** y **Events** (elige eventos, o **Every phone line event**). _"“All events” covers phone line events only: the paid wallet top-up (wallet.topup_paid) arrives only if you tick that event."_ (“todos los eventos” cubre solo los eventos de líneas telefónicas: la recarga pagada de la billetera llega solo si marcas ese evento). Haz clic en **Create webhook**.
- Editar abre **Edit webhook** con los mismos campos; guarda con **Save changes**.
- Eliminar pregunta **Delete this webhook?**: _"Deliveries to this URL stop right away."_ (las entregas a esta URL se detienen de inmediato).

<Warning>
  **El secreto de firma (`plwh_…`) se muestra una vez.** Justo después de **Create webhook**, el diálogo **Signing secret** lo muestra con **Copy** y la nota _"Shown once. Store it now — no read returns it again."_ (se muestra una vez; guárdalo ahora, ninguna lectura lo devuelve de nuevo). Cada entrega lleva `x-pilot-status-signature`: el HMAC-SHA256 en hexadecimal del cuerpo en bruto, con este secreto como clave. Los webhooks del workspace **no tienen rotación de secreto**: si perdiste el secreto, elimina el webhook y créalo de nuevo; el nuevo recibe un secreto nuevo, que se muestra una vez.
</Warning>

### Pestaña Deliveries

**Deliveries**: _"The latest 50 deliveries of the selected webhook, with the status and your endpoint's response. Click a row to see the payload sent."_ (las últimas 50 entregas del webhook seleccionado, con el estado y la respuesta de tu endpoint; haz clic en una fila para ver el payload enviado).

Elige el webhook en el mismo selector (la selección se comparte con la pestaña **Webhooks**). Ves los contadores **Total deliveries**, **Delivered**, **Failed**, y luego una tabla con **When**, **Event**, **Status** (**Pending**, **Delivered**, **Failed**), **Response** y **Attempts**. Al hacer clic en una fila se abre el detalle de la entrega con el payload. No hay filtros ni reenvío para este registro.

## Profile → API: claves de cuenta

**Profile**, pestaña **API** (`/profile?tab=api`), contiene **Account keys**: _"An account key is yours, not a workspace's: it manages your workspaces and acts inside any workspace you are an active member of. Each request picks the workspace with the x-workspace-id header and runs with your role there."_ (una clave de cuenta es tuya, no de un workspace: administra tus workspaces y actúa dentro de cualquier workspace del que seas miembro activo; cada solicitud elige el workspace con el encabezado x-workspace-id y se ejecuta con tu rol allí). La insignia dice **Scope: Everything in every workspace**.

Todo miembro, sea cual sea su rol, puede crear y revocar sus propias claves de cuenta aquí (hasta **20** por usuario), con el mismo flujo **Key name** / **Create key** / **Revoke** y el mismo diálogo de una sola visualización que las claves con nombre. Owners y Admins también tienen una tarjeta **Workspace keys** con **Open workspace keys**.

<Note>
  La clave de workspace no está aquí: revócala o regenérala en **Workspace keys** (`/workspace-api-keys`). El diálogo **Revoke this number's keys** también apunta allí (_"revoke the workspace key in Workspace keys"_).
</Note>

## Hazlo por API / MCP

| Acción en el panel | API | Herramienta MCP |
| --- | --- | --- |
| Listar claves por número | [`GET /v1/api-keys`](/es/api/api-keys) (clave de workspace) | `api_keys_list` (por OAuth/MCP, solo el Owner del workspace, verificado en cada llamada y registrado en el log de auditoría; consulta [Secretos y API keys por OAuth](/es/integrations/mcp-server#secretos-y-api-keys-por-oauth)) |
| Regenerar la clave de un número | [`POST /v1/api-keys`](/es/api/api-keys) con `whatsappNumberId` | `api_keys_regenerate_number` |
| Regenerar la clave principal | [`POST /v1/api-keys/regenerate`](/es/api/api-keys) | — |
| Listar / crear / revocar claves de workspace con nombre | [`/v1/workspaces/{id}/api-keys`](/es/api/workspaces#claves-de-workspace) (clave de cuenta) | `workspaces_api_keys_list`, `workspaces_api_keys_create`, `workspaces_api_keys_revoke` |
| Webhooks del workspace: listar, obtener, crear, editar, eliminar | [`/v1/workspace/webhooks`](/es/api/workspace-webhooks) | `workspace_webhooks_list`, `workspace_webhooks_get`, `workspace_webhooks_create`, `workspace_webhooks_update`, `workspace_webhooks_delete` |
| Entregas de webhooks del workspace | `GET /v1/workspace/webhooks/{id}/deliveries[/{deliveryId}]` | `workspace_webhooks_deliveries_list`, `workspace_webhooks_deliveries_get` |
| Revocación de emergencia (número / workspace / todo) | Solo en el panel | — |
| Claves de cuenta (Profile → API) | Solo en el panel | — |
| Privacy & retention, Number settings | [`PATCH /v1/numbers/{id}`](/es/api/numbers/settings) | `numbers_settings_update` |

La autenticación y los encabezados (`x-api-key`, `x-whatsapp-number-id`, `x-workspace-id`) se explican en [Autenticación](/es/api/authentication).
