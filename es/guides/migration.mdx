Si ya tienes automatización de WhatsApp funcionando sobre Evolution API (ya sea Evolution GO o Evolution V2), puedes pasarte a Pilot Status sin tocar una sola línea del código de tu aplicación. La **API Layer** de Pilot Status es una capa de compatibilidad que acepta solicitudes exactamente en el formato que tu integración ya envía, las traduce internamente y las enruta por la infraestructura de Pilot Status. Los cuerpos de solicitud, el formato de las respuestas, los payloads de webhook y los headers de autenticación siguen iguales. Lo único que cambia es el hostname de tu URL base.

## Qué es la API Layer

La API Layer se ubica delante de la plataforma Pilot Status y habla el mismo dialecto HTTP que los proveedores de WhatsApp que tu equipo ya conoce. Cuando tu aplicación envía una solicitud al endpoint de la API Layer, Pilot Status la interpreta con el esquema específico del proveedor, ejecuta la operación en su infraestructura administrada y devuelve una respuesta en el formato que tu código espera.

Esto significa que obtienes todos los beneficios de Pilot Status (proxies administrados, sin servidores propios, integraciones oficiales con Meta, escalado automático y SLA de disponibilidad) sin un sprint de migración, sin reescribir y sin un ciclo de QA para validar nuevos formatos de solicitud.

## Cómo migrar

<Steps>
  <Step title="Conecta tu número">
    En el panel, haz clic en **Connect number** (Conectar número) y elige la tarjeta **Migration** (Unofficial API → Migration). Conecta el número por código QR como siempre.
  </Step>
  <Step title="Obtén tu API key de Pilot Status">
    Cada número tiene una key predeterminada en la página **API Keys**; esta key reemplaza tu antiguo valor `apikey` de Evolution (mantén el mismo header `apikey`).
  </Step>
  <Step title="Cambia la URL base">
    Apunta tu integración a `https://pilotstatus.com.br/api/layer/evolution-go/` o `.../evolution-v2/`. Los cuerpos de solicitud, las rutas (v2 mantiene el último segmento `{instance}` = el nombre visible del número) y los handlers de webhook siguen iguales.
  </Step>
  <Step title="Reconfigura los webhooks y prueba">
    Configura tu webhook en la página **Webhooks** (los eventos llegan en el formato nativo de tu proveedor; consulta las páginas de la capa), luego envía un mensaje de prueba y confirma la entrega en **Logs**.
  </Step>
</Steps>

## Proveedores compatibles

<CardGroup cols={2}>
  <Card title="Evolution GO" icon="bolt">
    **Endpoint:** `/api/layer/evolution-go/`

    Compatibilidad directa para aplicaciones construidas sobre la API de Evolution GO. Se admiten todas las rutas de envío de mensajes, gestión de instancias y webhooks.
  </Card>

  <Card title="Evolution V2" icon="code">
    **Endpoint:** `/api/layer/evolution-v2/`

    Compatibilidad directa para aplicaciones construidas sobre Evolution API v2. Admite toda la superficie de la API v2 de mensajes, grupos y eventos.
  </Card>
</CardGroup>

## Qué se mantiene igual

Cuando migras con la API Layer, lo siguiente no cambia en absoluto en tu aplicación:

- **Formato del cuerpo de la solicitud**: los payloads JSON que envías hoy funcionan sin modificaciones.
- **Formato de la respuesta**: los nombres de campos, tipos y estructura son idénticos a los que ya interpretas.
- **Formato del payload de webhook**: los nombres de eventos y los esquemas de payload coinciden con tus handlers actuales.
- **Headers de autenticación**: sigue usando el mismo nombre y formato de header que exige tu proveedor (Pilot Status lo mapea internamente).
- **Rutas y métodos**: cada ruta de endpoint y método HTTP que llamas hoy se admite en la misma ruta relativa bajo la nueva URL base.

## Qué cambia

| Qué | Antes | Después |
| --- | --- | --- |
| **URL base** | Tu servidor propio | `https://pilotstatus.com.br/api/layer/{provider}/` |
| **Facturación** | Costos de tu servidor / VPS | Suscripción de Pilot Status |
| **Infraestructura** | Servidor, proxies y actualizaciones gestionados por ti | Totalmente administrada por Pilot Status |
| **Responsabilidad de disponibilidad** | Tuya | SLA de Pilot Status |

<Note>
  La API Layer está disponible en todos los planes pagos de Pilot Status. Puedes probar tu migración en el plan gratuito con tu primer número conectado antes de comprometerte con una suscripción.
</Note>

Para la referencia completa de la API Layer (incluidos los endpoints compatibles, el manejo de errores y el mapeo de instancias), consulta la [descripción general de la API Layer](/es/api/layer/overview).
