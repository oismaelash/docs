Un **WhatsApp Flow** es un formulario que se abre dentro del chat: una pantalla de reservas, un formulario de leads, una encuesta. El cliente toca un botón, completa una o más pantallas y envía. Esta guía recorre todo el camino, desde crear el Flow hasta leer las respuestas.

<Warning>
  Los Flows están disponibles **solo en números de la API oficial (Meta Cloud API)**. No están disponibles en números conectados por código QR. Un Flow pertenece a la cuenta de WhatsApp Business (WABA), así que cualquier número Meta de esa WABA puede enviarlo.
</Warning>

## Ciclo de vida

| Estado | Qué puedes hacer |
| --- | --- |
| `DRAFT` | Editar el JSON del Flow, previsualizarlo, enviarlo como prueba con `mode: "draft"`, eliminarlo. |
| `PUBLISHED` | Enviarlo a cualquier cliente. El JSON ya no puede cambiar. |
| `DEPRECATED` | Retirado: ya no se puede enviar. |

- **Publicar es irreversible.** Para cambiar un Flow publicado, **clónalo** en un nuevo borrador, edita el clon y publícalo.
- **Solo un `DRAFT` se puede eliminar.** Un Flow publicado solo se puede retirar (deprecate).

## Crear un Flow

<Tabs>
  <Tab title="Panel">
    Abre la pantalla **Flows**. Crea un borrador, escribe su JSON en el editor (o **genéralo con IA** a partir de una descripción), previsualízalo y publícalo. Ver [La pantalla de Flows](/es/dashboard/flows).
  </Tab>
  <Tab title="API">
    1. `POST /v1/flows` crea el borrador ([crear](/es/playground/flows/create-flow)).
    2. `POST /v1/flows/{id}/json` sube el JSON del Flow ([subir JSON](/es/playground/flows/upload-flow-json)).
    3. `POST /v1/flows/{id}/preview` devuelve un enlace de vista previa ([vista previa](/es/playground/flows/preview-flow)).
    4. `POST /v1/flows/{id}/publish` lo publica ([publicar](/es/playground/flows/publish-flow)).
    5. `POST /v1/flows/{id}/deprecate` lo retira más tarde ([retirar](/es/playground/flows/deprecate-flow)).

    Referencia completa: [API de Flows](/es/api/flows).
  </Tab>
</Tabs>

### Categorías

Cada Flow tiene una o más categorías: `SIGN_UP`, `SIGN_IN`, `APPOINTMENT_BOOKING`, `LEAD_GENERATION`, `CONTACT_US`, `CUSTOMER_SUPPORT`, `SURVEY`, `OTHER`.

## Enviar un Flow

**En un mensaje.** Agrega un bloque `flow` a [`POST /v1/messages/send`](/es/playground/messages/send-message):

```json
{
  "destinationNumber": "+5511999999999",
  "text": "Reserva tu visita",
  "flow": {
    "flowId": "2038526810137974",
    "cta": "Reservar",
    "action": "navigate",
    "screen": "WELCOME",
    "data": { "name": "Ana" }
  }
}
```

| Campo | Regla |
| --- | --- |
| `flowId` | El id del Flow en Meta. Obligatorio. |
| `cta` | Texto del botón, hasta **30 caracteres**. Obligatorio. |
| `action` | `navigate` o `data_exchange`. |
| `screen`, `data` | Solo con `navigate`. Con `data_exchange` la solicitud se rechaza con `FLOW_PAYLOAD_NOT_ALLOWED`. |
| `mode` | `draft` para enviar un Flow no publicado como prueba. |

Requiere la ventana de 24 horas abierta. Detalles: [Flows dinámicos](/es/guides/send-flow-dynamic).

**En una plantilla.** Agrega un **botón FLOW** a una plantilla. El Flow queda fijo al crear la plantilla y se puede enviar fuera de la ventana de 24 horas. Ver [Plantillas](/es/concepts/templates).

## Recibir las respuestas

Un Flow enviado por el cliente dispara el evento de webhook **`flow.response_received`**, con las respuestas como datos estructurados. Suscríbete a ese evento explícitamente. También puedes listar las respuestas guardadas con `GET /v1/flows/{id}/responses` ([listar respuestas](/es/playground/flows/list-flow-responses)). Detalles: [Respuestas de Flow](/es/guides/flow-responses).

## Conectar tu API (data_exchange)

Un Flow `data_exchange` le pide cada pantalla a tu backend mientras el cliente lo completa.

- **Cada número tiene su propia clave de cifrado.** Genérala o impórtala en la pantalla de Flows o por la API ([generar clave](/es/playground/numbers/generate-flow-endpoint-key)).
- **Pilot Status es el endpoint al que llama Meta.** Descifra la solicitud y reenvía JSON plano a tu URL, firmado en el encabezado `x-pilot-status-signature`. Verifica la firma antes de confiar en el cuerpo.
- **La URL del endpoint es una credencial.** Trátala como un secreto y no la compartas.
- **Rotar la clave afecta a todos los Flows `data_exchange` de ese número** a la vez. Planifica la rotación.

Detalles: [Conecta tu API a un Flow](/es/guides/flow-data-exchange) y [Flows con datos en vivo](/es/guides/flow-live-data).

## Depurar con trazas

`GET /v1/flows/{id}/traces` lista las llamadas recientes al endpoint ([listar trazas](/es/playground/flows/list-flow-traces)). Las trazas se guardan **24 horas**, y el cuerpo de la solicitud solo se guarda **cuando la llamada falló**.
