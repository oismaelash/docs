**Sí, puedes enviar botones y listas por la API sin una plantilla.** Los botones interactivos y las listas de selección única son **mensajes de formato libre (de servicio)** en el mismo endpoint que ya usas:

```text
POST https://pilotstatus.com.br/v1/messages/send
```

No hay plantilla que crear ni revisión de Meta. En los números de **Meta Cloud API (oficial)** hay una condición: la **ventana de servicio de 24 horas** debe estar abierta, y siempre lo está cuando tu bot responde un mensaje que el cliente acaba de enviar. En los números **no oficiales** no hay ventana.

Esta es la forma de un bot típico: el cliente escribe, respondes con un menú, el cliente elige una opción, respondes con el siguiente paso.

## Elige el tipo interactivo correcto

| Necesitas | Usa | Límite |
| --- | --- | --- |
| 2–3 opciones rápidas ("Sí / No", "Pagar / Hablar con nosotros") | `buttons` con `type: "reply"` | **3** botones, etiqueta de hasta 20 caracteres |
| Un menú de opciones (facturas, áreas, productos) | `list` | **10** filas en total, título de fila de hasta 24 caracteres |
| Opciones con una imagen cada una | `carousel` | 2–10 tarjetas: consulta [Carousel](/es/api/messages/send-interactive#carrusel) |
| Un formulario (varios campos, validación, pantallas) | `flow` | consulta [Flows dinámicos](/es/guides/send-flow-dynamic) |

Todos necesitan `text`: el cuerpo del mensaje encima de los botones o del botón de la lista. Son mutuamente excluyentes: un tipo interactivo por mensaje. (`buttons` también puede ir en un envío de plantilla; `list`, `carousel` y `flow` no.)

## Enviar una lista

```bash
curl -X POST "https://pilotstatus.com.br/v1/messages/send" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{
    "destinationNumber": "+5511999999999",
    "text": "You have 3 open invoices. Which one do you want to pay?",
    "footer": "Values updated today",
    "list": {
      "buttonText": "See invoices",
      "sections": [
        {
          "title": "Open invoices",
          "rows": [
            { "id": "inv-2041", "title": "Invoice 2041", "description": "$1,250.00 · due Oct 30" },
            { "id": "inv-2057", "title": "Invoice 2057", "description": "$480.00 · due Nov 05" },
            { "id": "inv-2063", "title": "Invoice 2063", "description": "$92.10 · due Nov 12" }
          ]
        }
      ]
    }
  }'
```

La respuesta es el `202` habitual con `id` y `correlationId`. Guarda el `id`: es lo que te permite relacionar la elección del cliente con este menú (consulta [Relaciona la elección con el menú](#relaciona-la-elección-con-el-menú) más abajo).

| Campo | Regla |
| --- | --- |
| `text` | **Obligatorio**: el cuerpo del mensaje, hasta **1024** caracteres |
| `footer` | Opcional, hasta **60** caracteres |
| `list.buttonText` | Etiqueta del botón que abre el menú, **1–20** caracteres |
| `list.sections` | **1–10** secciones; **10 filas en total** entre todas |
| `sections[].title` | Opcional |
| `rows[].title` | **1–24** caracteres: **mantenlo único dentro de la lista** |
| `rows[].description` | Opcional, hasta **72** caracteres |
| `rows[].id` | Opcional, hasta **200** caracteres: **defínelo siempre** (la clave de tu ERP, por ejemplo) |

`header` y `buttons` **no** se permiten junto con `list`.

<Tip>
  **¿Más de 10 opciones?** Envía las primeras 9 y usa la décima fila como "Más opciones" (`id: "page-2"`). Cuando el cliente la elija, envía la siguiente lista. Diez es el límite de Meta y se aplica en todos los tipos de número.
</Tip>

## Enviar botones de respuesta

```bash
curl -X POST "https://pilotstatus.com.br/v1/messages/send" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ps_your_key_here" \
  -d '{
    "destinationNumber": "+5511999999999",
    "text": "Invoice 2041 — $1,250.00, due Oct 30. How do you want to pay?",
    "header": { "type": "text", "content": "Invoice 2041" },
    "footer": "Payment link valid for 24 h",
    "buttons": [
      { "type": "reply", "displayText": "Bank slip", "id": "pay-slip:inv-2041" },
      { "type": "reply", "displayText": "Card", "id": "pay-card:inv-2041" },
      { "type": "reply", "displayText": "Talk to us", "id": "human" }
    ]
  }'
```

Hasta **3** botones. Además de `reply`, los botones pueden ser `url`, `call` o `copy`: las formas completas están en [Enviar interactivos](/es/api/messages/send-interactive).

<Warning>
  En los números de **Meta (oficiales)**, **no** mezcles un botón `url` con botones `reply` en un envío de formato libre: un orden se rechaza y el otro se acepta pero **nunca se entrega**. Envía el enlace en un mensaje aparte. Detalles en [Enviar interactivos](/es/api/messages/send-interactive#dónde-se-permiten-los-botones).
</Warning>

## Recibir la elección del cliente

La elección llega a tu webhook como cualquier otro mensaje entrante. **El aspecto del payload depende de cómo está conectado el número**: la misma regla que para cualquier otro evento entrante ([Qué eventos envía tu número](/es/api/webhooks/events#qué-eventos-envía-tu-número)).

<Tabs>
  <Tab title="Meta Cloud API (oficial)">
    Recibes el **sobre nativo de Meta** (campo de webhook `messages`), con `type: "interactive"`. **El `id` que definiste en la fila o el botón vuelve**, y `context.id` es el `wamid` del mensaje que llevaba el menú.

    ```json
    {
      "object": "whatsapp_business_account",
      "entry": [{
        "id": "987654321098765",
        "changes": [{
          "field": "messages",
          "value": {
            "messaging_product": "whatsapp",
            "metadata": { "display_phone_number": "5511888888888", "phone_number_id": "123456789012345" },
            "contacts": [{ "profile": { "name": "Ana" }, "wa_id": "5511999999999" }],
            "messages": [{
              "context": { "from": "5511888888888", "id": "wamid.MENU..." },
              "from": "5511999999999",
              "id": "wamid.CHOICE...",
              "timestamp": "1792756800",
              "type": "interactive",
              "interactive": {
                "type": "list_reply",
                "list_reply": { "id": "inv-2041", "title": "Invoice 2041", "description": "$1,250.00 · due Oct 30" }
              }
            }]
          }
        }]
      }]
    }
    ```

    Un botón de respuesta llega de la misma forma con `"type": "button_reply"` y `"button_reply": { "id": "pay-slip:inv-2041", "title": "Bank slip" }`.

    **Decide según `interactive.list_reply.id` / `interactive.button_reply.id`**: es la clave de tu ERP, intacta.
  </Tab>
  <Tab title="No oficial (conexión por código QR)">
    Recibes el evento canónico **`message.reply`** (la elección cita tu menú). `content` es el **título de la fila** o la **etiqueta del botón**; `quotedMessageId` es el `messageId` del `message.sent` de tu menú.

    ```json
    {
      "event": "message.reply",
      "data": {
        "from": "+5511999999999",
        "to": "+5511888888888",
        "messageId": "3EB0C1...",
        "fromMe": false,
        "content": "Invoice 2041",
        "contentReplied": "You have 3 open invoices. Which one do you want to pay?",
        "quotedMessageId": "3EB0A9...",
        "buttonId": "inv-2041",
        "correlationId": "corr_123",
        "createdAt": "2026-10-23T12:00:00.000Z"
      }
    }
    ```

    **Decide según `buttonId`**: lleva el `id` que definiste en la fila (desde 2026-10-23). Conserva `content` (el título) junto con `quotedMessageId` como alternativa; por eso los títulos de las filas deben seguir siendo únicos dentro de una lista.

    Suscríbete a **ambos**, `message.reply` y `message.received` (o `"*"`): `message.reply` no dispara también `message.received`.
  </Tab>
</Tabs>

### Relaciona la elección con el menú

Tu bot normalmente tiene varios menús abiertos con distintos clientes. Para saber a qué menú pertenece una elección, guarda un pequeño registro por cada menú enviado:

1. `POST /v1/messages/send` devuelve `id` → guarda `{ id, customer, options }`.
2. Obtén el id de WhatsApp de ese menú: en números no oficiales, `message.sent` incluye tanto `id` como `messageId`; en números oficiales, cada ítem de `statuses[]` incluye tu `id` en [`biz_opaque_callback_data`](/es/api/webhooks/events#vincular-un-estado-con-tu-envío-biz_opaque_callback_data) junto al `wamid` (`statuses[].id`).
3. La elección cita ese `messageId` (`quotedMessageId` en no oficiales o `context.id` en oficiales), así que encuentras el registro y la opción.

Si tus opciones se describen por sí mismas (`"id": "inv-2041"`), el paso 2 es opcional: el `id` de la fila por sí solo (`list_reply.id` en números oficiales, `buttonId` en no oficiales) ya te dice qué se eligió.

## La ventana de 24 horas y el costo (números oficiales)

- Los mensajes de formato libre (botones, listas, carruseles, texto simple) solo se entregan en un número de Meta mientras la **ventana de servicio de 24 horas** está abierta, es decir, dentro de las 24 h posteriores al último mensaje del cliente. Un bot que responde mensajes entrantes siempre está dentro de ella.
- Para iniciar tú una conversación (un recordatorio de pago, por ejemplo), usa primero una **plantilla** aprobada. Cuando el cliente responde, la ventana se abre y el bot puede continuar con listas y botones.
- Fuera de la ventana, el envío falla con `META_OUTSIDE_24H_WINDOW`. Puedes consultar la ventana antes de enviar con [`GET /v1/service-window`](/es/playground/messages/service-window).
- **Los mensajes de servicio ya no son siempre gratuitos.** Desde **2026-10-01**, Meta da **1.000 mensajes de servicio gratuitos por mes por número** y cobra la tarifa Utility del país a partir de ahí. Lo factura Meta, no Pilot Status. Consulta [Precios](/es/api/pricing).

Los números no oficiales no tienen ventana ni cobro de Meta.

## Errores comunes

| Hiciste | Qué ocurre | Haz esto en su lugar |
| --- | --- | --- |
| `list` + `buttons` en una solicitud | `400`: son mutuamente excluyentes | Un tipo interactivo por mensaje |
| `list` + `header` | `400` | Pon el título en `text` |
| `list` + `templateId` | `400` | Una lista va con `text`, no con una plantilla |
| 11 o más filas | `400`: 10 filas es el total, no por sección | Pagina con una fila "Más opciones" |
| Dos filas con el mismo título | Solo `buttonId` las distingue | Títulos únicos, y define siempre `id` |
| Webhook suscrito solo a `message.received` | Las elecciones en números no oficiales nunca te llegan | Suscríbete también a `message.reply`, o a `"*"` |
| Procesar `{ event, data }` en un número oficial | Todos los campos se leen como `undefined` | Procesa el sobre nativo de Meta: consulta la pestaña de arriba |
