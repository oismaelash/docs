Incrusta la **bandeja de WhatsApp (Chat)** de Pilot Status en tu propio SaaS, en white-label, mediante un iframe alojado más el SDK `@pilot-status/embed`.

## Requisitos previos compartidos (Chat \+ Connect)

1. **API key del tenant** (`ps_`, con alcance de tenant): se genera en **Workspace keys** (`/workspace-api-keys`). **Nunca** sale de tu backend. (Una clave con alcance de número solo puede incrustar su propio número.)
2. **SDK**: `<script src="https://pilotstatus.com.br/embed.js">` o `npm i @pilot-status/embed`; llama a `PilotStatus.init()`.
3. **`allowedOrigins`**: al emitir el token de Chat, lista los orígenes exactos (`scheme://host[:port]`, de 1 a 20) autorizados a incrustar.
4. **Token por superficie**: Chat usa `POST /v1/embed/sessions` (`surface: "chat"`, un JWT de corta duración guardado en memoria). Connect usa `POST /v1/numbers/remote-pairing` (un token de emparejamiento en la URL; consulta [Incrustar la página Connect](/es/integrations/embed-connect)).
5. **Renovación**: el TTL del token de Chat es de 15 min con una ventana de renovación deslizante; cuando expira por completo, el SDK llama a `onSessionExpired`.

## Flujo de Chat

<Steps>
  <Step title="Configuración única">
    Tu backend lista los números con `GET /v1/numbers` (`x-api-key`) y guarda el mapa `cliente → [whatsappNumberIds]`.
  </Step>
  <Step title="Emite un token en cada carga de página">
    Tu frontend le pide un token a tu backend; el backend llama:

    ```bash
    curl -X POST "https://pilotstatus.com.br/v1/embed/sessions" \
      -H "x-api-key: ps_your_tenant_key" \
      -H "Content-Type: application/json" \
      -d '{
        "surface": "chat",
        "whatsappNumberIds": ["wn_abc123"],
        "allowedOrigins": ["https://app.yoursaas.com"],
        "ttlSeconds": 900
      }'
    ```

    Respuesta `201`: `{ token, surface, whatsappNumberIds, allowedOrigins, expiresAt }`. El backend reenvía **solo el JWT** al frontend.
  </Step>
  <Step title="Monta la bandeja">
    ```html
    <script src="https://pilotstatus.com.br/embed.js"></script>
    <div id="inbox"></div>
    <script>
      PilotStatus.init();
      const { token } = await fetch("/api/my-saas/embed-token").then(r => r.json());
      const chat = PilotStatus.chat.mount("#inbox", {
        token, locale: "en", theme: "light",
        onUnreadCount: (n) => {},
        onConversationOpened: (id) => {},
        onSessionExpired: async () => {
          const { token: t } = await fetch("/api/my-saas/embed-token").then(r => r.json());
          chat.destroy();
          PilotStatus.chat.mount("#inbox", { token: t, locale: "en" });
        },
      });
      // chat.setTheme("dark"); chat.setLocale("pt"); chat.destroy();
    </script>
    ```
  </Step>
</Steps>

## Altura del chat (SDK 0.3.0)

Desde `@pilot-status/embed` **0.3.0** el iframe del chat tiene **altura fija**: ya no crece con la conversación. La lista de mensajes se desplaza dentro del iframe y el campo de mensaje queda fijo abajo.

- La altura viene de la opción `height` de `PilotStatus.chat.mount` (por defecto `"600px"`; acepta cualquier medida CSS: `"600px"`, `"80vh"`, `"100%"`).
- Con `height: "100%"`, el contenedor necesita altura propia (p. ej. `height: 70vh` o un layout flex con altura definida). `100%` de un contenedor sin altura queda en cero.
- Un mensaje nuevo recibido **nunca baja la conversación solo**: aparece el botón para ir a los más recientes, con el contador de nuevos. Quien envía su propio mensaje sigue bajando.

```html
<div id="inbox" style="height: 70vh"></div>
<script>
  PilotStatus.chat.mount("#inbox", { token, height: "100%" });
</script>
```

<Warning>
Los hosts con el SDK anterior (≤ 0.2.x) quedan en los 600px iniciales: el chat alojado ya no envía `resize`. Actualice con `npm i @pilot-status/embed@^0.3.0`.
</Warning>

## Llamadas de WhatsApp en el chat embebido

Todo token de chat (`surface: "chat"`) puede **recibir y hacer llamadas de WhatsApp**, sin opt-in y sin campo nuevo. El widget suena con las llamadas entrantes (atender / rechazar / colgar) y puede llamar al contacto abierto. Todo queda limitado a los `whatsappNumberIds` del token: una llamada en cualquier otro número devuelve `403`.

- **Micrófono:** el SDK ya crea el iframe con `allow="microphone"`. Si arma el `<iframe>` a mano, incluya `allow="microphone"`.
- **Configuración de llamadas** (activar llamadas en el número, preferencias de atención) sigue en el panel de Pilot Status; el embed no la cambia.
- **Cobro (Meta):** solo **la llamada iniciada por la empresa en un número oficial (API Cloud de Meta)** se cobra, por Meta, en su WABA: por minuto, en pulsos de 6 segundos, y solo cuando se atiende. La llamada entrante (iniciada por el usuario) es gratuita. Un número conectado por código QR no tiene cobro de Meta. Pilot Status no cobra nada por las llamadas. Avise a sus clientes con número oficial antes de mostrar el botón de llamar a los visitantes.

## Protocolo postMessage (padre ↔ iframe)

Sobre: `{ source: "pilot-status-embed", v: 1, type, payload }`. Los mensajes sin ese `source` se ignoran; el origen se valida en **ambos** lados.

| Paso | Quién | Mensaje |
| --- | --- | --- |
| A | SDK (padre) | crea `<iframe src="chat.pilotstatus.com.br/?parentOrigin=<origin>">` (sandbox `allow-scripts allow-same-origin allow-forms allow-popups`) |
| B | iframe → padre | `ready` (el SDK valida `origin === chat.pilotstatus.com.br`) |
| C | SDK → iframe | `init{ token, locale, theme }` (el iframe valida `origin === parentOrigin`) |
| D | iframe | guarda el token **solo en memoria**, nunca en la URL ni en localStorage |
| E | iframe → padre | `resize{height}` (solo Connect desde 0.3.0), `chat:unread-count{count}`, `chat:conversation-opened{conversationId}`, `session-expired` |
| — | SDK → iframe | `set-theme{theme}`, `set-locale{locale}` en tiempo de ejecución |

## Modelo de seguridad

- `x-api-key` vive **solo** en tu backend; el navegador solo maneja el JWT de corta duración.
- El JWT está **estrictamente limitado** a sus `whatsappNumberIds`: las rutas del chat vuelven a verificarlo en cada solicitud (defensa en profundidad).
- Token solo en memoria, TTL de ~15 min con renovación deslizante; `allowedOrigins` fija quién puede incrustar; el origen de postMessage se valida en ambos lados.
