El node oficial de la comunidad `n8n-nodes-pilot-status` agrega dos nodes a n8n:

- **Pilot Status**: llama a la API pública `/v1` para enviar mensajes y plantillas, listar logs y gestionar números, plantillas, Flows, grupos y más.
- **Pilot Status Trigger**: recibe los eventos de tu webhook e inicia un workflow.

Esta página muestra cómo configurar los dos e incluye workflows para importar y adaptar: uno para empezar con cada tipo de número (API Pilot Status, layer Evolution GO, layer Evolution v2, oficial Meta) y cinco recetas. Cada workflow se importó en n8n y se comprobó contra la definición de los nodes, y su lógica de enrutamiento se ejecutó con payloads de ejemplo de todos los formatos de webhook.

## Instala el node

<Steps>
  <Step title="Instala el node de la comunidad">
    En n8n, abre **Settings → Community Nodes → Install**, escribe `n8n-nodes-pilot-status` y confirma. Necesitas un n8n self-hosted (ahí los community nodes vienen activados por defecto). En n8n Cloud, n8n decide qué community nodes se pueden instalar; si este no aparece, usa una instancia self-hosted.
  </Step>
  <Step title="Crea la credencial">
    Agrega una credencial **Pilot Status API** y pega tu clave de API `ps_` del panel.

    Qué otros campos llenar depende del tipo de clave: consulta [Elige la clave de API](#elige-la-clave-de-api) abajo. Deja la **Base URL** por defecto (`https://pilotstatus.com.br`).
  </Step>
  <Step title="Agrega un node Pilot Status">
    Elige un **Resource** (por ejemplo **Message**) y una **Operation** (por ejemplo **Send**). El menú **Template ID** carga las plantillas del número de la credencial.
  </Step>
</Steps>

## Elige la clave de API

Pilot Status tiene tres tipos de clave ([detalles](/es/api/key-types)). La credencial tiene dos campos opcionales, **WhatsApp Number ID** y **Workspace ID**, que se envían en los headers `x-whatsapp-number-id` y `x-workspace-id`. Llénalos según la clave:

| Clave | Prefijo | Dónde crearla | WhatsApp Number ID | Workspace ID |
| --- | --- | --- | --- | --- |
| **Número** | `ps_number_` | Página **API Keys** | Déjalo vacío: la clave ya lleva su número | Déjalo vacío |
| **Workspace** | `ps_workspace_` | **Workspace keys** | Obligatorio para enviar, leer logs o actuar sobre un número | Déjalo vacío |
| **Cuenta** | `ps_account_` | **Profile → API** | Obligatorio para enviar, leer logs o actuar sobre un número | **Obligatorio**: el workspace en el que actúa la clave |

- **Un workflow, un número:** usa una **clave de número**. Solo alcanza ese número, lo que limita el daño si la clave se filtra.
- **Varios números:** usa una **clave de workspace** y crea una credencial por número, cada una con su **WhatsApp Number ID** (el `id` de **Number → Get Many**). Gestionar números (crear, conectar, eliminar) también requiere una clave de workspace.
- **Clave de cuenta:** solo cuando una persona automatiza varios workspaces. Sin **Workspace ID**, cada llamada responde `400 WORKSPACE_ID_REQUIRED`, y la persona dueña de la clave debe ser **Owner** o **Admin** para gestionar webhooks.
- **Trigger con registro Automatic** funciona con los tres tipos. El webhook se crea en el número de la credencial, así que una clave de workspace o de cuenta sin **WhatsApp Number ID** falla al activar con `400 NUMBER_REQUIRED`.

<Warning>
  **Una prueba de credencial verde no demuestra que el envío funcione.** Para una clave de cuenta sin **Workspace ID**, n8n prueba la credencial en `/v1/workspaces`, que no necesita workspace, así que la prueba pasa y el primer **Send** falla. Una clave de workspace sin **WhatsApp Number ID** también pasa la prueba y luego responde `403 TENANT_SCOPE_NOT_ALLOWED` en **Send**.
</Warning>

## Recibe eventos con el Trigger

<Steps>
  <Step title="Agrega el Pilot Status Trigger">
    Deja **Registration** en **Manual** y **Event** en **All Events** (la advertencia de abajo explica por qué).
  </Step>
  <Step title="Registra la URL">
    Copia la **Production URL** del Trigger y agrégala como webhook del número en la página **Webhooks** del panel de Pilot Status. Usa la **Test URL** mientras haces clic en **Listen for test event** en el editor.
  </Step>
  <Step title="Firma las entregas">
    Pega el secreto de firma del webhook en **Signing Secret**. El Trigger responde `401` a cualquier solicitud cuyo `x-pilot-status-signature` no coincida. Sin él, cualquiera que conozca la URL puede iniciar tu workflow.
  </Step>
  <Step title="Activa el workflow">
    La **Production URL** solo recibe eventos mientras el workflow está activo.
  </Step>
</Steps>

El Trigger entrega el cuerpo recibido sin cambios: `$json` es exactamente lo que Pilot Status envió.

### Dos formatos de webhook

Lo que llega depende de cómo se conectó el número ([detalles](/es/api/webhooks/events)):

| Número | Cuerpo que recibe el Trigger | Texto recibido en |
| --- | --- | --- |
| **API Pilot Status (no oficial, código QR)** | Eventos de Pilot Status: `message.received`, `message.reply`, … | `$json.data.content` |
| **Layer Evolution GO (no oficial)** | Eventos de Evolution GO: `Message`, `SendMessage`, `Receipt`, … | `$json.data.Message.conversation` |
| **Layer Evolution v2 (no oficial)** | Eventos de Evolution v2: `messages.upsert`, `messages.update`, … | `$json.data.message.conversation` |
| **Meta Cloud API (oficial)** | Sobre nativo de Meta: `{ object, entry }` | `$json.entry[0].changes[0].value.messages[0].text.body` |

<Warning>
  **En un número oficial, elige All Events.** El sobre de Meta no tiene el campo `event`, así que un Trigger configurado con un evento específico, como **Message Reply**, responde `200 Ignored event` a cada mensaje y el workflow nunca se ejecuta. Por el mismo motivo, no uses el registro **Automatic** con un evento `message.*` en un número oficial: Pilot Status descarta los nombres de evento que el número no emite, así que el webhook se crea con la lista vacía y no entrega nada.
</Warning>

<Warning>
  **Una respuesta llega como `message.reply`, no como `message.received`.** En un número por código QR, un mensaje que cita otro, incluido el toque en un botón de plantilla, dispara solo `message.reply`. Un Trigger en **Message Received** nunca ve los toques en botones.
</Warning>

Para no escribir cada workflow cuatro veces, los workflows de abajo empiezan con un node Code **Normalize**. Convierte los cuatro formatos en el mismo ítem plano:

| Campo | Significado |
| --- | --- |
| `source` | `pilot-status`, `evolution-go`, `evolution-v2` o `meta` |
| `isInbound` | `true` solo para un mensaje que envió el contacto. Los estados y el eco de tus propios envíos son `false` |
| `from` | el número del contacto en E.164 (`+5511999999999`) |
| `name` | el nombre del contacto en WhatsApp, cuando se conoce |
| `text` | texto del mensaje, o la etiqueta del botón o de la fila de lista tocada |
| `buttonId` | id o payload del botón o de la fila de lista tocada, cuando WhatsApp lo informa |
| `quotedMessageId` | el mensaje respondido, cuando lo hay |

```javascript Normalize (node Code)
// Turns every webhook format into the same flat item:
// - Pilot Status API (QR code) numbers send { event, data }
// - Evolution GO layer numbers send Evolution GO events ("Message", "SendMessage", ...)
// - Evolution v2 layer numbers send Evolution v2 events ("messages.upsert", ...)
// - Meta Cloud API (official) numbers send Meta's native envelope { object, entry }
const phoneOf = (jid) =>
  typeof jid === 'string' && jid.endsWith('@s.whatsapp.net') ? '+' + jid.split('@')[0].split(':')[0] : '';

// Evolution GO and v2 carry the same WhatsApp message object
const readWaMessage = (m = {}) => ({
  text:
    m.conversation ??
    m.extendedTextMessage?.text ??
    m.buttonsResponseMessage?.selectedDisplayText ??
    m.templateButtonReplyMessage?.selectedDisplayText ??
    m.listResponseMessage?.title ??
    m.imageMessage?.caption ??
    m.videoMessage?.caption ??
    '',
  buttonId:
    m.buttonsResponseMessage?.selectedButtonId ??
    m.templateButtonReplyMessage?.selectedId ??
    m.listResponseMessage?.singleSelectReply?.selectedRowId ??
    '',
  quotedMessageId:
    m.extendedTextMessage?.contextInfo?.stanzaId ??
    m.buttonsResponseMessage?.contextInfo?.stanzaId ??
    m.templateButtonReplyMessage?.contextInfo?.stanzaId ??
    m.listResponseMessage?.contextInfo?.stanzaId ??
    '',
});

return $input.all().map(({ json }) => {
  // Meta Cloud API (official)
  if (json.entry) {
    const value = json.entry[0]?.changes?.[0]?.value ?? {};
    const msg = value.messages?.[0];
    return {
      json: {
        source: 'meta',
        isInbound: Boolean(msg),
        from: msg ? '+' + msg.from : '',
        name: value.contacts?.[0]?.profile?.name ?? '',
        text:
          msg?.text?.body ??
          msg?.button?.text ??
          msg?.interactive?.button_reply?.title ??
          msg?.interactive?.list_reply?.title ??
          '',
        buttonId:
          msg?.button?.payload ??
          msg?.interactive?.button_reply?.id ??
          msg?.interactive?.list_reply?.id ??
          '',
        quotedMessageId: msg?.context?.id ?? '',
      },
    };
  }

  // Evolution v2 layer
  if (json.event === 'messages.upsert') {
    const d = json.data ?? {};
    const jid = d.key?.remoteJidAlt || d.key?.remoteJid;
    const from = phoneOf(jid);
    return {
      json: {
        source: 'evolution-v2',
        isInbound: Boolean(from) && !d.key?.fromMe,
        from,
        name: d.pushName ?? '',
        ...readWaMessage(d.message),
      },
    };
  }

  // Evolution GO layer
  if (json.event === 'Message' || json.event === 'MESSAGES_UPSERT') {
    const info = json.data?.Info ?? {};
    const from = phoneOf(info.Chat) || phoneOf(info.SenderAlt);
    return {
      json: {
        source: 'evolution-go',
        isInbound: Boolean(from) && !info.IsFromMe && !info.IsGroup,
        from,
        name: info.PushName ?? '',
        ...readWaMessage(json.data?.Message),
      },
    };
  }

  // Pilot Status API (QR code)
  const data = json.data ?? {};
  return {
    json: {
      source: 'pilot-status',
      isInbound: ['message.received', 'message.reply'].includes(json.event) && !data.fromMe,
      from: data.from ?? '',
      name: data.participantName ?? '',
      text: data.content ?? '',
      buttonId: data.buttonId ?? '',
      quotedMessageId: data.quotedMessageId ?? '',
    },
  };
});
```

## Importa un workflow

1. Copia el JSON de una receta.
2. En n8n, abre un workflow vacío y presiona **Ctrl+V** (**Cmd+V** en macOS) sobre el canvas. También puedes guardar el JSON en un archivo y usar **⋯ → Import from File**.
3. Abre cada node de Pilot Status, Google Sheets, OpenAI y correo y selecciona tu credencial.
4. Cambia los valores de ejemplo: nombres de plantilla, números de teléfono, id de la hoja, direcciones de correo.

<Note>
  El workflow responde **desde el número de la credencial**. Registra la URL del Trigger en ese mismo número: si el webhook es del número A y la credencial del número B, el contacto escribe a A y recibe la respuesta desde B.
</Note>

## Receta 1: plantilla con botones, respuesta al tocar

Envías una plantilla aprobada con dos botones de respuesta rápida, **Confirmar** y **Reprogramar**. Cuando el contacto toca uno, el workflow responde con un mensaje distinto para cada botón.

- **Start → Send template** envía la plantilla. Cambia el Manual Trigger por lo que inicia tu flujo (un formulario, un CRM, una programación).
- **Pilot Status Trigger → Normalize → Which button?** enruta el toque por la **etiqueta** del botón. La etiqueta funciona en todo tipo de número; el `buttonId` no siempre llega en botones de plantilla.
- **Reply: …** responde con texto libre. El toque abre la ventana de atención de 24 horas de WhatsApp, así que la respuesta en texto libre está permitida incluso en un número oficial.

Qué cambiar: el `templateId` (`appointment_confirmation`), el número de destino, las variables y las dos etiquetas en **Which button?**, que deben ser iguales a los botones de la plantilla (no distingue mayúsculas de minúsculas).

## Receta 2: un agente de IA responde los mensajes recibidos

Cada texto que envía un contacto va a un AI Agent de n8n con memoria por contacto, y la respuesta vuelve por WhatsApp.

- **Inbound text?** deja pasar solo los mensajes que envió el contacto. Sin él, el eco de la propia respuesta del agente volvería a iniciar el workflow.

Qué cambiar: el mensaje de sistema del **AI Agent**, el modelo y la credencial de OpenAI (o cambia el node de modelo por cualquier otro modelo de chat).

## Receta 5: guardar las respuestas de un WhatsApp Flow en una hoja

Cada vez que alguien envía un [WhatsApp Flow](/es/guides/flow-responses), las respuestas se convierten en una fila nueva de una hoja de Google.

`flow.response_received` mantiene el formato `{ event, data }` de Pilot Status incluso en números oficiales, así que aquí el Trigger puede escuchar solo ese evento y no hace falta el node Normalize.

- **Answers to columns** guarda la hora, el número del contacto, el id del Flow y las respuestas como texto JSON. En un Flow con endpoint de datos, lo que escribió la persona está en `submitted`, una entrada por pantalla; en los demás, está en `response`.
- **Append to sheet** escribe una fila por envío. Crea una pestaña llamada **Respuestas del Flow** con las columnas `receivedAt`, `phone`, `flowId` y `answers`.

Qué cambiar: `YOUR_SPREADSHEET_ID`. Para tener una columna por pregunta, cambia el campo `answers` por un campo por respuesta, por ejemplo `{{ $json.data.response.nota }}`.

## Solución de problemas

| Síntoma | Causa | Solución |
| --- | --- | --- |
| El Trigger nunca se dispara | El workflow está inactivo (Production URL), o el webhook se registró con la Test URL | Activa el workflow y registra la **Production URL** |
| El Trigger responde `200 Ignored event` | **Event** está en un evento específico, y el cuerpo entregado es otro evento o el sobre de Meta | Usa **All Events** y filtra en el workflow |
| Tocar un botón no hace nada en un número por código QR | El Trigger escucha **Message Received** | Los toques llegan como `message.reply`: usa **All Events** |
| `$json.data` es `undefined` | El número es oficial, y el cuerpo es el sobre de Meta | Agrega el node **Normalize** |
| `401 Invalid signature` | El **Signing Secret** no coincide con el webhook | Pega el secreto actual, o rótalo y pega el nuevo |
| `403 TENANT_SCOPE_NOT_ALLOWED` | Clave de workspace o de cuenta sin número | Llena el **WhatsApp Number ID** en la credencial |
| `400 WORKSPACE_ID_REQUIRED` | Clave de cuenta (`ps_account_`) sin workspace | Llena el **Workspace ID** en la credencial |
| El registro Automatic falla con `400 NUMBER_REQUIRED` | Clave de workspace o de cuenta sin número | Llena el **WhatsApp Number ID** en la credencial |
| La respuesta sale desde otro número | El webhook y la credencial son de números distintos | Usa el mismo número en los dos |
