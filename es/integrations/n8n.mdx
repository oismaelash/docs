El node oficial de la comunidad `n8n-nodes-pilot-status` agrega dos nodes a n8n:

- **Pilot Status**: llama a la API pública `/v1` para enviar mensajes y plantillas, listar logs y gestionar números, plantillas, Flows, grupos y más.
- **Pilot Status Trigger**: recibe los eventos de tu webhook e inicia un workflow.

Esta página muestra cómo configurar los dos e incluye cinco workflows para importar y adaptar. Cada workflow se importó en n8n y se comprobó contra la definición de los nodes, y su lógica de enrutamiento se ejecutó con payloads de ejemplo de los dos formatos de webhook.

## Instala el node

<Steps>
  <Step title="Instala el node de la comunidad">
    En n8n, abre **Settings → Community Nodes → Install**, escribe `n8n-nodes-pilot-status` y confirma. Necesitas un n8n self-hosted (ahí los community nodes vienen activados por defecto). En n8n Cloud, n8n decide qué community nodes se pueden instalar; si este no aparece, usa una instancia self-hosted.
  </Step>
  <Step title="Crea la credencial">
    Agrega una credencial **Pilot Status API** y pega tu clave de API `ps_` del panel.

    - Una clave **por número** no necesita nada más: cada llamada sale desde ese número.
    - Una clave **de la cuenta** necesita también el **WhatsApp Number ID**, que se envía en el header [`x-whatsapp-number-id`](/es/api/authentication). Sin él, las llamadas que actúan sobre un número fallan con `403 TENANT_SCOPE_NOT_ALLOWED`.
    - Deja la **Base URL** por defecto (`https://pilotstatus.com.br`).
  </Step>
  <Step title="Agrega un node Pilot Status">
    Elige un **Resource** (por ejemplo **Message**) y una **Operation** (por ejemplo **Send**). El menú **Template ID** carga las plantillas del número de la credencial.
  </Step>
</Steps>

## Recibe eventos con el Trigger

<Steps>
  <Step title="Agrega el Pilot Status Trigger">
    Deja **Registration** en **Manual** y **Event** en **All Events** (la advertencia de abajo explica por qué).
  </Step>
  <Step title="Registra la URL">
    Copia la **Production URL** del Trigger y agrégala como webhook del número en la página **Webhooks** del panel de Pilot Status. Usa la **Test URL** mientras haces clic en **Listen for test event** en el editor.
  </Step>
  <Step title="Firma las entregas">
    Pega el secreto de firma del webhook en **Signing Secret**. El Trigger responde `401` a cualquier solicitud cuyo `x-pilot-status-signature` no coincida. Sin él, cualquiera que conozca la URL puede iniciar tu workflow.
  </Step>
  <Step title="Activa el workflow">
    La **Production URL** solo recibe eventos mientras el workflow está activo.
  </Step>
</Steps>

El Trigger entrega el cuerpo recibido sin cambios: `$json` es exactamente lo que Pilot Status envió.

### Dos formatos de webhook

Lo que llega depende de cómo se conectó el número ([detalles](/es/api/webhooks/events)):

| Número | Cuerpo que recibe el Trigger | Ejemplo de campo |
| --- | --- | --- |
| **Código QR (no oficial)** | Eventos de Pilot Status: `{ event, data }` | `$json.data.content` |
| **Meta Cloud API (oficial)** | Sobre nativo de Meta: `{ object, entry }` | `$json.entry[0].changes[0].value.messages[0].text.body` |

<Warning>
  **En un número oficial, elige All Events.** El sobre de Meta no tiene el campo `event`, así que un Trigger configurado con un evento específico, como **Message Reply**, responde `200 Ignored event` a cada mensaje y el workflow nunca se ejecuta. Por el mismo motivo, no uses el registro **Automatic** con un evento `message.*` en un número oficial: Pilot Status descarta los nombres de evento que el número no emite, así que el webhook se crea con la lista vacía y no entrega nada.
</Warning>

<Warning>
  **Una respuesta llega como `message.reply`, no como `message.received`.** En un número por código QR, un mensaje que cita otro, incluido el toque en un botón de plantilla, dispara solo `message.reply`. Un Trigger en **Message Received** nunca ve los toques en botones.
</Warning>

Para no escribir cada workflow dos veces, las recetas de abajo empiezan con un node Code **Normalize**. Convierte los dos formatos en el mismo ítem plano:

| Campo | Significado |
| --- | --- |
| `source` | `canonical` (número por código QR) o `meta` (número oficial) |
| `isInbound` | `true` solo para un mensaje que envió el contacto. Los estados y el eco de tus propios envíos son `false` |
| `from` | el número del contacto en E.164 (`+5511999999999`) |
| `name` | el nombre del contacto en WhatsApp, cuando se conoce |
| `text` | texto del mensaje, o la etiqueta del botón o de la fila de lista tocada |
| `buttonId` | id o payload del botón o de la fila de lista tocada, cuando WhatsApp lo informa |
| `quotedMessageId` | el mensaje respondido, cuando lo hay |

```javascript Normalize (node Code)
// Turns both webhook formats into the same flat item:
// - QR-code (unofficial) numbers send { event, data }
// - Meta Cloud API (official) numbers send Meta's native envelope { object, entry }
return $input.all().map(({ json }) => {
  if (json.entry) {
    const value = json.entry[0]?.changes?.[0]?.value ?? {};
    const msg = value.messages?.[0];
    return {
      json: {
        source: 'meta',
        isInbound: Boolean(msg),
        from: msg ? '+' + msg.from : '',
        name: value.contacts?.[0]?.profile?.name ?? '',
        text:
          msg?.text?.body ??
          msg?.button?.text ??
          msg?.interactive?.button_reply?.title ??
          msg?.interactive?.list_reply?.title ??
          '',
        buttonId:
          msg?.button?.payload ??
          msg?.interactive?.button_reply?.id ??
          msg?.interactive?.list_reply?.id ??
          '',
        quotedMessageId: msg?.context?.id ?? '',
      },
    };
  }
  const data = json.data ?? {};
  return {
    json: {
      source: 'canonical',
      isInbound: ['message.received', 'message.reply'].includes(json.event) && !data.fromMe,
      from: data.from ?? '',
      name: data.participantName ?? '',
      text: data.content ?? '',
      buttonId: data.buttonId ?? '',
      quotedMessageId: data.quotedMessageId ?? '',
    },
  };
});
```

## Importa un workflow

1. Copia el JSON de una receta.
2. En n8n, abre un workflow vacío y presiona **Ctrl+V** (**Cmd+V** en macOS) sobre el canvas. También puedes guardar el JSON en un archivo y usar **⋯ → Import from File**.
3. Abre cada node de Pilot Status, Google Sheets, OpenAI y correo y selecciona tu credencial.
4. Cambia los valores de ejemplo: nombres de plantilla, números de teléfono, id de la hoja, direcciones de correo.

<Note>
  El workflow responde **desde el número de la credencial**. Registra la URL del Trigger en ese mismo número: si el webhook es del número A y la credencial del número B, el contacto escribe a A y recibe la respuesta desde B.
</Note>

## Receta 1: plantilla con botones, respuesta al tocar

## Receta 2: un agente de IA responde los mensajes recibidos

Cada texto que envía un contacto va a un AI Agent de n8n con memoria por contacto, y la respuesta vuelve por WhatsApp.

- **Inbound text?** deja pasar solo los mensajes que envió el contacto. Sin él, el eco de la propia respuesta del agente volvería a iniciar el workflow.
- **Memory per contact** usa el número del contacto como clave de sesión, así que cada conversación tiene su propio historial.
- **Send answer** envía `$json.output`, la respuesta del agente, como texto libre. Es una respuesta dentro de la ventana de 24 horas que el contacto acaba de abrir.

Qué cambiar: el mensaje de sistema del **AI Agent**, el modelo y la credencial de OpenAI (o cambia el node de modelo por cualquier otro modelo de chat).

<Tip>
  Los mensajes de grupo llegan como `message.group` y no se tratan aquí, así que el agente no responde en grupos.
</Tip>

## Receta 3: enviar una plantilla a cada fila de una hoja

Todos los días a las 9:00, el workflow lee una hoja de Google, envía una plantilla a cada fila que aún no se envió y escribe en la fila la hora del envío.

Crea una pestaña llamada **Contactos** con estas columnas:

| `phone` | `name` | `orderId` | `sent` |
| --- | --- | --- | --- |
| `+5511999999999` | Ana | `A-1001` | |

- **Not sent yet?** salta las filas con la columna `sent` llena.
- **Send template** pasa `name` y `orderId` como variables de la plantilla. Las claves del JSON deben ser iguales a los nombres de las variables de la plantilla.
- **Idempotency Key** es `orderId-phone`. Cuando n8n reintenta el node (está configurado con 3 intentos), o el workflow se ejecuta de nuevo antes de que se actualice la hoja, la API devuelve la primera respuesta en lugar de enviar dos veces. ## Receta 4: alerta por correo de mensajes fallidos

Cada 15 minutos, el workflow lista los últimos 100 mensajes enviados que fallaron y avisa por correo al equipo de cada uno que no había visto antes.

## Solución de problemas

| Síntoma | Causa | Solución |
| --- | --- | --- |
| El Trigger nunca se dispara | El workflow está inactivo (Production URL), o el webhook se registró con la Test URL | Activa el workflow y registra la **Production URL** |
| El Trigger responde `200 Ignored event` | **Event** está en un evento específico, y el cuerpo entregado es otro evento o el sobre de Meta | Usa **All Events** y filtra en el workflow |
| Tocar un botón no hace nada en un número por código QR | El Trigger escucha **Message Received** | Los toques llegan como `message.reply`: usa **All Events** |
| `$json.data` es `undefined` | El número es oficial, y el cuerpo es el sobre de Meta | Agrega el node **Normalize** |
| `401 Invalid signature` | El **Signing Secret** no coincide con el webhook | Pega el secreto actual, o rótalo y pega el nuevo |
| `403 TENANT_SCOPE_NOT_ALLOWED` | Clave de la cuenta sin número | Llena el **WhatsApp Number ID** en la credencial |
| La respuesta sale desde otro número | El webhook y la credencial son de números distintos | Usa el mismo número en los dos |
