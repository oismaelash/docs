Esta página es para **agentes de IA y desarrolladores** que necesitan autenticarse en Pilot Status (API de mensajería de WhatsApp). Es autosuficiente: todo lo que un agente necesita para obtener y usar una credencial está aquí.

## Obtener una credencial

No hay registro automático por la API. Una persona crea la cuenta y la clave:

1. Regístrate en [https://pilotstatus.com.br](https://pilotstatus.com.br).
2. En el panel, abre **Claves de API** y crea una clave. Las claves empiezan con `ps_` (por ejemplo `ps_workspace_...`, `ps_number_...`, `ps_account_...`).
3. Guarda la clave como secreto (variable de entorno, bóveda). Se muestra una sola vez.

Consulta [Claves de API en el panel](/es/dashboard/api-keys) y [Tipos de clave](/es/concepts/key-types).

## Métodos

### API REST: `x-api-key`

URL base: `https://pilotstatus.com.br/v1`. Envía la clave en el encabezado `x-api-key`.

```bash
curl https://pilotstatus.com.br/v1/numbers \
  -H "x-api-key: ps_tu_clave"
```

Detalles: [Autenticación de la API](/es/api/authentication).

### Servidor MCP: `x-api-key` o `Authorization: Bearer`

Endpoint: `https://mcp.pilotstatus.com.br/mcp` (Streamable HTTP). Acepta la clave `ps_` en cualquiera de los encabezados:

```http
x-api-key: ps_tu_clave
```

```http
Authorization: Bearer ps_tu_clave
```

Detalles: [Servidor MCP](/es/integrations/mcp-server).

### OAuth 2.1 para conectores MCP

Los clientes MCP que no guardan una clave fija (por ejemplo los conectores de claude.ai o ChatGPT) usan OAuth 2.1:

- Metadatos del servidor de autorización: `https://pilotstatus.com.br/.well-known/oauth-authorization-server`
- Registro dinámico de clientes (RFC 7591): `POST https://pilotstatus.com.br/api/oauth/register`
- Flujo authorization code con **PKCE `S256`** (clientes públicos, `token_endpoint_auth_method: none`)
- Grant types: `authorization_code`, `refresh_token`

El usuario inicia sesión y da su consentimiento en el navegador; luego el conector envía `Authorization: Bearer <access_token>` al servidor MCP.

#### Scopes

| Scope | Permite |
|---|---|
| `messages:send` | Enviar mensajes |
| `messages:read` | Leer logs y contenido de mensajes |
| `conversations:read` | Leer conversaciones |
| `numbers:read` | Listar y leer números |
| `numbers:write` | Actualizar números |
| `templates:read` | Leer plantillas |
| `templates:write` | Crear y gestionar plantillas |
| `analytics:read` | Leer analytics |
| `flows:read` | Leer WhatsApp Flows |

Nunca se emite un token con un scope que el rol del miembro que consintió no tenga.

## Usar la credencial

- Envíala en cada solicitud; no hay sesiones ni cookies.
- `401` significa credencial ausente, inválida, revocada o expirada. Los clientes OAuth deben renovar o volver a autorizar.
- `403` significa credencial válida, pero sin permiso para esa acción.
- Nunca pongas la clave en código del navegador, URLs o logs. Si se expone, genera otra en el panel.
