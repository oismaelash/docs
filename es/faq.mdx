Ya sea que estés evaluando Pilot Status por primera vez o quieras ampliar una integración existente, las respuestas a continuación cubren las preguntas que nuestros usuarios hacen con más frecuencia. Si no encuentras lo que necesitas aquí, el equipo siempre está disponible por WhatsApp.

<AccordionGroup>
  <Accordion title="¿Qué es Pilot Status?">
    Pilot Status es una plataforma de infraestructura de WhatsApp creada para desarrolladores y equipos de producto. Gestiona todo lo que es difícil de operar con WhatsApp a escala (conexiones persistentes, rotación de proxies, manejo de sesiones y entrega) para que puedas enfocarte en tu producto en lugar de tu infraestructura.

    Interactúas con Pilot Status mediante una API REST estándar y recibes eventos en tiempo real a través de webhooks. El panel le da a tu equipo una interfaz visual para gestionar números, consultar logs y chatear en vivo con los contactos.
  </Accordion>

  <Accordion title="¿Necesito un servidor o VPS para usar Pilot Status?">
    No. Pilot Status ejecuta y gestiona toda la infraestructura por ti. No hay servidores que aprovisionar, ni sesiones de WhatsApp que mantener activas, ni proxies que configurar. Envías solicitudes a la API y recibes webhooks: esa es toda la interfaz. Esto también significa que obtienes redundancia y gestión de disponibilidad integradas sin ningún esfuerzo de DevOps de tu parte.
  </Accordion>

  <Accordion title="¿Cuál es la diferencia entre la API oficial y la no oficial de WhatsApp?">
    La **API oficial** (Meta Cloud API) está respaldada directamente por Meta. Requiere una cuenta de WhatsApp Business verificada, usa plantillas de mensaje aprobadas por Meta para las conversaciones salientes y ofrece las mayores garantías de entregabilidad y cumplimiento. Es la opción correcta para industrias reguladas o mensajería de marketing y transaccional a gran escala.

    La **API no oficial** se conecta escaneando un código QR, igual que WhatsApp Web. No requiere una cuenta de Meta Business, admite tipos de mensaje más flexibles y es más rápida de configurar. No está respaldada oficialmente por Meta, por lo que es más adecuada para herramientas internas, prototipos y productos en los que el proceso de aprobación de Meta no es un requisito.

    Pilot Status admite ambas: todos los planes incluyen conexiones Meta Cloud API y Coexistence junto con la API no oficial (los cargos por mensaje de Meta, con precio según la categoría del mensaje, los factura Meta por separado; consulta los [precios de WhatsApp de Meta](https://developers.facebook.com/docs/whatsapp/pricing)).
  </Accordion>

  <Accordion title="¿Puedo migrar desde otro proveedor sin reescribir código?">
    Sí. Pilot Status incluye una **API Layer** compatible con los formatos de API de WhatsApp más comunes. Para migrar, cambias la URL base de tu integración existente para que apunte a Pilot Status: la estructura de tus solicitudes, el patrón de autenticación y tu manejador de webhooks siguen iguales. La mayoría de los equipos completa una migración en menos de una hora.
  </Accordion>

  <Accordion title="¿Hay un plan gratuito?">

Está pensado para evaluación y desarrollo en etapa temprana. Cuando estés listo para producción, puedes pasar a un plan de pago directamente desde el panel. Consulta la página de [Planes](/es/plans) para ver la comparación completa.
  </Accordion>

  <Accordion title="¿Mis datos y los mensajes de mis usuarios están seguros?">
    Sí. Los mensajes enviados a través de Pilot Status viajan con el cifrado de extremo a extremo de WhatsApp, el mismo cifrado que protege todas las conversaciones de WhatsApp. Pilot Status guarda logs de mensajes para que tengas un historial auditable, y puedes controlar o desactivar ese almacenamiento por número con los [modos de retención de PII](/es/trust/data-retention).

    Tus API keys están limitadas a tus números y deben mantenerse privadas. Puedes regenerarlas en cualquier momento desde la página **API Keys** del panel.
  </Accordion>

  <Accordion title="¿Recibo los eventos de mensajes en tiempo real?">
    Sí. Pilot Status dispara eventos de webhook en milisegundos tras cada evento de mensaje: mensajes entrantes, confirmaciones de entrega (enviado, entregado, leído) y cambios de estado de la conexión. Creas webhooks en la página **Webhooks** del panel (o mediante `POST /v1/webhooks`), y Pilot Status envía una solicitud POST a tu URL cada vez que ocurre un evento al que estás suscrito. Para ver los detalles completos del payload, consulta la documentación de [Webhooks](/es/concepts/webhooks).
  </Accordion>

  <Accordion title="¿Puedo enviar botones o listas sin plantilla (para un chatbot)?">
    Sí. Los botones de respuesta (hasta 3) y las listas de selección única (hasta 10 filas) son **mensajes de servicio de formato libre** en `POST /v1/messages/send`: sin plantilla y sin aprobación de Meta. En números oficiales (Meta Cloud API) solo se entregan dentro de la ventana de servicio de 24 horas, que siempre está abierta cuando tu bot responde a un cliente que acaba de escribir. La elección del cliente vuelve en tu webhook. Consulta [Chatbots con botones y listas](/es/guides/interactive-messages).
  </Accordion>

  <Accordion title="¿Pilot Status funciona con agentes de IA y herramientas de automatización como n8n?">
    Sí. Como Pilot Status expone una API REST estándar y dispara webhooks por HTTP, funciona con cualquier herramienta que pueda hacer solicitudes HTTP o escuchar webhooks. Esto incluye plataformas de automatización como **n8n** (hay un nodo comunitario oficial) y **Make**, frameworks de IA como **LangChain** y **GPT Maker**, y backends a medida construidos en cualquier lenguaje.

    Pilot Status también ofrece un **servidor MCP** alojado en `https://mcp.pilotstatus.com.br/mcp` para frameworks de agentes de IA que admiten el Model Context Protocol. Consulta [Agentes de IA](/es/guides/ai-agents).
  </Accordion>
