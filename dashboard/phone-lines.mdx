Phone lines live under **Phone lines** in the sidebar, right below **Numbers** (keyboard shortcut: `i`), with a **beta** badge. The item shows for **Owner and Admin**; Agent and Analyst do not see lines, because a line's page shows its WhatsApp activation code, and that code is a credential. For the same roles, the **Numbers** page also has a **Phone lines** card, with **Go to phone lines**.

The full walkthrough, from the holder verification to typing the code into WhatsApp, is in the guide [Phone lines: buy one and use it on WhatsApp](/guides/phone-lines).

## Who can do what

| Action | Owner | Admin | Agent / Analyst |
| --- | --- | --- | --- |
| See the lines, open a line, read the activation code and the code history, listen to recordings | Yes | Yes | No |
| **Wait for a new code**, **Cancel wait**, **Edit name** | Yes | Yes | No |
| Holder verification and **Buy a line** | Yes | No — the empty list says **Only the workspace owner can buy lines.** | No |
| **Add balance**, **Pay … now**, **Pay for all**, **Choose which to keep** | Yes | No — sees **Only the workspace owner can pay or choose which lines to keep.** | No |
| **Cancel line**, **Return number**, **Undo cancellation** | Yes | No | No |
| **Line webhooks** (create, edit, pause, delete, see deliveries) | Yes | Yes | No |

The permissions behind it: `phone_lines:read` and `phone_lines:webhooks` (Admin and up), `phone_lines:purchase`, `phone_lines:cancel` and `billing:wallet:topup` (Owner only).

## Lines list

The **Phone lines** page (`/linhas`) lists the lines that are still yours — active, payment due, or suspended. A returned or cancelled line leaves the list. With no lines yet, the page shows **No lines yet** and, for the Owner, a **Buy a line · …/month** button with **Billed monthly · cancel anytime**; other roles see **Only the workspace owner can buy lines.** If the list cannot be loaded, the page says **Could not load. Try again.**, with **Try again**.

At the top are **Line webhooks** and, once you have lines, **Buy a line**, and a summary such as **3 lines · 1 needs attention**. The list starts with what needs action: suspended lines first, then payment due, then cancellation scheduled, and the rest by renewal date. Each row has a copy button that copies the number with the country code (`+55…`).

Each line shows its name (or its number, if it has no name), its area code, and one of these statuses:

| Status | What the line shows |
| --- | --- |
| **Active** | The next renewal date and how many codes the line has requested. |
| **Payment due** | The date the renewal failed. The line still receives codes. |
| **Suspended** | The suspension date. The line does not receive new codes. |
| **Cancellation scheduled** | Until when the line stays active. |

A line's page can also show **Returned** and **Canceled**, the two final statuses.

### Notices at the top of the list

- **Unpaid lines** — a red notice (**One line needs payment**, or **… lines are suspended or unpaid**) says by when to settle. For the Owner, it has **Add balance**, **Pay for all** and, when more than one line is overdue, **Choose which to keep**; an Admin sees the notice with **Only the workspace owner can pay or choose which lines to keep.** See [Phone line pricing and billing](/phone-lines-pricing#overdue-lines).
- **Your verification is under review** — you can already use your lines normally while Pilot Status checks the document. If the check does not pass, the lines bought during the review go back to the carrier and what you paid for them returns to your wallet as balance.
- **We need another document to finish the account holder verification.** — **Send document** takes you back to the verification.
- **The account holder verification was rejected.** — the lines bought during the review go back to the carrier 3 days after the rejection, and what you paid for them returns as wallet balance; until then they stay active and do not renew. New lines cannot be bought — **Buy a line** says so and points you to support (**Talk to support**). See the [guide](/guides/phone-lines#step-by-step).

The verification notices only show for the Owner.

### Pay for all (retry the charge)

**Pay for all** charges every overdue line again, right away: first from the wallet balance, then the saved card for any shortfall. The result appears as a message — **… lines paid. They stay active.**, or **… lines could not be charged. Add balance or check your card.** It does not open a dialog. There is no automatic "retry" button beyond this: the same retry exists per line on its page (**Pay … now**).

## Buying lines

**Buy a line** opens **Buy phone lines** (`/linhas/comprar`), in three steps shown at the top: **Verification**, **Numbers**, **Confirm**. Only the Owner can buy.

### Step 1 — Verification

**Confirm who the account holder is.** This step only shows on the first purchase, while the account holder is not verified. A phone line is a regulated service, and the holder is checked once.

1. **You are buying as** — **Company · CNPJ** or **Individual · CPF**.
   - **CNPJ**: looked up in the federal registry. The CNPJ may be alphanumeric (the new Receita format, for example `12.ABC.345/01DE-35`); type it as on the CNPJ card. The screen shows **Checking the registry…** and then **Active · checked in the federal registry**. An inactive CNPJ is refused (**This CNPJ is not active in the federal registry.**); an unknown one gets **CNPJ not found in the federal registry.** If the registry cannot be reached, the purchase goes ahead and the document is checked by hand.
   - **CPF**: the check is done on the document. The summary then reads **Individual: the check is done on the document.** or, when the CPF was also checked at the Receita, **Individual: we checked the document and the CPF at the Receita.**
2. **Holder WhatsApp number** — with a country selector (Brazil preselected). For Brazil, type the area code and the number. It receives a 6-digit code.

   **Continue** stays disabled until the document number and the WhatsApp number are complete. A malformed document or phone gets **The document or WhatsApp number is not valid.**
3. **Document** — drag the file or click to choose: for a CNPJ, the **CNPJ card, articles of incorporation or registration proof**; for a CPF, an **ID card (RG), driver license (CNH) or CPF registration proof**. **PDF, JPG, PNG or WEBP, up to 10 MB.** Any other type is refused before upload (**Send a PDF, JPG, PNG or WEBP file.**), and so is a bigger file (**The file is larger than 10 MB.**). The dashboard reads the number on the document (**Reading the document… Do not close this page.**). If it finds no number, or cannot read it reliably, it says so and shows the upload area again so you can send a sharper file. Once received, the document shows as **Document received**, with **Replace**.
4. **Contacts** — a 6-digit code goes to the holder's **WhatsApp number**, sent from the Pilot Status WhatsApp (**We sent a 6-digit code to …, from the Pilot Status WhatsApp.**). A code also goes to the **e-mail of your account** (the signed-in user) when that e-mail is not verified yet; a verified e-mail just shows **Confirmed**. Type each code and click **Confirm**. **Did not get it? Resend code** sends a new one; after each send there is a 60-second countdown (**Resend in …**). Codes are valid for **10 minutes**; after 5 wrong attempts you need a new code. If there is no WhatsApp sender available, the code goes by e-mail and the WhatsApp number is recorded unconfirmed (**The code went by email because there is no WhatsApp sender yet. Your WhatsApp number is recorded, unconfirmed.**).

   The code messages: **Wrong code. Check the 6 digits.**, **This code has expired: it is valid for 10 minutes. Ask for a new one.** (the resend is offered right away), **Too many wrong attempts. Ask for a new code.** and **Wait a moment before asking for another code.**

<Note>
  The contact code only confirms who you are. It is **not** the WhatsApp activation code, which arrives by phone call on the line itself.
</Note>

When the contacts are confirmed, the verification is either approved or **Verification under review: you can already buy** — you buy and use the lines while the document is checked by hand. A rejected verification shows **The account holder verification was rejected** — **New lines cannot be bought with this verification. Talk to support to understand why.** — with **Talk to support**, and blocks new purchases. While the contact codes are still pending, **Fix details** reopens the form so you can change the document or the WhatsApp number.

### Step 2 — Numbers

**Pick the numbers.** Choose the **Area code** (area code 11 is preselected; type an area code, a state abbreviation or a state name to filter the list, which shows each state's name), click **Search numbers** and select up to **10** numbers (**… of 10 picked**). The search only runs when you click the button. They are landlines: they receive the WhatsApp code call, and they do not place calls or receive SMS. If an area code has no stock, the screen says **No number available in area code … right now. Try another area code.**

The picked numbers show as chips you can remove. At 10, the other numbers are disabled and the screen says **Limit of 10 numbers per purchase. For more, make another purchase after this one.** A **Continue** bar stays at the top of the panel while you scroll, with the total (**Continue · …**).

### Step 3 — Confirm

**Confirm the purchase.** It shows the price per line (**…/month**, the same on every plan and for any quantity), **Total now · … lines** and **Buy … lines · …**. Each line renews every month on the purchase day; the first month is charged in full, with no proration. The amount comes out of the wallet balance, and the saved card covers any shortfall. **Back** returns to the numbers.

After you click **Buy**, the screen shows **Buying: … of … done** and each number's result as it settles (**Buying…** while it runs). Each number can take up to a minute and a half, and you can leave the page: the purchase goes on and the lines show up in the list. The page address keeps the purchase, so reloading it, or coming back to it, reopens the results. If that purchase cannot be found, the wizard goes back to the numbers with **We couldn't find that purchase. Pick the numbers again to continue.**

At the end: **Done! Your … lines are active** or **… of … purchases completed**, with **Open line** for each line bought, **Go to phone lines** and, when something failed, **Pick other numbers** (it keeps selected the failed numbers worth another try, and drops the ones no longer available). A failed number shows why, for example:

- **This number is no longer available. Pick another one.**
- **The payment did not go through. Add balance or check your card.**
- **Phone lines are temporarily unavailable. Try again in a few minutes.**
- **The card processor did not answer, so we cannot tell whether your card was charged. Your wallet was not debited; check your card statement before trying again.**
- **The purchase could not be completed. The amount charged was returned to your wallet as balance.**
- **The purchase of this number was interrupted. If you were charged for it, our team returns the amount; check your lines and your wallet statement.**

When a number fails because it was no longer available or because phone lines were unavailable, the results add **If a number that failed was already charged, the amount went back to your wallet balance.**

### Add balance to finish the purchase

If a number fails for lack of balance, the **Add balance to finish the purchase** dialog opens by itself for the Owner; **Add balance and try again** reopens it. It shows the **Total** of the refused numbers, the **Wallet balance** and the **Amount to add**: the shortfall, raised to the minimum top-up of 1 (R$ 1.00 on a BRL account) when it is smaller (**The minimum top-up is …. Anything left over stays in the wallet.**). If the balance already covers the numbers, it says **Your balance already covers the purchase. Try again.** Under **How to pay**:

- **Pix (instant)** — only for BRL accounts; on any other account the option is not offered and the dialog says **Pix is available only for BRL accounts.** **Create a … Pix** shows the **Pix QR code** and **Copy Pix code** (the copy-and-paste code). Pay it in your bank app. The dialog keeps checking the balance; **I have paid** checks right away. Until the payment is confirmed it says **We have not received the Pix confirmation yet. If you have paid, wait a moment.** The dialog does not show an expiry time for the Pix.
- **Credit card** — **Pay … by card**. With a saved card, choose **Saved card •••• 1234**, charged on the spot, or **Another card**. **Another card** (or no saved card) takes you to the payment page and back to `/linhas/comprar`, where the purchase resumes with the same numbers. If the saved card asks for a confirmation, the dialog says to choose **Another card**.

Back on the confirmation, the page says **Balance added. Confirm to finish the purchase.** After the payment page, it may first say **Payment received. Waiting for the balance to reach the wallet…** (the buy button shows **Confirming payment…**); if the balance still has not arrived after about two minutes, it says **The payment has not reached the balance yet. If you have paid, wait a few minutes before trying again — do not pay twice.** A payment canceled on that page brings you back with **The payment was canceled. The numbers are still selected.**

Topping up never buys the line by itself: you go back to the confirmation and click **Buy** again.

## Line page

Click a line to open its page (`/linhas/{id}`). A line that does not exist in this workspace shows **Line not found.**, with **Go to phone lines**.

### Header

- **The line's name**, with the **pencil** (**Edit name**) next to it. It opens **Edit line name**: **Name** (optional, up to 60 characters) and **Save**. Left blank, the line shows its number; with a name, the number shows right below it. Owner and Admin can rename; **Name updated** confirms it, and a failure says **Failed to update name**. Next to the name, a copy button copies the number with the country code (`+55…`).
- **Area code · active since … · renews …** — the purchase date and the next renewal date. A line that is no longer yours shows **Returned on …** or **Canceled on …** instead.
- **The status** and, for the Owner, **Cancel line** (line in good standing) or **Return number** (overdue line). See [Cancel or return](#cancel-or-return).

### Payment due or suspended

A line with payment due shows **We could not charge … on …**, with the exact dates on which it will be suspended and the number returned, and the **Add balance** and **Pay … now** buttons. A suspended line shows **Line suspended for non-payment**, with the date the number will be returned, and the **Add balance** and **Pay … and reactivate** buttons. Both buttons retry the charge immediately (wallet first, then the saved card) and answer **Payment done. The line stays active.** or **Could not charge. Add balance or check your card.**

<Note>
  **Pay … now** and **Pay … and reactivate** charge **this line only**. When other lines are overdue too, the page says so (**Another line is also unpaid** or **… other lines are also unpaid**), with **See and pay all**, which takes you to the list — there, **Pay for all** charges them all at once.
</Note>

### Activation code

The code panel has the **Wait for a new code** button, which prepares the line to receive the WhatsApp call (**Preparing the line…** while it does). It is disabled while a request is waiting or being read, and on a suspended line (**A suspended line does not receive new codes. The history is still available.**); a line with payment due still receives codes. In WhatsApp, choose **Call me** — a landline does not receive SMS, so waiting for the SMS only burns the verification window. Before the first request, the panel says **No code yet. Tap Wait for a new code and, in WhatsApp, choose Call me.** After you click it, the panel goes through these states:

| What the dashboard shows | What it means |
| --- | --- |
| **Waiting** — **Waiting for the call from Meta** | The line waits for the call for 5 minutes (**The line waits for the call until …**), with the **Time left**; at zero it shows **Checking one last time…**. In WhatsApp, tap **Call me**; the call can take a minute or more, with no need to cancel and ask again. **Cancel wait** ends the request. |
| **Reading** — **The call arrived: reading the code…** | The audio is being transcribed; it usually takes a few seconds, but can take a minute or two. You can listen to the recording meanwhile (**Meanwhile, you can listen to the call:**). |
| The code, with **Copy** | **Last code · …** and the time it arrived, with **Received**. Type it into WhatsApp. The recording player sits below it. |
| **We got the call, but could not read the code. Listen to the recording below.** | Listen to the recording right below and read the digits by ear. |
| **No call arrived** | The window closed with no call. The panel lists the usual reasons (**Resend SMS** tapped instead of **Call me**, the WhatsApp timer, a cooldown after repeated attempts) and offers **Wait again** and **Talk to support**. |
| **Wait canceled** | The request was canceled. Click **Wait for a new code** before asking WhatsApp for the code again. |
| **We could not capture the call** | The call arrived, but the recording could not be stored. Ask WhatsApp for the code again; **Wait again** starts a new request. |

If someone else (another tab, a teammate) already asked for a code on the line, clicking **Wait for a new code** follows that request instead of starting a second one. Reopening the page while a request is waiting or being read picks it up where it is. If you click **Cancel wait** just as the call arrives, the dashboard says **The call just arrived, or the request had already ended. See the result on screen.**

The activation code is **not shown once**: it stays in the code history below, for as long as the line is yours.

### Call recording

Every captured call has a player (**Call recording**). The recording is Pilot Status's own copy — the carrier keeps it for 1 hour only — so you can listen to it again whenever you need, for as long as the line is yours.

- For the code on the panel, the player loads by itself. In the history, click **Listen** to load that call's recording.
- While it loads, the player says **Loading recording…**.
- If the recording does not load (or takes more than 30 seconds), it says **Could not load the recording.**, with **Try again**.
- A page left open for a long time still plays: the player fetches the recording again when needed.

### Code history

Below the panel is the **Code history**: the 20 most recent requests, with **When**, **Code**, **Recording** (**Listen**) and **Status** — **Waiting**, **Reading the code**, **Received** (with the code, or with "—" when the call carried no 6-digit code), **Recording received** (the call arrived, but reading it failed), **Did not arrive**, **Canceled** or **Failed**. With no request yet, it says **No code received yet.** On a suspended line, the history is **read only** (**Code history · read only**). When the number goes back to the carrier — returned or cancelled — the line's codes and recordings are deleted, and its page no longer shows the history.

### Cancel or return

**Cancel line** opens **Cancel …?** and **Return number** opens **Return …?**. Both explain what happens and ask you to type the line's number — area code and number, without `+55` (**Type the number to confirm: …**); the button stays disabled until it matches. **Keep the line** closes the dialog. Both also warn: **If the WhatsApp account on this number is still in use, move it to another number first.**

- **Cancel …?** — **The line keeps working until …, which is already paid. The period is not refunded.** On that day the number goes back to the carrier, with no guarantee you can buy it back, taking the code history and control of the WhatsApp account activated on it; until then you can undo the cancellation.
- **Return …?** — **This cannot be undone. You lose:** the number (it goes back to the carrier stock and can be acquired by another company), the codes received with their call recordings, and control of the WhatsApp account activated on it — whoever gets the number next can request a verification code and take over the account.

- **Cancel line** (line in good standing) schedules the cancellation for the end of the month already paid, with no refund (**Cancellation scheduled for ….**). The list shows the line as **Cancellation scheduled**, and its page shows **Cancellation scheduled: the line stays active until … and then the number is returned.**, with **Undo cancellation** — which answers **Cancellation undone. The line renews as usual.**
- **Return number** (overdue line) returns the number to the carrier right away. You go back to the list, with the notice **… was returned**: **The code history and the recordings were deleted. There is no pending charge for this line.**

Once the number goes back to the carrier, the line's page only says **This line no longer belongs to you. The number went back to the carrier.**

## Choose which lines to keep

With more than one overdue line, **Choose which to keep** opens the **Choose which lines to keep** dialog (a link in an overdue-payment notice can open it too; links in those notices only open the dialog or point to **Pay for all**, they never pay by themselves). It lists the unpaid lines, each with its codes, since when it is yours and what keeping it costs now, and says how much is in the wallet and how many of them the balance covers. Check the ones you want to keep and click **Keep … and return …**; it stays disabled until at least one line is checked (returning every line is done one by one, with **Return number**). **Add balance** takes you to the wallet.

- the checked lines are charged right away (wallet first, then the saved card);
- the **unchecked ones are returned right away**, for good, with their code history.

The result appears as a message: **… lines kept and … returned.** If a checked line cannot be charged, the dashboard says **… chosen lines could not be charged. Add balance and try again.** The unchecked lines are returned either way, even when a checked line was not charged.

## Line webhooks

**Line webhooks** (`/linhas/webhooks`, title **Phone line webhooks**), at the top of the list, is the webhook registry of the Phone Lines product — separate from the number webhooks: a number webhook never receives line events. Owner and Admin manage it.

- **New webhook** — an optional name (up to 100 characters; left blank, it becomes the URL's host), the `https` URL and the events: **Every phone line event** or the ones you pick (**Line purchased**, **Call audio received**, **Code received**, **Code not obtained**, **Line renewed**, **Charge failed**, **Line suspended**, **Number returned**, **Line canceled**, **Verification updated**). **Create webhook** saves it. The URL and at least one event are required (**Invalid webhook: use an https URL and pick at least one event.**); a longer name is refused on save (**Invalid name: use at most 100 characters.**), and so is a URL pointing to an internal or private-network address (**URL refused: it points to an internal or private network address, which we never call. Use your server's public address.**).
- **Edit webhook** (**Save changes**), **Deactivate** / **Activate** and **Delete** (**Delete this webhook?**) — an inactive webhook shows as **Paused** and gets no deliveries; deleting stops deliveries to that URL right away.
- **Deliveries** — pick a webhook to see its most recent deliveries (up to 50, no filters): **When**, **Event**, **Status** (**Pending**, **Delivered**, **Failed**), **Response** and **Attempts**. Clicking a delivery opens its details, with the body that was sent, the endpoint's response and the attempts. There is no resend and no test delivery.
- The summary of the picked webhook shows its name, URL, **Active** or **Paused**, its events and **Last delivery … · HTTP …** (or **No delivery yet**). With no webhook yet, the page says **No phone line webhook yet.**
- A webhook created under **Workspace keys** that subscribes to workspace events (such as `wallet.topup_paid`) is listed here too, but can only be deleted here: **This webhook subscribes to workspace events (such as wallet.topup_paid), which this screen does not edit.**, with a link to edit it in **Workspace keys**.

<Warning>
  **The signing secret is shown only once.** Right after **Create webhook**, a **Signing secret** dialog shows the secret (it starts with `plwh_`), with **Copy** and **Got it**: **Shown once. Store it now — no read returns it again.** Every delivery carries the `x-pilot-status-signature` header — the hex-encoded HMAC-SHA256 of the raw body, keyed with this secret. The dashboard, the API and the MCP never show it again, and Pilot Status support cannot read it either. Editing the webhook does not change it, and this registry has no rotation: **if you lost it, create a new webhook (you get a new secret), point your system to it, and delete the old one.**
</Warning>

The counters at the top show **Total Webhooks**, **Active** and **Inactive** — or, with a webhook picked, **Total deliveries**, **Delivered** and **Failed** for the deliveries listed.

A line's events carry its name, and **Call audio received**, **Code received** and **Code not obtained** also carry `audioUrl`, the address of the call recording, which your system downloads with the API key. A **Code received** delivery carries the activation code itself.

Endpoints, payloads, signature verification and retries: [Phone line webhooks](/api/phone-lines/webhooks).

## Lines under Plans

Under **Plans** (sidebar), three tabs show the money side of the lines:

- **Finance → Phone line charges** — the wallet balance, whether it covers the renewals of the next 7 days, each line's next renewal with who will pay it (**Wallet pays**, **Saved card pays**, **Wallet + card** or **Balance too low**), and the **Charge history**, with period, status (**Paid**, **Failed**, **Pending**, **Refunded**), attempts and the next attempt. A **Refunded** charge says why — for example, **Holder verification rejected; the amount went back to the wallet.** On the same tab, **Consolidated spend** breaks out what was spent on **Phone lines**, and **Receipts and invoices** has a **Payment proof** for every paid charge.
- **Wallet** — the wallet **Statement** has **All**, **WhatsApp** and **Phone lines** buttons to filter by product. Lines show up as **Purchase** (first month) and **Monthly fee** (renewals).
- **History** — the trail of billing events includes the lines': **Line purchased**, **Line monthly fee paid**, **Line charge failed**, **Line monthly fee refunded**, **Line suspended for non-payment**, **Line reactivated**, **Line returned** and **Line canceled**, each with the line's name and number.

Details in [Phone line pricing and billing](/phone-lines-pricing).

## Who gets the notices

Line notices go to the **account holder**'s contacts given in the verification and to the workspace **Owner**; other workspace members do not get them. They cover the purchase, the renewals coming up in the next 48 hours, a paid renewal, a failed renewal, the day before a suspension, the suspension, the reactivation, the return, a scheduled cancellation that took effect, a balance that does not cover the next 7 days of renewals, and the account holder verification (another document requested, approved, rejected).

Every notice goes by e-mail. Some also go by WhatsApp, and only to a confirmed number: the holder's WhatsApp confirmed in the verification, and the Owner's phone when it is verified in their profile. The same address never gets the same notice twice.

## Do it via API / MCP

Every `/v1/phone-lines` route takes a **workspace-scoped** API key (a number key is refused). The MCP server covers the verification, the call recording and the webhooks; the rest is API or dashboard only.

| Dashboard action | API (`/v1`) | MCP tool |
| --- | --- | --- |
| List lines, open a line | [`GET /v1/phone-lines`, `GET /v1/phone-lines/{id}`](/api/phone-lines/list) | None — API only |
| Holder verification (start, confirm codes, resend code, new document) | [`/v1/phone-lines/verification`](/api/phone-lines/verification) | `phone_lines_verification_get`, `phone_lines_verification_start`, `phone_lines_verification_confirm_contact`, `phone_lines_verification_resend_contact`, `phone_lines_verification_resend_document` (Owner only) |
| Search numbers | [`GET /v1/phone-lines/available`](/api/phone-lines/available) | None — API only |
| Buy lines | [`POST /v1/phone-lines`](/api/phone-lines/purchase) (`Idempotency-Key` required) | None — API only |
| Wait for a new code, read the code, cancel the wait, code history | [`POST /v1/phone-lines/{id}/activations` and related](/api/phone-lines/activation-codes) | None — API only |
| Listen to the call recording | [`GET /v1/phone-lines/activations/{activationId}/audio`](/api/phone-lines/activation-codes) | `phone_lines_activation_audio` (returns where to download it, never the audio) |
| Cancel line / Return number | [`DELETE /v1/phone-lines/{id}`](/api/phone-lines/cancel) | None — API only |
| Edit name | — | Dashboard only |
| Undo cancellation | — | Dashboard only |
| Pay … now, Pay for all, Choose which to keep | — | Dashboard only |
| Add balance to the wallet | `POST /v1/billing/checkout` — see [Wallet and card](/api/wallet-and-card) | `billing_checkout`, `billing_topups_get` (Owner) |
| Line webhooks and their deliveries | [`/v1/phone-lines/webhooks`](/api/phone-lines/webhooks) | `phone_lines_webhooks_list`, `phone_lines_webhooks_get`, `phone_lines_webhooks_create`, `phone_lines_webhooks_update`, `phone_lines_webhooks_delete`, `phone_lines_webhooks_deliveries_list`, `phone_lines_webhooks_deliveries_get` (Admin and up) |

A webhook created through the API or MCP shows up on this screen, and vice versa. `phone_lines_webhooks_create` returns the `plwh_` secret only in its response, exactly like the dashboard. Overview of the API: [Phone Lines API](/api/phone-lines/overview).
