Phone lines live under **Phone lines** in the sidebar, right below **Numbers** (keyboard shortcut: `i`). The item shows for **Owner and Admin**; Agent and Analyst do not see lines, because a line's page shows its WhatsApp activation code, and that code is a credential. For the same roles, the **Numbers** page also has a **Phone lines** card, with **Go to phone lines**.

The full walkthrough, from the holder verification to typing the code into WhatsApp, is in the guide [Phone lines: buy one and use it on WhatsApp](/guides/phone-lines).

## Who can do what

| Action | Owner | Admin | Agent / Analyst |
| --- | --- | --- | --- |
| See the lines, open a line, read the activation code and the code history, listen to recordings | Yes | Yes | No |
| **Wait for a new code**, **Cancel wait**, **Edit name** | Yes | Yes | No |
| Holder verification and **Buy a line** | Yes | No — the empty list says **Only the workspace owner can buy lines.** | No |
| **Add balance**, **Pay … now**, **Pay for all**, **Choose which to keep** | Yes | No — sees **Only the workspace owner can pay or choose which lines to keep.** | No |
| **Cancel line**, **Return number**, **Undo cancellation** | Yes | No | No |
| **Line webhooks** (create, edit, pause, delete, see deliveries) | Yes | Yes | No |

The permissions behind it: `phone_lines:read` and `phone_lines:webhooks` (Admin and up), `phone_lines:purchase`, `phone_lines:cancel` and `billing:wallet:topup` (Owner only).

## Lines list

The **Phone lines** page (`/linhas`) lists the lines that are still yours — active, payment due, or suspended. A returned or cancelled line leaves the list. With no lines yet, the page shows **No lines yet**, the price and **Billed monthly · cancel anytime**.

At the top are **Line webhooks** and **Buy a line**, and a summary such as **3 lines · 1 needs attention**. The list starts with what needs action: suspended lines first, then payment due, then cancellation scheduled, and the rest by renewal date. Each row has a copy button for the number.

Each line shows its name (or its number, if it has no name), its area code, and one of these statuses:

| Status | What the line shows |
| --- | --- |
| **Active** | The next renewal date and how many codes the line has requested. |
| **Payment due** | The date the renewal failed. The line still receives codes. |
| **Suspended** | The suspension date. The line does not receive new codes. |
| **Cancellation scheduled** | Until when the line stays active. |

A line's page can also show **Returned** and **Canceled**, the two final statuses.

### Notices at the top of the list

- **Unpaid lines** — a red notice (**One line needs payment**, or **… lines are suspended or unpaid**) says by when to settle. For the Owner, it has **Add balance**, **Pay for all** and, when more than one line is overdue, **Choose which to keep**; an Admin sees the notice with **Only the workspace owner can pay or choose which lines to keep.** See [Phone line pricing and billing](/phone-lines-pricing#overdue-lines).
- **Your verification is under review** — you can already use your lines normally while Pilot Status checks the document. If the check does not pass, the lines bought during the review go back to the carrier and what you paid for them returns to your wallet as balance.
- **We need another document to finish the account holder verification.** — **Send document** takes you back to the verification.
- **The account holder verification was rejected.** — the lines bought during the review go back to the carrier 3 days after the rejection, and what you paid for them returns as wallet balance; until then they stay active and do not renew. New lines cannot be bought — **Buy a line** says so and points you to support (**Talk to support**). See the [guide](/guides/phone-lines#step-by-step).

The verification notices only show for the Owner.

### Pay for all (retry the charge)

**Pay for all** charges every overdue line again, right away: first from the wallet balance, then the saved card for any shortfall. The result appears as a message — **… lines paid. They stay active.**, or **… lines could not be charged. Add balance or check your card.** It does not open a dialog. There is no automatic "retry" button beyond this: the same retry exists per line on its page (**Pay … now**).

## Buying lines

**Buy a line** opens **Buy phone lines** (`/linhas/comprar`), in three steps shown at the top: **Verification**, **Numbers**, **Confirm**. Only the Owner can buy.

### Step 1 — Verification

**Confirm who the account holder is.** This step only shows on the first purchase, while the account holder is not verified. A phone line is a regulated service, and the holder is checked once.

1. **You are buying as** — **Company · CNPJ** or **Individual · CPF**.
   - **CNPJ**: looked up in the federal registry. The CNPJ may be alphanumeric (the new Receita format, for example `12.ABC.345/01DE-35`); type it as on the CNPJ card. The screen shows **Checking the registry…** and then **Active · checked in the federal registry**. An inactive CNPJ is refused (**This CNPJ is not active in the federal registry.**); an unknown one gets **CNPJ not found in the federal registry.** If the registry cannot be reached, the purchase goes ahead and the document is checked by hand.
   - **CPF**: the check is done on the document.
2. **Holder WhatsApp number** — with a country selector (Brazil preselected). It receives a 6-digit code.
3. **Document** — drag the file or click to choose: for a CNPJ, the **CNPJ card, articles of incorporation or registration proof**; for a CPF, an **ID card (RG), driver license (CNH) or CPF registration proof**. **PDF, JPG, PNG or WEBP, up to 10 MB.** The dashboard reads the number on the document (**Reading the document… Do not close this page.**); if it cannot read it reliably, it asks you to send a sharper file (**Replace**).
4. **Contacts** — a 6-digit code goes to the **e-mail of your account** (the signed-in user) and to the holder's **WhatsApp number**, sent from the Pilot Status WhatsApp. Type each code and click **Confirm**. **Did not get it? Resend code** sends a new one after a short countdown (**Resend in …**). Codes are valid for **10 minutes**; too many wrong attempts require a new code. If there is no WhatsApp sender available, the code goes by e-mail and the WhatsApp number is recorded unconfirmed.

<Note>
  The contact code only confirms who you are. It is **not** the WhatsApp activation code, which arrives by phone call on the line itself.
</Note>

When the contacts are confirmed, the verification is either approved or **Verification under review: you can already buy** — you buy and use the lines while the document is checked by hand. A rejected verification shows **The account holder verification was rejected** and blocks new purchases. **Fix details** goes back to the form.

### Step 2 — Numbers

**Pick the numbers.** Choose the area code (search by area code or state), click **Search numbers** and select up to **10** numbers (**… of 10 picked**). They are landlines: they receive the WhatsApp code call, and they do not place calls or receive SMS. If an area code has no stock, the screen says so; try another one.

### Step 3 — Confirm

**Confirm the purchase.** It shows the price per line (**…/month**, the same on every plan and for any quantity), **Total now · … lines** and **Buy … lines · …**. Each line renews every month on the purchase day; the first month is charged in full, with no proration. The amount comes out of the wallet balance, and the saved card covers any shortfall.

After the purchase, each number shows its result (**Buying…** while it runs — each number can take up to a minute and a half, and you can leave the page). Then **Done! Your … lines are active** or **… of … purchases completed**, with **Open line** for each line bought and **Pick other numbers**. If a failed number was already charged, the amount went back to your wallet balance.

### Add balance to finish the purchase

If a number fails for lack of balance, **Add balance and try again** opens the **Add balance to finish the purchase** dialog. It shows the **Total**, the **Wallet balance** and the **Amount to add** (the shortfall, never less than the minimum top-up; what is left over stays in the wallet). Under **How to pay**:

- **Pix (instant)** — only for BRL accounts (**Pix is available only for BRL accounts.**). **Create a … Pix** shows the **Pix QR code** and **Copy Pix code** (the copy-and-paste code). Pay it in your bank app. The dialog keeps checking the balance; **I have paid** checks right away. Until the payment is confirmed it says **We have not received the Pix confirmation yet.** The dialog does not show an expiry time for the Pix.
- **Credit card** — **Saved card •••• 1234** is charged on the spot; **Another card** takes you to the payment page and back to `/linhas/comprar`, where the purchase resumes with the same numbers (**Balance added. Confirm to finish the purchase.**). If the payment has not reached the balance yet, the page warns you not to pay twice.

Topping up never buys the line by itself: you go back to the confirmation and click **Buy** again.

## Line page

Click a line to open its page (`/linhas/{id}`).

### Header

- **The line's name**, with the **pencil** (**Edit name**) next to it. It opens **Edit line name**: **Name** (optional, up to 60 characters) and **Save**. Left blank, the line shows its number; with a name, the number shows right below it, with a copy button. Owner and Admin can rename.
- **Area code · active since … · renews …** — the purchase date and the next renewal date.
- **The status** and, for the Owner, **Cancel line** (line in good standing) or **Return number** (overdue line). See [Cancel or return](#cancel-or-return).

### Payment due or suspended

A line with payment due shows **We could not charge … on …**, with the exact dates on which it will be suspended and the number returned, and the **Add balance** and **Pay … now** buttons. A suspended line shows **Line suspended for non-payment**, with the date the number will be returned, and the **Add balance** and **Pay … and reactivate** buttons. Both buttons retry the charge immediately (wallet first, then the saved card) and answer **Payment done. The line stays active.** or **Could not charge. Add balance or check your card.**

<Note>
  **Pay … now** and **Pay … and reactivate** charge **this line only**. When other lines are overdue too, the page says so (**Another line is also unpaid** or **… other lines are also unpaid**), with **See and pay all**, which takes you to the list — there, **Pay for all** charges them all at once.
</Note>

### Activation code

The code panel has the **Wait for a new code** button, which prepares the line to receive the WhatsApp call. It is disabled while a request is waiting or being read, and on a suspended line (**A suspended line does not receive new codes.**). In WhatsApp, choose **Call me** — a landline does not receive SMS, so waiting for the SMS only burns the verification window. After you click it, the panel goes through these states:

| What the dashboard shows | What it means |
| --- | --- |
| **Waiting** — **Waiting for the call from Meta** | The line waits for the call for 5 minutes, with the **Time left**. In WhatsApp, tap **Call me**; the call can take a minute or more. **Cancel wait** ends the request. |
| **Reading** — **The call arrived: reading the code…** | The audio is being transcribed. You can listen to the recording meanwhile. |
| The code, with **Copy** | **Last code · …** and the time it arrived. Type it into WhatsApp. |
| **We got the call, but could not read the code** | Listen to the recording right below. |
| **No call arrived** | The window closed with no call. The panel lists the usual reasons (**Resend SMS** tapped instead of **Call me**, the WhatsApp timer, a cooldown after repeated attempts) and offers **Wait again**. |
| **Wait canceled** | The request was canceled. Click **Wait for a new code** before asking WhatsApp for the code again. |
| **We could not capture the call** | The call arrived, but the recording could not be stored. Ask for the code again. |

The activation code is **not shown once**: it stays in the code history below, for as long as the line is yours.

### Call recording

Every captured call has a player (**Call recording**, **Listen**). The recording is Pilot Status's own copy — the carrier keeps it for 1 hour only — so you can listen to it later from the history. If it fails to load, the player says **Could not load the recording.**

### Code history

Below the panel is the **Code history**: the 20 most recent requests, with **When**, **Code**, **Recording** (**Listen**) and **Status** — **Waiting**, **Reading the code**, **Received** (with the code, or with "—" when the call carried no 6-digit code), **Recording received** (the call arrived, but reading it failed), **Did not arrive**, **Canceled** or **Failed**. On a suspended line, the history is **read only** (**Code history · read only**). When the number goes back to the carrier — returned or cancelled — the line's codes and recordings are deleted, and its page no longer shows the history.

### Cancel or return

**Cancel line** opens **Cancel …?** and **Return number** opens **Return …?**. Both explain what happens — the number goes back to the carrier's stock, with no guarantee you can buy it back, taking the code history, the recordings and control of the WhatsApp account activated on it — and ask you to type the line's number (**Type the number to confirm: …**). **Keep the line** closes the dialog. If the WhatsApp account on the number is still in use, move it to another number first.

- **Cancel line** (line in good standing) schedules the cancellation for the end of the month already paid, with no refund. The page then shows **Cancellation scheduled: the line stays active until … and then the number is returned.**, with **Undo cancellation** — which answers **Cancellation undone. The line renews as usual.**
- **Return number** (overdue line) returns the number to the carrier right away. You go back to the list, with the notice **… was returned**: **The code history and the recordings were deleted. There is no pending charge for this line.**

Once the number goes back to the carrier, the line's page only says **This line no longer belongs to you. The number went back to the carrier.**

## Choose which lines to keep

With more than one overdue line, **Choose which to keep** opens the **Choose which lines to keep** dialog: the unpaid lines (each with its codes and since when it is yours), the wallet balance and how many of them the balance covers. Check the ones you want to keep and click **Keep … and return …**:

- the checked lines are charged right away;
- the **unchecked ones are returned right away**, for good, with their code history.

If a checked line cannot be charged, the dashboard says so (**… chosen lines could not be charged. Add balance and try again.**).

## Line webhooks

**Line webhooks** (`/linhas/webhooks`, title **Phone line webhooks**), at the top of the list, is the webhook registry of the Phone Lines product — separate from the number webhooks: a number webhook never receives line events. Owner and Admin manage it.

- **New webhook** — an optional name (up to 100 characters; left blank, it becomes the URL's host), the `https` URL and the events: **Every phone line event** or the ones you pick (**Line purchased**, **Call audio received**, **Code received**, **Code not obtained**, **Line renewed**, **Charge failed**, **Line suspended**, **Number returned**, **Line canceled**, **Verification updated**). **Create webhook** saves it. A URL pointing to an internal or private-network address is refused on save.
- **Edit webhook** (**Save changes**), **Deactivate** / **Activate** and **Delete** (**Delete this webhook?**) — an inactive webhook shows as **Paused** and gets no deliveries; deleting stops deliveries to that URL right away.
- **Deliveries** — pick a webhook to see its most recent deliveries (up to 50, no filters): **When**, **Event**, **Status** (**Pending**, **Delivered**, **Failed**), **Response** and **Attempts**. Clicking a delivery opens its details, with the body that was sent. There is no resend.
- A webhook created under **Workspace keys** that subscribes to workspace events (such as `wallet.topup_paid`) is listed here too, but can only be deleted here: **This webhook subscribes to workspace events (such as wallet.topup_paid), which this screen does not edit.**, with a link to edit it in **Workspace keys**.

<Warning>
  **The signing secret is shown only once.** Right after **Create webhook**, a **Signing secret** dialog shows the secret (it starts with `plwh_`), with **Copy** and **Got it**: **Shown once. Store it now — no read returns it again.** Every delivery carries the `x-pilot-status-signature` header — the hex-encoded HMAC-SHA256 of the raw body, keyed with this secret. The dashboard, the API and the MCP never show it again, and Pilot Status support cannot read it either. Editing the webhook does not change it, and this registry has no rotation: **if you lost it, create a new webhook (you get a new secret), point your system to it, and delete the old one.**
</Warning>

The counters at the top show **Total Webhooks**, **Active** and **Inactive** — or, with a webhook picked, **Total deliveries**, **Delivered** and **Failed** for the deliveries listed.

A line's events carry its name, and **Call audio received**, **Code received** and **Code not obtained** also carry `audioUrl`, the address of the call recording, which your system downloads with the API key. A **Code received** delivery carries the activation code itself.

Endpoints, payloads, signature verification and retries: [Phone line webhooks](/api/phone-lines/webhooks).

## Lines under Plans

Under **Plans** (sidebar), three tabs show the money side of the lines:

- **Finance → Phone line charges** — the wallet balance, whether it covers the renewals of the next 7 days, each line's next renewal with who will pay it (**Wallet pays**, **Saved card pays**, **Wallet + card** or **Balance too low**), and the **Charge history**, with period, status (**Paid**, **Failed**, **Pending**, **Refunded**), attempts and the next attempt. A **Refunded** charge says why — for example, **Holder verification rejected; the amount went back to the wallet.** On the same tab, **Consolidated spend** breaks out what was spent on **Phone lines**, and **Receipts and invoices** has a **Payment proof** for every paid charge.
- **Wallet** — the wallet **Statement** has **All**, **WhatsApp** and **Phone lines** buttons to filter by product. Lines show up as **Purchase** (first month) and **Monthly fee** (renewals).
- **History** — the trail of billing events includes the lines': **Line purchased**, **Line monthly fee paid**, **Line charge failed**, **Line monthly fee refunded**, **Line suspended for non-payment**, **Line reactivated**, **Line returned** and **Line canceled**, each with the line's name and number.

Details in [Phone line pricing and billing](/phone-lines-pricing).

## Who gets the notices

Line notices go to the **account holder**'s contacts given in the verification and to the workspace **Owner**; other workspace members do not get them. They cover the purchase, the renewals coming up in the next 48 hours, a paid renewal, a failed renewal, the day before a suspension, the suspension, the reactivation, the return, a scheduled cancellation that took effect, a balance that does not cover the next 7 days of renewals, and the account holder verification (another document requested, approved, rejected).

Every notice goes by e-mail. Some also go by WhatsApp, and only to a confirmed number: the holder's WhatsApp confirmed in the verification, and the Owner's phone when it is verified in their profile. The same address never gets the same notice twice.

## Do it via API / MCP

Every `/v1/phone-lines` route takes a **workspace-scoped** API key (a number key is refused). The MCP server covers the verification, the call recording and the webhooks; the rest is API or dashboard only.

| Dashboard action | API (`/v1`) | MCP tool |
| --- | --- | --- |
| List lines, open a line | [`GET /v1/phone-lines`, `GET /v1/phone-lines/{id}`](/api/phone-lines/list) | None — API only |
| Holder verification (start, confirm codes, resend code, new document) | [`/v1/phone-lines/verification`](/api/phone-lines/verification) | `phone_lines_verification_get`, `phone_lines_verification_start`, `phone_lines_verification_confirm_contact`, `phone_lines_verification_resend_contact`, `phone_lines_verification_resend_document` (Owner only) |
| Search numbers | [`GET /v1/phone-lines/available`](/api/phone-lines/available) | None — API only |
| Buy lines | [`POST /v1/phone-lines`](/api/phone-lines/purchase) (`Idempotency-Key` required) | None — API only |
| Wait for a new code, read the code, cancel the wait, code history | [`POST /v1/phone-lines/{id}/activations` and related](/api/phone-lines/activation-codes) | None — API only |
| Listen to the call recording | [`GET /v1/phone-lines/activations/{activationId}/audio`](/api/phone-lines/activation-codes) | `phone_lines_activation_audio` (returns where to download it, never the audio) |
| Cancel line / Return number | [`DELETE /v1/phone-lines/{id}`](/api/phone-lines/cancel) | None — API only |
| Edit name | — | Dashboard only |
| Undo cancellation | — | Dashboard only |
| Pay … now, Pay for all, Choose which to keep | — | Dashboard only |
| Add balance to the wallet | `POST /v1/billing/checkout` — see [Wallet and card](/api/wallet-and-card) | `billing_checkout`, `billing_topups_get` (Owner) |
| Line webhooks and their deliveries | [`/v1/phone-lines/webhooks`](/api/phone-lines/webhooks) | `phone_lines_webhooks_list`, `phone_lines_webhooks_get`, `phone_lines_webhooks_create`, `phone_lines_webhooks_update`, `phone_lines_webhooks_delete`, `phone_lines_webhooks_deliveries_list`, `phone_lines_webhooks_deliveries_get` (Admin and up) |

A webhook created through the API or MCP shows up on this screen, and vice versa. `phone_lines_webhooks_create` returns the `plwh_` secret only in its response, exactly like the dashboard. Overview of the API: [Phone Lines API](/api/phone-lines/overview).
