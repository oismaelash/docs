Members live in **Profile → Membros** (`/profile?tab=membros`). The tab appears only for **Owner and Admin**. It has three cards: **Equipe** (the team: invitations and members), **Workspace** (name and new workspaces) and, for the Owner only, **Zona de perigo** (danger zone: transfer ownership, archive).

<Note>
  This tab's labels are in Portuguese whatever the dashboard language. Below, each label is quoted as it appears, with its meaning in parentheses.
</Note>

## The team card

**Equipe** shows a summary such as **3 membros · 1 convite(s) pendente(s)** and the list of people. Each row has the person's name and e-mail, a role badge — **Proprietário** (Owner, with a crown), **Administrador** (Admin), **Atendente** (Agent) or **Analista** (Analyst) — and, for invitations, the state:

| Badge | Meaning |
| --- | --- |
| **Convite pendente** | Invitation sent, not answered yet. |
| **Convite expirado** | Not accepted within 7 days; the link no longer works. |
| **Convite recusado** | The person declined. |

Under a pending invitation, a line says how the e-mail went: **E-mail enviado em …** (sent), **Enviando o e-mail…** (still in the queue) or **E-mail não entregue. Use "Reenviar" — o link é a única forma de entrar.** (not delivered: resend, or share the link yourself).

Each row also shows which numbers the person sees — **Todos os números** (all numbers) or the chosen ones.

## Inviting someone

Under **Convidar alguém** (invite someone): type the e-mail, pick the role, click **Convidar**. Below the role, a line explains it:

- **Administrador** — runs day-to-day operations: everything except money and credentials in clear.
- **Atendente** — serves customers: conversations, labels and sending.
- **Analista** — only the numbers, with no access to conversations (the PII cut).

For Atendente and Analista, **Acesso aos números:** (number access) has a button that opens the number scope dialog — see [Limiting a member to some numbers](#limiting-a-member-to-some-numbers). For Administrador the screen says **Administradores veem todos os números.** (Admins see every number.)

The person receives an e-mail with a link that is valid for **7 days**.

<Warning>
  **The invitation link is shown once**, right after you send it, under **Link do convite** with a **Copiar** (copy) button — *Guardamos só o hash: este link não aparece de novo. Se perder, use "Reenviar".* Pilot Status stores only a hash of it, so neither the dashboard nor support can show it again. If you lose it, use **Reenviar** (resend): that issues a new link and kills the old one.
</Warning>

That is also the escape hatch when e-mail is not an option: copy the link and deliver it however you like.

Rules the form enforces:

- **Owner is never assignable.** Becoming the owner is a [transfer of ownership](#transfer-ownership), with its own confirmation.
- **The Owner can invite Admins, Agents and Analysts. An Admin can invite only Agents and Analysts** — creating an Admin changes who is in charge, and that is the owner's call.

Errors you may see: **Esta pessoa já está no workspace.** (already a member), **Você já está neste workspace.** (you invited yourself), **E-mail inválido.**, **Seu papel não pode atribuir esse papel.** (your role cannot assign that role) and **Muitos convites em pouco tempo. Tente daqui a pouco.** (too many invitations; wait a bit).

If the form is replaced by a notice that invitations are in **liberação gradual** (gradual rollout), invitations are not enabled on the platform yet. It is not a plan limit and there is nothing to do; existing members keep working.

## Unlimited members

Every plan, Free included, has **unlimited members**. There is no seat counter and no member cap: invite as many people as you need, and neither invitations nor active members count against any limit. What changes between plans is how many numbers you can connect — see [Plans](/plans).

A pending invitation that is not accepted within 7 days expires and simply stops working. Nothing to clean up, no job to run.

## Resending and revoking

**Reenviar** (resend), on a pending row, issues a new link and invalidates the previous one: *Convite reenviado — o link anterior deixou de valer.* Owner and Admin can resend.

**Revogar** (revoke), on a pending row, is the same action as removing a member — one button, because an invitation and a membership are the same row underneath. Pending rows show **Revogar**; active ones show **Remover**. Both are **Owner-only**. Revoking asks **Revogar o convite de …?** — *the link stops working; you can invite again later* — with **Revogar convite**.

## Changing a role

The **Owner** changes the role from the row's role selector (Administrador, Atendente, Analista) and confirms in **Tornar … [role]?** with **Trocar papel**. An Admin sees the roles but cannot change them. The change takes effect on the person's next request — there is no cache to wait out and no need for them to sign in again.

Promoting an Agent or Analyst to Admin clears their number limit, because Admins see the whole workspace by definition; the confirmation says so (*A restrição de números deixa de valer: passa a ver todos os números.*).

The Owner's row has no controls: the owner cannot be removed or demoted — transfer ownership first.

## Limiting a member to some numbers

For an **Atendente** or **Analista**, the numbers button on the row (or **Acesso aos números:** in the invite form) opens **Números que … pode ver** (numbers … can see). Owner and Admin can do it. *Outside the scope, numbers disappear from the selector and the server refuses the requests — it is not just the screen hiding them.*

Pick one:

- **Todos os números** — all numbers, *including the ones connected later*.
- **Só os números escolhidos** — only the numbers you tick. **Marcar todos** ticks all and **Limpar** clears; with more than 6 numbers there is a search by name or number. You must tick at least one — an empty choice cannot be saved.

Click **Salvar** (or **Aplicar** in the invite form). A member limited to specific numbers does **not** gain new numbers automatically — add them here when you connect one. Owners and Admins always see every number, so their rows show the scope without a button.

## Removing someone — and their API keys

The Owner clicks **Remover** and confirms **Remover … do workspace?** — *the person loses access at once; to come back, they need a new invitation* — with **Remover do workspace**.

Removing a member takes effect immediately: their OAuth and MCP tokens stop working on the next call, and any refresh tokens they hold are revoked, so nothing can resurrect the old access.

**API keys are different, and Pilot Status will stop and ask.** If the person created API keys that are still in use, the removal is blocked and the dialog **… criou N chave(s) de API** (… created N API key(s)) opens — *they keep working after the removal; decide before continuing*. It lists each key — its name, its last four characters, when it was last used (or **nunca usada**) — with three buttons:

<CardGroup cols={2}>
  <Card title="Revogar as chaves e remover" icon="ban">
    Revoke the keys and remove. The keys stop working immediately; anything integrating through them breaks now.
  </Card>

  <Card title="Manter as chaves (passam para mim)" icon="key">
    Keep the keys; they are reassigned to you. Nothing breaks; you now own them.
  </Card>
</CardGroup>

**Cancelar** leaves everything as it was. There is no default, on purpose. Revoking silently takes down production integrations in the middle of an offboarding; leaving keys orphaned is worse, because they keep working and nobody knows whose they are.

<Note>
  Revoking a key never deletes it — the record stays so that message and call history keeps pointing somewhere real. A revoked key simply stops authenticating.
</Note>

## The workspace card

**Workspace** — *each workspace has its own numbers, members and billing.*

- **Nome do workspace** (workspace name) — the name shown in the workspace switcher and in the invitation members receive. Up to 60 characters; **Salvar nome** saves it. Owner and Admin.
- **Criar outro workspace** (create another workspace) — type the name of the new workspace (up to 60 characters) and click **Criar workspace**. You join it as Owner, it becomes the active workspace, and the workspace switcher appears at the top. **Use my backup card** makes your backup card pay when the new workspace's wallet does not cover a charge. If you already own the maximum number of workspaces, the screen says *Você já atingiu o limite de … workspaces dos quais pode ser dono.* See [how many workspaces you can own](/api/workspaces#how-many-workspaces-you-can-own).

## Danger zone

Only the **Owner** sees **Zona de perigo**.

### Transfer ownership

Pick who takes over in **Escolha quem assume…** — only people who already **accepted** the invitation are listed (*Ninguém aceitou convite ainda* when there is no one) — and click **Transferir**. The dialog **Transferir a posse para …?** explains: *you become Admin and lose access to billing, revealing credentials and destroying numbers; only the new owner can give it back.* **Transferir a posse** confirms, and the page reloads with the new owner.

### Archive the workspace

Archiving **locks everyone out, you included**, and cannot be undone from the dashboard — reverting it needs support. Type the workspace's exact name to confirm and click **Arquivar**. You are then taken back to the dashboard.

## Accepting an invitation

The invited person opens the link and signs in. **The e-mail on the account must match the e-mail that was invited** — otherwise anyone who intercepted the link could join with their own account, and the invitation would stop being nominal.

The link then shows what is being offered — the workspace, the role, and the address the invitation was sent to — and asks. **Opening the link does not join anything**; accepting is a deliberate click.

Once accepted, the workspace becomes the active one right away. It stays available in the workspace switcher from then on.

### Declining

The same screen offers **Decline**, behind a confirmation because it cannot be undone from the invitee's side: declining burns the link, and getting in later means being invited again.

Whoever sent the invitation sees the row turn into **Convite recusado** — which is the point of the state existing. A declined invitation and a revoked one used to be indistinguishable, and the difference is what decides between resending and having a conversation.

A declined invitation stops working immediately.

## Do it via API / MCP

Writing to the member list needs a credential with a **user** behind it — an OAuth/MCP token or an [account key](/api/key-types#account-keys) (`ps_account_`, with `x-workspace-id`) — acting with that user's current role. A workspace or number key gets `403 MACHINE_CREDENTIAL_CANNOT_MANAGE_MEMBERS`. Details in [the workspace API](/api/workspace).

| On this screen | API | MCP tool |
| --- | --- | --- |
| Read the workspace | `GET /v1/workspace` | `workspace_get` |
| List members and invitations | `GET /v1/workspace/members` | `workspace_members_list` |
| Invite | `POST /v1/workspace/members` | `workspace_members_invite` |
| Resend an invitation | `POST /v1/workspace/members/{id}/resend` | `workspace_members_resend` |
| Change a role | `PATCH /v1/workspace/members/{id}` | `workspace_members_update` |
| Change a member's numbers | [`PATCH /v1/workspace/members/{id}/numbers`](/api/workspace#change-which-numbers-a-member-sees) | `workspace_members_set_numbers` |
| Remove / revoke (with `?apiKeyAction=revoke` or `keep`) | [`DELETE /v1/workspace/members/{id}`](/api/workspace#removing-a-member-who-created-api-keys) | `workspace_members_remove` |
| List / create workspaces | [`GET` / `POST /v1/workspaces`](/api/workspaces) (account key only) | `workspaces_list`, `workspaces_create` |
| Rename the workspace | [`PATCH /v1/workspace`](/api/workspace#rename-the-workspace) | `workspace_update` |
| Transfer ownership | [`POST /v1/workspace/transfer-ownership`](/api/workspace#transfer-ownership) — **owner's OAuth token or account key only**; no workspace or number key reaches it | `workspace_transfer_ownership` |
| Archive the workspace | [`POST /v1/workspace/archive`](/api/workspace#archive-the-workspace) — **owner's OAuth token or account key only**; no workspace or number key reaches it | `workspace_archive` |
