The **Chatwoot** screen connects **one WhatsApp number at a time** to a Chatwoot account. Once connected, WhatsApp conversations show up in a Chatwoot inbox and agent replies go back out on WhatsApp.

This page describes the screen: what each button and modal does. For the integration itself (prerequisites like `FRONTEND_URL` and `WHATSAPP_CLOUD_BASE_URL`, how templates and Flow answers behave in Chatwoot, what agents see), read [Chatwoot integration](/integrations/chatwoot). For native voice calls, read [Chatwoot Voice Calls](/integrations/chatwoot-voice).

## How to get there

Sidebar → **Chatwoot** (path `/chatwoot`; keyboard shortcut `g`).

The screen works on the number picked in the **number selector** in the header. You need a connected number to use it. To set up Chatwoot for another number, switch numbers in the header. Each number has its own integration.

## Who can use it

| Role | What they get |
| --- | --- |
| **Owner** | Everything, including **reveal** and **copy** of the number's `ps_` API key in the native setup kit. |
| **Admin** | Everything except revealing the key. The kit shows the key masked (`••••••••` plus the last 4 characters), with no reveal or copy button. |
| **Agent**, **Analyst** | The screen is hidden from the sidebar and the route is blocked. All of it requires the `integrations:manage` permission. |

## Before connecting: the setup form

When the number has no integration yet, the screen shows **Connect this number to your Chatwoot**. The page says it takes about 2 minutes and needs three things from your Chatwoot account: **Chatwoot address**, **Account ID** and **Access token**.

| Field | What to type |
| --- | --- |
| **Your Chatwoot address** | The address you see in the browser when you use Chatwoot, with nothing after the domain (for example `https://chatwoot.your-domain.com` or `https://app.chatwoot.com`). A trailing slash is removed. |
| **Your account ID** | The number in the Chatwoot URL right after `/app/accounts/`. |
| **Access token** | In Chatwoot: your avatar → **Profile** → **Access Tokens**. The **Reveal token** / **Hide token** button toggles visibility while you type. After you type the address and the account ID, the link **Open the tokens page in my Chatwoot** opens `<address>/app/accounts/<id>/profile/settings` directly. |

If the address is **not** `app.chatwoot.com`, a notice says it looks like a self-hosted Chatwoot. It asks you to check the `FRONTEND_URL` variable on your instance first, because without it the inbox is rejected. See [the prerequisite](/integrations/chatwoot).

Buttons:

- **Test credentials**: a dry run. It checks the three values against your Chatwoot **without creating or changing anything**. You get a checklist with one line per check (green or red). When everything passes: **All good — you can connect.** Editing any field clears the result.
- **Connect Chatwoot**: creates the inbox in your Chatwoot and the webhook back to Pilot Status. You never paste a webhook URL by hand.
- **Advanced options** — *channel mode, native voice (most people don't need to touch this)*: opens the **Channel mode** selector (see below).

<Note>
  The access token is **never shown back**, on this screen or in any API response. Pilot Status only tells you whether a token is stored. To change it, type a new one under **Update credentials**.
</Note>

## Channel mode

The **Channel mode** selector (with a **Which one to choose?** guide) has three options:

- **Automatic (recommended)**: we pick the mode by number. Official goes native, non-official goes to the mirror.
- **API mirror (Model A)**: Pilot Status mirrors messages and media into Chatwoot. Chat only. Works on a shared Chatwoot.
- **Native WhatsApp Cloud (Model B)**: Chatwoot talks to Meta directly through the Pilot Status layer. Enables voice and calling. Requires a dedicated Chatwoot. This option is only offered when the number is eligible for a native inbox: official Meta numbers, or Pilot Status web numbers on the Evolution GO provider (voice only).

The trade-offs are explained in [Channel mode: API mirror vs native Cloud](/integrations/chatwoot#channel-mode-api-mirror-vs-native-cloud).

## After connecting

### Status header

The screen header shows a status badge: **Connected**, **Error**, **Pending**, **Disabled** or **Disconnected**. A green card reads *All set — your conversations are mirroring to inbox …*. The **Open inbox in Chatwoot** button opens your Chatwoot account dashboard.

### Update credentials

A collapsible **Update credentials** section holds the same form with the current address and account ID filled in. The token field says **•••••••• (leave blank to keep)**. Leave it blank to keep the stored token. Click **Update** to save. Saving runs the connection again with the new values.

### Mirroring

The **Mirroring** switch (**Active** / **Paused**) pauses or resumes the integration. *Paused = we stop sending to Chatwoot; no message is lost.* Nothing is deleted.

If the last sync failed, a **Last error** box shows a readable explanation and the raw error below it. Common cases:

- The token has no access to the account.
- The inbox or conversation was deleted in Chatwoot (it is recreated automatically).
- Your Chatwoot rejected the WhatsApp Cloud channel because `WHATSAPP_CLOUD_BASE_URL` is not pointing at the Pilot Status layer.
- The inbox could not be created (check the token's permissions and the account ID).

### Connection details

A read-only block:

- **Inbox**: the Chatwoot inbox ID.
- **Account**: the account ID.
- **Instance URL**.
- **Token**: **Stored** or **Missing**. The value itself is never shown.
- **Last sync**: relative time; hover for the exact time.

### Maintenance: reconnect and disconnect

- **Reconnect** recreates the inbox without re-entering credentials.
- **Disconnect** opens the **Disconnect Chatwoot?** dialog: *This deletes the inbox in Chatwoot. Open conversations don't migrate.* Confirm with **Disconnect**. The dashboard always deletes the inbox in Chatwoot when it disconnects, and it clears the stored credentials.

### Change channel mode

**Change channel mode — now: …** shows the saved mode and the same selector. After you pick a different mode, the **Switch mode → …** button applies it. *It reconnects and creates a new inbox in Chatwoot. History re-mirrors; open conversations don't migrate.* Pick the mode before connecting when you can.

### Sync history to Chatwoot

This card is shown only while mirroring is **Active**. *It replays this number's already-stored messages into the Chatwoot inbox so agents can see the recent history.* Its main use is coexistence Meta numbers, whose imported history appears in **/chat** but is not mirrored on its own. When a number does not qualify, the server refuses and the reason appears inline on the card.

Click **Sync** to open the **Sync history to Chatwoot?** dialog. It lists three things to expect:

- Messages are inserted at import time, and the original date and time are prefixed into each message body.
- Old media may not import (Meta references expire) and shows as "[mídia]".
- Agents may get a burst of notifications, and conversations may reopen.

Options in the dialog:

- **Window**: **30 days** or **90 days**.
- **Mark read when done**: on by default.

Confirm with **Sync**. While it runs, the card shows **Queued…** or **Syncing…**, a `done / total` counter, a progress bar and a **Cancel** button. When it finishes, you see one of these:

- **N messages synced**.
- A summary like `N sent · N failed · N media expired`, plus the error and a **Try again** button.
- **Canceled**.

Running it again is safe: only messages that never landed are posted again. Details: [Send history to Chatwoot](/integrations/chatwoot#send-history-to-chatwoot).

### Native Chatwoot / Voice: the native setup kit

For eligible numbers, a **Native Chatwoot / Voice** card appears. On official numbers it reads *native messages + voice via Chatwoot*. On Evolution GO web numbers it reads *native voice via Chatwoot (messages go through mirroring)*. A badge shows whether the inbox currently is **Native** or **Legacy (API)**.

*The native inbox is created automatically on connect. The values below are informational.* Each value has a copy button:

| Value | What it is |
| --- | --- |
| **Phone** | The number in E.164 format with `+`. |
| **Phone number ID** | The Meta phone number ID. Evolution GO numbers get a synthetic ID used only for voice. |
| **WhatsApp Business Account ID** | The WABA ID (synthetic for Evolution GO numbers). |
| **API key** | The number's **`ps_` API key**, which a native `whatsapp_cloud` inbox uses as its channel API key. The **Owner** can **reveal** and copy it. Everyone else sees `••••••••` plus the last 4 characters. This is the same key managed on the [API Keys screen](/dashboard/api-keys). Regenerating it there breaks the native inbox until you paste the new key into Chatwoot. |
| **Base URL** | The Pilot Status Meta layer address (`https://<your Pilot Status host>/api/layer/meta`). This is the value for `WHATSAPP_CLOUD_BASE_URL` on your Chatwoot. |
| **Webhook URL** | `<your Chatwoot address>/webhooks/whatsapp/+<number>`. Shows *connect to generate* until the integration exists. |

Actions on the card:

- **Test configuration**: a server-side self-check. It uses the number's `ps_` key to call the layer's `/{phoneId}/settings` and `/{phoneId}/call_permissions` endpoints (the same ones Chatwoot calls) and lists each check in green or red.
- **View documentation**: opens [Chatwoot Voice Calls](/integrations/chatwoot-voice).
- **Manual setup (fallback)**: a collapsible box with a Rails console snippet to copy. You only need it if the inbox was created by hand in Chatwoot. It turns on calling for that channel:

  ```ruby
  ch = Channel::Whatsapp.find_by(phone_number: "+<number>")
  ch.update!(provider_config: ch.provider_config.merge("calling_enabled" => true))
  ch.inbox.reauthorized!
  ```

## Do it via API / MCP

| Screen action | Public API | MCP tool |
| --- | --- | --- |
| See the status | [`GET /v1/chatwoot`](/playground/chatwoot/chatwoot-status) | `chatwoot_get` |
| Connect | [`POST /v1/chatwoot`](/playground/chatwoot/connect-chatwoot) | `chatwoot_connect` |
| Update credentials, pause or resume mirroring, reconnect, switch mode | [`PATCH /v1/chatwoot`](/playground/chatwoot/update-chatwoot) | `chatwoot_update` |
| Disconnect | [`DELETE /v1/chatwoot`](/playground/chatwoot/disconnect-chatwoot). Pass `?deleteInbox=true` to also delete the inbox, as the dashboard does. | `chatwoot_disconnect` |
| Test credentials | [`POST /v1/chatwoot/test`](/playground/chatwoot/test-chatwoot-credentials) | `chatwoot_test` |
| Sync history (start, progress, cancel) | `POST`, `GET`, `DELETE` on `/v1/chatwoot/history-sync` | `chatwoot_history_replay`, `chatwoot_history_replay_get`, `chatwoot_history_replay_cancel` |
| Native setup kit and **Test configuration** (voice self-check) | Dashboard only. The public API does not return the kit, because it would expose the `ps_` key. To get the key, see [API keys](/api/api-keys). | — |

With a number-scoped API key, the number comes from the key. With a workspace key or OAuth, send the number in the `x-whatsapp-number-id` header. The API never returns the Chatwoot access token, only `hasToken`.
