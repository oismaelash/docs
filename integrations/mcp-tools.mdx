The 148 tools of the [hosted MCP server](/integrations/mcp-server), grouped by the same themes that [Code Mode](/integrations/mcp-code-mode)'s `describe` uses. Each row gives the purpose in one line and the arguments the tool **cannot run without**; everything else is optional. Your MCP client shows the full description and schema of each tool, and in Code Mode `describe({ theme })` returns them as TypeScript.

## Read this first

- **`whatsappNumberId`.** Every tool except `docs_search` also accepts `whatsappNumberId`, the id of the number to act on (from `numbers_list`). With an OAuth connection or a workspace-wide key it is **required for number-scoped tools** (messages, conversations, groups, templates, webhooks, calls, Chatwoot…); it is ignored when the API key is already bound to one number. It is not listed in the tables below.
- **Who may call.** "ADMIN or OWNER", "OWNER only" and "OAuth only" are the workspace roles and credential types the API demands; other callers get `403`. With an OAuth connection the role is read live on every call.
- **Confirmation token.** `templates_delete`, `workspace_archive`, `workspace_transfer_ownership` and `workspace_members_remove` run in two calls: the first returns a preview and a `confirm_token`, the second (same arguments plus `confirm_token`) runs. [How it works](/integrations/mcp-server#confirmation-for-destructive-tools)
- **`confirm: true`.** `flows_publish`, `flows_endpoint_key_rotate` (when a key is already registered) and `subscription_extra_numbers_add` (on a FREE plan) refuse to run without the boolean `confirm: true`. Only send it after the user said yes.
- **Per-number grant.** An OAuth connection that granted only some numbers cannot use account-level tools such as `billing_checkout`, `api_keys_*` and `numbers_create`.
