The **Pilot Status Skill** teaches an AI agent to use the public `/v1` API through a bundled command-line tool, `pilot-status`. It works in Claude Code, Claude Desktop / claude.ai (with code execution), Codex and any agent that supports [Agent Skills](https://agentskills.io). You can also run the CLI yourself.

- **OAuth login** in the browser, the same authorization server as the [hosted MCP](/integrations/mcp-server). No API key to copy; the token stays on your machine and renews itself.
- **API key** for CI and servers (`PILOT_STATUS_API_KEY`).
- **One command per public API capability**: the same names and arguments as the MCP tools.
- **Destructive or paid actions, and sends to third parties, never run without confirmation**: they print a preview and stop until you re-run them with `--yes`.

Requires **Node.js 18+**. No dependencies: the CLI is a single file.

## Log in

```bash
node pilot-status/scripts/pilot-status.mjs login
```

The browser opens on the Pilot Status consent screen (shown as **Pilot Status CLI**). Approve it for the workspace you want.

- **No browser on this machine** (SSH, container): `login --no-browser`, open the printed URL anywhere, and paste back the URL the browser ended on.
- **Several workspaces**: one login per workspace with `login --profile <name>`; then `--profile <name>` on any command, or `use <name>`. `profiles` lists them.
- **CI / servers**: set `PILOT_STATUS_API_KEY` (it wins over any profile), or `login --api-key` reading the key from stdin.
- **Log out**: `logout` revokes the login. An access token already issued stays valid for at most one hour.

Credentials live in the Linux Secret Service when available, otherwise in `~/.config/pilot-status/credentials.json` with mode `0600`. On macOS the Keychain is opt-in: `PILOT_STATUS_CREDENTIALS=keychain`.

## Use

```bash
pilot-status tools --group messages          # list commands
pilot-status describe <command>              # description + JSON Schema of the arguments
pilot-status run <command> --json '{"...":"..."}' [--number <whatsapp-number-id>]
pilot-status api GET /v1/...                 # any endpoint, raw
```

Every command prints JSON. `--json @file.json` and `--json -` (stdin) also work.

### Confirmation before destructive, paid or send actions

Deleting, overwriting, disconnecting, charging money or **sending something to a third party** (a message or template, a story, a group, a call) **never happens on the first call**. The command prints `"status": "CONFIRMATION_REQUIRED"` with a preview (phone numbers masked to the last 4 digits) and exits with code `3`. Re-run the same command with `--yes` to apply it. The Skill instructs the agent to show you the preview and wait for your explicit yes.

Unattended jobs (CI, cron) that must send without a person confirming set `PILOT_STATUS_ALLOW_SEND=1`. It waives the confirmation **only for sends**: destructive and paid commands still need `--yes`. An agent never sets it. `tools` and the preview say why a command needs confirmation (`confirmReason`: `destructive`, `charge` or `send`).

### Exit codes

| Code | Meaning |
|---|---|
| `0` | OK |
| `1` | API error (see `error` / `code`) |
| `2` | Bad usage |
| `3` | Confirmation required |
| `4` | Log in again |
