The official community node `n8n-nodes-pilot-status` brings two nodes to n8n:

- **Pilot Status** — calls the public `/v1` API: send messages and templates, list logs, manage numbers, templates, Flows, groups and more.
- **Pilot Status Trigger** — receives your webhook events and starts a workflow.

This page shows how to set both up and gives five workflows you can import and adapt. Every workflow was imported into n8n and checked against the node definitions, and its routing logic was run with sample payloads of both webhook formats.

## Install the node

<Steps>
  <Step title="Install the community node">
    In n8n, open **Settings → Community Nodes → Install**, type `n8n-nodes-pilot-status` and confirm. This needs a self-hosted n8n (community nodes are on by default there). On n8n Cloud, n8n decides which community nodes can be installed; if this one is not offered, use a self-hosted instance.
  </Step>
  <Step title="Create the credential">
    Add a **Pilot Status API** credential and paste your `ps_` API key from the dashboard.

    - A **number-scoped** key needs nothing else: every call goes out from that number.
    - An **account-wide** key also needs **WhatsApp Number ID**, sent as the [`x-whatsapp-number-id`](/api/authentication) header. Without it, calls that act on one number fail with `403 TENANT_SCOPE_NOT_ALLOWED`.
    - Leave **Base URL** at its default (`https://pilotstatus.com.br`).
  </Step>
  <Step title="Add a Pilot Status node">
    Pick a **Resource** (for example **Message**) and an **Operation** (for example **Send**). The **Template ID** dropdown loads the templates of the credential's number.
  </Step>
</Steps>

## Receive events with the Trigger

<Steps>
  <Step title="Add the Pilot Status Trigger">
    Keep **Registration** on **Manual** and **Event** on **All Events** (see the warning below for why).
  </Step>
  <Step title="Register the URL">
    Copy the **Production URL** from the Trigger and add it as a webhook of the number on the **Webhooks** page of the Pilot Status dashboard. Use the **Test URL** instead while you click **Listen for test event** in the editor.
  </Step>
  <Step title="Sign the deliveries">
    Paste the webhook's signing secret into **Signing Secret**. The Trigger then answers `401` to any request whose `x-pilot-status-signature` does not match. Without it, anyone who learns the URL can start your workflow.
  </Step>
  <Step title="Activate the workflow">
    The **Production URL** only receives events while the workflow is active.
  </Step>
</Steps>

The Trigger passes the delivered body through untouched: `$json` is exactly what Pilot Status sent.

### Two webhook formats

What arrives depends on how the number was connected ([details](/api/webhooks/events)):

| Number | Body the Trigger receives | Example of a field |
| --- | --- | --- |
| **QR code (unofficial)** | Pilot Status events: `{ event, data }` | `$json.data.content` |
| **Meta Cloud API (official)** | Meta's native envelope: `{ object, entry }` | `$json.entry[0].changes[0].value.messages[0].text.body` |

<Warning>
  **On an official number, pick All Events.** Meta's envelope has no `event` field, so a Trigger set to a specific event such as **Message Reply** answers `200 Ignored event` to every message and the workflow never runs. For the same reason, do not use **Automatic** registration with a `message.*` event on an official number: Pilot Status drops event names the number cannot emit, so the webhook is created with an empty list and delivers nothing.
</Warning>

<Warning>
  **A reply arrives as `message.reply`, not `message.received`.** On a QR-code number, a message that quotes another one, including a tap on a template button, fires `message.reply` only. A Trigger set to **Message Received** never sees button taps.
</Warning>

To avoid writing every workflow twice, the recipes below start with a **Normalize** Code node. It turns both formats into the same flat item:

| Field | Meaning |
| --- | --- |
| `source` | `canonical` (QR-code number) or `meta` (official number) |
| `isInbound` | `true` only for a message the contact sent. Statuses, and the echo of your own sends, are `false` |
| `from` | the contact's number in E.164 (`+5511999999999`) |
| `name` | the contact's WhatsApp name, when known |
| `text` | message text, or the label of the tapped button or list row |
| `buttonId` | id or payload of the tapped button or list row, when WhatsApp reports one |
| `quotedMessageId` | the message being replied to, when there is one |

```javascript Normalize (Code node)
// Turns both webhook formats into the same flat item:
// - QR-code (unofficial) numbers send { event, data }
// - Meta Cloud API (official) numbers send Meta's native envelope { object, entry }
return $input.all().map(({ json }) => {
  if (json.entry) {
    const value = json.entry[0]?.changes?.[0]?.value ?? {};
    const msg = value.messages?.[0];
    return {
      json: {
        source: 'meta',
        isInbound: Boolean(msg),
        from: msg ? '+' + msg.from : '',
        name: value.contacts?.[0]?.profile?.name ?? '',
        text:
          msg?.text?.body ??
          msg?.button?.text ??
          msg?.interactive?.button_reply?.title ??
          msg?.interactive?.list_reply?.title ??
          '',
        buttonId:
          msg?.button?.payload ??
          msg?.interactive?.button_reply?.id ??
          msg?.interactive?.list_reply?.id ??
          '',
        quotedMessageId: msg?.context?.id ?? '',
      },
    };
  }
  const data = json.data ?? {};
  return {
    json: {
      source: 'canonical',
      isInbound: ['message.received', 'message.reply'].includes(json.event) && !data.fromMe,
      from: data.from ?? '',
      name: data.participantName ?? '',
      text: data.content ?? '',
      buttonId: data.buttonId ?? '',
      quotedMessageId: data.quotedMessageId ?? '',
    },
  };
});
```

## Import a workflow

1. Copy the JSON of a recipe.
2. In n8n, open an empty workflow and press **Ctrl+V** (**Cmd+V** on macOS) on the canvas. You can also save the JSON to a file and use **⋯ → Import from File**.
3. Open each Pilot Status, Google Sheets, OpenAI and e-mail node and select your credential.
4. Replace the example values: template names, phone numbers, spreadsheet id, e-mail addresses.

<Note>
  The workflow replies **from the number of the credential**. Register the Trigger URL on that same number: if the webhook belongs to number A and the credential to number B, the contact writes to A and gets the answer from B.
</Note>

## Recipe 1: template with buttons, reply on tap

You send an approved template with two quick-reply buttons, **Confirm** and **Reschedule**. When the contact taps one, the workflow answers with a different message for each button.

- **Start → Send template** sends the template. Swap the Manual Trigger for whatever starts your flow (a form, a CRM, a schedule).
- **Pilot Status Trigger → Normalize → Which button?** routes the tap by the button's **label**. The label works on both kinds of number; `buttonId` is not always reported for template buttons.
- **Reply: …** answers with free text. The tap opens WhatsApp's 24-hour service window, so a free-text reply is allowed even on an official number.

What to change: `templateId` (`appointment_confirmation`), the destination number, the variables, and the two labels in **Which button?**, which must match the template's buttons exactly (case is ignored).

## Recipe 2: AI agent answers inbound messages

Every text a contact sends goes to an n8n AI Agent with a per-contact memory, and the answer goes back on WhatsApp.

- **Inbound text?** lets through only messages the contact sent. Without it, the echo of the agent's own answer would start the workflow again.
- **Memory per contact** uses the contact's number as the session key, so each conversation has its own history.
- **Send answer** sends `$json.output`, the agent's reply, as free text. It is a reply inside the 24-hour window the contact just opened.

What to change: the system message of **AI Agent**, the model, and the OpenAI credential (or replace the model node with any other chat model).

<Tip>
  Group messages arrive as `message.group` and are not handled here, so the agent does not answer in groups.

## Recipe 3: send a template to every row of a sheet

Every day at 9:00, the workflow reads a Google Sheet, sends a template to each row that was not sent yet, and writes the time of the send back to the row.

Create a tab named **Contacts** with these columns:

| `phone` | `name` | `orderId` | `sent` |
| --- | --- | --- | --- |
| `+5511999999999` | Ana | `A-1001` | |

- **Not sent yet?** skips rows whose `sent` column is filled in.
- **Send template** passes `name` and `orderId` as template variables. The keys of the JSON must match the template's variable names.
- **Idempotency Key** is `orderId-phone`. When n8n retries the node (it is set to try 3 times), or the workflow runs again before the sheet is updated, the API returns the first response instead of sending twice. See [Idempotency](/api/messages/send#idempotency).
- **Mark row as sent** finds the row by `orderId` and fills in `sent`.

What to change: `YOUR_SPREADSHEET_ID` (the id in the sheet's URL), the template, and the variables.

## Recipe 4: e-mail alert for failed messages

Every 15 minutes, the workflow lists the last 100 failed outbound messages and e-mails the team about each one it has not seen before.

It polls [`GET /v1/messages`](/api/messages/list) instead of listening to `message.failed`, because the webhook does not cover every case: an official number never sends `message.failed` (failures arrive inside Meta's `statuses[]`), and some failures reach no webhook at all. The log has every failure, on every kind of number.

- **One item per message** splits the API's `data` list into one item per message.
- **Only new failures** remembers the message ids it has already seen across executions, so each failure is reported once.
- The e-mail shows the `errorCode` and the reason. The [error code catalog](/api/messages/log-error-codes) explains each code.

What to change: the SMTP credential and the two e-mail addresses. To alert on Slack or Telegram instead, replace the last node.

<Note>
  On the first run every failure in the list is new, so you get up to 100 e-mails. Run it once by hand with the e-mail node disabled to fill the memory first.
</Note>

## Recipe 5: save WhatsApp Flow answers to a sheet

Each time someone submits a [WhatsApp Flow](/guides/flow-responses), the answers become a new row of a Google Sheet.

`flow.response_received` keeps the Pilot Status `{ event, data }` format even on official numbers, so here the Trigger can listen to that one event and no Normalize node is needed.

- **Answers to columns** keeps the time, the contact's number, the Flow id, and the answers as JSON text. On a Flow with a data endpoint, what the person typed is in `submitted`, one entry per screen; otherwise it is in `response`.
- **Append to sheet** writes one row per submission. Create a tab named **Flow answers** with the columns `receivedAt`, `phone`, `flowId` and `answers`.

What to change: `YOUR_SPREADSHEET_ID`. To get one column per question, replace the `answers` field with one field per answer, for example `{{ $json.data.response.nota }}`.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| The Trigger never fires | The workflow is inactive (Production URL), or the webhook was registered with the Test URL | Activate the workflow and register the **Production URL** |
| The Trigger answers `200 Ignored event` | **Event** is set to a specific event, and the delivered body is a different event or Meta's envelope | Use **All Events** and filter in the workflow |
| Button taps do nothing on a QR-code number | The Trigger listens to **Message Received** | Taps arrive as `message.reply`: use **All Events** |
| `$json.data` is `undefined` | The number is official, and the body is Meta's envelope | Add the **Normalize** node |
| `401 Invalid signature` | The **Signing Secret** does not match the webhook | Paste the current secret, or rotate it and paste the new one |
| `403 TENANT_SCOPE_NOT_ALLOWED` | Account-wide key without a number | Fill in **WhatsApp Number ID** in the credential |
| The answer comes from another number | The webhook and the credential belong to different numbers | Use the same number in both |
