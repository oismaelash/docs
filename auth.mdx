This page is written for **AI agents and developers** who need to authenticate against Pilot Status (WhatsApp messaging API). It is self-contained: everything an agent needs to obtain and use a credential is below.

## Get a credential

There is no self-registration through the API. A human creates the account and the key:

1. Sign up at [https://pilotstatus.com.br](https://pilotstatus.com.br).
2. In the panel, open **API Keys** and create a key. Keys start with `ps_` (for example `ps_workspace_...`, `ps_number_...`, `ps_account_...`).
3. Store the key as a secret (environment variable, vault). It is shown only once.

See [API keys in the dashboard](/dashboard/api-keys) and [Key types](/concepts/key-types).

## Methods

### REST API: `x-api-key`

Base URL: `https://pilotstatus.com.br/v1`. Send the key in the `x-api-key` header.

```bash
curl https://pilotstatus.com.br/v1/numbers \
  -H "x-api-key: ps_your_key"
```

Details: [API authentication](/api/authentication).

### MCP server: `x-api-key` or `Authorization: Bearer`

Endpoint: `https://mcp.pilotstatus.com.br/mcp` (Streamable HTTP). It accepts a `ps_` key in either header:

```http
x-api-key: ps_your_key
```

```http
Authorization: Bearer ps_your_key
```

Details: [MCP server](/integrations/mcp-server).

### OAuth 2.1 for MCP connectors

MCP clients that cannot hold a static key (for example claude.ai or ChatGPT connectors) use OAuth 2.1:

- Authorization server metadata: `https://pilotstatus.com.br/.well-known/oauth-authorization-server`
- Dynamic Client Registration (RFC 7591): `POST https://pilotstatus.com.br/api/oauth/register`
- Authorization code flow with **PKCE `S256`** (public clients, `token_endpoint_auth_method: none`)
- Grant types: `authorization_code`, `refresh_token`

The user signs in and consents in the browser; the connector then sends `Authorization: Bearer <access_token>` to the MCP server.

#### Scopes

| Scope | Allows |
|---|---|
| `messages:send` | Send messages |
| `messages:read` | Read message logs and content |
| `conversations:read` | Read conversations |
| `numbers:read` | List and read numbers |
| `numbers:write` | Update numbers |
| `templates:read` | Read templates |
| `templates:write` | Create and manage templates |
| `analytics:read` | Read analytics |
| `flows:read` | Read WhatsApp Flows |

A token is never issued with a scope the consenting member's role does not have.

## Using the credential

- Send it on every request; there are no sessions or cookies.
- `401` means the credential is missing, invalid, revoked or expired. OAuth clients should refresh or re-authorize.
- `403` means the credential is valid but lacks permission for that action.
- Never put a key in client-side code, URLs or logs. Rotate it in the panel if exposed.
